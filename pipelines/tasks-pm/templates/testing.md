# Тестирование — {feature}

Чеклист тестировщика. Цель — проверить фичу по сценариям и зафиксировать результат.

## Прочитать перед стартом

- [ ] `business_context.md` — цель и границы фичи
- [ ] `MANUAL_TESTING.md` — сценарии ручной проверки от аналитика
- [ ] `FIXTURES.md` — тестовые данные, аккаунты, окружение
- [ ] `IMPL_REPORT.md` — что сделано, на что обратить внимание (от кодера)
- [ ] `_secretary/` — собранный контекст

## Запуск

- [ ] Запуск приложения **согласован** с юзером (порт, окружение)
- [ ] После теста — **погасить сервер** (не оставлять висеть)

## Сценарии

- [ ] **Happy path** — основной поток работает как заявлено
- [ ] **Эджкейсы** — граничные значения, пустые/невалидные данные, ошибки сети/БД
- [ ] **Человеческие эджкейсы** — двойной клик, refresh посреди операции, back, копипаст, неожиданный порядок действий

## TEST_REPORT (заготовка)

- **Что проверено:** список сценариев
- **Результат:** что прошло / что упало
- **Найденные баги:** шаги воспроизведения, ожидаемое vs фактическое
- **Регресс:** не сломалось ли смежное
- **Вердикт:** готово к приёмке / нужны правки

## Подтверждение юзера

- [ ] Результаты показаны юзеру
- [ ] Юзер подтвердил приёмку (или вернул в работу с замечаниями)
