# Анализ — {feature}

Чеклист аналитика. Цель — выдать пакет документов, по которому кодер пишет без догадок.

## Git-проверка (перед стартом)

- [ ] `git fetch origin` + `git branch -a` — увидеть все живые ветки
- [ ] Нет ли feature-ветки с близкой темой (читать REPORT/коммиты, не описания)
- [ ] От какой базы ответвляться — уточнить, не решать самому

## Чеклист изучения

- [ ] `business_context.md` — прочитан, цель и границы фичи ясны
- [ ] `_secretary/` — собранный контекст изучен
- [ ] **Бэкенд** — какие модули/эндпоинты затрагиваются, текущее поведение
- [ ] **Фронтенд** — какие компоненты/страницы, текущее поведение
- [ ] **Переиспользование** — что уже есть в кодовой базе, что не писать заново (DRY)

## Пакет документов (сдать кодеру)

- [ ] **SPEC.md** — что строим, поведение, границы, открытые вопросы
- [ ] **TDD_PLAN.md** — сценарии (happy + edge), порядок red→green→refactor
- [ ] **CONTRACTS.md** — API/интерфейсы/типы, контракты между слоями
- [ ] **MANUAL_TESTING.md** — как проверить руками (для тестировщика)
- [ ] **FIXTURES.md** — тестовые данные, аккаунты, окружение
- [ ] **codex-ревью** пакета пройдено (второе мнение по спеке/плану)

## Узкие места

Технические риски, неизвестные, места требующие отдельного внимания при реализации.
