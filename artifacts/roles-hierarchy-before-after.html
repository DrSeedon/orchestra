Migration SQL

ALTER TABLE sessions ADD COLUMN role TEXT
  DEFAULT 'worker';
ALTER TABLE sessions ADD COLUMN parent_id TEXT
  REFERENCES sessions(name);
ALTER TABLE sessions ADD COLUMN department TEXT;

-- Migrate existing data
UPDATE sessions SET role = 'orchestrator'
  WHERE is_orchestrator = 1;
UPDATE sessions SET role = 'worker'
  WHERE is_orchestrator = 0;

Backward Compatibility

Transition Strategy

Phase 1: Add role + parent_id columns. Keep is_orchestrator as computed property: role in ('orchestrator', 'sub-orchestrator'). All existing code continues working.

Phase 2: Replace is_orchestrator checks with role checks throughout codebase. Update spawn_worker to accept role parameter.

Phase 3: Drop is_orchestrator column. Full hierarchical routing.

Role Resolution Algorithm

build_prompt(role: str) → str
def build_prompt(role: str) -> str:
    base = read("prompts/base.md")

    # 1. Check custom/ first, then built-in roles/
    role_path = f"prompts/roles/custom/{role}.md"
    if not exists(role_path):
        role_path = f"prompts/roles/{role}.md"

    role_md = read(role_path)
    frontmatter = parse_yaml(role_md)

    # 2. Load modules from frontmatter
    modules = []
    for mod in frontmatter.get("modules", []):
        modules.append(read(f"prompts/modules/{mod}.md"))

    # 3. Assemble
    return base + role_md + "\n".join(modules)

    # 4. Apply tool restrictions from frontmatter
    #    allowed_tools / disallowed_tools -> session config

Cost Comparison

Without Hierarchy

Root orch manages 8 workers directly. Context grows with each worker interaction. Orch becomes bottleneck.

~$15/task — orch spends 60% of tokens on coordination overhead

With Hierarchy

Root orch talks to 2 sub-orchs. Each sub-orch manages 3-4 workers. Context stays small at each level.

~$5/task — delegation reduces context per agent by 3x
