ALTER TABLE sessions ADD COLUMN role TEXT DEFAULT 'worker';
ALTER TABLE sessions ADD COLUMN parent_id TEXT DEFAULT '';

UPDATE sessions SET role = 'orchestrator'
  WHERE is_orchestrator = 1;

СЕЙЧАС Структура промптов

app/prompts/
├── base.md            ← общие правила для всех
├── orchestrator.md    ← 221 строка, всё в одном
└── worker.md          ← 66 строк

Проблема: orchestrator.md — монолит на 221 строку. Содержит decision tree, worker management, task management, codex review, pricing — всё в одном файле для одной роли.

Sub-orchestrator невозможен — нет промпта "может спавнить воркеров, но подчиняется другому оркестратору".

ПОСЛЕ Модульные промпты по ролям

app/prompts/
├── base.md                    ← общие правила (без изменений)
├── orchestrator.md            ← backward compat (= base-orchestrator)
├── worker.md                  ← backward compat
└── roles/
    ├── orchestrator.md      ← главный оркестратор
    ├── sub-orchestrator.md  ← мини-оркестратор отдела
    │                           spawn_worker ✅, подчиняется parent
    ├── worker.md            ← исполнитель (= текущий worker.md)
    ├── reviewer.md          ← только проверяет, не кодит
    ├── watcher.md           ← мониторинг, алерты
    └── {custom}.md          ← пользовательские роли

Принцип: prompt = base.md + roles/{role}.md + custom system_prompt при spawn.

Sub-orchestrator = orchestrator tools (spawn, kill, merge) + worker rules (report to parent). Лучшее от обоих миров.

Рольspawn_workerreport_toможет кодить
orchestrator✅userтривиал
sub-orchestrator✅parentтривиал
worker❌parent✅
reviewer❌parent❌ read-only
watcher❌parent❌ мониторинг

🔍 SEO Department — пример конфигурации

Как будет выглядеть SEO-отдел с ролями и иерархией

  • orchestrator ParsingMaxim — главный оркестратор проекта
    • sub-orchestrator seo-lead — руководит SEO-отделом
      • worker seo-analyst — анализ позиций, ключевых слов
      • worker seo-writer — генерация контента, мета-теги
      • watcher seo-monitor — еженедельный чек индексации
    • sub-orchestrator tech-lead — руководит разработкой
      • worker backend — серверный код
      • worker frontend — клиентский код
      • reviewer code-reviewer — ревью PR'ов

Конфигурация spawn

# Главный оркестратор спавнит суб-оркестратора SEO:
spawn_worker(
    name="seo-lead",
    model="opus",
    role="sub-orchestrator",          ← новое
    mcp_servers=["seo-mcp", "zahoron-api"],  ← ORC-22.1
    task="Управляй SEO-отделом...",
    system_prompt="SEO department lead...",
)

# seo-lead спавнит своих воркеров:
spawn_worker(
    name="seo-analyst",
    model="sonnet",
    role="worker",
    mcp_servers=["seo-mcp"],          ← только SEO тулы
    task="Проанализируй позиции...",
)

spawn_worker(
    name="seo-monitor",
    model="haiku",
    role="watcher",                   ← пассивный мониторинг
    task="Проверяй индексацию раз в неделю",
)
