P0 — Crash / Data Loss 7
P0 CORR compact() re-entry — _compacting cleared before ack send → recursive compact, session_id=None session.py:649 Codex ✓

compact() сбрасывает _compacting = False на строке 649 до вызова send(preamble) на строке 652. В этот момент _handle_turn_end видит _compacting=False и при высоком context запускает _auto_compact() — рекурсивный compact. Два compact'а гонятся на session_id (один обнуляет, другой читает) → session_id может стать None навсегда = полная потеря контекста.

Нет re-entrancy guard'а — оба пути (auto_compact + manual compact_worker) могут вызвать compact() одновременно.

Fix
Добавить guard if self._compacting: return в начало. Не сбрасывать _compacting до завершения ack send. Отправлять ack через backend напрямую (bypass send() который сам гейтится на _compacting).
P0 CORR compact 60s blind poll возвращает fabricated ok:True session.py:654 Codex ✓

После send(preamble) compact поллит 60 раз по 1с ожидая status=IDLE. Если ack turn не завершился (SDK hiccup) — цикл выходит по таймауту и возвращает {"ok": True} с after_pct которое может быть ложью. MCP compact_worker рапортует успех на сессию которая ещё mid-turn.

Fix
Трекать ack turn через event/future в _handle_turn_end, await с таймаутом, вернуть ok:False при таймауте вместо фейковго успеха.
P0 CORR persist race — full-row save_session из turn_end + refresh_context перезаписывает stale status session.py:421,704 Codex ✓

_persist() снимает полный снимок _to_db_dict() и пишет через executor. _handle_turn_end (строка 438) и _refresh_context_from_api (строка 704) оба зовут _persist() почти одновременно. Два снимка с разным status/cost пишутся в SQLite в произвольном порядке (executor threads) → stale status="running" может перезаписать свежий status="idle".

Fix
Serialize persists per-session (single-flight pattern), или перейти на field-scoped UPDATE для context_pct/cost вместо full-row.
P0 CORR merge holds .git lock, remove_worktree doesn't → repo corruption on merge+kill workspace.py:252 Codex ✓

merge_worktree_to_main берёт file lock .git/orchestra-merge.lock — два merge'а сериализуются. Но remove_worktree (через manager.remove()) lock НЕ берёт. Concurrent merge + kill в одном репо: git worktree remove --force может выполниться пока merge в процессе git checkout main / git stash pop → repo на wrong branch или stuck stash.

Fix
Брать тот же .git/orchestra-merge.lock в remove_worktree перед работой с worktree.
P0 REL Orphaned worktree+branch при crash create_session → повторный spawn невозможен навсегда manager.py:503 Codex ✓

Если create_session падает после create_worktree но до self.sessions[id] = session — worktree на диске и git-ветка остаются. delete_session(id) чистит только БД. Повторный spawn с тем же именем → worktree already exists → падает навсегда + ест диск.

Fix
В except блоке: if session.worktree_path: await asyncio.to_thread(remove_worktree, ...). ~5 строк.
P0 REL Zombie CLI процесс при timeout connect/reconnect — process leak backend_claude.py:128 Codex ✓

connect() делает self._client = self._make_client() затем await client.connect() с таймаутом. При TimeoutError _client уже создан с живым subprocess, но disconnect() не зовётся → CLI zombie висит до смерти сервера. То же в reconnect().

Fix
try/except вокруг connect: except: await self._client.disconnect(); self._client = None; raise. ~6 строк.
P0 ARCH restart_cli вызывает несуществующий _disconnect_client → 500 на каждый клик main.py:558 Codex ✓
