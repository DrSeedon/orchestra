Prompt Restructuring Plan

Current prompt system analysis, problems found, and concrete restructuring plan based on Anthropic best practices and multi-agent prompt engineering guidelines.

1. Current State

File Structure

app/prompts/ ├── base.md 45 lines — shared by all ├── orchestrator.md 201 lines — orch role body ├── worker.md 95 lines — worker role body ├── roles/ │ ├── orchestrator.md 12 lines — frontmatter only │ ├── worker.md 11 lines — frontmatter only │ └── full-cycle.md 95 lines — frontmatter + body └── skills/ ├── html-artifacts.md 63 lines └── vps-deploy.md 58 lines

Assembly Formula

SYSTEM_PROMPT =
  base.md                    # platform basics, MCP, rules
  + roles/{role}.md body     # role-specific behavior
    ↳ fallback: orchestrator.md | worker.md
  + [orchestrator only]:
    + roles catalog           # auto-generated from roles/*.md
    + skills catalog           # auto-generated from skills/*.md
    + other orchestrators list # dynamic from DB
    + current workers list     # dynamic from DB

Skills now injected as native files in worktree/.claude/skills/ (not in system prompt).

2. Problems Found

Structural

Confusing dual-file pattern

roles/orchestrator.md = frontmatter-only stub that points to orchestrator.md via prompt: orchestrator.md. Same for worker. Two files to express one role. full-cycle.md does it right — frontmatter + body in one file.

Structural

No XML tags

Anthropic recommends XML tags (<instructions>, <context>, <rules>) for Claude prompts — 20-40% more consistent outputs. Current prompts use plain markdown headers only. Claude can confuse instructions with examples.

Content

Monolithic orchestrator prompt

201 lines covering: decision tree, task management, worker lifecycle, naming conventions, system_prompt examples, workflow, context management, conflict rules, production safety, pricing… All in one file with no clear section boundaries.

Content

No priority hierarchy

Critical rules ("NEVER touch prod") sit at the same level as nice-to-haves ("worker naming convention"). No severity markers. Claude treats everything equally, diluting critical instructions.

Content

Duplicated content

base.md has "Global rules" + forbidden tools. orchestrator.md repeats "NEVER use built-in Agent tool". Worker.md repeats "NEVER use built-in SendMessage". Same concept, 3 places. Drift guaranteed.

Scaling

No per-project customization

All orchestrators get identical orchestrator.md regardless of project. A SEO project orchestrator gets the same 201-line prompt as an infra project orchestrator. No way to inject project-specific context into the prompt template.

3. Recommendations

Recommendation 1

XML-tagged sections HIGH

Wrap prompt sections in XML tags. Claude parses them unambiguously. Priority tags signal importance.

Example structure 
<role>
You are an orchestrator managing worker agents...
</role>

<rules priority="critical">
- NEVER touch prod while worker is fixing
- NEVER use built-in Agent tool
</rules>

<rules priority="standard">
- Keep valuable workers, kill disposable ones
- Update tasks when status changes
</rules>

<workflow>
1. Decide if you need workers...
</workflow>

<tools>
- spawn_worker(...) — description
</tools>

<context>
{{dynamic: workers list, orchestrators, etc.}}
</context>
Recommendation 2

Merge role files HIGH

Kill the dual-file pattern. Each role = one file in roles/ with frontmatter + body. Delete top-level orchestrator.md and worker.md.

Before → After
prompts/orchestrator.md ← body here prompts/worker.md ← body here prompts/roles/orchestrator.md ← frontmatter only, prompt: orchestrator.md prompts/roles/worker.md ← frontmatter only, prompt: worker.md
prompts/roles/orchestrator.md ← frontmatter + FULL body prompts/roles/worker.md ← frontmatter + FULL body prompts/roles/full-cycle.md ← already correct

Recommendation 5

Composable prompt layers LOW

Allow per-project prompt overrides via scope/.orchestra/prompt-context.md. Injected after base + role. Project-specific stack info, conventions, file boundaries.

4. Implementation Plan

  1. Merge role files (30 min, no code changes)
    Move orchestrator.md body → roles/orchestrator.md. Move worker.md body → roles/worker.md. Delete top-level files. Update _role_prompt_file() fallback logic if needed.
  2. Add XML tags to base.md (15 min)
    Wrap sections in <platform>, <mcp-tools>, <rules priority="critical">, <forbidden-tools>. Move deduplicated rules from role files here.
  3. Restructure orchestrator with XML (45 min)
    Split 201-line monolith into tagged sections. Add priority attributes. Test with real orchestrator session to verify behavior.
  4. Restructure worker with XML (20 min)
    Same XML treatment. Simpler — worker prompt is already well-organized. Remove duplicated rules that now live in base.md.
  5. Restructure full-cycle with XML (15 min)
    Already good structure. Just add XML tags and priority markers to rules section.
  6. Test with live agents (30 min)
    Spawn test orchestrator + worker, verify they follow critical rules, respond correctly to edge cases. Compare output quality before/after.

Total: ~2.5 hours. No Python code changes needed (unless file structure changes require updating _role_prompt_file logic). Pure prompt content work.
