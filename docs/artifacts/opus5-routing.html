Canary Opus 5 for Claude roles. Keep Sol as the worker default.

Opus 5 is a large, same-API-price upgrade over Opus 4.8 and is now live in Claude Code. Its relative Max quota weight is not published, and it does not make the separate Codex pool irrelevant.

Decision: canary orchestrators and existing Opus 4.8 specialists on claude-opus-5[1m] at medium effort; promote routes that pass; do not bulk-migrate Sol workers.
Benchmark correction: the DeepSWE 53.8% “max” point is Claude Sonnet 5, not GPT-5.6 Sol. The chart contains no Sol curve. The separate comparison table gives Sol 72.7% versus Opus 5 at 68.8%.

What changes

Move Claude roles

Opus 5 improves Frontier-Bench by 22.2 points, OSWorld by 14.9, DeepSWE by 9.8, and SWE-bench Pro by 10.0 over Opus 4.8, at the same API price.

Anthropic explicitly calls out judgment, multi-agent coordination, verification, long-horizon consistency, and vision—the traits Orchestra uses.

Do not replace the Sol fleet

Sol is still better on the supplied DeepSWE comparison (72.7 vs 68.8), is effectively tied on BrowseComp, and consumes a separate Codex subscription pool.

Moving routine workers to Opus 5 converts spare Codex capacity into pressure on the already scarcer Claude pool.

Orchestrator canary gate

Run

20–30 completed user turns on one top-level orchestrator, pinned to claude-opus-5[1m], medium effort.

Promote only if

No tool/stop regressions; median agentic steps ≤ +15%; cost and 5h burn per completion ≤ +25%; no missed mid-turn messages or pipeline-gate violations.

For specialist workers, run 15–20 representative matched tasks and use the same +15% step and +25% cost/quota thresholds before replacing Opus 4.8 routes.
