Что именно проверили

От текста к структуре

Чем правее, тем меньше fidelity доверено одной генерации.

BASELINE

Current

Подробный generated summary, «last 5–10 in detail», общий pre-save в четыре вида файлов.

PROMPT ONLY

Exact wording

Меняется одна строка: последние три сообщения дословно. Тип redaction всё ещё выбирает модель.

RAW USER TAIL

Mechanical recent

Последние три user strings выбираются и редактируются кодом, затем добавляются после summary.

HOT + EVIDENCE

Typed state + ledgers

Короткое горячее состояние, raw user tail, tool events, measured diff и только явно адресованный durable write.

Наблюдаемая развилка: raw user tail чинит recent; targeted promotion убирает write sprawl; tool ledger поднимает command recall до 100%. Но hot-state потерял часть старой durable preference и отрицательных file/action статусов.

Пять dev и восемь свежих holdout fixtures; три replica на вариант; CI кластеризованы по восьми fixtures. Pilot 3 calls, primary 96, idempotence 24, re-compaction 24, judges 8+8. Все before/after ledgers валидированы. Claude API-equivalent total: $23.7488; Sol — отдельный subscription pool.
Почему zero leaks не значит safe
У каждого варианта было только три exposed outputs. Даже 0/3 даёт two-sided exact 95% upper bound 70.8%. Все восемь наблюдаемых утечек у остальных вариантов попали в CLAUDE.md; две также попали в handoff.
Где hot-state терял exact
Он поднял commands до 100% и decisions до 100%, но удержал file/status anchors 66.7% против 86.1% current и user facts/preferences 50% против 100%. Самый тяжёлый кластер — recent-secret: 15/21 exact против 21/21 current.
