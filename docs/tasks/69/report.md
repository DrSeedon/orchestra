# #69 — миграция: репозиторий от git, а не от scope; parent-стратегия через границу репо

Находка из #67 (`docs/tasks/67/report.md`), направление задано оркестратором.

## 1. Репозиторий воркера

| Было | Стало |
|---|---|
| бандл: `git_at(from_host, from_scope, "bundle create …")` | `git_at(from_host, src_repo, …)`, где `src_repo` спрошен у git |
| fetch/worktree add: в `to_scope` | в `dst_repo` = `src_repo` с переписанным префиксом |
| путь: `worktrees/{slugify(scope)}/{name}` | `worktrees/{slugify(repo_root)}/{name}` — формула платформы |
| путь считался в 2 местах (`migrate_git`, `rewrite_cwd`) | считается 1 раз в `target_worktree`, переиспользуется |
| `chown` на `{to_scope}/.git` | `chown` на `{dst_repo}/.git` |

Как определяется репозиторий (`worker_repo`): `cd <worktree> && cd "$(git -c safe.directory='*'
rev-parse --git-common-dir)/.." && pwd`. Один вызов, абсолютный ответ и для связанного
worktree, и для основного. Не прочитали — фолбэк на scope **с предупреждением**, что для
вложенных репозиториев он неверен (молчаливый фолбэк здесь и был бы багом).

Добавлен гейт: нет `dst_repo/.git` на приёмнике → `die` с объяснением. Перенос воркера в
чужой репозиторий молча выдал бы ему чужую историю — это хуже отказа.

## 2. `strategy=parent` через границу репозитория

**Решение: фолбэк на mainline репозитория РЕБЁНКА, но громкий.** Обоснование:
«ответвись от ветки родителя» через границу репозитория не значит ничего — там другая
история, и ветки с таким именем в репозитории ребёнка просто нет. Отказ в спавне наказывал бы
за конфигурацию, которая сама по себе законна (`site/` и `infra/` внутри `seedon`).

Существенно, что фолбэк **узкий**: он срабатывает, только если репозитории действительно
разные. Проверка — через git (`repo_root`, новый тонкий публичный враппер над `_resolve_repo`),
а не сравнением префиксов путей: `seedon/site` лежит ВНУТРИ `seedon`, и префиксное сравнение
ответило бы «тот же репозиторий». Если репозиторий тот же — исходный `ValueError` летит наверх
без изменений: там отсутствие ветки настоящая ошибка. Не смогли определить репозитории —
считаем, что границы нет: исходная ошибка честнее выдуманного объяснения.
