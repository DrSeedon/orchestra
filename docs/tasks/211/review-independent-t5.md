При отсутствующем destination и живом stale-claim прогон молча усыновляет чужой claim.

## 2. BLOCKING — упавший install оставляет состояние, которое rollback не переваривает, и бросает файлы «на полпути»

`manage-claude-env-hook.sh:130` + `159`.

`installed.sha256` пишется только в `verify_installed_hashes` (159), ПОСЛЕ обоих
`atomic_install`. Если install умер между ними (нет места, права, любой сбой) — `STATE_DIR`
есть, `installed.sha256` нет.

Дальше rollback: первый цикл (115-125) уже увёл ОБА destination в claim-файлы, затем на 130
`expected=$(awk ... installed.sha256)` по отсутствующему файлу. Проверил отдельно: awk
фатально падает, `set -e` убивает скрипт на месте — `restore_claims` на 133 **не выполняется
никогда**:

```
до
awk: fatal: cannot open file `/tmp/definitely-missing.sha256'
exit=2        ← строка «после» не напечаталась
```

Итог: при `state=present` предсуществовавший `/etc/orchestra/claude-env.sh` не на своём месте
и не восстановлен — лежит только в `$STATE_DIR/backup/hook`, достаётся руками.

Ответ на вопрос «откат возвращает систему в исходное состояние при падении на каждом шаге» —
**нет, не на каждом**. Честно про масштаб: потери данных нет (бэкап цел), агенты не страдают
(оба файла отсутствуют → «как сегодня»), так что severity можно понизить. Но заявленный
контракт отката на этом пути не выполняется.

> Решение оркестратора: понижение severity принято, блокером оставлен — контракт заявлен
> и не выполняется, чинить будем.

## 3. BLOCKING — битый hook убивает Bash у ВСЕХ агентов, и содержимое перед установкой никто не валидирует

Замерил все четыре режима (`claude -p`, только Bash, `type grep`):

| CLAUDE_ENV_FILE | результат |
|---|---|
| не выставлен | `grep is a function` — воспроизвёл исходную проблему |
| **файла нет** | `grep is a function` + `MARKER-OK`, нормальный выход → **безопасно, ровно «как сегодня»** |
| **файл битый** | `/bin/bash: -c: line 1: syntax error near unexpected token '('`, **Exit code 2, команда агента не выполнилась вообще** |
| файл рабочий | `grep is /usr/bin/grep` — фикс работает, замер автора подтверждаю независимо |

Механизм виден в выводе: Claude Code **вклеивает содержимое env-файла прямо в строку**
`bash -c`:

```
source <snapshot> 2>/dev/null || true && this is not valid shell ((((
```

То есть худший исход — не «как сегодня», а **у каждого агента падает каждая Bash-команда**.
Планка, заданная в задании, нарушена.

Скрипт валидирует systemd-сторону (`systemd-analyze verify`, 160) и **не валидирует
shell-сторону вообще** — ни источник перед `atomic_install` (156-158), ни бэкап перед
`atomic_restore_noreplace` (169), который вернёт в этот путь произвольный предсуществовавший
файл. Закрывается одной строкой `bash -n` в обоих местах.

Смягчающее: сам скрипт битый файл породить не может — `atomic_install` ставит через temp +
`mv -f`, это атомарный rename, полуфайла читатель не увидит.

## Проверено и чисто

- Частичный откат безопасен в обе стороны. Падение между index 0 и 1 даёт «drop-in есть,
  hook-файла нет» → по замеру выше это «как сегодня». Обратный порядок убирает drop-in →
  переменная не выставлена вовсе.
- Остаточные `*.rollback-claim.<pid>`, `*.new.<pid>`, `*.restore.<pid>` в
  `/etc/systemd/system/orchestra.service.d/` **инертны**: `man systemd.unit:158` — «All files
  with the suffix ".conf" from this directory will be merged». Суффикса нет → systemd их
  не читает.
- Install не рестартует и не активирует: строка 162 дословно
  `Installed Claude env hook; Orchestra restart is required and was NOT performed`.
- `CLAUDE_ENV_FILE` реально поддерживается этой сборкой CLI — строка найдена
  в `/usr/lib/node_modules/@anthropic-ai/claude-code/bin/claude.exe`.

## suggestion

`manage-claude-env-hook.sh:177` — единственный оставшийся `mv -T` без no-clobber
(`removed/$key`) в скрипте, весь смысл которого в no-clobber. Сценарий потери построить
не смог: повторный откат раньше падает на hash-сверке. Стоит выровнять ради одного правила
на весь файл.
