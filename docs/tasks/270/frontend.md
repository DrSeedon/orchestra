# #270 — дашборд во время перезапуска Orchestra

Повод: юзер перезапустил Orchestra, написал «ау» и получил в чат
`503: {"error":{...,"code":"restart_pending",...}}`.

## Почему страница «немела», а оверлея не было

Отказ ставит только `RequestCensusMiddleware` и только МУТИРУЮЩИМ вызовам
(`mutating_admission_verdict`, `app/main.py:134`). Чтения при этом идут нормально, поэтому
существующий контур («сервер не отвечает» → полноэкранный оверлей `_showRebootOverlay` →
`_pollReconnect` → `_recoverAfterOutage`) в фазе `restart_pending` не срабатывает вовсе: сервер
жив и отвечает. Видимым признаком оставался текст ошибки в чате — сырой служебный JSON.

## Что сделано (`app/static/js/app.js`, +54)

- `api()`: на `!resp.ok` тело читается один раз; `_restartPendingFromBody(status, text)`
  (`status === 503` и `error.code === 'restart_pending'`, разбор через `JSON.parse`, не подстрокой)
  → `_setRestartPending(true)` и `Error` с человеческим текстом и `name = 'RestartPendingError'`.
  Это единственный существующий путь ответов — своего опроса не заводим.
- Полоса `#restart-banner` строится в JS (шаблон доехал бы до юзера только рестартом — тем самым,
  про который она и рассказывает). Класс — как у соседних полос, намеренно НЕ красная:
  «⏳ Orchestra перезапускается — отправка на паузе, вызовы отклоняются ДО изменений. Вернётся
  сама, перезагружать страницу не нужно». Скриншот: `restart-banner.png`.
- `updateInputState()`: при паузе поле и кнопка недоступны, placeholder «Идёт перезапуск
  Orchestra…». `sendChat()` дополнительно выходит сразу — страховка от Enter.
- Снятие паузы, три пути:
  1. `_recoverAfterOutage()` — перезапуск состоялся, сервис ушёл и вернулся. Это штатный конец;
     оверлей и поток событий уже умеет существующий контур, страница живёт без перезагрузки.
  2. Заголовок `X-Orchestra-Restarting: 1|0` на ответе heartbeat — признак в обе стороны, ждём
     от серверной части #269 (запрошен у `back`). Пока его нет, ветка просто не срабатывает.
  3. Потолок `_RESTART_PENDING_MAX_MS = 120000` — перезапуск может НЕ состояться: `restart_preflight`
     не сливает хвост мутаций, зовёт `open_mutating_admission()` и молча продолжает работу, не
     сказав об этом ни одному клиенту. Без потолка полоса висела бы вечно.

Спавн и мерж блокировать нечего: в дашборде их кнопок нет (`grep` по `dashboard.html` и
`app.js` — только рендер названий тулов). Единственное мутирующее действие юзера — отправка.

## Проверка

`tests/test_frontend.py`, два новых теста + помощник `_open_restart_page` (все `/api/` идут через
управляемый обработчик):

  дословный отказ сервера → полоса, недоступные поле и кнопка, человеческий текст в чате без
  `restart_pending` / `{"error"` / `503`, оверлея НЕТ (сервер отвечает). Затем сервис уходит

## Грабли этой задачи (обе поймались прогоном, обе стоили по заходу)

- **Ронять в симуляции один маршрут недостаточно.** Сначала я отдавал 502 только на
  `/api/models` (туда смотрит heartbeat) — оверлей не появился ни разу: соседний успешный
  `/api/sessions` каждые 3 с зовёт `_onServerOk()`, а тот обнуляет `_rebootFails`. Перезапуск
  роняет ВСЕ запросы разом, симуляция обязана делать то же.
- **Ассерт «сырого JSON нет» нельзя ставить по всему `#chat`.** В живой истории агента лежит
  сообщение ТОГО САМОГО инцидента, ради которого задача и заведена, — проверка краснела на
  чужом тексте. Целиться надо в свой узел (последний с нашей фразой).

## Границы

- Новых классов Tailwind нет (переиспользованы классы соседних полос) — `build-tailwind.sh` не нужен.
- Заголовок `X-Orchestra-Restarting` — зона `back` (#269). Без него пауза снимается возвратом
  сервиса или потолком в 2 минуты; с ним состояние становится однозначным и видно даже странице,
  загруженной посреди перезапуска.
