# #66 — статус `broken` виден в дашборде

Серверная половина (#62) отдаёт `broken` для сессии, чей `worktree_path` не существует.
Фронт этого значения не знал и красил такую сессию серой заглушкой `●`.

Цена молчания известна: 04.08 семь воркеров seedon двое суток числились `idle` с живым
ctx%, и это выяснилось только когда в них полетела задача.

## Проверка граблей ДО правки: сколько владельцев у статусов

Грепнул все перечисления статусов в `app/static/js/*.js`. Оказалось лучше, чем в прошлый
раз: четыре словаря (`_STATUS_ICON`, `_STATUS_COLOR`, `_STATUS_BG`, `_STATUS_TITLE`) —
уже ЕДИНЫЙ владелец и для вкладок (`_paintStatusDot`), и для списка агентов
(`renderAgentItem`). Добавление ключа в них закрывает оба места сразу.

Нашлась ровно одна вторая копия — инлайн-словарь цветов в отрисовке вывода
`mcp__orchestra__get_worker_info` (`{'running':…,'idle':…,'error':…,'stopped':…,'starting':…}`).
Свёл к общему владельцу: недостающие ключи (`error`, `stopped`, `starting`) добавлены
в `_STATUS_COLOR`, инлайн-словарь удалён. Теперь перечисление статусов в `app.js` одно.

## Что сделано

- `broken` добавлен во все четыре словаря: иконка `⛔`, цвет `#ef4444`, фон
  `rgba(239,68,68,0.15)`, подпись «broken — worktree агента не существует: задачу слать
  бесполезно, нужен спавн заново».
- Красный, а не серый, выбран намеренно: серый в этом интерфейсе означает «нет данных»,
  а здесь данные есть и они плохие.
- `_orchState` проверяет `broken` ПЕРВЫМ: у сломанного worktree `running`/`any_running`
  ничего не значат, и вкладка не должна светиться зелёным.
- Подпись `title` теперь ставится и в списке агентов — наведение объясняет, что делать.

## Проверка глазами

`docs/tasks/66/broken-badge.png` — `back` с красной плашкой `⛔ broken` среди зелёных
`⚡ running` и жёлтого `☕️ idle`. Замер со страницы:

```
подмена app.js: 1× | статус подставлен агенту: back
плашка: text='⛔ broken', color=rgb(239,68,68), bg=rgba(239,68,68,0.15),
        title='broken — worktree агента не существует: задачу слать бесполезно…'
```

**Отклонение от буквы задания, намеренное:** просили подставить несуществующий
`worktree_path` в read-only копии БД. Живой сервер на копию не переключить (это рестарт
с другим `ORCHESTRA_DB_PATH`), поэтому `status: "broken"` подставлен в ответ
`/api/sessions` перехватом — то есть ровно то значение, которое сервер вычисляет сам
через `_display_status()`. Проверяется отрисовка, а логика сервера уже покрыта #62.
Счётчик срабатываний подмены печатается рядом с результатом.

## Про барьер `exclude-newer` в `uv.lock`

Просили восстановить из main, потому что «на ветке барьера нет». **Проверил — премиса не
подтвердилась:**

```
моя ветка:  grep -c exclude-newer uv.lock  → 1
main:       git show main:uv.lock | grep -c → 1
git diff HEAD main -- uv.lock                → пусто (файлы идентичны)
git log main..HEAD -- uv.lock                → пусто (ветка файл не трогала)
```

Main подтянут в ветку по указанию; после мержа барьер на месте, `uv.lock` по-прежнему
совпадает с main байт в байт. Восстанавливать нечего.
