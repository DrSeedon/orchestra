# #126 Phase 2 — план фикса `_prompt_injected` после сжатия

**Границы:** `app/session.py` — моя зона. `app/backend_claude.py` — зона
`prompt-engineer`, **не трогаю**. Codex не зову (квота), ревью делает оркестратор.

---

## Уточнение механизма — фикс НЕ там, где мы втроём предполагали

Перед тем как писать код, проследил путь целиком. Картина точнее, чем в моём
research.md, и это **меняет и место фикса, и его цену**.

### Что происходит на самом деле

1. `compact()` на 1344 зовёт `_ensure_backend(force_fresh=True)`.
2. `force_fresh=True` → `_make_backend(force_fresh=True)` → `resume_session_id=None`
   (`session.py:557`).
3. `resume_id` пуст → `backend_claude.py:167-168` уходит в **ветку `else`** и
   **выставляет `options.system_prompt`** с преcетом и нашим `append`.

**Вывод: ack-ход после сжатия системный промпт ПОЛУЧАЕТ.** Утверждение «сессия
живёт на нативном session, куда системный промпт не передавался никогда» — для
самого ack-хода **неверно**.

### Где роль теряется на самом деле

Потеря отложенная, на **следующем** подключении:

4. В ack-ходе `turn_end` присваивает `self.session_id` новый нативный id (1273).
5. Backend живёт до ближайшего `_disconnect_backend()` — гибернация (idle),
   `stop()`, ретрай на 1430, рестарт Orchestra.
6. Следующий `send()` зовёт `_ensure_backend()` **без** `force_fresh` →
   `resume_session_id=self.session_id` → ветка `if resume_id:` →
   **`system_prompt` не задаётся вообще**.
7. Компенсация на `:680` требует `not self._prompt_injected`, но флаг остался
   `True` с `:771` — **инжект не срабатывает**.

**Итог: роль теряется не в момент сжатия, а на первом реконнекте после него.**
Это ровно тот дефект, что описал `prompt-engineer`, но точка отказа — шаг 6-7,
а не ack-ход. Практический эффект тот же и масштаб тот же (34 живые сессии),
поэтому вердикт «чинить» не меняется.

### Почему это важно для выбора решения

Раз ack-ход и так получает системный промпт, **вариант «передавать `system_prompt`
при resume» решает задачу дважды** для post-compact-случая. А главное — он в
`backend_claude.py`, то есть не в моей зоне.

## Оценка двух путей (пункт 2 задания)

| | **A. Сброс `_prompt_injected` в `compact()`** | **B. `system_prompt` при resume** |
|---|---|---|
| Файл | `app/session.py` (**моя зона**) | `app/backend_claude.py` (**зона #125**) |
| Размер | 1 строка | правка ветвления опций |
| Цена | ~270k input **один раз** после сжатия, `cache_read` жив | 0 доп. токенов |
| Риск | нулевой, механизм уже работает на резюме | **высокий, см. ниже** |
| Покрытие | только post-compact | все резюмы |

### Почему B не «просто дешевле»

Дока (`prompt-caching`, primary): системный промпт — **первый слой префикса**, и
«a change to the system prompt invalidates everything». Сейчас на резюме мы его
**не шлём**, и префикс совпадает с тем, что CLI восстановил из своего транскрипта.
Начать слать его на каждом резюме — значит на **каждом** реконнекте рисковать
несовпадением префикса и обнулением кеша целиком. Замер #125 (`cache_read` 0.889
на инжект-ходе) показывает, что нынешний путь **кеш не рушит**; за B такого
замера нет.

То есть B меняет цену «270k input один раз после сжатия» на «возможный полный
промах кеша на каждом резюме». При наших числах (обычный ход читает 95.9% из
кеша) это потенциально **дороже**, а не дешевле. Плюс B — это правка контракта
резюма для **всех** сессий, включая те, что сжатия не проходили.

### Выбор: A

Обоснование: единственная зона риска — стоимость, она **измерена и ограничена**
одним ходом; кеш при этом жив (0.889). B дешевле по токенам, но платит риском
инвалидации всего префикса на каждом резюме, не подтверждён замером, и лежит вне
моей зоны. **Беру A. Если оркестратор захочет B — это отдельная задача для
`prompt-engineer` с обязательным замером cache_read до/после.**

Стоимость A в контексте: ~270k input ≈ **$1.35** по Opus $5/M **в худшем случае
полного промаха**; при живом кеше (0.889 read) реально ≈ **$0.30**, один раз на
сжатие. Против этого — агент, работающий без роли неопределённо долго. Размен
очевиден.

## Тикеты

### T1 — сбрасывать `_prompt_injected` при смене session_id в `compact()`
- **Files:** `app/session.py` (`compact()`, рядом с 1375-1385, после успешного ack)
- **Что:** после успешного сжатия выставить `self._prompt_injected = False`, чтобы
  первый `send()` после реконнекта переинжектил роль по существующему пути `:680`.
  Ставить **только на успешном пути** — ветки отказа (`abort_compact`, таймаут ack,
  лимит) возвращают старую сессию и переинжект им не нужен.
- **Почему именно там:** это единственная точка, где `session_id` меняется на
  нативный без прохождения через `:1588`. Существующий механизм инжекта не
  трогаем — только снимаем флаг, который его блокирует.
- **AC:**
  1. после успешного `compact()` `_prompt_injected is False`;
  2. на ветках отказа компакта флаг **не** сбрасывается (иначе лишние 270k на
     ровном месте после неудачи);
  3. первый `send()` после успешного компакта содержит
     `[Orchestra platform note:` и текст `_current_prompt`;
  4. существующие тесты `tests/test_session.py` зелёные.
- **blocked-by:** none

### T2 — регрессионные тесты
- **Files:** `tests/test_session.py`
- **Что:** тест-кейс, доказывающий пункт 3 (роль снова в промпте после сжатия) —
  требование оркестратора №3.
- **AC:**
  1. тест падает на коде **до** T1 и проходит после (проверить мутацией);
  2. отдельный кейс на ветку отказа: компакт не удался → флаг не тронут;
  3. фулл-сьют зелёный под тест-локом.
- **blocked-by:** T1

## Риски
- Сброс флага на успешном пути даёт один дорогой ход после **каждого** сжатия.
  Измеренная граница — 270k input при живом кеше; это приемлемо и обратимо
  (revert одной строки).
- Если сессия после компакта так и не реконнектится (backend жив до самого
  конца), переинжект не случится вовсе — флаг просто останется `False` без
  последствий. Это не регресс: сейчас в этом случае роль тоже есть, из ack-хода.
