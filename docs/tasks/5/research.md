## Что происходит при вставке (`handlePaste`, app/static/js/app.js:2235)

```js
const oldText = input.value;
input.value = oldText + '\n⏳ uploading image...';   // textarea захвачена
await fetch('/api/upload', {method:'POST', body: formData});
input.value = oldText + '\n' + data.path;            // ← всё, что напечатали, стёрто
```

Установлено по коду, до замеров:

1. **base64/FileReader в этом пути НЕТ.** Файл уходит как `FormData` (бинарный multipart),
   `item.getAsFile()` отдаёт готовый Blob из буфера обмена. Значит «чтение файла в браузере»
   как статья расхода отпадает — проверить замером, но кандидатов на узкое место остаётся два:
   сеть и повторное скачивание превью.
2. **Превью качает ту же картинку обратно с сервера.** `showImagePreview(data.url, …)` ставит
   `img.src = '/uploads/<md5>.png'` — второй полный перегон тех же байтов по сети. На канале, где
   TTFB 0.69–0.96 с, это удваивает ожидание. Локально видно не будет, мерить с эмуляцией канала.
   Лечится `URL.createObjectURL(file)` — ноль сети.
3. **Ввод запирается не «блокировкой», а перехватом `value`.** Печатать физически можно, но
   набранное после вставки затирается строкой `oldText + data.path` по возврату fetch. Это
   потеря текста, а не косметика.
4. **Ошибка проглатывается молча.** `catch { input.value = oldText; }` — ни строки юзеру.
   А если сервер вернул JSON без `path` (400: `file too large`, запрещённое расширение), не
   срабатывает даже catch: в textarea навсегда остаётся `⏳ uploading image...`.
5. **Рядом уже есть правильный образец** — drop-путь: `_handleChatDrop` дописывает через
   `_appendDroppedPath` (`input.value +=`, без затирания), проверяет `resp.ok`, `data.path` и
   показывает `_showChatDropError('Upload failed — …')`. Чинить paste надо этими же двумя
   функциями, а не новым механизмом.

## Сервер (`app/routes/tg.py:17`)

`content = await file.read()` (целиком в память) → md5 → запись, если файла нет → `_cleanup_uploads()`
синхронно в запросе. Сейчас в `data/uploads/` 1 файл на 28 КБ при лимите 1 ГБ, то есть уборка =
один `iterdir` + `stat`, доли мс. Кандидат на медленность — только при разрастании каталога.
