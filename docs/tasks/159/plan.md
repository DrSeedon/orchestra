## Approach

**Самодостаточный минимум + ссылка за подробностями.** Не чистый указатель (риск: агент без
доступа к репозиторию Orchestra упрётся в никуда) и не копия 564 строк (риск: вторая копия
разойдётся с оригиналом — грабля «одна мысль = один owner»).

**Критерий приёмки формы, заданный оркестратором:** агент БЕЗ доступа к репозиторию Orchestra
должен по одному скиллу дойти до работающего оркестратора на VPS. Всё сверх этого — ссылка.

Ссылка даётся **публичным URL**, а не путём в ФС (документ в `main` публичного
`github.com/DrSeedon/orchestra` — проверено `git cat-file -e`), поэтому работает у агента
любого проекта.

### Что входит в самодостаточный минимум (по решению оркестратора)
1. Хост `158.220.127.161` + вход `ssh root@`, дальше `su -s /bin/bash kesha` (без `-s` виснет)
2. Куда класть проект: `/home/kesha/projects/<name>`
3. Прокси НЕ нужен + обоснование замером (405 за 53 мс без прокси); прокси-строки из `.env`
   ноутбука закомментировать
4. Имя оркестратора `<проект>-orchestrator`, scope = каталог проекта, модель с `[1m]`
5. Личная память подхватывается по совпадению ИМЕНИ агента
6. Аутентификация — подписка, отдельный ключ не заводить
7. Приёмка: чем доказать, что переехало (проверки с разным выводом при успехе/провале)

### Что НЕ копируем (ссылкой)
systemd-юниты, точка отката, 37 граблей, ручной путь заведения сессии через `save_session`,
`migrate_agent.py` в деталях, сброс протухшей сессии.

### Чего в скилле не будет
- ссылок на `orchestra-agents` и `vps-deploy` — их не существует (Finding 3);
- дефекта `MemoryHigh`/`MemoryMax` в tmpfs — по прямому указанию оркестратора, он уйдёт
  отдельной задачей;
- хардкода `/mnt/data/...` — известная грабля мёртвых на сервере скиллов.
