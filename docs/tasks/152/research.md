## Разбор

### 1. Зеркало AGENTS.md — ЕДИНСТВЕННАЯ реальная находка. ПЕРЕХОДИТЬ

Codex умеет читать `CLAUDE.md` напрямую. Проверено на 0.145.0 в чистом репозитории:
```
без настройки:                                    маркер найден 0 раз
-c project_doc_fallback_filenames=["CLAUDE.md"]:  маркер найден 1 раз
```
Это ровно та потребность, ради которой написан `sync_agents_md` (50 строк + tmp+mv +
`tracked_paths`-гейт + вызов на каждом реконнекте).

**Замер применимости:** в живых воркти **31 файл `AGENTS.md`, из них наших зеркал — 31,
собственных трекнутых — 0.** То есть настройка покрывает 100% случаев, а гейт «не трогать
чужой AGENTS.md» защищает от ситуации, которой сейчас не существует ни разу.

**Проверенное ограничение (важно для плана):** это **fallback, а не override**. Когда в
каталоге есть ОБА файла, выигрывает `AGENTS.md`:
```
AGENTS.md + CLAUDE.md → в промпт попал AGENTS-MARKER, не CLAUDE-маркер
```
Следствие: просто добавить настройку недостаточно — старые зеркала придётся удалить, иначе
Codex продолжит читать именно их, и мы получим «настройка есть, а поведение прежнее».

**Цена:** настройка живёт в `~/.codex/config.toml` — вне репозитория. На VPS и новой машине
её надо выставлять отдельно, иначе Codex-агенты молча останутся без проектных правил. Это
тот же класс, что `project_doc_max_bytes` (уже обожглись: 32 KiB против 96 KiB).

### 3. Субагенты — ОСТАВИТЬ. Постановка задачи содержит фактическую ошибку

**Мы НЕ запрещаем встроенные субагенты.** Запрет распространяется только на оркестраторов
(`app/backend_claude.py:63-71`), воркерам Task/Agent доступны. Более того, тотальный бан
**обсуждался и был отменён юзером** — `docs/tasks/no-subagents/research.md` (2026-07-01):
«бан = деградация (агент натыкается на deny, костылит)». Направление сменили на «сделать
субагентов видимыми» (`subagent-visibility`, `subagent-telemetry`).

**Замер реального использования (и ловушка, в которую я едва не попал):**
```
subagent_start всего:              1681
  из них type=local_bash:          1677   ← фоновый bash, НЕ субагенты
  настоящих субагентов:               4   ← все у роли full-cycle
spawn_worker:                        89
```
Первый прогон дал «615 субагентов у оркестраторов», что противоречило бы запрету. Причина —
один тип события используется для двух разных вещей. Вывод из сырых данных: воркеры
built-in субагентов почти не зовут, хотя им **можно**. Значит проблема не в запрете.

**Проверка обоснования запрета (как требовал оркестратор — не по аналогии со скиллами):**
нативные механизмы существуют и это надо признать: `claude --worktree`, `isolation: worktree`
в `~/.claude/agents/*.md`, подкоманда `claude agents` с `--model/--effort/--mcp-config/--cwd`.
`claude agents --json` даже видит наши живые сессии. Но покрытия потребности нет:

| потребность Orchestra | `claude agents` | замер |
|---|---|---|
| переживать простой процесса | ✗ реестр процессный | **72 idle-сессии** при 8 живых процессах `claude`; натив показал 2 |
| Codex-агенты | ✗ структурно невозможно | **7 живых Codex-сессий** |
| учёт \$/токенов/turns | ✗ в JSON нет | в БД: `cost_usd`, `total_turns`, `context_pct` на сессию |
| иерархия и адресация | ✗ | `parent_name`, `task_id`, `send_message` между агентами |

Итог: `claude agents` — это «покажи запущенные процессы», а `spawn_worker` — «создай
персистентного агента с бюджетом, историей и адресом». Похоже по названию, не покрывает по
сути. **Обоснование запрета для оркестраторов подтверждено, но формулировка в комментарии
кода неточна:** там сказано «bypass Orchestra's worktree isolation», хотя изоляцию CLI
как раз умеет; настоящая причина — учёт, персистентность и кросс-рантайм.

### 6. Не используем вовсе — НЕ ПРИМЕНИМО

`codex plugin` + marketplace — механизм установки ЧУЖИХ плагинов из snapshot'ов
(`add/list/marketplace/remove`). Мы ничего эквивалентного не строим: наши скиллы едут
из репозитория пайплайна. Это не «костыль поверх готового», а другая задача.
Слэш-команды/output styles — интерактивные удобства TUI; наши агенты неинтерактивны.

## Counter-evidence и риски

- **Против п.1:** удаление зеркала завязывает работу Codex-агентов на файл вне репозитория
  (`~/.codex/config.toml`). Сейчас зеркало самодостаточно: воркти уехала на другую машину —
  правила уехали с ней. После перехода — нет. Это реальный минус, а не формальность.
- **Против п.3:** я мерил `claude agents --json` на машине с 8 живыми процессами. Возможно,
  под нагрузкой он показывает больше. Но структурные пробелы (Codex, стоимость, idle) от
  нагрузки не зависят — они архитектурные.
- **Ограничение всего аудита:** проверено на ОДНОЙ машине и ОДНОЙ версии каждого CLI.
  `--help` неполон (доказано в #151), поэтому «не нашёл механизм» ≠ «механизма нет».
  Там, где я утверждаю отсутствие, я опирался на `features list` и поведение, но
  исчерпывающего перебора возможностей CLI не делал.

## Рекомендация

**Одна задача к реализации: п.1.** Остальное — обосновано либо уже закрыто. Это близко к
отрицательному результату, который оркестратор просил принять честно: из шести кандидатов
пять не подтвердились, и два из них (2 и 4) были закрыты нами же ранее.

Порядок для будущего тикета:
1. Выставить `project_doc_fallback_filenames=["CLAUDE.md"]` в `~/.codex/config.toml`
   (и задокументировать для VPS — иначе тихая потеря правил).
2. Удалить зеркала — **иначе настройка не даст эффекта** (AGENTS.md выигрывает у fallback).
3. Удалить `sync_agents_md` и вызовы; `AGENTS.md` убрать из `_WORKTREE_EXCLUDES`.
4. Приёмка: `codex debug prompt-input` из живой воркти показывает содержимое `CLAUDE.md`
   при ОТСУТСТВУЮЩЕМ `AGENTS.md`; чужие репозитории — AFTER == BEFORE.
