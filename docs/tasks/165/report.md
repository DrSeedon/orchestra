## Проверка фактом

Правились документы, кода нет — поэтому «тесты» здесь это проверка того, что документированный
путь работает. Всё снято на ЖИВОМ локальном инстансе `127.0.0.1:8888`, без рестарта; боевой
Contabo — только read-only.

**Прогон 1 (исследование, research.md):** проба ответила `PROBE-165-ALIVE`, 1 turn, свой
`session_id`. Различающая проверка: ручной `INSERT` её бы провалил.

**Прогон 2 (приёмка скилла):** взял **дословно то тело запроса, которое написано в скилле**, и
отправил на живой API:

```
POST /api/sessions ← JSON из раздела 4 скилла, как есть
→ 201
  {'name': 'probe165b-orchestrator', 'status': 'idle', 'role': 'orchestrator',
   'is_orchestrator': True, 'tg_topic': True}
```

Подтвердились три утверждения скилла разом: тело валидно, роль оркестратора выставляется,
`tg_topic` включается САМ (в скилле написано «не передавай, платформа включит сама»).

Личная память в том же прогоне: файл `docs/workers/probe165b-orchestrator.md` с маркером
`MEM-165B` положен ДО вызова → `grep -c MEM-165B` по `system_prompt` из БД → **1**.

**Уборка после обоих прогонов:** сессии удалены, строки `sessions`/`logs`/`inbox` вычищены
(`SELECT count(*) WHERE name LIKE '%probe165%'` → `0`), git worktree снят платформой,
скретч-каталоги отправлены в корзину через `gio trash`. Живой сервис не рестартился ни разу.

## Breaking

Ломающих изменений в коде нет — код не трогал. Меняется рекомендованный ПОРЯДОК ДЕЙСТВИЙ:
- Штатный переезд больше НЕ требует `systemctl restart orchestra` и окна на общем сервере.
- Штатный переезд больше НЕ везёт транскрипт. Кому нужна память диалога — сноска про скрипт.
- `scripts/migrate_agent.py` не удалён и не изменён.

## Что осталось за рамками

- **#163** (лишние секреты/IP в публичном документе) не трогал — отдельная задача, смешивать
  запрещено заданием. Новых секретов не добавил.
- **Ветка воркера с уже сделанной работой** осталась на уровне LIKELY: `create_worktree`
  переиспользует существующую ветку (`workspace.py:522-535`), но замер делался на свежей.
  Именно поэтому в скилле стоит жёсткое «мержи ДО переезда», а не «подхватится» — по прямому
  решению оркестратора.
- **Реальный переезд VPN-Service** по новому пути не выполнялся: задача была про скилл.

## Найденные проблемы (не чинил, фиксирую)

- **`GET /api/sessions/{name}` режет `system_prompt` до 500 символов** (`to_dict`). На проверке
  «подхватилась ли память» это даёт ОДИНАКОВЫЙ ответ при успехе и провале — ровно тот класс
  проверки, который проект считает не проверкой. Меня это чуть не увело в ложный вывод (см.
  research.md, контр-свидетельство 1). Ground truth — поле из БД. Не баг платформы в смысле
  `report_bug` (обрезка намеренная, экономит трафик дашборда), но грабля для любого агента,
  который будет проверять промпт через API.
