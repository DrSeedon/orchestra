# #146 — зеркало orc.seedon.ru: обход обрыва 16 КБ

Решение проблемы из #142/#143. Дашборд остаётся на Contabo, московский сервер
(89.23.102.244) передаёт байты. Фильтр решает по адресу назначения — меняем
назначение на российский адрес, обрыв исчезает.

**Итог: 0 обрывов из 12 через зеркало против 3 из 12 напрямую в том же прогоне,
и при этом зеркало БЫСТРЕЕ прямого пути.**

## Приёмка замером

Один и тот же `app.js` (378876 байт), 12 проб каждый, прогоны чередовались.

| путь | обрывов | медиана | разброс |
|---|---|---|---|
| **зеркало `orc.seedon.ru`** | **0 из 12** | **0.79 с** | 0.73–0.95 |
| прямой `orchestra.seedon.ru` (контроль) | 3 из 12 | 1.12 с | 1.00–15.0 |

Базы до правки: 6 из 8 и 5 из 12 обрывов на прямом пути. Контроль в том же
прогоне обязателен — сеть плавает (в #143 ловил 7/8 → 2/8 → 11/16 за час),
без него нельзя отличить эффект зеркала от погоды.

### Латентность: лишний хоп не замедлил, а ускорил

Ожидание было «браузер → Москва → Франция = медленнее». Факт обратный:
**0.79 с против 1.12 с.** Причина в том, что прямой путь даже без полного
обрыва теряет пакеты и тратит время на восстановление, а участок
Москва↔Contabo чистый (5/5 за 0.39–0.62 с). Три пробы из 12 на прямом пути
упирались в 15 с — это они и растягивают хвост.

## Что сделано

Один новый файл `/etc/nginx/sites-available/orc-mirror` + симлинк.
**Существующие конфиги не изменялись.** Бэкап: `/root/nginx-backup-146/`.

Ключевые решения, которых не было в постановке:

1. **`proxy_ssl_server_name on` + `proxy_ssl_name orchestra.seedon.ru`.**
   Апстрим — HTTPS, а не локальный порт. Без SNI рукопожатие к Contabo уходит
   безымянным, и тот отдаёт дефолтный виртуалхост вместо дашборда.
2. **`Connection ""`, а не `"upgrade"`.** В соседнем `orchestra-clients` стоит
   безусловный `"upgrade"`; для SSE это неверно — SSE обычный GET, не апгрейд.
   Копирование чужого блока дало бы неочевидную поломку потока.
3. `proxy_buffering off` + `proxy_read_timeout 86400s` — иначе поток событий
   копится в буфере nginx и приходит пачками или рвётся.

## Проверки живьём (не чтением конфига)

- **SSE держится 30 секунд**, `code=200`, соединение не закрылось само.
  События приходят инкрементально с таймингами 10.12 → 10.14 с, не одной пачкой:
  ```
  [10.12] data: {"type": "__session", "session_id": "75285d62-..."}
  [10.13] data: {"id": 15807, ...}
  [10.13] data: {"id": 15808, ...}
  ```
  При `after_id=99999999` поток корректно ЖДЁТ новых событий, а не закрывается.
- **Логин работает**, кука ставится на хост зеркала:
  `set-cookie: session=...; HttpOnly; Max-Age=2592000; Path=/; SameSite=lax; Secure`.
  Явного `Domain=` в `app/routes/system.py:92` нет → кука host-scoped и
  приклеивается к `orc.seedon.ru`. Дашборд с кукой отдаёт 200 и 23958 байт.
- **API через зеркало**: `/api/sessions` 242145 байт за 0.92 с (объём сильно
  больше порога 16 КБ, проходит целиком), `/api/orchestrators` 56320 б,
  `/api/stats` 200.

## Соседи не задеты

| хост / сервис | до | после |
|---|---|---|
| `test.seedon.ru` (клиентский, бэкенд 18001) | 302, 0.43 с | 302, 0.45 с |
| `test123.seedon.ru` | 404, 0.65 с | 404, 0.28 с |
| `seedon.ru` | — | 200, 0.42 с |
| xray на 2053 | слушает | слушает |
| порт 18001 | слушает | слушает |

Ловушка с wildcard не сработала: `orchestra-clients` — это
`map $host $backend_port` с `default 0 → return 404`, и в мапе единственная
запись `test.seedon.ru`. То есть wildcard-блок и до нас никого, кроме одного
хоста, не обслуживал. Точный `server_name orc.seedon.ru` приоритетнее wildcard —
подтверждено живым запросом, а не логикой.

`nginx -t` перед reload прошёл (предупреждение про `ssl_stapling` —
предсуществующее, из клиентского блока). Использован `reload`, не `restart`:
не рвёт живые соединения соседей.

## Что это НЕ чинит

- Причина обрыва никуда не делась — прямой `orchestra.seedon.ru` рвётся
  по-прежнему. Зеркало её обходит, а не устраняет. Обращение в Contabo из
  отчёта #143 остаётся актуальным.
- Зеркало — единая точка отказа: ляжет московский сервер, и дашборд
  недоступен по `orc.seedon.ru` (прямой адрес продолжит работать как есть).
- Трафик дашборда теперь идёт через машину с клиентскими сайтами. Нагрузка
  копеечная (реверс-прокси без обработки), но это общий ресурс.
- `/api/logs/sync` на 2 МБ из #142 никуда не делся — через зеркало он просто
  доезжает целиком. Урезать его по-прежнему полезно.

## Откат

```
rm /etc/nginx/sites-enabled/orc-mirror && nginx -t && systemctl reload nginx
```
Состояние вернётся точно к исходному, конфиги соседей не трогались.
Полный бэкап — `/root/nginx-backup-146/`.
