# #136 — просмотр .json больше не округляет длинные числа

## Что было

`app/static/js/app.js:1086`: `pretty = JSON.stringify(JSON.parse(raw), null, 2)`. Разбор в
объект прогоняет каждое число через `double`, поэтому целое больше 2^53 показывалось
ближайшим представимым: `1917704623170653147` → `1917704623170653200`. Файл на диске цел,
а скопированное из окна значение — неверно, и ничем не помечено.

## Что стало

Форматируется ТЕКСТ файла, а не разобранный объект: `_prettyJsonText(raw)` в
`app/static/js/utils.js` (рядом с `_stripXmlTags`, там же живут чистые текстовые хелперы).
Сканер идёт по символам, отслеживает строковые литералы и экранирование, выбрасывает старые
пробелы и расставляет отступы — числа и строки переносятся посимвольно. Раскладка та же, что
у `JSON.stringify(x, null, 2)`: два пробела, `": "` после ключа, `{}` и `[]` пустых
контейнеров в одну строку.

`JSON.parse(raw)` остался ровно как проверка валидности (результат выбрасывается): битый json
по-прежнему показывается сырым, как раньше. Подсветка, скролл, модалка не тронуты.

## Проверка на живом :8888 (`docs/tasks/136/verify-json.py`)

Подменяются ОБА файла из worktree (`app.js` и `utils.js`), счётчики перехвата напечатаны
(`{'app.js': 1, 'utils.js': 1}`), факт применения — `typeof _prettyJsonText = function`.

| проверка | результат |
|---|---|
| каждый числовой литерал в окне совпал с файлом | 7 из 7, расхождений нет |
| 19-значный id показан целиком | `1917704623170653147`, `...200` в тексте нет |
| окно — валидный json тех же значений | да |
| обычный json выглядит как раньше | посимвольно равен прежнему выводу, первое расхождение `None` |
| ошибок в консоли | нет |

Скриншоты: `json-bigint.png` (файл с длинными id), `json-plain.png` (обычный).
Фикстуры: `bigint-sample.json` (19-значный id, отрицательный id чата, `9007199254740993`,
20-значное число, пустые `{}`/`[]`, экранированные кавычки и обратный слэш), `plain-sample.json`.

**Мутации** (точечной заменой, обе откачены, `grep -c MUTANT` = 0):
- вернуть `JSON.stringify(JSON.parse(raw), null, 2)` в просмотрщик → 3 из 5 живых проверок красные;
- заставить `_prettyJsonText` делать тот же круг → pytest падает на `assert '1917704623170653147' in '{\n  "id": 1917704623170653200, …'`.

## Замер на всех .json репозитория (171 файл, node)

- 125 файлов — вывод посимвольно совпал с прежним;
- 46 — отличаются ТОЛЬКО литералом числа: в файле `1.0`, старый просмотрщик печатал `1`.
  Теперь печатается `1.0`, то есть то, что в файле;
- расхождений сверх литерала числа — **0** (проверено: `JSON.stringify(JSON.parse(новый), null, 2)`
  равен старому выводу для всех 46).

То есть раскладка не изменилась нигде; изменилось только то, что число показывается так, как
записано.
