# #238 — план: `owned_dirs` принуждается в момент записи, а не в промпте

Основание — `docs/tasks/238/research.md` §2 и §7 (взятое из LoopX место, не модель).
Одобрен оркестратором только пункт (1); пункт (2) — приёмочная команда, исполняемая платформой —
вынесен в отдельную задачу #240 и здесь НЕ планируется.

## Что меняется по существу

Сегодня `owned_dirs` доезжает до двух мест: блок пересечения при спавне
(`app/manager.py:585-607`) и абзац в промпте (`app/manager.py:477-480 _ownership_prompt`).
В момент записи файла периметр не проверяет никто. Добавляем третье место — `PreToolUse`
на файловых инструментах, по образцу `loopx/claude_goal_mode/hooks/goal_policy.py:196-198`,
но с НАШЕЙ моделью данных (список каталогов, а не один корень репозитория).

Хук уже существует и уже собирается в `_make_client` (`app/backend_claude.py:602-609`), но
только для `Bash` и только при `CLAUDE_BASH_HOOK_ENABLED=1`. Мы добавляем рядом второй набор
матчеров под **своим** флагом.

## Решения, зафиксированные до реализации (иначе исполнитель их выдумает)

1. **Имя флага — `CLAUDE_WRITE_SCOPE_HOOK_ENABLED`, взводит только точное значение `"1"`.**
   Отдельный от `CLAUDE_BASH_HOOK_ENABLED`, потому что это другой периметр риска и другое окно
   активации. Правка приезжает в `main` **инертной**, как #211 T1 и #231.
2. **Пустой `owned_dirs` → гейта нет вовсе**, матчеры не ставятся. У нас владение необязательно
   (`app/manager.py:585` — нормализация пустого списка законна), и большинство воркеров без него.
3. **Исключения привязаны к сессии, а не к шаблону пути.** Разрешены сверх `owned_dirs` ровно
   два: `<cwd>/docs/tasks/<task_id>/**` при непустом `task_id` и файл `<cwd>/docs/workers/<name>.md`.
   Чужой id и чужое имя — запрещены. Без привязки правка даёт ОБРАТНОЕ своей цели: право писать
   в чужую личную память.
4. **Нормализация пути:** относительный резолвится от `cwd` сессии; затем `Path.resolve()`
   (снимает `..` и симлинки); принадлежность — `root == p or root in p.parents`. Нерезолвимый
   путь (`OSError`) → **deny**, потому что это заведомо сломанный вход, и разрешать его нечем.
4a. **Значения, задающие периметр, приходят СНАРУЖИ и санитизируются — иначе это не
   предохранитель.** `owned_dirs`, `task_id` и имя сессии задаёт оркестратор при спавне, то
   есть модель; #227 замерил, что прямой запрет модели не удержал 1 из 1. Поэтому:
   - **идентификаторы исключений** (`task_id`, `session_name`) дают исключение, только если
     значение непусто после `strip()` и является ОДНОЙ безопасной компонентой пути: нет `/`
     и `\`, не `.` и не `..`. Иначе соответствующее исключение просто не выдаётся.
     Замер ревью: `parse_owned_dirs` тут ни при чём, а `task_id="../workers"` при наивной
     сборке `<cwd>/docs/tasks/<task_id>` резолвится в `<cwd>/docs/workers` и открывает
     личную память ВСЕХ агентов — то есть ровно то, против чего задача;
   - **корни владения**: каждый резолвится и принимается, только если остаётся под резолвленным
     `cwd`; вышедший наружу корень **отбрасывается**. Проверено командой: `parse_owned_dirs`
     (`app/workspace.py:2237-2255`) делает только `strip().strip("/")` и `..` СОХРАНЯЕТ, то есть
     `owned_dirs=["../"]` сегодня дало бы корень `<cwd>/..`;
   - **асимметрия пустоты, критическая:** пустой `owned_dirs` НА ВХОДЕ → гейта нет (п. 2);
     непустой вход, из которого после санитизации не осталось ни одного корня → гейт РАБОТАЕТ
     с нулём корней, то есть запрещено всё, кроме исключений сессии. Иначе значение `["../"]`
     выключало бы предохранитель целиком — отказ в ту сторону, в которую отказывать нельзя.
5. **Матчеры — по одному на инструмент**, ровно четыре: `Edit`, `Write`, `MultiEdit`,
   `NotebookEdit`. Альтернация в `matcher` (`"Edit|Write"`) НЕ используется: её семантика в
   SDK не проверена, а гадать про предохранитель нельзя. `NotebookEdit` берёт путь из
   `notebook_path`, остальные — из `file_path`.
6. **Текст отказа обязан содержать путь-нарушитель и слово `owned_dirs`.** Отказ без адреса
   и без причины стоит агенту хода на угадывание.
7. **Что этот гейт НЕ закрывает — в отчёт, дословно:** запись через `Bash` он не видит. Это
   признание самих LoopX (`goal_policy.py:33-36`) и наш замер #228 (recall денилиста 39%,
   45.2% исторических команд многострочные). Правка закрывает **случайный** выход за периметр,
   не намеренный.
