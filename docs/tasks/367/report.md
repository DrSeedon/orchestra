## Числовые результаты приёмки

### Батчинг (T8a)
Флаг `parallel_tool_calls` + фраза в промпте на ox-alpha: **раунды не снизились**
(A/B/A/B интерливинг: до [2,3], после [4,3]). Причина измерена: ox-alpha батчит
нативно и без флага (живой замер: 3 вызова в одном ответе без флага и без просьбы;
в боевых сессиях 1.24 вызова/раунд). Флаг оставлен как страховка для провайдеров,
которые без него шлют один вызов, + ретрай без ключа при 400.

### Фикс дефектов (T8b — главная экономия)
Задача, попадающая в старый grep-дефект (поиск альтернатив `a|b`), та же постановка,
интерливинг: **старые тула — 5 и 9 раундов, новые — 2 и 4** (медиана 7→3, −57%).
Механизм: «(no matches)» заставлял агента перепроверять через bash — каждый дефект-лжец
стоил лишних раундов. Это и есть ответ юзеру про «меньше турнов»: экономию дала починка
лжи, не флаг.

### Потолок (группа D)
`MAX_TOOL_ROUNDS` 50 → **100**. Вывод из пост-батчинговой картины: наблюдённый максимум
потребности >50 (цензурирован потолком, воркер #369); фиксы дефектов меренно режут раунды
до 4×; 100 = 2× цензурированного максимума с запасом; худший случай хода = 10% суточной
квоты аккаунта (при 200 было бы 20%). Wind-down: предупреждение в историю+чат за 10 и за 3
раунда до конца, удаляется из истории в finally (turn-scoped, B3) — исчерпание перестало
быть «молчаливой смертью без отчёта». Чем число плохо: по-прежнему экстраполяция якоря,
не подгонка распределения (n мало); если воркеры упрутся в 100 — в логах будут round guard
события, и поднять можно будет с доказательством.

### T9 — усечению контекста вернули видимость
`_fit_context` при реальном усечении теперь выдаёт AgentEvent("warning") с числом
выброшенных сообщений. Событие видимость даёт, память не возвращает — агент по-прежнему
не помнит выброшенное, но хотя бы знает, что оно выброшено. Открытый вопрос записан в KB.

## Breaking
- **offset в read теперь 1-based** (номер строки в выдаче; 0 = с начала). Старые 0-based
  вызовы читают со сдвигом на строку — схема обновлена одновременно, харнесу меньше суток.
- **grep-паттерн теперь Python re** (был BRE/rg вперемешку): `a\|b` означает литерал
  `a|b`, альтернатива — просто `a|b`. Строка в KB про «рабочую форму `a\|b`» помечена
  ОТОЗВАНО.
- edit при успехе отвечает «replaced N× in path» вместо «wrote N chars» (потребителей
  старой строки в коде нет — проверено grep).
- Новые файлы от write получают mode по umask процесса (0644 при 0022) вместо 0600 —
  решение согласовано с оркестратором (S_IMODE + umask, тесты обоих плеч).

  0o42 вместо 0o22; поймано тестом обоих плеч.
