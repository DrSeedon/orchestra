## Главная находка: панель истории usage была мертва в проде

**Симптом.** На живом дашборде в тултипе usage вместо графиков — «Снимков ещё нет:
график появится после двух замеров в одном окне». Снимков при этом 6583 за 29 суток.

**Причина — не рассинхрон, а коллизия глобального имени, моя, из #19.**
`app/static/js/app.js:1727` уже держит `async function _fetchHistory(name, scope)`.
В #19 я объявил в `usage.js` свою `async function _fetchHistory(until)`. Оба — объявления
верхнего уровня в одной глобальной области, а `app.js` в шаблоне идёт ПОСЛЕ `usage.js`,
поэтому побеждает его версия. Панель звала чужую функцию с `name=''`, получала `[]`
и честно сообщала «снимков нет».

Доказательство, снятое в живой странице:

```
_fetchHistory('') вернул array(0), исключения нет
прямой fetch того же URL         → array(2016)
_sparkError=''  _sparkData.length=0  _sparkStepMin=5 (начальное значение, присвоения не было)
```

**Почему не поймали ни #13, ни #19, ни тесты.** Тесты панели грузят `utils.js` + `usage.js`
и НЕ грузят `app.js` — в стенде коллизии не существует. Прогон глазами в #19 я делал на
своём стенде, где страница тоже без `app.js`. Ошибка воспроизводится только там, где на
одной странице живут оба файла, то есть исключительно в проде.

**Починено** (`866b857`): функция переименована в `_sparkFetch`.

**Лечим причину, а не случай.** Дефект был невидим по построению: стенды грузят
ПОДМНОЖЕСТВО скриптов, прод грузит все. Поэтому добавлен `tests/test_static_js_globals.py`
— он сканирует скрипты СТРАНИЦЫ, беря их список и порядок из `dashboard.html`, а не из
захардкоженного перечня внутри теста (добавят файл — проверится и он), и падает на любом
имени, объявленном в двух файлах. Проверено мутацией: со старым именем тест красный.

Масштаб на сегодня: **одна коллизия на 416 глобальных имён** в пяти скриптах страницы.
То есть правило соблюдалось само собой, пока его никто не записал, — ровно тот случай,
когда дешевле поставить страж, чем надеяться на аккуратность.

## Граница механизма: баннер версии #15 не срабатывает в своём же окне

Это не деталь реализации, а свойство, которое обязан знать каждый, кто на баннер
полагается.

Баннер показывается только когда непусты ОБА значения — версия страницы и версия
сервера (`app.js`: `if (serverBuild && _pageBuild && serverBuild !== _pageBuild)`).
Версию страницы кладёт в HTML сам сервер (`data-build`). Значит **страница,
отрисованная СТАРЫМ сервером, своей версии не знает** (`_pageBuild === ''`), и после
рестарта баннер ей не покажут — она узнает о новой версии только при перезагрузке
руками.

Иначе говоря: щит приезжает тем же рестартом, от последствий которого должен защищать.
Он работает начиная со СЛЕДУЮЩЕГО окна, когда обе половины новые. Практическое
следствие для чеклистов рестарта: шаг «юзер увидит баннер и обновит вкладку» на первом
таком рестарте не сработает — перезагрузку надо просить явно.
