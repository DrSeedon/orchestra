### №2 — Статусы PASS / FAIL / BLOCKED / NEXT / QUEUE / PAUSED на каждый этап → **НАЗВАНО ИНАЧЕ, частично**

Единого словаря из шести значений у нас нет. Есть четыре независимых словаря, покрывающих те же

| Состояние автора | Наш эквивалент | Где |
|---|---|---|
| PASS / FAIL | AC тикета (бинарная проверка) + «check it against its AC» | `roles/full-cycle.md`, Phase 2 п.2 / Phase 3 п.2 |

| NEXT | порядок по `blocked-by` («implement in dependency order») | `roles/full-cycle.md`, Ticketing rules |

### №5 — Субагент пишет вывод в файл, а не отдаёт сессию родителю → **МЕХАНИЗМ ПОДТВЕРЖДЁН; РАЗМЕР ЭКОНОМИИ НЕ ИЗМЕРЕН; у нас УЖЕ ЕСТЬ**

Автор честно пишет, что не мерил («логично»). Померил за него — с двух сторон.

То есть **полный текст ребёнка приходит в контекст родителя сам**, без запроса. Тезис бьёт в
настоящую механику, а не в воображаемую.

**(б) Наша экономия — цифры по логам #174.** Субворкеры `r174-handoff` и `r174-transcripts`
(таблица `logs`, боевая БД read-only):

| Величина | Байт |

| Совокупный объём сессий двух субворкеров (tool + tool_result + text + status) | **1 073 152** |

| Артефакты на диске (`docs/tasks/174/{handoff,transcripts}/research.md`) | **59 693** |

Разбивка входящих в родителя (`type='user_message'`): 192 + 227 + 1568 + 773 + 674 байт.

**⚠️ Что эти числа НЕ означают (правка после ревью, round 1 — finding принят).** Первая редакция
этого раздела гласила: «в родителя ушло 0.32 % от объёма работы субагентов — отношение 313 : 1»
и помечала «экономия трёхзначная» как CONFIRMED. **Это была ошибка ровно того класса, который

сохранённые события двух отдельных сессий (`tool`, `tool_result`, `text`, `status`); знаменатель —
пять записей `user_message`, пришедших родителю. Это не один счётчик одного потока данных и не
два варианта одной работы, поэтому их отношение **не является измерением сэкономленного контекста**.

Достоверно измерено ровно следующее, и не больше:

- в контекст родителя от двух субагентов попало **3 434 байта** — это полный объём, точное число;
- собственный объём журналов этих субагентов — **1 073 152 байта**;
- **0.32 %** — доля переданных сообщений от выбранного объёма логов, то есть отношение двух
  разных выборок, а не сбережённая доля контекста;
- артефакты на диске — **59 693 байта**, адресуемы по пути и читаются только при нужде.

**Размер экономии неизвестен.** Контролируемого сравнения (та же работа инлайн против той же
работы через субагентов) мы не проводили, и без него множитель назвать нельзя ни сверху, ни снизу.
Подтверждён **механизм**: полный вывод ребёнка в Codex попадает в контекст родителя по умолчанию
(прогон выше), а наша схема «короткий отчёт + артефакт по пути» этого не делает.

**Где это у нас записано:** `base.md` Standard rules — «Persist knowledge to files […] Context is
lost on compaction/restart, files are not»; `roles/full-cycle.md` `<parallelism>` — субворкеры
