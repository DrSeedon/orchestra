# #274 фаза 1 — три макета картинки `/limits`

Пересобрать: `.venv/bin/python docs/tasks/274/mockups.py` (HTML → PNG через Playwright,
один прогон рисует все три). Данные — замороженный `sample-usage.json`, живой `/api/usage`
от 14.08.2026 08:00 UTC.

## Две поправки к постановке (проверено в коде, не по памяти)

1. **Сейчас это не matplotlib, а Pillow.** `app/charts.py:1-10` рисует вручную через PIL;
   matplotlib упомянут там только как отвергнутый вариант (`docs/tasks/20/research.md`).
   Картинку `/limits` собирает `_collect_limits_chart_data` (`app/tg_bridge.py:3365` в main)
   и отдаёт `render_chart("bars", "Лимиты", ...)` — две серии, «выжжено» и «прошло окна».
   На моей ветке этого кода ещё нет: #236 и #273 смержены в main после моего ответвления.
2. **Арифметику изобретать не пришлось — она уже есть.** `_quota_headroom`
   (`app/routes/system.py:897`) считает ровно то, что просит юзер: `rate` — сколько процентов
   недели стоит один процент пятичасового окна, `windows_left` — сколько полных пятичасовых
   осталось, `available_pct` / `locked_pct` — сколько из видимо свободного пятичасового
   реально возьмёшь. Фронт берёт это же через `_quotaCap()` (`app/static/js/usage.js:91`).
   Макеты считают всё от `rate`, второй арифметики в них нет.

   ⚠️ **Дыра для фазы 2:** `quota_headroom` считается ТОЛЬКО в роуте `/api/usage`
   (`system.py:947`), а `/limits` зовёт `_get_usage_data()` напрямую (`tg_bridge.py:3332`) —
   то есть сегодня на пути картинки этих чисел НЕТ. Реализация обязана позвать
   `_quota_headroom(data.get("anthropic"))` сама, иначе главная мысль картинки не
   нарисуется. И у неё есть законный `None` (курс не измерен, история недоступна) — в этом
   случае картинка должна честно сказать «курс не измерен», а не подставить ноль.

## Числа, которыми нарисованы макеты

Печатает сам скрипт, воспроизводится:

```
курс: одно 5h-окно = 13.19% недели (замер за 72 ч)
в неделю влезает 7.58 окна; сожжено 6.67; осталось 0.91
5h выглядит свободным на 96%, доступно 91.0%, заперто 5.0%
```

Это и есть противоречие, ради которого задача: шкала «5 часов» показывает 96% свободных,
а недельного запаса хватит на 0.9 окна.

## Варианты

| | идея | сильная сторона | слабая |
|---|---|---|---|
| **A** `a-grid.png` | неделя = 8 клеток-пятичасовок, красные сожжены, зелёные доступны, пунктирная не влезает | пересчитывается взглядом, «сколько ещё раз я сяду работать» — сразу | клетка 8 неполная (неделя вмещает 7.6), это надо один раз объяснить |
| **B** `b-nested.png` | длинная полоса недели с насечками по окнам + вторая полоса «ближайшие 5 часов» с запертой зоной | единственный вариант, где ВИДНА связь: полосатый хвост на второй полосе — это упор в первую | при сегодняшних данных зелёного 91% и полоса выглядит просторной; драматизм появляется, когда недельного мало |
| **C** `c-cards.png` | три числа крупно + фраза-вывод | быстрее всех читается с телефона, фраза дословно отвечает на «мало недельного ≠ доступен фулл 5h» | нет картинки как таковой — это текст крупным шрифтом |

Все три: тёмный фон дашборда (палитра из `app/charts.py`), ширина 1000, высота 985–1270,
134–174 КБ. Термины убраны: «занято», «сожжено», «обнулится», «недели не хватит».
Пул без данных пишет «нет данных — сервис не ответил» (сейчас это Grok, он отдаёт `{}`).

## Что я бы предложил

**B как основа + заголовок из C.** Связь двух окон — это про геометрию (одно упирается в
другое), её показывает только вложенная шкала; а первую строку глазами читают как в C.
A хорош, но неполная последняя клетка — лишнее объяснение в картинке, которая должна
пониматься без объяснений.

## Не проверено

- Как это выглядит в пузыре Telegram на телефоне: макеты рендерились в Chromium на VPS
  1000 px. Мелкий шрифт здесь 22 px, то есть ~6 pt при сжатии до ширины пузыря (~340 pt) —
  нижняя строка пулов может оказаться на грани читаемости. Проверяется только отправкой
  в TG и взглядом с телефона.
- Поведение при `quota_headroom = None` и при отсутствующих пулах в макетах не нарисовано:
  сегодня без данных только Grok.
