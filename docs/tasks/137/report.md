## T2 — личная память

**Красное сначала, как договорились.** Тест
`test_personal_memory_written_mid_session_is_re_read_from_disk`
(`tests/test_session.py`) — сосед уже существовавшего
`test_role_is_back_in_the_prompt_on_the_turn_after_compact`, то есть стоит на том же
живом шве: мок-бэкенд, реальный `session.send()`, проверка того, что **фактически ушло
модели**. До правки падал, показывая устаревший блок дословно:

```
assert 'FRESH: learned this mid-session' in '...\nROLE: worker.\n\n
<worker-memory>\nSTALE: written at spawn\n</worker-memory>\n\n---\n\nnext task'
```

**Правка.** `_load_worker_memory` переехал из `app/manager.py` в `app/prompting.py`
как `load_worker_memory` (без изменений тела), рядом появился
`refresh_worker_memory(prompt, name, role, scope)`. В точке инжекта
(`app/session.py`, внутри `if ... not self._prompt_injected`) блок `<worker-memory>`
пересобирается с диска. Прямой импорт `manager` из `session` невозможен — цикл;
`app.prompting` обе стороны уже импортируют.

**Мутационная проверка.** Сделал `refresh_worker_memory` no-op (`return prompt`) —
тест покраснел; откат проверен (`grep -c MUTANT` → 0). То есть тест держится на шве, а
не на кеше.

**Цена, замер (ты просил число).** Важная поправка к постановке: освежение стоит
**внутри** ветки `not self._prompt_injected`, то есть работает раз на резюм/компакт, а
не каждый ход. Реальные размеры памяти: 26 файлов, медиана **5 068 Б**, максимум
**44 969 Б**.

| файл | время вызова |
|---|---|
| медианный (5 311 Б) | **0.317 мс** |
| максимальный (44 969 Б) | **0.419 мс** |

Верхняя граница абсурда: если бы освежение шло **каждый** ход, за всю историю проекта
(14 077 ходов) оно стоило бы **4.5 с суммарно**. Реально — на порядки меньше.

**Границы (`load_worker_memory` был fail-soft и остался).** Проверено тестами
`TestRefreshWorkerMemory` (`tests/test_prompting.py`): файла нет / нечитаем (chmod 000) /
scope не существует → блок пустеет, исключение на границу хода не выходит, для
нечитаемого пишется `WARNING Failed to read worker memory ...`. Отдельно закрыты
идемпотентность (инжект повторяется на каждом резюме) и память со спецсимволами regex
(`\1`, `\g<0>`) — вставляется буквально.

**Баг, который я внёс сам и поймал замером, а не рассуждением.** Первая версия
регулярки съедала перевод строки перед блоком, и получалось
`ROLE: worker.<worker-memory>` вместо пустой строки-разделителя. Нашёл, прогнав функцию
на шести граничных случаях до написания тестов. Исправлено, разделитель закреплён
ассертом.

**Размер против твоего лимита — честно.** Уложился в **3 файла**, как ты ограничил.
По строкам вышел за «десяток»: `+55/-26`, из них **21 строка — перенесённая функция
дословно** (оттого и `-26` в manager). Собственно новой исполняемой логики ~12 строк
(тело `refresh_worker_memory`, регулярка, вызов в `session.py`), остальное — докстринги
и комментарии. Моя оценка в Phase 2 («5-8 строк») занижала: я считал логику и забыл про
документирование. Рефакторинг не разворачивал: чужой код не трогал, поведение
существующих вызовов не менял.

## Формулировка модуля

`modules/self-improvement.md` описывал старое поведение («re-read only at spawn/restart,
NOT at compact» + совет дублировать урок в compact-хендофф). Переписан на новое:
память перечитывается при каждом переинжекте, дублировать в хендофф больше не нужно.

## Тесты

```
tests/test_session.py test_prompting.py test_manager.py
test_default_pipeline.py test_identity_drift.py  → 395 passed (97 с)
```
Полный сьют не гонял (по условию). Асинхронные тесты прогнал **4 раза подряд** — по
правилу «одна зелёная проверка на async ничего не доказывает»: 190 passed × 3 повтора,
стабильно. `uv.lock` не тронут (`git status` чист по нему).

В хвосте лога есть `RuntimeError: Event loop is closed` — это шум teardown при закрытии
subprocess-транспорта на выходе, не падение теста; итоговая строка `395 passed`, красных
нет.
