## Найденные баги/проблемы

1. **Платформа, заведён `report_bug`.** Гард из #179 грепает JSONL-транскрипт, куда попадает
   содержимое прочитанных ревьюером файлов. Ревьюируемый `plan.md` по существу задачи содержит
   строку `` (`bwrap`, `RTM_NEWADDR`, `sandbox failed`) `` — гард сработал на моём собственном
   тексте, вернул `exit 70` и **не записал файл ревью**. Состоявшееся доказательное ревью было
   уничтожено; восстановил из `/tmp/*.jsonl`. Доказательство: паттерн даёт 2 совпадения в
   `.jsonl` и 0 в выводе ревьюера. Ломает любую задачу про песочницы и надёжность ревью.
2. **Моя ошибка, исправлена.** Правки промптов сначала ушли в главный чекаут `/home/kesha/orchestra`
   (три файла, ветка `main`) — собирал абсолютные пути, потому что оттуда же читал для замера.
   Коммита не было. Снял `git diff` в патч, откатил главный чекаут в чистое состояние
   (`git status` пуст), применил патч у себя. Урок записан в личную память.
3. **Открытый пункт, не в этой задаче.** Потолок раундов остаётся правилом, а не enforcement:
   обход через `codex exec` запретить промптом нельзя, наблюдать можно только постфактум по
   `logs`. Настоящий предохранитель — счёт раундов на стороне платформы; оркестратор заводит
   отдельной задачей.
4. **Принятый риск, зафиксирован в плане с датой.** Владелец правила — скилл, а его доставка
   не гарантирована: платформа пропускает инъекцию, если репозиторий трекает свой `SKILL.md`
   (`tracked_skill`), и момент загрузки скилла агентом наш код не детектирует. Худший случай
   после правки равен текущему состоянию, поэтому не блокирует.
