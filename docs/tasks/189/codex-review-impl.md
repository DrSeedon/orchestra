## Findings

- **blocking — `app/tg_bridge.py:3178`** — если якорь уже доставлен, но `_mirror_send()` или последующая отправка `@mention` вызвала `_TgDeliveryOverloaded`, курсор откатывается. При повторе строки `_pending_turn_end_mention` снова устанавливается, но ранний `continue` пропускает отправку тега. Если новых логов больше нет, тег владельца потерян навсегда. Предложение: при уже отправленном якоре пропускать только повтор якоря и зеркала, но продолжать обработку pending mention; добавить тест с текстом оркестратора, `TG_USER_MENTION` и перегрузкой после якоря.

- **suggestion — `app/tg_bridge.py:803`** — callback захватывает изменяемый `state`. Если отправка первого ⚙️ завершится после `turn.new_block()`, callback запишет старый `message_id` уже в новый блок. Следующая пачка начнёт редактировать старое сообщение вместо создания нового. Предложение: захватывать `block_seq` и присваивать ID только при его совпадении либо хранить Future/ID отдельно для каждого блока.

- **suggestion — `app/tg_bridge.py:662`** — лимит прогресса считается через `len()`, а Telegram ограничивает текст в UTF-16. Тело из emoji/non-BMP может занимать до 7000 UTF-16 единиц при формальном лимите 3500 символов; первоначальная отправка режется общим кодом, но `edit_message_text()` на строке 2061 отправляет текст напрямую и получит `message is too long`. Предложение: ограничивать `_progress_text()` через `_utf16_len` и UTF-16-aware truncation; добавить тест с 40 строками из emoji.
