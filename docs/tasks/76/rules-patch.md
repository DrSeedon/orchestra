## G. Вопрос юзеру: правило про CHANGELOG в глобальном промпте

**Где лежит:** `~/.claude/CLAUDE.md`, раздел «📒 CHANGELOG.md», вне репозитория.

**Текущий текст:**
> Если в проекте есть — вести обязательно, вместе с commit+push.

**Почему для Orchestra неверно с 04.08.** Задача #52 убрала этот шаг: воркеры не правят
`CHANGELOG.md` вовсе, он собирается скриптом `scripts/build-changelog.py` из
`docs/tasks/<id>/report.md`. Единственное требование к воркеру — первая строка отчёта
читается как строка changelog. Правка воркером сейчас = конфликт мержа и затирание
собранного блока.

Коллизия не теоретическая: глобальное правило прямо предписывает то, что проектный процесс
запрещает, и агент, читающий оба файла, получает противоречие без указания, какой сильнее.

**Что предлагаю спросить:**

> В глобальном `~/.claude/CLAUDE.md` строка «CHANGELOG вести обязательно вместе с commit+push»
> с 04.08 конфликтует с процессом Orchestra: там #52 запретила воркерам трогать `CHANGELOG.md`
> — он собирается скриптом из отчётов. Три варианта:
>
> 1. **Дописать в глобальное правило оговорку** (правлю я, одна строка):
>    «Если в проекте CHANGELOG собирается скриптом (`git log -- CHANGELOG.md` + грепнуть
>    `scripts/`) — не трогать его руками, писать в тот источник, из которого он собирается.»
>    Правило остаётся одно, работает и там, и там.
> 2. **Оставить глобальное как есть**, а в `CLAUDE.md` Orchestra добавить перебивающую строку.
>    Минус: две записи про одно в разных файлах — ровно тот класс, который мы сегодня чинили.
> 3. Ничего не менять и считать, что проектный файл всегда сильнее глобального. Тогда это
>    стоит написать явно ОДИН раз в глобальном — сейчас приоритет нигде не зафиксирован.
>
> Рекомендую первый: он же чинит и общий случай, а не только Orchestra.

Отдельно: вариант 1 — это ровно правило B4 («файл собирается скриптом → сперва `git log` и
грепни `scripts/`), поднятое на уровень глобального промпта. Если юзер согласится с ним, в
`CLAUDE.md` проекта строку B4 можно не дублировать — останется один owner на оба контура.
