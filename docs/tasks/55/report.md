## Главная проверка: коммит РЕАЛЬНО проходит

Требование было именно такое — не «права выставлены», а сделан коммит. Стенд
(`tests/test_migrate_agent.py::test_migrated_worker_can_actually_commit`) подменяет только
транспорт: `ssh`/`scp` исполняются локально, `root@…` идёт через `sudo`, логика `migrate_git`
работает как в бою. Исходный репозиторий с веткой воркера, целевой клон, оба у сервисного
юзера; перенос делает «root».

После `migrate_git` тест пишет файл в перенесённый worktree и делает `git add` + `git commit`
от сервисного юзера — оба возвращают 0. Мутацией доказано, что это не совпадение: убрал
передачу `.git` → тест красный (`cannot lock ref 'HEAD' … Permission denied`).

## Мутационная проверка — каждый страж по отдельности

| Мутация | Что должно упасть | Результат |
|---|---|---|
| Убрать `give_to_service_user(.../.git)` | коммит + отсутствие чужих владельцев | **2 теста красные** |
| Игнорировать `LoadState` в `unit_service_user` | несуществующий юнит читается как root | **2 теста красных** |
| Глотать ошибку проверки владельцев (семантика старого `find … 2>/dev/null \| wc -c`) | несуществующий путь = «чисто» | **1 тест красный**, в логе — тот самый вывод `owner /gone → kesha (было чужих: 0)` |
| Вернуть постоянный `git config --global --add safe.directory` | запись в чужой gitconfig | **1 тест красный** |

Откат каждой мутации подтверждён маркером в файле; итог — `17 passed`.

Первая попытка мутации №3 **пережила** тест: я удалил только ветку `rc == 66`, а generic-ветка
`rc != 0` всё равно роняла. Пришлось воспроизвести старую СЕМАНТИКУ (глотать ошибку и
возвращать «чужих нет») — только тогда тест покраснел. Урок тот же, что в #34: мутация должна
воспроизводить дефект, а не просто менять строку рядом.

## Три дефекта, найденные сверх репорта

1. **`chown` только worktree не лечит симптом.** Репорт предлагал `chown -R` — но фикс
   `4b722ba` ровно это и сделал, а `dubious ownership` остался: git проверяет ещё и gitdir
   в `.git` основного репозитория. Замер: worktree чужих 0 из 0, и всё равно `fatal`.
2. **Сервисный юзер угадывался по владельцу каталога.** На этом VPS 03.08 каталог был
   root'овым при `User=kesha` — скрипт сделал бы `chown -R root` и отчитался об успехе.
   Ground truth — юнит; ловушка `systemctl show <нет-юнита> -p User` → пустое + exit 0
   закрыта гейтом `LoadState`. Это тот же класс, что записанный в граблях `OOMScoreAdjust`:
   проверка, дающая одинаковый вывод при успехе и провале, — не проверка.
3. **Проверка chown была слепой** — `find … 2>/dev/null | wc -c` печатал `0` и для
   несуществующего пути. Тот же класс, третий раз за задачу.

## Границы честности

  коммит после переноса, отсутствие чужих владельцев под worktree и `.git`, отсутствие записи
  в gitconfig логин-юзера, все четыре мутации.

  `safe.directory` в root-конфиге снят (`git config --global --get-all safe.directory` → пусто).
