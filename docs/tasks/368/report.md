# #368 — Отчёт: счётчик запросов OpenRouter в полосу лимитов

Дата: 2026-08-22. План одобрен оркестратором; модельное ревью отменено юзером
(«никаких ревью им нельзя») — проверку вёл оркестратор по артефактам + мутационные пробы.

## Что сделано

Гибрид «локальный счёт каждой HTTP-попытки + сверка вчера по /activity»:

- **T1** (`7df27007`, доведён `963738b1`): `app/openrouter_counter.py` — SQLite-счётчик
  (таблица `openrouter_attempts`: ts, day UTC, status), API по контракту из плана дословно;
  хук в `app/harness/llm.py` — запись ДО исхода попытки: ретраи после 429/5xx, транспортные
  ошибки и mid-stream сбои считаются все. Оба хука обёрнуты: сбой учёта не рвёт стрим,
  гасит `mark_unhealthy()` → healthy()=False. Само-исцеление: успешная операция снимает флаг.
- **T2** (`84f7b712`): `app/openrouter_activity.py` — reconcile() чистая (delta без clamp),
  fetch_day_sync(): нет ключа / «сегодня» отсекаются ДО сети; живая проба: за 21.08 провайдер
  отдал ровно 92.
- **T3** (`fc787596`): ветка `"openrouter"` в `/api/usage` (system.py): daily n/1000, minute m/20,
  source local, reconciliation с TTL 1ч / failure-TTL 10мин (паттерн #197). Сломанный счётчик →
  `available:false`, никогда ноль.
- **T4** (`36d6b8f7`): группа OpenRouter в usage.js renderUsageBar (сутки-бар + m/20 красным при
  переполнении + countdown до UTC-полуночи); «нет данных» при недоступности; в тултипе ⓘ —
  источник счёта и вчерашняя сверка (провайдер/локально/Δ + разбивка попыток по статусам).

## Breaking / совместимость

- Новый ключ `openrouter` в ответе /api/usage: потребители читают только известные ключи
  (_provider_usage_snapshot позиционный, limits_card.collect .get, фронт — именованные) —
  проверено file:line в плане.
- Батчинг тулов (harness-tools) полосу не сломает: счётчик считает HTTP-вызовы, а не ходы —
  полоса просто замедлится вместе с реальным расходом.

## Ограничения и TODO

- Локальный счёт видит только трафик этого процесса: чужой расход того же ключа вскрывается
  только вчерашней сверкой (Δ в тултипе). Первую осмысленную сверку за 22.08 можно снять завтра —
  она же даст эмпирический ответ, считает ли провайдер отклонённые 429 (наши ~30 burst-запросов
  утром 22.08 частично были upstream-429).
- Окно X-RateLimit-* платформенного 429 так и не поймано живьём — opportunistically: заголовки
  429 теперь проходят через llm.py; если понадобится, логирование добавить одной строкой в хук.
- Полный сьют не гонялся (глобальный тест-лок требует согласия PM); целевой файл + смежные
  usage/harness/regression наборы зелёные. По команде — возьму лок и прогоню целиком.
