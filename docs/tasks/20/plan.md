# #20 — план: тул `send_chart`

Основание — `research.md` (фаза 1): рисуем Pillow, в процессе `mcp_stdio`, готовый PNG
уходит в уже существующий маршрут `send_file`. Ниже — что именно меняется в коде.

## Форма тула

Один тул, один маршрут: **отрисовал → отправил в TG → вернул путь**. Второго вызова нет.

```python
@mcp.tool()
async def send_chart(kind: str, title: str, data: dict, caption: str = "") -> str
```

- `kind` — ровно четыре значения, ничего сверх померенного в фазе 1:
  `bars` | `bars_log` | `series` | `cards`.
- `title` — панчлайн словами. **Числа про данные сюда не пишутся** (см. «Подпись»).
- `data` — форма зависит от `kind`, описана в docstring тула.
- `caption` — текст сообщения в Telegram (рядом с картинкой, не на ней).

Возвращает: `Chart sent to TG: <path> (msg_id=...)`. Файл остаётся на диске.

Типизированный `dict` вместо JSON-строки — FastMCP отдаёт агенту готовую схему,
экранировать JSON руками не нужно. Прецедент строк (`mcp_servers`, `owned_dirs`)
касается редких необязательных полей, а здесь это основная нагрузка.

### Формы `data`

```
bars / bars_log:
  {"unit": "МБ",
   "categories": ["1 сут", "7 сут", "30 сут", "год"],
   "series": [{"name": "до", "values": [...], "tone": "bad"},
              {"name": "после", "values": [...], "tone": "good"}]}

series:
  {"unit": "%",
   "series": [{"name": "5h окно", "points": [["2026-08-01T10:00:00", 12.3], ...]}]}

cards:
  {"metrics": [{"label": ".md на диске", "value": "401", "note": "5.54 МБ"},
               {"label": "в индексе", "value": "315", "note": "78 %", "tone": "bad"}]}
```

`tone` — необязательный: `good` / `bad` / `neutral` (по умолчанию цвет из палитры по
индексу). Он нужен: в замере фазы 1 красный «до» против зелёного «после» читался мгновенно,
а два соседних цвета палитры — нет.

## Подпись обязана описывать НАРИСОВАННОЕ окно

Центральное требование, найдено на собственном баге фазы 1: заголовок «самый длинный
провал 9 ч 11 мин» стоял над графиком за 7 суток, где он 4 ч 5 мин. Картинка утверждала то,
чего в ней нет. Текст врёт молча, а глаз верит ему быстрее, чем таблице.

**Решение, делающее это невозможным по конструкции: числовую строку под заголовком считает
ТУЛ по тем данным, которые реально нарисованы. Агент её не передаёт.**

| kind | что вычисляется |
|---|---|
| `bars`, `bars_log`, 2 серии | категория с наибольшим отношением: `год: 4.25 → 0.86 МБ (4.9× меньше)`; при равных отношениях берётся последняя категория — в C1 «30 сут» и «год» дают ровно 4.96×, и без правила тай-брейка тест был бы плавающим |
| `bars`, `bars_log`, иначе | `максимум: <категория> <значение> <unit>` |
| `series` | `<N> точек за <D>, <G> провалов, самый длинный <H ч M мин>` (или «провалов нет») |
| `cards` | ничего — числа на карточках и есть факты |

Остаточный риск, который я не закрываю: агент может написать неверное число словами в
`title`. Запрещать цифры в заголовке нельзя («Расход лимита, 7 суток» — нормальный
заголовок). Это оговаривается в промпте; тул отвечает за свою строку.

## Доставка: ничего нового в очереди

`send_chart` вызывает существующую функцию `send_file(path, caption)` прямо в
`mcp_stdio.py`. Проверено: `@mcp.tool()` в FastMCP возвращает обычную функцию, поэтому
вызов работает и переиспользует её обработку ошибок целиком.

Дальше маршрут ровно тот же, что у любого файла сегодня:
`/api/tg/send_file` → `send_file_to_tg` → `_tg_send_file_safe(..., important=True)`.
**Новых полос в очереди не появляется, приоритеты не меняются, `tg_bridge.py` не правится.**
Косметика и доставка не начинают делить очередь просто потому, что очередь не трогается.

## Fail loud

Валидация до рисования, каждая ошибка называет, что чинить. Пустой картинки и молчания нет.

- `kind` вне четвёрки → перечислить допустимые;
- пустые `categories` / `series` / `points` / `metrics`;
- нечисловое, `NaN`, `inf` в значениях — с индексом;
- длина `values` не равна длине `categories` — с обеими длинами;
- `bars_log` со значением ≤ 0 (логарифм не определён);
- неразбираемая метка времени — с самим значением;
- пустой `title`;
- отсутствует файл шрифта — с путём;
- **потолки читаемости** (из находки F2 «≤3–4 крупных элемента»):
  `bars` — 2..8 категорий и ≤3 серий; `cards` — 2..4 метрики; `series` — ≤3 линий,
  ≤50 000 точек;
- `bars` c одной категорией → ошибка с указанием взять `cards`: это и есть тот самый
  «график из двух чисел», который рисовать не надо.

Ошибка рендера поднимается как `ApiToolError(code="domain_error", ...)` — агент получает
причину текстом. Если рисование прошло, а отправка упала, ошибку поднимает уже `send_file`;
файл при этом остаётся на диске, и путь есть в сообщении об ошибке.

## Прочие решения

- Холст 1200×750, кегли фиксированы (заголовок 44, значения 34, подписи 30). Ручки размера
  нет — это развилка без пользы. Ограничения Telegram (сумма сторон ≤ 10000, отношение ≤ 20,
  ≤ 10 МБ) соблюдены с запасом.
- Шрифт `/usr/share/fonts/truetype/dejavu/DejaVuSans{,-Bold}.ttf` — наличие проверено.
- Порог провала в `series` считается сам: медианный интервал × 3. Отдавать его агенту —
  ручка, которую он будет выставлять наугад.
- Прореживания точек нет: 1751 точка рисуется за 54 мс. Вместо него — потолок 50 000 и
  громкая ошибка.
- Файлы: `<корень оркестры>/data/charts/<utc>-<8 hex>.png`, корень берётся от `app/charts.py`.
  Имя из заголовка не делаю: кириллицу и слэши пришлось бы вычищать, а пользы ноль.
  При записи чистятся все, кроме `_KEEP = 200` свежих, — иначе каталог растёт вечно.
  Гонка двух воркеров безопасна: чистка режет только самые старые, свежесозданный файл
  под неё не попадает.
