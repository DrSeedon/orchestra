## Codex-ревью: два раунда, оба дали дефекты

`docs/tasks/context-engineering/codex-review-impl.md`.

**Раунд 1 — три замечания, два блокирующих, все приняты:**
1. `AGENTS.md`-симлинк → `cp` пошёл бы по ссылке и перезаписал файл вне worktree. Починил отказом: симлинк → warning + пропуск (зеркало симлинком не бывает; если он там — его положили не мы).
2. Любой ненулевой код `git ls-files` трактовался как «не отслеживается». Для не-репозитория / проблем с ownership git возвращает 128, и мы бы перезаписали чужой файл. Теперь «не отслеживается» = строго `returncode == 1`, остальное → warning + пропуск.
3. Ранний `return` в noop-ветке пропускал `_exclude_claude_dir`, поэтому старый worktree с уже актуальным зеркалом продолжал висеть untracked-мусором. Исключение перенесено выше сравнения байт.

**Раунд 2 — ещё один блокирующий, принят:**
4. Фиксированное имя `AGENTS.md.tmp` могло совпасть с существующим файлом или симлинком в стороннем репозитории, а две параллельные синхронизации писали бы в один inode. Теперь имя уникальное (`.AGENTS.md.<pid>.<uuid8>.tmp`), плюс `finally`-очистка при сбое `cp`/`mv`.

Второй раунд подтвердил прошлый замер: на shared-runtime коде он окупается (там 7 находок из 13 против 1 из 11 на прозе). Третий раунд не гонял: Codex сам сформулировал условие достаточности — «после уникального tmp и cleanup схема будет достаточной», — и оно выполнено, плюс на каждый пункт есть тест.
