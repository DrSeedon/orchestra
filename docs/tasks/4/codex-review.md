## Self-review дифа

Проверял по одному вопросу: может ли новый writer потерять историю или показать
на графике то, чего не было.

- **Тесты доказаны мутацией, а не зелёным прогоном.** Первый мутационный прогон был
  ложным: `git stash push app/routes/system.py` ничего не застэшил, потому что фикс уже
  лежал в WIP-коммите → «до-фиксовый» прогон шёл по фикшенному коду и дал 7/7 passed.
  Перепроверил через `git show 70c243e^:app/routes/system.py` — на настоящем до-фиксовом
  коде **3 из 7 падают**, включая `test_silent_provider_never_restamps_stale_value`.
  Остальные 4 зелены на обеих версиях: это регрессионные сторожа (100% как данные,
  «не настроен» без ключа, roundtrip метки), они и должны были работать раньше.
- **Запись снимков не отключена.** Метка `unavailable` делает `providers` непустым, поэтому
  строка пишется даже когда молчат все провайдеры — раньше в этом случае не писалось ничего.
  Отдельный тест: `test_snapshot_still_written_when_only_codex_answers`.
- **«Не настроен» не превратился в вечный шум.** Codex помечается только при
  `shutil.which(CODEX_BIN)`; на машине без Codex ключа по-прежнему нет.
- **Живой стенд честный.** Codex сейчас на исчерпанных лимитах и при этом **отвечает**
  (`utilization: 100`). То есть проверка «провайдер молчит» сделана принудительным
  падением `_fetch_codex_usage`, а не подменой факта исчерпания лимита.

### Слабые места, которые оставляю осознанно

1. **`codex_spark` при недоступности codex исчезает без метки.** Он производный от того же
   запроса; отдельного «спросили» у него нет. Серия просто прервётся.
2. **Постоянно недоступный Codex даст метку каждые 5 минут** (~288 строк/сутки, ~40 КБ).
   Считаю приемлемым: это честный сигнал, а не мусор, и он же диагностирует причину.
3. **`five_hour_pct` при молчании anthropic пишет 0, а не NULL.** Раньше туда попадало
   устаревшее кешированное значение — тоже неправда. Практического потребителя нет:
   `_usage_providers_from_row` сперва возвращает `provider_usage`, если он непустой, а
   непустым он теперь бывает всегда. Правильное лечение — nullable-колонки, то есть
   миграция, а её без согласования не делаю.
