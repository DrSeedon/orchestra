## Живая приёмка (форма соседнего проекта: argv / все серверы / реальный вызов)

Настоящий процесс `claude` с двумя MCP-серверами, оба несут секреты в `env`:

```
(1) argv:  --mcp-config /home/kesha/.orchestra/mcp-config/live-accept.json
           утечек значений: 0   (проверены ВСЕ 7 живых claude-процессов)
(2) серверы: orchestra ПОДНЯЛСЯ, websearch ПОДНЯЛСЯ   (сверка со списком, не «хотя бы один»)
(3) тул:   TOOLCALL_OK                                 (модель реально вызвала probe_ping)
```

**Первая версия этой проверки соврала, и это стоит записать.** Она печатала «3 вхождения
секрета в argv» — потому что секрет был литералом в моей же команде, и `ps -eo args` ловил
командную строку самого проверяющего. Инструмент проверки попал в измеряемое множество.
Починка: проверяющий читает значения ИЗ ФАЙЛА конфига и исключает себя по pid.

Последняя — самая поучительная: фикс на замечание сам оказался дефектом. Уникальные имена

подметалка удалена, осиротевшие файлы названы остаточным риском (см. ниже).

Плюс принятые suggestion: атомарная запись через временный файл + `os.replace` (обрезанный

кодовые точки (иначе `UnicodeEncodeError` падал бы ниже, без имени виновника).

Вердикт третьего раунда: все masking- и TOML-находки закрыты; единственная остававшаяся
blocking (подметалка) закрыта после него, потолок раундов при этом не превышен.

## Остаточные риски — названы явно, а не «случай не применим»

1. **Бэкенд Codex без MCP-серверов работает на ОБЩЕМ `~/.codex`** и видит глобальные
   серверы оттуда. Изолировать нечего (конфига нет), подменить идентичность нечем
   (env-блока нет). Managed-путь сюда не приходит: `_make_mcp_config` всегда кладёт сервер
   `orchestra`. Ветка достижима только при конструировании бэкенда в обход менеджера —
   так делают 19 существующих юнит-тестов.
2. **Осиротевшие файлы конфига Claude.** Имя уникально на экземпляр, удаление — в
   `disconnect()`. Процесс, умерший до `disconnect()`, оставляет файл 600 навсегда.
   Автоматическую чистку по возрасту делать НЕЛЬЗЯ (см. раунд 3). Правильное место —
   старт сервиса, когда множество живых бэкендов известно; отдельной задачей.
3. **Контекст самой модели не защищён**: агент, запустивший `ps`, видит значение в своём
   `tool_result`. Маскируется то, что уходит в БД, дашборд, RAG и TG-зеркало.
4. **Секрет, разорванный между двумя partial-чанками SSE**, не совпадёт ни с одним.
   Персистентная запись маскируется на шве T1 и потому чиста.
5. **Правило по имени ключа** не ловит секрет без распознаваемого имени и закодированные
   представления (base64 целого JSON).
6. **`;` внутри маски.** В шелл-строке `TOKEN=v; cmd` точка с запятой попадает внутрь маски:
   один символ диагностики против половины секрета в журнале.

## Окно применения

Правка в `app/` действует только с рестарта. Замерено: `KillMode=control-group`, процессы
агентов лежат в cgroup `orchestra.service` → рестарт убивает их вместе с сервисом, они
переподключаются с новым argv. **Отдельного «окна доживания» нет** — это лучше, чем
предполагала постановка. До рестарта каждый новый коннект продолжает писать секреты в argv.

## Уроки

1. **Проверка, инструмент которой попадает в измеряемое множество, врёт.** `ps`-скан с
   секретом-литералом в собственной команде нашёл «утечку» в самом себе. Значения для
   проверки читать из файла, себя исключать по pid.
2. **Фикс на замечание — тоже код, и тоже подлежит ревью.** Подметалка появилась как ответ
   на suggestion и оказалась опаснее проблемы, которую решала.
3. **Красный тест на несуществующий модуль пишется через `find_spec` + assert**, иначе
   `ModuleNotFoundError` на сборке — это «сломано», а не «красное».
4. **Плоский `mcp_env` — граница доверия.** Кастомный сервер со спавна перетирает ключи
   доверенного; идентичность брать только из `mcp_servers["orchestra"]["env"]`.
