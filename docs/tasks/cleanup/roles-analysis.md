# Роли: researcher / experimenter / full-cycle — объединять?

> ⚠️ **SUPERSEDED (2026-07-01):** юзер дал финальное видение — объединяем в super-full-cycle
> (фаза 1 = research+experiment). Конкретный дизайн: `roles-plan.md`. Этот файл — анализ
> «дублирования» (вывод: специфика разная, но юзер хочет ОДИН мультиинструмент с жёсткими
> фазами → сливаем СУТЬ, сохраняя определённость через команды оркестратора по фазам).

**Дата:** 2026-07-01
**Вопрос юзера:** можно ли объединить в мультиинструмент? Чтобы researcher СРАЗУ после approve делал implement + codex (не только research).

---

## Факты — что делает каждая роль (прочитал промпты)

| Роль | Output | Pipeline | Ключевое отличие |
|------|--------|----------|------------------|
| **researcher** | ЗНАНИЯ (не код). Каждый факт = источник. | scope&search → verify&cross-check → synthesize. Пишет docs/research/*.md | Web-поиск + **counter-evidence** + confidence HIGH/MED/LOW. Верификация 2+ источника. НЕ трогает код. |
| **experimenter** | ДАННЫЕ из прогонов (числа). | hypothesis → experiment → conclusion. 1 гейт. Пишет docs/experiments/*/ | **Эмпирика**: прогнать, замерить, 2-3 итерации, pass/fail ДО прогона (анти-p-hacking). Temp-файлы, не прод. |
| **full-cycle** | КОД. | research → plan → implement → codex. 2 гейта. | Реализация фичи end-to-end. research тут = «понять код что трогаю», НЕ web-ресёрч с источниками. |

---

## Есть ли РЕАЛЬНОЕ дублирование?

**НЕТ по сути, ДА по форме промптов.**

### researcher Phase 1 (research) vs full-cycle Phase 1 (research) — РАЗНЫЕ:
- researcher research = **внешние знания**: WebSearch, counter-evidence, источники с датами, confidence-уровни. Цель — узнать ПРАВДУ о мире/технологии.
- full-cycle research = **внутренний контекст**: grep/read кода что буду трогать, риски правки. Цель — понять КОД перед реализацией.
→ Оба называются «research», но это разные активности. Слить = потерять специфику (researcher-промпт учит верификации источников, full-cycle — чтению кода).

### experimenter — УНИКАЛЕН:
Эмпирические замеры (прогнать N раз, числа, pass/fail заранее) — ни researcher (тот читает, не прогоняет), ни full-cycle (тот кодит фичу) этого не делают. Это отдельная дисциплина (benchmark/proof).

**Дублирование = только shared base.md + report-format модуль** (это уже вынесено в модули, не дублируется физически).

---

## Конфликт с Agent Determinism (CLAUDE.md проекта)

Принцип: «1 задача = 1 workflow, не давать 3 способа — агент выберет худший, минимум развилок».

- **Против объединения:** мультирежимный агент = развилка «какой режим?». Агент может выбрать не тот. Больше свободы = меньше предсказуемости.
- **За частичное:** full-cycle УЖЕ мультифазный (research→plan→implement→codex с гейтами). Значит фазы внутри одной роли — ОК, если маршрут ЖЁСТКИЙ (один путь, гейты на месте).

Ключ: разница между «фазы одного детерминированного маршрута» (ОК) и «выбор режима» (развилка, плохо).

## Варианты

### A. Фазы-флаги в full-cycle (mode=research / mode=full)
Спавнишь full-cycle с mode → стоп после research ИЛИ research+implement. researcher/experimenter удаляются как режимы.
- ➕ один промпт, меньше файлов.
- ➖ **ЛОМАЕТ специфику**: researcher-верификация источников и experimenter-замеры — это НЕ «фаза full-cycle», а другой тип работы с другими правилами (counter-evidence, p-hacking guard). Впихнуть в full-cycle = либо раздуть его промпт до нечитаемости, либо потерять эти правила.
- ➖ mode-флаг = развилка (против determinism). Агент/оркестратор должен выбрать mode — лишнее решение.
- ➖ researcher output = docs/research (знания), full-cycle = код. Разные артефакты в одном промпте = путаница.

### B. Оставить 3 роли (статус-кво)
- ➕ **determinism**: каждая роль = один жёсткий маршрут, один тип output. Оркестратор выбирает роль по задаче (research → researcher, замер → experimenter, фича → full-cycle) — это ЕГО решение на спавне, не развилка внутри агента.
- ➕ специфика сохранена (верификация, p-hacking guard, code-review).
- ➖ 3 промпт-файла (но base/report-format уже в модулях — дублирования минимум).

### C. Всё в один 'agent' (макс гибкость)
- ➖ прямо против determinism. Агент с 5 режимами = максимум непредсказуемости. Отклоняю сразу.

## РЕКОМЕНДАЦИЯ: **B (оставить 3 роли)** + опционально узкое расширение

Обоснование через Orchestra determinism:
1. Роли **осмысленно разные по output** (знания / числа / код) и по правилам (источники / замеры / ревью). Это НЕ дублирование — это специализация. Слияние теряет специфику.
2. Выбор роли на СПАВНЕ (оркестратором) — это правильная точка решения (одна, явная), НЕ развилка внутри агента. mode-флаг (вариант A) переносит решение ВНУТРЬ = добавляет развилку = против принципа.
3. full-cycle уже мультифазный — этого достаточно для «сделать всё от research до кода». researcher/experimenter — для случаев где output НЕ код (юзер хочет знания или замеры, а не фичу).

### Про исходный запрос юзера («researcher сразу implement после approve»)
Если нужно «поресёрчил → сразу закодил» — это **уже есть = full-cycle** (research→plan→implement→codex). researcher существует для случаев где implement НЕ нужен (чистое знание: «какой прокси не блокирует РКН», «сравни подходы»). Смешивать не нужно — для «research+code» бери full-cycle, для «только знания» — researcher.

**Итого:** НЕ объединять. Роли — осмысленная специализация, а не мусор. Объединение противоречит determinism и теряет специфику. Если юзер хочет «research→код в одном» — это full-cycle, роль уже есть.

### Если оркестратор всё же хочет сократить
Минимальный компромисс: убрать **experimenter** ТОЛЬКО если он реально не используется (проверить историю спавнов). researcher + full-cycle покрывают 95% случаев. Но это отдельное решение по данным использования, не по «дублированию» (его нет).
