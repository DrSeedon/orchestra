# #80 — план: у блокирующего состояния появляется выход, а вторичный провал перестаёт его создавать

## Домашнее задание оркестратора: как отсеиваются терминальные состояния

Проверил до планирования, потому что от ответа зависит форма правки.

Фильтр блокировки (`merge_operations.py:234-238`):
```sql
WHERE session_id=? AND resolved_at IS NULL
  AND state IN ('PENDING','RUNNING','PARTIAL','UNKNOWN')
```
Терминальные состояния отсеиваются **вторым условием — `state IN (...)`**: `SUCCEEDED` и
`FAILED` в списке отсутствуют. Первое условие (`resolved_at IS NULL`) сегодня истинно у
ВСЕХ строк без исключения, то есть **фактически фильтр работает как `state IN ACTIVE_STATES`,
а `resolved_at` — заготовка, которую никто не заполняет**.

**Отсюда решение по форме B, и оно отличается от буквальной формулировки задачи.** Если бы
B писал `resolved_at` автоматом, мы получили бы ровно то, о чём предупреждал оркестратор:
второй механизм поверх первого — одни операции перестают блокировать по состоянию, другие
по флагу. Поэтому:

- **B чинит КЛАССИФИКАЦИЮ, а не флаг**: git прошёл (`commit_point=REACHED`) и все провалы
  вторичные → операция терминальна (`SUCCEEDED` с предупреждениями), а не `PARTIAL`.
  Не попадает в `ACTIVE_STATES` → не блокирует. `resolved_at` при этом не трогается.
- **`resolved_at` получает РОВНО ОДНОГО писателя — вариант A** (явное закрытие человеком),
  для случаев, которые B не покрывает по построению: `UNKNOWN` и настоящие `PARTIAL`.

Одна мысль — один владелец: состояние решает, блокирует ли операция; `resolved_at` решает,
снял ли человек блокировку вручную.

## Два инварианта, которые держим жёстко

1. **Не мержим второй раз поверх незавершённой операции.** Любая незакрытая `PARTIAL`/
   `UNKNOWN` продолжает блокировать, пока её не закрыл человек (A). B не ослабляет это: он
   не закрывает PARTIAL, он не даёт ей появиться там, где её быть не должно.
2. **`UNKNOWN` не закрывается автоматически НИКОГДА.** Неизвестный git-исход, закрытый
   автоматом, — это потерянные данные без следа. Только человек, только A.
