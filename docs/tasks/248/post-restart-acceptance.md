# #248 — приёмка, которую НЕЛЬЗЯ выполнить до рестарта

Этот файл существует потому, что рестарт отложен (ревью #237 вернуло три блокера, 13.08.2026).
Пока он не выполнен, часть работы #248 остаётся **непроверенной в проде**, и это не формальность.

## Почему живой мерж 13.08 ничего не доказал про новый код

Во время фазы 3 через `merge_worker` прошли три настоящие ветки:

| operation | результат | что реально проверено |
|---|---|---|
| `d594d32e-1f06-4d48-b1a1-04009ac99d16` (T1) | SUCCEEDED | старый путь не сломан |
| `070741db-321d-4037-be33-c4dc6b22601b` (T2) | SUCCEEDED, `commit_point=REACHED` | старый путь не сломан |
| `2d9b5062-c3f3-439d-8eba-66c62c51376e` (артефакт ревью) | SUCCEEDED | старый путь не сломан |

Все три исполнялись **кодом, загруженным в память сервера при его старте**, то есть кодом ДО #248.
`app/routes/` живёт в памяти systemd до рестарта, `app/mcp_stdio.py` — в процессе агента до его
реконнекта (грабля из `CLAUDE.md`, раздел «Shared runtime: тесты зелёные ≠ работает»).

Отсюда точная формулировка, и другой быть не должно:
**доказано «я не сломал текущий мерж для остальных», НЕ доказано «новый мерж работает».**

## Что выполнить ПОСЛЕ рестарта

1. **Живой мерж на новом коде.** Взять любую настоящую ветку воркера и смержить штатным
   `merge_worker`. Ожидание: `SUCCEEDED`, `commit_point=REACHED`, в заголовке squash — `#N:` бондированной
   задачи, в теле ровно один `Orchestra-Operation:` трейлер.
2. **Проверить, что задача закрылась сама.** До #248 статус двигали руками, и в 17 случаях из 28 забывали.
   После мержа с `task_outcome=complete` задача обязана быть `done` без единого ручного `task_update`.
3. **Смешанный рантайм.** Часть агентов после рестарта ещё на старом MCP. Убедиться, что их мерж
   проходит по legacy-пути (`LEGACY_MERGE_CONTINUE`), а не отказывает: новое обязательное поле,
   уронившее всех живых агентов, у нас уже было (#215/#217).
4. **Только после 1–3** считать поведенческую часть #248 принятой в проде.

## Кто это делает

Оркестратор (`Orchestra-orchestrator`) — он владеет рестартом. Исполнителю задачи выполнить это
невозможно по построению: до рестарта нового кода в живой системе не существует.
