# #151 — отчёт: нативные скиллы Codex

## Что сделано

Codex-агенты получают скиллы через **нативный механизм CLI** (`<cwd>/.codex/skills/<name>/SKILL.md`),
а не через сгенерированное нами оглавление в промпте. Механизм доставки один
(`inject_skills_to_worktree` из #149), адресов два — отличается только имя каталога.
Оглавление осталось ручным fallback за флагом, по умолчанию выключенным.

## Приёмка поведением

### Нативный механизм работает при ВЫКЛЮЧЕННОМ оглавлении
Живая воркти Codex-воркера `sensar-roadmap`, инструмент — `codex debug prompt-input`
(рендерит модель-видимый промпт локально, без API):
```
(file: .../sensar-roadmap/.codex/skills/codex-debate/SKILL.md)
(file: .../sensar-roadmap/.codex/skills/html-artifacts/SKILL.md)
наше оглавление "Available skills (progressive loading)": 0
```
Оба скилла видны агенту, наш механизм отключён — значит сработал нативный, а не остаток
старого пути. Это и есть требование «на время проверки отключи оглавление».

### Глобальные скиллы юзера целы
```
pdf                  1
deepgram-transcribe  1
~/.agents/skills/*   17
```
Все 19 на месте: источники суммируются, наш добавляется третьим.

### Безопасность чужих репозиториев — критерий AFTER == BEFORE
| репо | BEFORE | AFTER | вердикт |
|---|---|---|---|
| seedon | 1 | 1 | ✅ идентично |
| polus | 16 | 16 | ✅ идентично |
| games | 1 | 1 | ✅ идентично |

`games` (без `.codex` в ignore) получил ровно одну строку `.codex/` в `info/exclude`;
`AGENTS.md`/`codex_sessions.json`/`*.round` — 0 совпадений, ограничение `only=` не ослаблено.
Всё, что клал вручную вне механизма, убрано (`games/.codex` удалён, дерево вернулось к 1 строке).

## Найдено приёмкой: `.codex` как ФАЙЛ — 8 из 17 репозиториев

Первый прогон дал пять `install failed` подряд в `Aperant`. Причина не в правах: репозиторий
**трекает read-only zero-byte ФАЙЛ с именем `.codex`**, поэтому `mkdir -p` не мог создать
каталог. Пересчёт по всем cwd оркестраторов:
```
FILE: kesha-tg-bot, TradingCryptoBot, Parsing, seedon, Aperant,
      dev-lead (worktree), stargate-tactics, polus     → итого 8 из 17
```
Без гейта это пять предупреждений на КАЖДОМ коннекте в половине проектов — навсегда.
Добавлен ранний выход: каталог занят не-каталогом → тихий `info` и `return 0`, файл
репозитория не трогаем. Ничего повреждено не было (проверено: `.codex` в Aperant остался
0 байт с исходным mtime, дерево чистое).

Это ровно тот класс, который #149 закрывал для `tracked_paths`: **платформа не пишет поверх
того, что принадлежит репозиторию** — теперь и когда «принадлежит» выражено типом файла.

## Компромиссы (цифрами, а не словом «мусор»)

1. **Двойные копии на диске.** Живых сессий: Claude 66, Codex 7. Каталог `.claude/skills`
   лежит у **5** Codex-агентов — для Codex он невидим (проверено: 3 файла на диске → 0 в
   промпте), но занимает место. Не чиню: удаление в чужих деревьях деструктивно, отдельная
   задача (#150 у оркестратора).
2. **Флаг выключен по умолчанию → на CLI без discovery агент останется без скиллов молча.**
   Смягчено, но не устранено: инъекция теперь логирует факт и ПУТЬ
   (`Injected N skills into <path>/.codex/skills/`), так что «почему у агента нет скиллов»
   отвечается одним грепом лога, а не гаданием. Полноценного fail loud нет — мы принципиально
   не детектим возможности чужого CLI.

## Что НЕ делал

- Не удалял `build_codex_skills_index` и его тесты — fallback жив.
- Не переписывал frontmatter скиллов: `roles:`/`integrations:` не мешают discovery (F8).
- **Папочной доставкой (`scripts/`, `assets/`) работу не оправдываю** — все пять наших скиллов
  плоские `.md`, сегодня выгоды нет. Формат `<name>/SKILL.md` её разблокирует на будущее.

## Adversarial self-review — что осталось слабым

1. **`_SKILL_HOME_DIRS` знает только claude и codex.** Новый рантайм (grok, opencode) не
   получит скиллов и не упадёт — просто тишина. Сделано намеренно (`else: ".claude"` подложил
   бы Claude-файлы чужому CLI), но это молчание, а не отказ.
2. **Гейт «каталог занят файлом» не различает причины.** Симлинк на каталог, сломанный симлинк
   и обычный файл обрабатываются одинаково — пропуском. Для наших восьми случаев верно;
   для симлинка на легитимный каталог скиллов это ложный отказ.
3. **Приёмка нативного пути проведена на ОДНОЙ воркте и одной версии CLI (0.145.0).** Что
   discovery ведёт себя так же на всех восьми проектах, не проверено — проверено, что не
   ломает их деревья.
