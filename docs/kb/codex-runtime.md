## Установлено

### Codex / Sol

- Свежие правила «не работают» у Sol-воркеров → Codex режет `AGENTS.md` (зеркало `CLAUDE.md`) по `project_doc_max_bytes` ПОСРЕДИ фразы, кириллица = 2 байта/символ. Обрыв тихий: греп по `CLAUDE.md` находит правило всегда. Замер #323: зеркало 172 576 Б при потолке 131 072 — отрезано 41 504 Б, до Codex-воркеров не доезжал весь хвост файла. Текущий machine-local ceiling читать в `~/.codex/config.toml`, а не помнить; **этот файл держать с запасом под потолком** (#327 — 177 594 → см. итог задачи)
- Codex-воркер видит правила месячной давности → зеркало `AGENTS.md` и скиллы создаются при КОННЕКТЕ бэкенда (`workspace.sync_agents_md`); до реконнекта у бывшего Claude-воркера их нет вовсе. Если репозиторий ТРЕКАЕТ свой `AGENTS.md`, зеркало не трогает его
- Codex жжёт время в `sleep` (74 сна на 1579 вызовов, у Claude — ноль) → формулировка «do NOT poll, just wait» читается им буквально → в описаниях тулов писать END YOUR TURN NOW; глобально `sleep` не блокировать
- Codex ретраит вечно на исчерпанной квоте → «You've hit your usage limit» не матчилось паттернами, и Codex НЕ шлёт отдельный text-event перед error → терминальный лимит проверять прямо в error handler
- Codex падает на длинном JSONL → не баг Codex: `asyncio.StreamReader` по умолчанию 64KB → `limit=16MB` + fail-soft readline
- **Контекст GPT-5.6 зависит от поверхности, не путать model card с CLI.** Official model card: 1 050 000 total / 922 000 max input / 128 000 max output. Живой ChatGPT-auth каталог CLI 0.147.0 (23.08.2026): default `context_window=272000`, `max_context_window=872000`, `effective_context_window_percent=95`; верхняя настройка `model_context_window=872000` даёт в `token_count` **828 400** effective, а auto-compact зажимается кодом CLI до 90% = **784 800**. До #209 Orchestra работала на 258 400; после следующего рестарта переносит оба machine-local значения из `~/.codex/config.toml` во все managed homes. Это максимум подписочного CLI на текущем каталоге, не полные API 1.05M.
- **Цена Sol снизилась и для подписки тоже, но двумя разными шкалами.** API promo (минимум до 21.11.2026): $4/M input и $20/M output; >272K input на API = 2× input и 1.5× output для всего запроса. Подписочная шкала: 100/10/500 credits за 1M input/cached/output против 125/12.5/750 у GPT-5.5; точный >272K multiplier для ChatGPT credits дока не заявляет. Большой потолок сам по себе ничего не списывает, но длинная история увеличивает токены каждого хода. `service_tier="fast"` расходует GPT-5.6 credits **2.5×** ради 1.5× скорости, но этот ключ есть только в базовом `~/.codex/config.toml` и НЕ входит в managed-home whitelist: standalone Codex работает fast, Orchestra-воркеры остаются standard.
- Codex compact идёт нативно в том же thread и для auto, и для ручного `compact_worker` (auto-policy взводится от 60% с задержкой 25 минут). Custom summary → fresh session относится к Claude. Перед настройкой сверяй `_precompact_policy()` и `compact()` с текущим кодом
- `codex_review` — это bg job (type=run), возвращается сразу и будит воркера → не ждать его, закончить ход
- **Ревью «упало» (`FAILED`, пустой артефакт) при `rc=0` → полный текст лежит в `/tmp/codex_review_*.jsonl`, последний `item.type=="agent_message"`. Не перезапускать раунд:** уведомление джоба даёт хвост в 3000 символов, jsonl содержит всё, а перезапуск тратит раунд из потолка и деньги за уже выполненную работу. Восстановленный текст помечать в артефакте как восстановленный. Замер: #214/#217 — так подняли два раунда целиком
- `codex_review(mode="review")` на закоммиченной работе отвечает «no changes to review» и раунд сгорает → для закоммиченного: `git diff <merge-base> HEAD > /tmp/x.diff` + `mode="exec"`
- **Ревью на этом VPS идёт БЕЗ песочницы (`-s danger-full-access -a never`, #179) — осознанный размен:** ядро запрещает непривилегированные user namespace, вендорный bwrap падает до старта любой команды, и это ломает все режимы, включая read-only. Следствие: ревьюер технически может писать в дерево — не давать ему заданий, где запись правдоподобна, и не считать ревью изолированным. Провал исполнения громкий: маркеры в JSONL → `exit 70` вместо тихого exit 0
- **Предохранитель цикла (ревью, ретраи, дебаты), у которого условие остановки зависит от продуктивности проверяющего («3 раунда БЕЗ ПРОГРЕССА»), на порождающем предмете не срабатывает никогда → потолок безусловный и по ТИПУ предмета: исполняемый артефакт — 3 раунда, проза — 2, и второй только если артефакт между раундами менялся.** «Раунд принёс новые замечания» основанием для следующего раунда НЕ является; потолок действует и через тул, и через `codex exec` руками. Замер: #177 — seedon #110, один ход 96 минут, из них 38 подряд в шести раундах ревью прозы, остановил человек. Причина живучести — два owner'а одного правила: скилл требовал безусловные 3 раунда, роль — «3 rounds without progress», агент слушался роли
- **Одна модель, написавшая постановку, отревьюившая её и реализовавшая — это петля усиления, а не три проверки.** На открытой задаче она расширяет объём сама себе и сама же одобряет расширение. Замер: #176 — весь контур на `gpt-5.6-sol`, итог 364 мёртвые строки из 843 (43.2%) и три круга переделок. Разрывать петлю в самом дешёвом месте: постановку или ревью уводить на ДРУГОЙ рантайм

### Модели и лимиты

- Opus 5 вдруг с 200K контекста → голый `claude-opus-5` репортит `contextWindow: 200000`, а `claude-opus-5[1m]` — 1000000 (проверено пробой CLI, докой НЕ подтверждается) → всегда пинить `[1m]`, alias `opus` в сохранённой модели сессии не использовать. Отдельного бакета у Opus 5 нет — ест общий 5h/7d счётчик
- `UPDATE sessions SET model=...` отработал, а после рестарта модель прежняя → живой сервер перезаписывает `sessions.model` из памяти при auto_resume → править при остановленном сервере и ПЕРЕПРОВЕРЯТЬ после рестарта; при смене бэкенда Codex→Claude обнулять ещё и `session_id`
- full-cycle крашится сразу на старте на Claude-модели → `effort=xhigh` из pipeline.yaml, а Claude API отвергает xhigh без thinking → auto-downgrade xhigh→high (`backend_claude.py`)
- Финальное ревью на Spark пропускает баги → в A/B Spark прошляпил реальный double-count, который поймал Sol → финальные ревью не роутить на дешёвую модель

### Приоритет пулов — история и отозванные сравнения

- **ПРИОРИТЕТ ПУЛОВ (решение юзера 12.08.2026, дословно: «кодекс выжигаем как можем... опус юзаем только для специальных сложных задач»). Порядок: Luna по умолчанию → Sol, когда Luna не справится → Opus только на специальные сложные задачи.**
  - **Основание — асимметрия ПОСЛЕДСТВИЯ, а не цены.** Стена Claude = работать нечем; стена Codex = откат на Opus и работаем дальше. Дешёвый по последствиям пул тратится первым, даже когда он дороже арифметически. Пересмотреть правило может только новый довод про ПОСЛЕДСТВИЯ; арифметика про цену расхода — не довод.
  - **Старое сравнение «$5.39 против $25.67 за п.п.» (#219) НЕ ЦИТИРОВАТЬ: занижено вчетверо, потому что мерилось против $100-го плана OpenAI, а 16.08 план апгрейднут до $200** (`prolite → pro`, #334). Отсюда общее: процент утилизации несопоставим во времени через смену тарифа — сверяй знаменатель, прежде чем сравнивать проценты. Разбор — `docs/archive/sessions/2026-08.md`.
  - **Обнуление квоты имеет ТРИ неразличимых по счётчику источника: плановый сброс окна, смена тарифа и веерный подарок провайдера.** Любой вывод из обнулений обязан сперва их разделить; купить сброс нельзя, запас `earned` исчерпан (#325, #334).
  - **Промо Anthropic «+50% к недельным лимитам Claude Code» истекает 19.08.2026** — дословно «After August 19, 2026, weekly usage limits in Claude Code return to their standard levels». Оба наших замера пула сделаны ВНУТРИ промо: стандартный уровень ≈$1 900/нед против измеренных ≈$2 850. Дешёвый фальсификатор: первое полное окно после 20.08 (25.08 07:00 → 01.09) обязано отдать ≈$1 900; отдало ≈$2 850 → промо продлили, вывод про разворот снимается.
  - **Измеряешь потребление ОБЩЕГО аккаунта → посчитай ВСЕ машины, которые его делят.** Сверка двух источников на ОДНОЙ машине полноты не доказывает: обе описывают одного потребителя, и сошедшиеся 4.6% читались как доказательство. Замер #334: ноутбук делит с VPS оба аккаунта, пропуск 12–37% пула Claude и 11–15% Codex; после включения второй машины два независимых окна дали $2 844.94 и $2 848.60 против расхождения 22.6% по одному VPS.
  - **ПОТОЛОК (решение юзера 12.08 21:08): «кодекс до конца не выжигай, опус юзай, 95 хотя бы было бы на тесты нам луны».** Держать ≥5% пула Codex под Luna-исполнителей закрытых тикетов. При Codex ≥90%: новые задачи на **Opus**, Sol не брать, Luna — только на закрытые тикеты с готовым красным оракулом. Идущих Sol-воркеров не переключать на лету: смена бэкенда Codex→Claude рвёт нативную сессию.
  - Внутри Codex Luna даёт ту же работу на закрытых заданиях в 13–20 раз дешевле (#199, #208) — сэкономленный пул тратить на бо́льшую параллельность, а не беречь.
- Цены для калькуляции — ОДИН владелец: `TOKEN_PRICES` в `app/models.py`. Числа здесь не дублировать: копия в этом файле разошлась с кодом и считала бы на 25–50% мимо (#188)
