# research-embeddings — личная память

## Проверка «загружена ли ML-модель в процесс»

`find` по `*.onnx` и `/proc/PID/maps` дают ЛОЖНОЕ «модели нет»: ONNX Runtime читает веса
в heap, файл mmap'нутым не остаётся — в maps видны только `.so` рантайма.

Смотреть:
```bash
grep -E '^(Rss|Pss|Anonymous|SwapPss):' /proc/PID/smaps_rollup   # веса = Anonymous
journalctl -u <unit> | grep -i 'embedder loaded'                  # факт загрузки
```
Пустой Python ≈ 10 МБ, так что Anonymous > 1 ГиБ = модель резидентна.

Ещё две ловушки оттуда же:
- fastembed без `FASTEMBED_CACHE_PATH` кладёт модель в `/tmp/fastembed_cache`, а не в HF-кеш.
  Маленький `~/.cache/huggingface` ≠ «модель не скачана».
- Отсутствие `RAG_ENABLED` в `.env` ≠ «выключено». Проверять, есть ли гейт В КОДЕ:
  у kesha-bot гейта нет вообще, `_rag.run(loop,"backfill")` зовётся безусловно.

## Живость SQLite-базы — смотреть ВСЕ таблицы, не одну

Обжёгся на #132: увидел `log_chunks = 0`, объявил RAG на VPS мёртвым и предложил его выключить.
На деле `file_chunks = 4126` и база писалась в тот же день — система индексировала только файлы.
Выключение сломало бы рабочий поиск.

Правило: `.tables` + count по каждой значимой + mtime файла. Один нулевой счётчик означает
«эта грань не используется», а не «база мертва».

Отдельно: self-review это НЕ поймал, потому что я перепроверял выводы, а не первичный факт
под ними. Проверять в первую очередь тот факт, который удобен для желаемого вывода.

## /tmp и `D` в tmpfiles — поле возраста КВАЛИФИЦИРУЕТ директиву

Ошибся на #132: прочитал `D /tmp 1777 root root 30d` как «чистит каталог на каждом ребуте»
и предупредил о гарантированной потере кеша. Ребут случился — **кеш уцелел**.

Правильно (`man 5 tmpfiles.d`, раздел *Age*): «The age field only applies to lines starting
with d, D, e, v, q, Q, C…». То есть `D` + `30d` удаляет только содержимое СТАРШЕ 30 дней.
Безусловная очистка была бы при возрасте `0`. Boot-юнит `--remove` передаёт
(`systemd-tmpfiles --create --remove --boot`), механизм отрабатывает — просто свежие файлы
не подпадают. При `relatime` atime обновляется на каждом доступе, так что живой кеш
30 дней не наберёт.

Проверять: `cat /usr/lib/tmpfiles.d/tmp.conf` (какой возраст!), `findmnt -no FSTYPE /tmp`
(tmpfs = точно исчезнет), `systemctl cat systemd-tmpfiles-setup.service` (какие флаги).

**Урок шире самого /tmp:** искал в man «что делает D», нашёл подтверждение и остановился.
Надо было спросить «при каких условиях D НЕ срабатывает». Для директивы/флага всегда
читать соседние поля — они меняют семантику.
