# memory-research — личная память

## ПРАВИЛО (принято оркестратором в #138, метит в CLAUDE.md)
**Среднее по выборке не двигается, а гипотеза про РАЗНОРОДНЫЕ данные → разбей по объективному
признаку самих данных ДО отказа от гипотезы, а не после.**
Симметричные помехи взаимно гасятся в среднем и невидимы в нём by design.
Признак должен быть свойством ДАННЫХ (где физически лежит ответ), а не подобранным после
просмотра результатов — иначе это подгонка, а не защита от неё.

Замер #138: `files only` в среднем ХУЖЕ прода (0.4268 против 0.4893), t=−0.81 — по этой цифре
гипотезу полагалось закрыть. Разбиение по «где лежит gold» показало обратное: на файловых
запросах (19/28) выключение логов даёт **0.5088 → 0.6289**, на логовых (9/28) чистый лог-поиск
**0.5278** против 0.4481 в общей выдаче. Каждый корпус в отдельности ищет лучше, чем оба вместе.

## Метрика может наказывать твой же арм по построению (#138)
Считал раздельные списки как конкатенацию «файлы, потом логи» → лог-ответ, стоявший в СВОЁМ
списке первым, получал ранг 6 и показывал «REGRESSION во всех вариантах». Чуть не отнёс это
оркестратору как отказ. Артефакт: конкатенация предполагает чтение подряд сверху —
ровно поведение слитого списка, которое разведение и убирает.
**Правило: разбирать метрику надо и когда она говорит ПРОТИВ тебя.** Метрику, которая
льстит, перепроверяют все; ту, что мешает, — почти никто, и она так же может врать.

## Как мерить нарезку, не ломая gold-разметку (#138, инструмент готов)
`chunk_id` — артефакт одной нарезки. Якорь = **символьный диапазон пассажа в файле**,
попадание = пересечение диапазонов. `docs/tasks/138/bench/regold3.py` + `gold_anchors_v3.json`
(20/22 якоря, 0 ошибок round-trip).
Два тупика, в которые не возвращаться:
1. Реконструкция документа склейкой снапшотных чанков через `\n` **НЕ round-trip'ится**
   (9448 → 10289 кусков, `CLAUDE.md` 33 → 44): чанкер мержит мелкие секции и режет пробелы.
   Чанковать надо **файлы с диска** — 451/459 воспроизводят снапшот побайтово.
2. Якорить сырой подстрокой — теряешь 9/22 на одних пробелах. Нужно нормализованное
   пространство + отображение индексов обратно в сырые смещения.

## Прогоны на VPS Contabo (158.220.127.161)
```
ssh root@158.220.127.161 'nohup systemd-run --scope -q -p MemoryMax=4G --uid=kesha --gid=kesha \
  -E BENCH_DB=... -E ORCHESTRA_ROOT=/home/kesha/orchestra \
  -E FASTEMBED_CACHE_PATH=/home/kesha/orchestra/data/models -E HF_HUB_OFFLINE=1 \
  nice -n 15 /home/kesha/orchestra/.venv/bin/python <script> > run.log 2>&1 & echo started'
```
- **Длинный прогон рвёт ssh** (`Connection reset by peer` посреди эмбеддинга ~50k чанков) →
  только `nohup ... &` + `bg_create(type=command)` на появление файла результата. Не держать
  прогон на живом соединении и не поллить его руками.
- На снапшотную БД нужен `sqlite_vec.load(conn)`, иначе `no such module: vec0`.
- `sudo -n -u kesha systemd-run --scope` → `Interactive authentication required`.
  Запускать scope от root с `--uid`/`--gid`.
- Ноут юзера не стенд: `/tmp` там tmpfs = RAM, гейт по `MemAvailable` из `/proc/meminfo`.
