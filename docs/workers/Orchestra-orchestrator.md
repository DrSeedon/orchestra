# Личная память — Orchestra-orchestrator

- `GET /api/usage` отдаёт `utilization` в ПРОЦЕНТАХ (0–100), не долей. `five_hour.utilization: 1.0` = 1%, а не «выжрано». 11.08 объявил юзеру «Claude 5h выжран в ноль» при реальных 1% и зря увёл задачу на Sol. Порог тревоги — от 80.
- Не тянуть `logs.content` из БД без `substr(content,1,200)`: один запрос на 6 строк вывалил в контекст три полных копии `session.py`. Для дат/фактов хватает `ts` + первых 200 знаков.
- Снимок живой `data/orchestra.db` — только `sqlite3.Connection.backup` (WAL), и это работает: `sqlite3.connect("file:data/orchestra.db?mode=ro",uri=True)` → `.backup(dst)`.
- **Первое срабатывание квотного предупреждения (#186) — проверка гипотезы, а не подтверждение.** Порог `D > 14` стоит на ДВУХ авариях, безопасный конец шкалы не проверен вообще: недель без стены на Max 20 в истории нет. Пришло сообщение, а неделя потом прошла спокойно → пересчитывать порог, а не подкручивать текст.
- `get_worker_info` вываливает в контекст весь системный промпт воркера (56 КБ). Для статуса, модели и ctx% хватает `list_agents`.
- **Алерт сторожа про `ugrep` по ВОЗРАСТУ — почти всегда ложный.** 12.08: pid с `cmdline` = `ugrep -E "^FAILED|passed|failed"`, age 267 с, и это был обычный `grep` в конце конвейера `pytest ... | grep ... | tail -3`: state `S`, CPU 0.0%, RSS 7 МБ — он просто ждал вывода живого pytest. Убийство сорвало бы законный прогон тестов. Перед решением смотреть НЕ возраст, а: state (`D`/`R` против `S`), `pcpu`, RSS и **жив ли производитель** (`ps -o args= -p $(ps -o ppid= -p PID)`). Возраст сам по себе — не признак вреда: конвейер с долгим тестом законно ждёт минутами.
