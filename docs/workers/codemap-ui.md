# codemap-ui — личная память

## docs/codemap/
- `validate.py` требует **побайтовое равенство** `nodes/edges/flows` в `codemap.json` и в блоке
  `<script id="codemap-data">` внутри `codemap.html`. Значит: данные правим ТОЛЬКО в json, а html
  пересобираем целиком (шаблон + `json.dumps(..., separators=(',',':'))` вместо `__DATA__`).
  Руками синхронизировать два места — гарантированное расхождение.
- Новый признак для подачи (`group`, `weight`, `summary`) кладётся в json: лишние ключи валидатор
  не ломают, а хардкод в html развалит равенство при следующей регенерации карты.
- Лок и фингерпринты считаются по `app/**`, поэтому правки в `docs/` карту не протухают —
  `working_tree_dirty` остаётся `false`, валидатор зелёный при грязном `docs/`.

## Браузерные проверки (Playwright)
- Селектор по классу скоупить к области рисования: `.edge` ловил ещё и SVG-образцы из легенды
  в сайдбаре — счёт 78 вместо 72, проверка врала в обе стороны.
- `inner_text()` отдаёт текст ПОСЛЕ `text-transform: uppercase` — сравнение с исходной строкой
  («Файлы модуля») падает на ровном месте. Сравнивать в одном регистре.
- Точку для проверки панорамы искать через `document.elementFromPoint`, а не «где-то справа внизу»:
  случайная точка попадает в узел, mousedown уходит в drag, панорама «не работает».

## CSS
- Специфичность решает молча: `.dim {opacity:.13}` (0,1,0) проигрывала `.edge {opacity:.5}` —
  приглушение посторонних связей не работало ВООБЩЕ, а выглядело как «слабоватый эффект».
  Состояния писать парой классов (`.edge.dim`) и проверять через `getComputedStyle`, а не глазами.
- Инлайновый `style="color: var(--t-core)"` пересчитывается при смене `data-theme` сам —
  а `element.style.color = getComputedStyle(...)` замораживает цвет старой темы.
  Поэтому наблюдатель за атрибутом темы не нужен: достаточно ссылок на переменные.
