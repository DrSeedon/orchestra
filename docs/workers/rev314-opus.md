# rev314-opus — личная память

## Ревью статистического вывода

- **Артефакт лежит в ЧУЖОЙ ветке** → `git show <sha>:<path> > /tmp/...`, ветки не переключать.
  Скрипты автора читать ПОСЛЕ того, как свои числа сошлись, иначе повторишь его же ошибку.
- **Автор выбрал параметр по таблице-сетке (M, порог, окно применимости) → пересчитай сетку
  мелко ВОКРУГ выбранной точки и проверь, существует ли решение при ДРУГИХ значениях.**
  Крупный шаг таблицы (10→16→24→34→48) прячет ровно то, что делает выбор подгонкой. В #314:
  на шаге 38 зазор между классами менял ЗНАК (−5.1), а при M=10 разделение вообще существовало
  с другим порогом — то есть заголовок «разделение появляется только к 34» опровергался
  собственной таблицей автора двумя строками ниже.
- **«3 из 3 поймано, 0 из 3 ложных» → спроси, какой ТРИВИАЛЬНЫЙ конфаунд даёт то же самое.**
  В #314 признак «тариф = Max20» давал те же 3/3 и 0/3 и тот же p, не сделав ни одного замера.
- **Предрегистрированный фальсификатор → посчитай, когда предлагаемое правило физически МОЖЕТ
  сработать, и сравни с моментом предсказанного события.** В #314 гейт мог открыть рот
  20.08 13:29, а стена предсказана на 20.08 11:00 — ветка «стена» была размечена как
  подтверждение, хотя означала опровержение.
- Знаменатель доли (слепота / время / выборка) проверять отдельно от числителя: числитель у
  автора сошёлся точь-в-точь, а доля была занижена в 1.3 раза из-за лишних окон в знаменателе.

## Технически

- Реплей `weekly_runway` по истории: базу считать ТОЛЬКО по снимкам `ts <= now`, иначе
  переякоривание из будущего тихо завышает результат.
- Живая БД: `sqlite3.connect('file:/home/kesha/orchestra/data/orchestra.db?mode=ro', uri=True)` —
  читает WAL, копировать не надо.
