# fix-reboot — личная память

## Как тестировать фронтенд в этом репо
JS-инфраструктуры тестов нет (`tests/` = pytest), но фронт всё равно можно проверить
поведением, а не глазами:

1. `node --check app/static/js/app.js` — только синтаксис. Ничего не доказывает о логике.
2. Реальный тест: вырезать нужный блок из `app.js` по маркерам (`// === Имя ===` … следующая
   функция), скормить его `eval` в `.mjs`-скрипте поверх стабов `document`/`fetch`/`location`/
   `AbortSignal`. Тестируется НАСТОЯЩИЙ код файла, а не его копия — копия разошлась бы.
3. Зелёный харнесс проверять мутацией: `sed`-ом убрать сам фикс из вырезанного блока и
   убедиться, что тесты краснеют. Без этого шага харнесс может не проверять ничего.

Харнесс в репо не класть: извлечение по номерам строк/маркерам протухнет от первой правки рядом.
Он одноразовый, для доказательства в отчёте.

## Ошибки fetch различимы, и это важно
`AbortSignal.timeout` → `TimeoutError` (сервер жив, но медленный).
Мёртвый сервер → `TypeError` (refused) мгновенно, либо `502` от прокси.
Ловить их одним `catch` = путать «медленно» со «смертью».
