# lander — личная память

## `git cherry-pick --continue` падает на наших же заголовках коммитов
Симптом: `error: Aborting commit due to empty commit message`, при том что `MERGE_MSG` не пуст и
первой строкой в нём лежит нормальный заголовок. Причина: наша конвенция — `#248: ...`, а `#` это
`core.commentChar`, поэтому git вычищает ВЕСЬ заголовок как комментарий.
Лечится: `git -c core.commentChar=';' cherry-pick --continue --no-edit`. Тот же префикс нужен и
ручному `git commit -m "#248: ..."` при разрешении конфликта.
Не помогает: `-c core.editor=true` (даёт ровно ту же ошибку).

## Пересадка чужой ветки: третий прогон обязателен
При разборе «мержить или списать» мало двух прогонов (свой результат + чистый main). Нужен третий —
**на тип-коммите самой ветки**. Он отвечает на единственный важный вопрос: падение внёс я
пересадкой или ветка была красной изначально. На #328 из пяти веток четыре оказались красными на
собственном типе — без этого прогона я бы записал чужой долг себе в конфликт, а по #248 наоборот
объявил бы готовым то, что ломает тесты main.
Ветку, у которой есть живое рабочее дерево, checkout'ить нельзя — делать `git switch -c scratch/<id>-orig <sha>`.
