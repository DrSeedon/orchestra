# feat-review-council — личная память

## Дешёвый одноразовый вызов LLM для замеров (проверено #184, 11.08.2026)

Нужен прогон «модель отвечает на текст, без тулов» сотни раз — вызывай так, из ПУСТОГО
каталога (иначе подтянется `CLAUDE.md`/`AGENTS.md` и испортит сравнение):

```
claude -p --model claude-opus-5[1m] --output-format json \
  --strict-mcp-config --mcp-config '{"mcpServers":{}}' --tools "" \
  --system-prompt "<персона>" "<вход>"
```

Замерено на тривиальном промпте: так — **$0.044**, дефолтом (`--append-system-prompt`,
тулы и MCP на месте) — **$0.202**. Разница 4.6× и вся в холодном префиксе: 23 000 токенов
определений тулов против 4 358. `--output-format json` отдаёт `total_cost_usd` и `usage` —
телеметрия на каждый вызов бесплатно. Реальный вызов с текстом на 2-3 КБ: медиана $0.059,
32 с. ThreadPoolExecutor на 4 потока — 28 прогонов за 5.5 минут.

У `codex exec` отдельного системного промпта НЕТ (`--help` проверен) — персона идёт началом
промпта, и это забивает сравнение рантаймов: разделить «рантайм» и «форму подачи» уже нельзя.
Планируешь кросс-рантайм замер — закладывай эту примесь в дизайн заранее.

## Слепое судейство: повторы, добавленные ПОСЛЕ раскрытия ключа, — не данные

Наступил на это в #184. Схема была правильная: перемешать выходы, спрятать метки арм-ов,
записать оценки в файл, только потом открыть ключ. Дальше я увидел единственный найденный
эффект, дозаказал ещё два повтора, чтобы «уточнить», и отсудил их уже зная арм-ы. Ревьюер
это поймал за минуту: заявленные «10 из 10» распались на слепые 3/3 и досуженные 2/2.

Правило для себя: **доливать прогоны в уже раскрытую ячейку можно, но они exploratory
навсегда.** Хочешь подтверждающих — новый слепой ключ на новую партию, отдельный файл оценок.
Дозаказ ради «уточнения» бьёт ровно туда, где вывод и так держится на волоске.
