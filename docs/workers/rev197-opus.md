# rev197-opus — личная память

## Версию библиотеки в этом репозитории проверять ТЕМ интерпретатором, что запускает прод

`python3 -c "import starlette; print(starlette.__version__)"` в оболочке даёт **системный**
`~/.local/lib/python3.13` — там свои, обычно СТАРЫЕ версии. Прод запущен из проектного venv:

```
systemctl show orchestra -p ExecStart
  -> /mnt/data/Projects/Python/orchestra/.venv/bin/python3 -m uvicorn app.main:app
/mnt/data/Projects/Python/orchestra/.venv/bin/python3 -c "import starlette; print(...)"
```

Замер #197: системный питон говорил `starlette 1.0.0`, проектный venv и прод — `1.1.0`.
На этом расхождении оркестратор выдал автору ложную находку «ты написал не ту версию».
Всегда: сперва `ExecStart`, потом версия ИМ.

## Прогоны здесь — только `uv run` с `PYTHONPATH=$PWD`

Голый `python3` не видит `app` (`ModuleNotFoundError: No module named 'app'`), а после
`uv run` — не видит `fastapi`, если PYTHONPATH указывает мимо. Рабочая форма для проб:

```
timeout 300 env PYTHONPATH=$PWD uv run python /tmp/<probe>.py <arm>
```

**Не писать `env` без команды** — распечатает всё окружение с боевыми токенами в контекст.

## Обвинять правку в флаке только на РАВНЫХ и БОЛЬШИХ выборках

#197: с правкой 5 падений из 9, базлайн 5 из 5 зелёный — выглядело как явная регрессия.
На равных выборках по 14: 3/14 против 2/14, то есть флак предсуществующий. Малая выборка
базлайна («5 из 5 зелёный») была просто везением. Порядок: заподозрил регрессию → гони
ОБА плеча одинаковое и большое число раз, и только потом пиши вывод.

Дальше сужать причину отключением компонентов правки по одному
(`cp file /tmp/bak` → нейтрализовать → прогон → `cp /tmp/bak file`): если флак
воспроизводится во ВСЕХ плечах, правка ни при чём.

## Проба дренажа: свой эндпойнт САМ попадает в счётчик

`is_mutating_path` считает мутирующим любой неизвестный POST, поэтому эндпойнт, который
изнутри зовёт `drain_mutating_requests()`, ждёт сам себя и всегда возвращает `false`.
Настоящий `/api/restart` исключён через `_CENSUS_EXEMPT_PATHS`. Доказательство строить на
ЗНАЧЕНИЯХ счётчиков (`inflight_mutating_count()`), а не на булевом ответе дренажа.
