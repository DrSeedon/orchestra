# research-codex-html — личная память

## Вытаскивание зашитых промптов из бинаря Codex

`strings` по бинарю Codex **врёт молча**: рвёт строку на первом не-ASCII символе, а у OpenAI
в промптах типографские апострофы (U+2019). Симптом — текст обрывается на полуслове
(`...based on the user'`) и выглядит как «всё, что там есть». Читать надо сырые байты:

```python
B = pathlib.Path(BIN).read_bytes()
i = B.find(b'"instructions_template": ')
text, _ = json.JSONDecoder().raw_decode(B[i+25:i+200025].decode('utf-8','replace'))
```

Где что (проверено на `@openai/codex@0.146.0`, бинарь
`/usr/lib/node_modules/@openai/codex/node_modules/@openai/codex-linux-x64/vendor/x86_64-unknown-linux-musl/bin/codex`):

- 8 системных промптов моделей — поля `"instructions_template"`, слаг ищется в `"slug"` за ~6 КБ до
- HTML/CSS-ассеты вьюера — рядом со смещением 249.8 млн, маркер `<!--__INLINE_VISUALIZATION_FRAGMENT__-->`
- Живые промпты, которые реально ушли модели, — в `~/.codex/sessions/**/rollout-*.jsonl`.
  **Это и есть способ доказать, что извлечённый из бинаря ассет не мёртвый:** ищи в rollout
  дословное предложение из шаблона.

`grep` по такому извлечённому файлу иногда молча возвращает пустоту (бинарные остатки) —
не верить, перепроверять через python `.find()`.

## Codex-ревью при выбранной квоте

Лимит терминальный: `turn.failed` приходит ДО того, как модель увидит задание. Локальность
цели («прочитай один файл») не помогает. Если в постановке написано «квота выбрана до <дата>» —
ревью не запускать вовсе, сразу писать честное «вердикта нет» + собственный состязательный проход.
