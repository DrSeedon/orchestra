# src325-openai-reset — личная память

## Веб-ресёрч: обходы, которые работают
- `help.openai.com` и `support.claude.com` — оба Intercom, оба отдают **403 на голый curl** (проверено: `403 9935`). Штатный обход — `curl -s https://r.jina.ai/<url>`: отдаёт тот же документ текстом, `Updated: N days ago` сохраняется. Это не пересказ модели, цитировать можно.
- `developers.openai.com/codex/<page>.md` отдаёт **308** и редиректит на `learn.chatgpt.com/docs/<page>.md`. Всегда `curl -sL` и цитировать конечный URL.
- `api.github.com/search/code` → **401 Requires authentication** без токена. А `api.github.com/repos/<o>/<r>/releases?per_page=100&page=N` — **без токена работает**, 4 страницы = 400 релизов. Для «когда появилась фича X» это дешевле и точнее, чем code search.
- Реддит/X через r.jina.ai не идут (x.com → 403), а `threads.com` — идёт (200).

## Грабля, стоившая машины (18.08.2026)
Искал в 311-МБ бинарнике паттерном `.{0,50}(purchase|buy|checkout)[^\n]{0,60}reset[^\n]{0,30}|…` — катастрофический бэктрекинг на blob-строках `.rodata` (в Rust-бинарнике одна «строка» = десятки КБ без переносов). `ugrep` съел 5.6 ГБ RSS, машина ушла в своп, оркестратор убил процесс. У Orchestra `OOMScoreAdjust=800` — при нехватке памяти ядро убьёт ЕЁ, а не мой grep.
**Как надо:** `strings -n 10 <bin> > /tmp/x.txt` один раз, затем `grep -c -F "<литерал>"` в цикле по кандидатам. Линейно, мгновенно, и отрицательный результат по 10 литералам — нормальное доказательство отсутствия. Никаких `.{0,N}` вокруг альтернации по большому входу.
