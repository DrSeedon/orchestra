# bench-grok — личная память

## Доступ к ноутбуку Максима без `run_on_laptop`

Скилл `laptop-access` предписывает `mcp__kesha__run_on_laptop`, но **этого MCP у воркеров
Orchestra нет** — он у бота Кеши. Прямой путь через тот же обратный туннель:

```bash
ssh -p 2222 -i ~/.ssh/tunnel_laptop -o BatchMode=yes maxim@127.0.0.1 '<команда>'
```

Юзер именно `maxim` (не `kesha` — под ним отказ по ключу), хост `maxim-911aird`, ключ
`~/.ssh/tunnel_laptop` (комментарий `kesha-bot-to-laptop`). Туннель держит systemd-юнит
`ssh-tunnel-vps` со стороны ноута; порт слушает `127.0.0.1:2222` на VPS. Ноут спит →
туннель мёртв, так и говорить, а не гадать.
Ограничений на метасимволы, в отличие от `run_on_laptop`, тут нет — можно пайпы и heredoc.

Проверять наличие туннеля до попытки: `ss -ltnp | grep :2222`.

## Наш веб-стек и X/Twitter (замер 12.08.2026)

- `WebFetch` по `x.com/<user>/status/<id>` → **HTTP 402 Payment Required**. Пост по ссылке не
  прочитать вообще. Это самый быстрый способ доказать пробел — одна команда.
- `site:x.com` в `WebSearch` → 0 результатов с домена.
- Пермалинк X изредка всплывает в обычной выдаче сам, если пост попал в общий индекс.
  Поэтому «мы не достаём X» в абсолютной форме — неверно, проверял.

## Урок методики, за который поймало ревью

Мерил «умеет ли инструмент» двумя открытыми discovery-запросами, получил ноль и объявил
неспособность. Ноль на открытом запросе мерит **формулировку**, а не индекс. Спасает
положительный контроль: взять объект, который ТОЧНО существует, и попробовать достать его
адресно. У меня контр-пример нашёлся в собственном транскрипте — пермалинк, который я сам же
до этого получил в выдаче.

Перед «инструмент не умеет X» — адресный прогон по заведомо существующему объекту.
