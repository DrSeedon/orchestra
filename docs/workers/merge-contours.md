# merge-contours — личная память

Роль: сведение разошедшихся контуров (VPS ↔ origin), разбор конфликтов по классам.

- «N конфликтов» и «N коммитов расхождения» — НЕ размер работы, пока не проверен `git cherry <base> <side>`.
  После `filter-branch`/переписи истории у одной и той же работы разные SHA, и Git считает её чужой.
  Замер #155: постановка «996 своих коммитов, 52 конфликта», по факту `git cherry` дал
  **900 patch-equal и 35 уникальных**, из них 2 оказались дублями другой нарезки squash.
  Итог — 33 cherry-pick и 8 ручных резолвов вместо разбора 52 конфликтов вслепую.
  Порядок: `git fetch` обеих сторон в ОДИН скретч-клон → `git cherry main other` →
  чинить только `+`. `git merge` тут врёт по объёму, а `git rebase` спотыкается на уже-upstream.
- `git cherry` печатает коммиты СТАРЫЙ→НОВЫЙ. `tac` перед `cherry-pick` = хронология наизнанку:
  первым лёг самый свежий, конфликт на файле, которого ещё нет («deleted in HEAD»).
  Порядок брать из `git rev-list --reverse --no-walk=sorted` и сверять первый/последний по дате.
- Конфликт «одна и та же строка правил / один и тот же пункт памяти» — это НЕ «взять обе».
  Сначала прочесть, не является ли одна сторона ПРОДОЛЖЕНИЕМ другой: в #155 сторона VPS дважды
  переписывала тот же буллет про флак (#105 добавил метод чередования, #107 вычеркнул починенный
  тест). Слепой «keep both» дал бы три редакции одной мысли, включая уже неверную.
  Правило: одинаковая мысль → заменить на позднюю; разные мысли → обе.
- `git cherry-pick --continue` после резолва ТЕРЯЕТ subject, оставляя только
  `(cherry picked from ...)`. История перестаёт искаться по `#id`. Проверять
  `git log --oneline base..HEAD | grep '#<id>'` ПОСЛЕ пика, чинить `filter-branch --msg-filter`
  и доказывать сохранность содержимого `git diff <backup> HEAD` = пусто.
- Приёмка «ничего не потеряно» считается по СОДЕРЖИМОМУ, а не по `git cherry`: после ручных
  резолвов patch-id уже другой, и десяток коммитов вечно висит как «уникальный».
  Работают два счёта: `comm -23` отсортированных `git ls-tree -r --name-only` обеих сторон
  (файлы, которых нет) и `git merge-base --is-ancestor origin/main HEAD` (сторона не откачена).
  `comm` без `LC_ALL=C sort` молча врёт на кириллических путях — предупреждение об order легко проглядеть.
- Красный тест в фоновом прогоне, зелёный в интерактивном — сперва СРАВНИ ОКРУЖЕНИЕ, а не код.
  Замер #155: `test_workspace.py` дал 306/306 руками и 2 падения из-под `bg_create`, потому что
  фон стартует без `LC_ALL` из профиля, и git печатает `fatal:` по-русски, а тест ждёт
  `'not a git repository'`. Воспроизводится в одну команду: `LC_ALL=ru_RU.UTF-8 pytest <тест>`.
  Доказательство «не моё» — тот же тест на НЕслитом main под тем же локалем.
- Доставка на живой VPS, где работают агенты: `git push <ssh> ветка:refs/heads/ветка` —
  рабочий `main` и сервис не трогаются вовсе. Проверка импорта — в `git worktree add --detach`
  на /tmp с последующим `worktree remove`, а не в чекауте. Перед доставкой ПЕРЕЧИТАТЬ HEAD VPS:
  за время работы там появился новый коммит (#119 Phase 2), и снимок часовой давности его терял.
