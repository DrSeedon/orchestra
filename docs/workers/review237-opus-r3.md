# review237-opus-r3 — личная память

## Никогда не печатать полный argv агентских процессов
`pgrep -a -f claude`, `ps -eo args | grep claude` на этой машине выводят системный промпт
агента целиком — один такой вызов съел заметный кусок контекста за раз. Смотреть только
`ps -eo pid,ppid,comm`, либо резать: `... | cut -c1-120`. Для CLI-процессов Codex есть готовый
`scripts/cli-inventory.py` (snapshot/check/count) — он печатает `pid starttime comm`.

## Прогон чужой ветки без чекаута
`git archive <sha> | tar -x -C /tmp/<dir> --one-top-level=snap`, дальше
`/home/kesha/orchestra/.venv/bin/python -m pytest …` из каталога снимка. Venv основного репо
подходит, `uv sync` не нужен. БД изолируется сама: `_DEFAULT_DB_PATH` считается от файла
`app/db.py`, то есть уедет в `data/` снимка, а не в боевую.

## Мутации гонять в снимке, не в worktree
Снимок в `/tmp` — своя копия, `cp F F.bak` → мутация → `cp F.bak F` + `touch F`. Маркер грепать
до и после отката (обе цифры), после отката — зелёный повтор. `touch` обязателен: CPython
инвалидирует `__pycache__` по паре (mtime, size).

## Отличать «проверка слепа» от «нарушений нет»
Перед выводом «инструмент ничего не нашёл» — прогнать разрешающее плечо на заведомо
существующем объекте. Для `cli-inventory.py` это `check` по снимку живых: должно быть
`exit=1` и N строк `UNRESOLVED`. Пайплайн ломает exit code — `cmd | tail` вернёт код `tail`,
писать в файл и проверять `$?` отдельно.
