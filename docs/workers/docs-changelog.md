# docs-changelog — личная память

## Актуализация CHANGELOG: сперва найти ГРАНИЦУ, а не поверить постановке

Задача приходит как «CHANGELOG отстал, задокументируй период». Период в постановке —
**подсказка, а не граница**. Дважды подряд оказывалось, что часть работы уже задокументирована
(другим воркером в другой ветке, уже смерженной), и переписывание её заново дало бы дубли версий.

Порядок, который работает:

1. `grep -n '^## v' CHANGELOG.md | head` — верхняя версия.
2. `git log main --oneline -S'<верхняя версия>' -- CHANGELOG.md` — **коммит, который её добавил.
   Это и есть настоящая граница**, а не дата в заголовке версии: заголовок говорит, ЧТО описали,
   коммит — ГДЕ остановились.
3. `git log main <тот-коммит>..main` — реальный undocumented-хвост.
4. `grep -nE '#(N|M|…)([^0-9]|$)' CHANGELOG.md` по id из хвоста — какие уже упомянуты.
   **Без `([^0-9]|$)` grep `#1` матчит `#12`, `#14`, `#134`** и врёт, что задача описана.

## Источники: два прохода, и второй важнее

- `git log main` — НЕ своя ветка. Своя ветка теряет коммиты, влитые в main после её создания.
- `docs/tasks/<id>/report.md` + `research.md` по КАЖДОМУ id. Счётчик коммитов не покажет
  отозванные и отрицательные результаты, а они — самое ценное. Три задачи подряд (#132/#133/#134)
  закончились «не делаем», и в git это выглядит как «только доки, ничего не менялось».
- Задачи без `report.md` (только `codex-review.md`) читаются по диффу: `git show <sha> -- <файл>`.
  Комментарии в самом дифе часто содержат готовый triggered case — авторы их туда пишут.

## Грабли

- `git log --format=%B -n1 <sha>` печатал тело ПОСЛЕДНЕГО коммита, а не запрошенного.
  Рабочее: `git show -s --format='%s%n%n%b' <sha>`.
- Номера задач в разных доках — **разные пространства имён**. В `docs/tasks/133/research.md`
  «#8» означает старый RAG-документ, а не задачу #8 про дашборд. Сверять по содержанию,
  не по номеру.
- Один коммит бывает squash-пакетом из 7 задач (`946c43f` = #4/#5/#6/#7/#10/#12/#14).
  `git show --stat` по нему — единственный способ увидеть, что в него реально вошло.

## README: править только разошедшееся

Проверять фактом, а не глазами: ключи `.env.example` против README, `[project.optional-dependencies]`
в `pyproject.toml` против команд Quick Start, версии моделей грепом по `app/`.
Так нашлось, что `uv sync` в README тихо не ставит RAG — ровно грабля, на которой уже
споткнулся деплой в #131.
