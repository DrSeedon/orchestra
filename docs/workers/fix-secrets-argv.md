## Рантаймы: флаги CLI зависят от ПОДКОМАНДЫ, а не от бинарника
- `codex --profile` работает у `exec/review/resume/...`, но **отвергается у `app-server`** —
  а Orchestra запускает Codex именно как `codex … app-server --stdio`
  (`app/backend_codex.py`, сборка `codex_cmd` в `connect()`). Проверять флаг на ТОЙ подкоманде,
  которой пользуется прод, а не на удобной для пробы.
- `$CODEX_HOME/config.toml` **читается и в `app-server`** — это рабочий файловый маршрут
  для настроек Codex (проверено прогоном с JSON-RPC хендшейком).
- Отсутствующий профиль Codex не вызывает ошибки: стартует молча и без MCP. Любой файловый
  конфиг требует fail-loud проверки применения.
- Codex отказывается создавать PATH-алиасы, если `CODEX_HOME` лежит в `/tmp`.

## Где в Orchestra живут секреты и логи (пригодится снова)
- `db.add_log` (`app/db.py`) — единственный INSERT в `logs`, но **не единственный выход
  наружу**: рядом `broker.publish` в `app/live_broker.py` (4 точки в `session.py`), эфемерный
  SSE-поток, который в БД не пишется. Задача про «маскировать в логах» = два шва, не один.
- `_sanitize` в `app/runtime_history.py` — готовые регулярки под секреты (Bearer, PEM,
  named secrets). Применяются только к рендеру истории, не к записи логов. Брать регулярки,
  не функцию.
- `session.to_dict` MCP-конфиг наружу не отдаёт; RAG индексирует только `user_message`/`text`.

## Как писать КРАСНЫЙ тест на ещё не существующий модуль
Прямой `from app.new_module import f` даёт `ModuleNotFoundError` на сборке — это «сломано»,
а не «красное», и по нему не видно, чего не хватает. Обёртка превращает провал в внятный assert:
```python
def mask():
    assert importlib.util.find_spec("app.secret_mask") is not None, "app.secret_mask не реализован (T1)"
    from app.secret_mask import mask_secrets
    return mask_secrets
```
Тот же приём для ещё не написанного МЕТОДА: `prepare = getattr(b, "_prepare_codex_home", None)` +
`assert callable(prepare)`. Проверять после коммита: `grep -cE "^ERROR|errors during collection"`
в логе прогона обязан дать 0 — иначе тесты не красные, а битые.

## Плоский `mcp_env` — граница доверия, а не просто словарь
`_codex_factory` (`runtime_registry.py:230-234`) схлопывает env ВСЕХ MCP-серверов в один dict,
а `_make_mcp_config` (`manager.py:409-414`) кладёт кастомные серверы ПОСЛЕ `orchestra` →
их ключи перетирают доверенные. Защищено только ИМЯ `orchestra`, имена переменных — нет.
**Любое решение, опирающееся на `ORCHESTRA_SESSION_ID`/`ORCHESTRA_SCOPE`, обязано брать их из
`mcp_servers["orchestra"]["env"]`, а не из плоского `mcp_env`.** Иначе спавн с кастомным
сервером подменяет значение, включая `../..`.

## Проверка, которая ловит саму себя
`ps`-скан с секретом-ЛИТЕРАЛОМ в собственной команде нашёл «утечку» в своём же процессе:
инструмент проверки попал в измеряемое множество. Правило: значения для сверки читать ИЗ
ФАЙЛА, себя исключать по pid, и вообще — прежде чем поверить сканеру процессов/файлов,
спросить, видит ли он себя.
