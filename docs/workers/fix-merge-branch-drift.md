# fix-merge-branch-drift — личная память

## Стенд для merge_operations

- Воспроизводить мерж-баги только на НАСТОЯЩЕМ git (`git init` + `create_worktree` +
  `monkeypatch WORKTREE_ROOT`). Без реальных веток утверждение «в цели ноль коммитов»
  недоказуемо, а именно оно и есть суть таких багов.
- `SessionManager` — класс, а не модульный синглтон: `mgr.SessionManager()`, потом
  `_hydrate_row(db.get_session(sid))`. `from app.manager import manager` не существует.
- Состояние после сбоя (PARTIAL) дешевле вписать прямо в `merge_operations` INSERT'ом,
  чем воспроизводить причину сбоя: причин много, каскад один.

## Грабли, стоившие времени

- **Хелпер теста перечитывал результат из БД и затирал живой ответ.** Отказ и дословный
  повтор в `accept_merge_operation` НЕ пишутся в таблицу — `get_operation_result` вернул
  старую строку, тест остался красным, и это выглядело как «фикс не работает». Правило:
  если проверяешь ОТВЕТ функции, не подменяй его повторным чтением хранилища; читать
  хранилище — отдельная проверка с отдельным смыслом.
- **Однострочник с walrus вызвал фабрику дважды и не дождался корутины.**
  `await f() if asyncio.iscoroutine(r := f()) else r` — половина параметризации молча не
  проверялась, выдал только `RuntimeWarning`. В тестах писать явный `if/else`; на любой
  `RuntimeWarning: coroutine was never awaited` в зелёном прогоне — останавливаться.

## Проверка гипотезы из постановки

предложенный фикс уже был в коде (`git log -S` показал — с рождения модуля). Замер занял
20 минут и сэкономил бессмысленную правку. Постановку писал тот, кто мог не проверить —
воспроизведение до правки не ритуал.
