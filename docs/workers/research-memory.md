# research-memory — личная память

## Диагноз из задачи — гипотеза, а не факт

Оркестратор даёт СИМПТОМ и часто своё объяснение к нему. Объяснение может быть
неверным: по #120 мне выдали «переименование поля `.output`», а реально мок
перестал перехватывать и тест лез в реальную систему. Воспроизводи сам и смотри
на вывод, а не на формулировку задачи. Стоит одной пробы, экономит починку
не того.

То же после потери контекста (compact/смена рантайма): в передаточной сводке
есть РЕЧЬ, но нет вызовов инструментов и их вывода. Всё, что «помнится» про свои
прошлые замеры, — не доказательство, перемерь.

## Проверяй ЦИТАТУ заявки, а не только заявку

Прежде чем опровергать громкий тезис — найди его в первоисточнике. По #121 мне
дали «бесплатный доступ ко всему интернету»; в README автора такого нет
(там «一键装上互联网能力» + «zero API fees» по 6 названным площадкам), фраза
пришла из агрегаторов. Опровергать надо то, что автор написал, иначе бьёшь
чучело и вывод разваливается на ревью.

Зеркально: вторичный обзор тоже может врать в минус. Тот же #121 — обзор писал
«no tests, vibe-coded», реально 32 файла / 385 тестов / 7929 строк (больше, чем
прод-кода). Считай сам: `ls tests/`, `grep -c 'def test_'`. Контр-находка в
пользу проверяемого объекта — такой же результат, как находка против.

## Рекомендацию по починке мерь так же строго, как находку

Диагноз замерил — а лекарство приписал по логике. По #121 я замерил, что
Hiddify:12334 мёртв, и вывел «поднять его + yt-dlp, две команды». Оркестратор
прогнал Reddit по ЖИВЫМ прокси: `:12343` → 403, `:12342` → 000, `:12345` → 000.
Reddit режет датацентровые IP как класс, поднятие прокси ничего не чинит.
Причина ошибки: я нашёл ОДНУ поломку (мёртвый порт) и принял её за ЕДИНСТВЕННУЮ,
хотя рядом в собственном отчёте цитировал их `channels/reddit.py` — «blocked,
all variants». Свои же находки противоречили моей рекомендации, и я это не сверил.

Правило: прежде чем писать «чинится за N команд» — прогони предлагаемый путь
целиком, на всех живых вариантах. Оценка стоимости починки — такое же
утверждение, требующее замера, как и всё остальное.

## Моки умирают молча при смене seam

Перенёс спавн/IO на новую функцию — **грепни тесты на СТАРОЕ имя**, не только
прод-вызовы. `monkeypatch.setattr(module.asyncio, "create_subprocess_shell", ...)`
не падает, когда код перестал звать этот seam: мок просто перестаёт перехватывать,
и тест уходит в реальную систему. У меня так сьют реально исполнял
`sh -c "python monitor.py"` пять раз за прогон (#120).

Проверка: `grep -rn --include='*.py' "<старое_имя>" tests/`.

## Зелёный тест ≠ рабочий тест

Прежде чем поверить починенному тесту — временно сломай проверяемое поведение в
проде и убедись, что тест **падает**. Мок-заглушка, которая никогда не срабатывает,
проходит «тихую» половину ассертов и выглядит зелёной. Мутацию откатывать через
`cp` бэкапа + проверять `git diff` пустой.

## Гонки в тестах: ждать содержимое, а не существование

`open(path, "w")` создаёт файл ПУСТЫМ, запись прилетает позже. Цикл
`if file.exists(): break` → `int('')` на загруженной машине. Ждать непустой
`read_text().strip()`. Проверять стабильность повтором (8×) И параллельно (3×) —
одиночный зелёный прогон гонку не опровергает.

## Команды, которые здесь работают

- Тесты: `UV_CACHE_DIR=/tmp/uv-cache nice -n 15 uv run python -m pytest -q > /tmp/pytest-<id>.log 2>&1`
- Полный сьют — только под `acquire_test_lock` → прогон → `release_test_lock`,
  один раз, `nice -n 15` (машина юзера рабочая, CPU грелся до 93°C).
- Долгий прогон — `bg_create(type="run", ...)` и **закончить ход**, не поллить.
- Скрипт-проба из `/tmp` требует
  `uv run --project <путь_к_worktree> python /tmp/x.py` — иначе не найдёт `app.`
