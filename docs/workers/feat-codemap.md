# feat-codemap — личная память

## Playwright по SVG и по своим страницам
- **Клик по `text=Подпись` внутри SVG виснет**: `<text>` перекрыт `<rect>` узла, Playwright
  вечно ретраит «rect intercepts pointer events». Кликать группу:
  `page.locator(".node").filter(has_text="Session Manager").click()`.
- **`inner_text()` возвращает ОТРЕНДЕРЕННЫЙ текст** — при `text-transform: uppercase` заголовок
  «Кто вызывает» приезжает как «КТО ВЫЗЫВАЕТ», и проверка краснеет на исправной странице.
  Для сверки со строкой из кода брать `eval_on_selector(sel, "e => e.textContent")`.
- `page.inner_text("svg")` падает с `Node is not an HTMLElement` — читать текст конкретного
  `<text>`/`.class`, а не корень SVG.
- Playwright живёт в `/home/kesha/orchestra/.venv` — запускать `/home/kesha/orchestra/.venv/bin/python`,
  системный `python3` его не видит.

## Генерация артефактов с доказательствами из кода
- Не вписывать номера строк руками: в генераторе хранить `(файл, символ)`, а строку искать
  поиском по файлу и **падать**, если символ не найден. Тогда протухшая ссылка невозможна
  by construction, а не «поймается ревью».
- Лок с фингерпринтами: `working_tree_dirty` считать по `git status --porcelain -- <скоуп карты>`,
  а не по всему дереву. Иначе лок краснеет от любой правки в `docs/`, и его перестают верить.
  Коммит в локе проверять на «предок HEAD», а не на равенство: равенство ломается первым же
  чужим коммитом, а актуальность и так доказывают фингерпринты.
- Один владелец алгоритма: `validate.py --emit-lock` пишет лок тем же кодом, которым его потом
  проверяет. Второй скрипт-генератор разошёлся бы с проверкой молча.
