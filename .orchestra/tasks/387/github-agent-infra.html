Подробности по проектам

Cloudflare Computer — почему архитектура знакома после #380/#381
  • SQLite в Durable Object — единственный источник состояния workspace.
  • Worker shell/JavaScript быстрые; Linux container даёт настоящие binaries и network.
  • Если spawn мог быть принят до transport failure, команда не replay-ится.
  • Orchestra уже строит похожие receipt/fencing контракты; импорт Cloudflare stack не нужен.
OpenViking — реальная дельта к нашему search_memory
  • У нас плоский hybrid search по Markdown/messages; у них directory recursion и уровни детализации.
  • У них trace показывает, почему retrieval пришёл к конкретному файлу.
  • Их benchmark vendor-supplied и на Doubao, поэтому нужен наш corpus.
  • Auto-memory сначала держать выключенной: curated память Orchestra безопаснее.
Omarchy — полезные части без переустановки
  • Одна quota panel объединяет Claude, Codex, Fireworks и записи других машин.
  • Systemd coredump превращается в диагностическую задачу агенту.
  • Update включает snapshot, migrations и config; bad update откатывается из boot menu.
Needle 2 — размер впечатляет, аргументы опасны
  • 45M parameters, CQ2-bit, 14 МБ binary, около 28 МБ RAM, 256-token window.
  • Schema grammar гарантирует форму JSON, но не истинность выбранных значений.
  • В issue #61 fine-tune улучшил tool retrieval, но не убрал fabricated arguments.
Semantica — 80% пользы в двух SQLite-таблицах
  • Nodes: user request, task, turn, review, merge, deploy, incident.
  • Edges: CAUSED, BLOCKED_BY, REVIEWED, MERGED_AS, RETRIED_FROM.
  • Отдельно server fact, user claim и agent claim — граф не должен уравнивать их.
  • Не хранить скрытую chain-of-thought; только опубликованное основание и серверные факты.
