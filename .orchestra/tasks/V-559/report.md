# V-559 — сколько стоит cache-read в двух подписках

Исследовано 12.09.2026. Платных запусков моделей не было. Живая SQLite открыта только
через `mode=ro`; копия базы не делалась. Числовые, обезличенные результаты находятся в
[evidence/claude-stable-runs.json](evidence/claude-stable-runs.json) и

[analyze_current.py](analyze_current.py).

## Короткий ответ

* **Claude Max:** чтение кеша выглядит практически бесплатным (или очень дешёвым), не
  заметной статьёй. Старые **0,00286 п.п./М** не доказали тарифный ноль, но новая проверка
  дала независимый ceiling: в одном непрерывном срезе **202,444,224 read-токена** прошли
  за 1,092 часа при неизменном отображаемом недельном проценте; при целочисленном счётчике
  это ограничивает наблюдаемый вклад всего среза сверху примерно **<0,00494 п.п./М**.
  Точный ноль не установлен.
* **Codex:** это другой контракт. Официальная карта считает input, cached-input и output
  в кредитах; cached-input тарифицируется, обычно как **10% input-ставки**, а cache-write
  не тарифицируется. В нашей БД есть много токенов для расчёта, но нет чистого парного
  эксперимента read/no-read, поэтому собственным пулом точную маржинальную цену чтения мы
  не измерили.
* **Fable 5.1:** скидка **$0,25/М** относится к token-billed поверхностям (например API),
  не является опубликованной скидкой Claude Max. При почти нулевом baseline read в Max
  скидывать практически нечего; это не доказывает, что Fable-read в Max математически
  равен нулю.
* **Codex-таблица:** активные строки API-долларов совпадают с текущим API-прайсом. Строка
  `gpt-5.4-mini` устарела: код считает `$0,30/$0,03/$1,25`, официальный текущий прайс —
  `$0,75/$0,075/$4,50` за input/cached/output. GPT-5.4 уже выведен из Codex для ChatGPT
  login, но его строка в коде по API-цене совпадает.

Каждый пункт выше — не счёт владельцу и не доказательство точного провайдерного тарифа,
если это прямо не сказано: `cost_usd` Orchestra — API-equivalent, а не invoice.

## Claude: усиление проверки без повторения регрессии

V-541 использовал 126 трёхчасовых интервалов и наблюдательную OLS-регрессию: read
**0,0028608 п.п./М**, day-bootstrap **−0,004738…0,011191**. Это совместимо с нулём,
но не является доказательством нулевого тарифа: общий пул, задержанный snapshot и
ненаблюдаемая активность оставляют смешение факторов.

В этой работе применён другой тест — целочисленный верхний предел на длинных плато. Для
среза с 09.09 по 12.09 отобраны серии snapshot-ов с одинаковым `seven_day_pct`, тем же
днём weekly reset и без разрыва более 380 секунд. Получилось **978** пригодных snapshot-ов
и **80** плато. Самое сильное:

| начало → конец | длительность | read | create | output | weekly pct |
|---|---:|---:|---:|---:|---:|
| 11.09 13:06:26 → 14:11:58 UTC | 1,092 ч | 202,444,224 | 430,060 | 276,336 | 67 → 67 |

Суммарно по 80 плато — **3,710,894,879 read**, но для ceiling используется один
максимальный непрерывный run, чтобы не складывать 80 независимых единиц округления. При
условии, что отображаемый недельный процент округлён/усечён до целого и за run нет скрытого
reset или истечения старых недельных начислений, одинаковое значение означает менее одного
п.п. истинного роста; все остальные наблюдаемые токены только увеличивают расход. Значит,
вклад read в этом run не больше примерно `1 / 202.444 = 0.00494 п.п./М`.

Это не причинный тарифный эксперимент: время окончания хода и время snapshot не совпадают
идеально, а лимит отображается с округлением. Но это уже не та же регрессия и не её
повтор. Для масштаба, API-пропорциональная модель V-541 (`0,036606 п.п./М` для 1h API
эквивалента) предсказала бы для этого run около **7,41 п.п.**, тогда как экран остался на
67. Это опровергает заметную API-подобную цену read в данном наблюдении; не опровергает
малую положительную цену ниже разрешения счётчика.

**Вывод Claude:** разумная рабочая классификация — «почти ноль / совместимо с нулём», а не
«доказанно бесплатно». Запись кеша остаётся заметной статьёй: V-541 оценил её в
**0,8708 п.п./М** (bootstrap **0,6091…1,1939**). Ceiling read относится к конкретному
наблюдаемому окну, не является универсальным SLA Anthropic и не переносится на API.

Официальная справка Claude говорит, что повторное содержимое **Projects** не считается в
лимитах; это формулировка про Projects, а не формула всех cache-read в Claude Code Max
([Usage limit best practices](https://support.claude.com/en/articles/9797557-usage-limit-best-practices),
доступ 12.09.2026). Открытой официальной формулы п.п./М для Max Code не найдено.

## Codex: что есть и чего нет

В текущей read-only выборке `turn_usage` есть **3 855** Codex-ходов:

* input **13,455,677,733**;
* cached-input **13,128,466,944** (это **97,57% input**, не добавлять второй раз);
* output **36,068,521**;
* cache-write **0**;
* 32 Spark-хода не имеют опубликованной цены и помечены `cost_unaccounted`.

Это достаточно, чтобы посчитать API-equivalent и официальные credits для каждого
ценообразуемого хода. Например, по текущей карте: cached-input стоит 0,5 кредита/М у
Luna, 10 у Sol и 25 у Astra; cache-write бесплатен. Но наши **3 277** сохранённых
`quota_primary_pct` — целые значения, а активность окна смешанная. Нет пары одинаковой
задачи с контролируемым cold/read режимом и нет неокруглённого provider-credit delta.
Поэтому эти данные дают состав и расчётный расход, **не измерение причинного вклада
cache-read в недельный пул**.

Официальная карта Codex определяет credits как сумму по input, cached-input и output и
прямо говорит, что cache writes не тарифицируются
([Codex rate card](https://help.openai.com/en/articles/20001106-codex-rate-card),
доступ 12.09.2026). Следовательно, утверждение «Codex-read бесплатен» неверно уже на
уровне опубликованного контракта, но это не означает, что `$` из нашей БД — сумма счёта.

## Fable 5.1: API-реклама против подписки

Anthropic публикует для Fable 5.1 `$10/М input`, `$50/М output` и cache-read `$0,25/М`,
то есть на 75% ниже Fable 5; сама формулировка ограничивает это поверхностями, где
использование тарифицируется по токенам, «such as on our API»
([Introducing Claude Fable 5.1](https://www.anthropic.com/claude-fable-and-mythos-5-1),
доступ 12.09.2026). Это не опубликованный коэффициент недельного пула Max.

Наши данные показывают общий `anthropic` weekly window без отдельной Fable-ёмкости; в KB
зафиксировано, что Fable ограничен долей общего weekly pool. В сочетании с Claude ceiling
это означает: скидка `$0,50 → $0,25` в API не создаёт у нас заметной экономии подписочного
пула, потому что исходный read уже наблюдается как <~0,005 п.п./М в наиболее сильном
run. Это **не** доказательство, что у Fable нет отдельного внутреннего счётчика или что
каждый Fable-read бесплатен; это вывод о практической ценности скидки при измеренном
baseline и отсутствии опубликованного Max-тарифа.

## Аудит `app/backend_codex.py::_codex_cost`

Функция в [backend_codex.py:124](/home/kesha/orchestra/worktrees/home-kesha-orchestra/cache-truth/app/backend_codex.py:124)
считает API-equivalent в долларах: cached-input вычитается из input, cache-write — из
остатка input, затем применяются цены из [строк 67–74](/home/kesha/orchestra/worktrees/home-kesha-orchestra/cache-truth/app/backend_codex.py:67).
Это корректно для семантики Codex «cached внутри input» и не делает двойного счёта.
Но `cache_write` в этой функции, если когда-либо придёт ненулевым, считается по API-ставке
`write`/fallback input. Это намеренно API-equivalent и **не** подписочный Codex-credit
расчёт: официальная карта подписки говорит, что запись кеша бесплатна. Сейчас в БД
`cache_create_tokens = 0`, поэтому расхождение не меняет сохранённые суммы.

Проверка текущими данными: пересчёт по актуальным API-ставкам для 3 822 priced-ходов
даёт **$7 067,0871**, тогда как исторически записано **$7 906,3940**. Это не ошибка
самой функции: строки `turn_usage` сохраняют тариф своего дня, поэтому после изменения
промо-ставки Sol историческая сумма не обязана пересчитываться текущей таблицей. Для
новых строк активных моделей таблица совпадает с официальными API-страницами. Spark
остаётся без долларовой оценки по дизайну.

Отдельно: официальная карта subscription-credit — это не API-dollar table. Для текущих
строк коэффициент ровно **25 credits = $1 API-equivalent** (например Sol 100/10/500
credits соответствует $4/0,4/20), но это нормализация для дашборда, не выставленный
провайдером счёт. OpenAI также описывает отображаемые dollar values как planning estimates,
not invoices ([Using Codex with your ChatGPT plan](https://help.openai.com/en/articles/11369540),
доступ 12.09.2026).

## Предлагаемая правка KB

Постоянные правила не менял. В KB стоит заменить формулировку «Fable-скидка не даёт ничего
на подписке» на более точную: «в опубликованном API даёт 75% скидку на cache-read; для
Claude Max отдельный тариф не опубликован, наши данные дают почти нулевой/совместимый с
нулём read, поэтому практическая экономия в Max не обнаружена; точный ноль не доказан».
Также отдельно пометить `gpt-5.4-mini` как устаревшую строку API-equivalent до решения
владельца о правке кода.
