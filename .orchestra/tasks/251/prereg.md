# #251 — предрегистрация очной ставки Grok 4.6 против 4.5 на поиске по X

Дата фиксации: 2026-08-13, **до первого модельного прогона**.

## Вопрос

- Контекст: Orchestra рассматривает Grok не как ещё одну общую модель, а как отдельный
  подписочный пул с уникальным доступом к первичным постам X.
- Изменение: сделать `grok-4.6` основной моделью Grok и, если она реально лучше, удалить 4.5.
- Контроль: `grok-4.5` в том же CLI 1.0.3, под тем же аккаунтом, конфигом, effort и корпусом.
- Решающий исход: проверяемость X-результата (правильный permalink, автор, время и дословный
  текст), а не общая красота ответа. Скорость и расход — вторичные.

## Гипотезы и фальсификаторы

- H1: 4.6 лучше 4.5 на X retrieval. Опровергается, если средняя разница качества не превышает
  собственный шум метрики либо 4.6 фабрикует хотя бы одну ссылку/цитату.
- H2: модели практически равны на X retrieval. Опровергается устойчивым перевесом 4.6 выше
  предрегистрированного порога без регрессии проверяемости.
- H3: X-инструменты недоступны именно в подписочном Grok Build. Опровергается хотя бы одним
  адресным прогоном, вернувшим точный заведомо существующий пост через X-tool; открытый ноль
  сам по себе H3 не подтверждает.

## Корпус: три задания, побайтно одинаковые для обеих моделей

Каждое задание исполняется **три раза новой сессией** на каждой модели: 18 прогонов. Никаких
дополнительных прогонов после раскрытия результатов в подтверждающую выборку не доливается.

### A — адресный fetch заведомо существующего поста/треда

Вход содержит permalink `https://x.com/grok/status/1948007957700268362`. Ground truth,
полученный до прогонов обычным WebSearch: автор `@grok`; 2025-07-23 09:11; текст начинается
`Here are my available tool calls` и перечисляет `x_keyword_search`, `x_semantic_search`,
`x_user_search`, `x_thread_fetch`.

### B — keyword/account discovery

Найти у `@ArtificialAnlys` пост про результат Grok 4.6 = 61 и сравнение с Sol. Ground truth:
permalink `https://x.com/ArtificialAnlys/status/2087564648325530099`; автор
`@ArtificialAnlys`; атомарные факты `Grok 4.6`, `61`, `GPT-5.6 Sol`.

### C — semantic discovery без ключевой цитаты и permalink

Найти пост `@grok`, смысл которого: ни одна модель не заменяет все остальные, выбирать надо по
задаче. Ground truth: `https://x.com/grok/status/2035155040218874325`; автор `@grok`;
2026-03-20 20:42; дословный якорь `Use the right one per task—no universal king.`

## Формат ответа и оценка

Одинаковая JSON-схема: `found`, `post_url`, `author_handle`, `timestamp`, `verbatim_text`,
`thread_urls`, `tools_used`. В prompt явно: использовать нативные X tools, не общий web;
неизвестное оставить `null`, не угадывать.

Каждый ответ — 10 баллов:

- точный permalink — 2;
- точный handle — 1;
- точные дата/время там, где ground truth задан (A/C), либо все три атомарных факта (B) — 2;
- дословный якорь/содержание без смыслового искажения — 2;
- в native trace есть X-specific tool (`x_*`) с успешным result — 2;
- нет выдуманного URL, автора, времени или цитаты — 1 (при любой фабрикации = 0 за пункт).

Для B два балла времени/фактов начисляются за все три факта; 2/3 = 1, меньше = 0.

## Собственный шум и порог удаления 4.5

- Шум модели: абсолютные разницы баллов между тремя повторами одного задания; headline —
  медиана всех попарных разниц внутри обеих моделей.
- Межмодельная разница: средний балл 4.6 минус средний балл 4.5 по 9 ответам каждой.
- **4.5 удалять только если одновременно:** преимущество 4.6 ≥1.0 балла из 10 **и строго
  больше медианного собственного шума**; у 4.6 ноль фабрикаций; адресный A ≥8/10 во всех трёх
  повторах; 4.6 не проигрывает 4.5 по числу успешных X-tool результатов.
- Разница меньше порога = **разницы нет**, не «слабое преимущество». Скорость не может сама
  удалить 4.5; она только tie-breaker после равного качества.
