# #437 preregistration — subscription counter regression

Frozen before the cache-write regression and before every Fable 5.1 call.

## Question

For five-hour Claude Max windows, estimate whether movement of the subscription counter is associated with cache-read tokens, cache-write tokens, or output tokens generated by Orchestra. The intercept remains explicit and represents counter movement not explained by the recorded Orchestra turns; it is not redistributed among token coefficients.

## Immutable data slice

- Database: `/mnt/data/Projects/Python/orchestra/data/orchestra.db`, opened read-only.
- Table: `turn_usage`.
- Rows eligible for token aggregation: `runtime = 'claude'` and
  `2026-07-29T05:17:21.890375+00:00 <= ts <= 2026-09-01T18:45:10.186332+00:00`.
- Quota boundary rows: the same slice with `quota_five_hour_pct IS NOT NULL`.
- The upper timestamp is the maximum quota-bearing Claude row observed during preregistration; later rows are excluded even if the live DB grows.
- Token values are used as stored. No API-dollar weights are applied.

## Primary window rule A

1. Sort quota-bearing rows by `ts` ascending. `id` is not an ordering key.
2. Start a new window whenever `quota_five_hour_pct` strictly decreases from the prior quota-bearing row. Equal values remain in the same window.
3. `five_hour_resets_at` is not used: provider timestamps jitter by sub-second amounts on successive samples and would split one physical window into many false windows.
4. Window bounds are the timestamps of its first and last quota-bearing rows, inclusive.
5. Assign **all** eligible Claude turns, including the 646 historically observed rows without a quota sample, to a window when their `ts` falls inside those inclusive bounds. Rows before the first quota-bearing row or after the last quota-bearing row of a segment are excluded.
6. Outcome `y = last(quota_five_hour_pct) - first(quota_five_hour_pct)`. With the monotonic boundary rule, `max-min` is deterministically identical and is recorded as an equivalence check, not a separate sensitivity arm.
7. Keep capped, short, and incomplete windows in the primary arm. This avoids selecting on the outcome or on how much local activity happened.
8. Predictors are per-window sums divided by 1,000,000: `cache_read_MTok`, `cache_create_MTok`, `output_MTok`. Fresh input is omitted from the load-bearing model because the frozen #434 slice measured only 60,639 input tokens against billions cached; it is reported descriptively.

Primary models, ordinary least squares with an intercept:

- Control: `y ~ 1 + cache_read_MTok + output_MTok`.
- Extended: `y ~ 1 + cache_read_MTok + cache_create_MTok + output_MTok`.

Report `R²` for both and `extended R² - control R²`.

The control passes when cache-read is near zero relative to output (absolute read/output coefficient ratio <0.01) and output is positive and at least 10× larger in magnitude than cache-read. Exact reproduction of another session's 55-window coefficients is not required because its window definition is unavailable.

## Identifiability checks for cache write

Before interpreting the extended coefficient:

- report Pearson correlations among read/write/output;
- report VIF for each predictor, computed by regressing that predictor on the other two with an intercept;
- report the condition number of the design after centering and scaling each predictor to unit variance (intercept excluded from scaling, then prepended);
- report p10/median/p90/min/max of `cache_create/cache_read` for windows with positive cache read;
- report the cache-write coefficient with an OLS standard error and 95% normal interval.

Interpretation gate: VIF >10, standardized condition number >30, or a 95% interval spanning both a practically large positive and negative effect means cache write is **not identifiable**. No directional recommendation may be made from that coefficient.

## Sensitivity arms fixed before the extended regression

- **B — quota-observed turns only:** same windows/outcome as A, but aggregate X only from rows whose own `quota_five_hour_pct` is non-null. This tests the assignment of quota-null turns.
- **C — coverage floor:** primary aggregation, but retain only windows with duration at least 1 hour and at least 5 quota-bearing rows. This tests very short/incomplete windows without selecting on `y`.
- **D — unsaturated:** primary aggregation, but exclude windows whose last quota value is 100. This tests right-censoring at the provider cap.

For B/C/D, run both control and extended models and the same identifiability diagnostics. A conclusion is stable only when the signs of output and cache-write do not reverse across A–D and the control read/output ordering passes in every arm. A cache-write result that changes sign or fails identifiability in any material arm is reported as unresolved.

## Pre-freeze contamination disclosure

Before this file was written, an exploratory reconstruction was used to discover the missing window definition. It observed:

- 3,953 total Claude turns, 3,307 with a quota value;
- 77 monotonic-decrease segments;
- on all 77 segments with all turns assigned by timestamp, the two-predictor control was approximately `intercept=27.49`, `cache_read=-0.14 %/MTok`, `output=141.77 %/MTok`;
- an exploratory `n_quota >= 20` filter happened to yield 55 windows and is therefore contaminated by the target count; it is excluded from all confirmatory arms.

The control coefficients are not blind evidence. Cache-write coefficients, VIF, condition numbers, ratios, and sensitivity results had not been calculated before this freeze and are the confirmatory output.

Before the commit freeze, an external result from the user's separate interactive session was disclosed: extended coefficients approximately `intercept=36.44`, `cache_read=-0.166`, `cache_create=0.13`, `output=140.86 %/MTok`, `R²=0.345`, and `ΔR²=0.000`. Therefore the extended result is now a **reproduction control, not blind discovery**. The local run passes by sign/order of magnitude and negligible incremental explanatory power; exact coefficients are not an acceptance criterion because the external 55-window membership is unavailable.

## Fable gate after the zero-cost regression

No Fable call is permitted unless all A–D control arms reproduce cache-read ≈0 and positive, much larger output weight. The later live experiment targets only whether Fable output tokens move the subscription counter like raw tokens (1× Opus) or API-price-weighted tokens (2× Opus). The Fable-scoped weekly counter may increase by at most 1 p.p.; the run stops immediately at that boundary. `/api/usage` is not an oracle; only fresh upstream telemetry is allowed.

After the regression, compute `tokens_per_5h_pp = 1,000,000 / output_coefficient`. The live target is chosen before calls so total planned Fable output is approximately one raw-weight five-hour p.p.; under the 2× hypothesis the same output is approximately two p.p. Actual output tokens, not requested length, are the denominator. Because the provider reports integer p.p., classify only when aggregated matched A/B intervals separate the hypotheses after allowing ±1 p.p. rounding; otherwise report inconclusive and do not spend past the Fable-scoped weekly cap.
