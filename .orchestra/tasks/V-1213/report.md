# V-1213 — порядок возврата Hub и отчёта

Исправлено в worker-copy; перенос и коммит в `task-V-1213/fix-hub-report-order` делает платформа. Git основного репозитория, сервисы и живые провайдеры этой задачей не изменялись.

## Поведение

- `_sync_back` сохраняет снимок возврата и внутренний журнал транзакции до применения файлов. После импорта фиксируются изменённые/удалённые пути, затем результат локального коммита, и только потом отправляется outbox.
- Родитель получает статус синхронизации и local HEAD, когда Git его предоставляет. Конфликты, отказы импорта/стейджинга, ошибки коммита и неуспешный провайдер больше не выглядят полным успехом. Явный текст работника сохраняется после итогового статуса.
- У каждого сообщения сохраняется broker-owned UUID. Потеря HTTP-ответа повторяет тот же UUID и тело через существующий API доставки. Принятые durable receipts, включая WAITING_QUOTA, подавляют дублирующий автоотчёт прежним механизмом.
- Неудача удаления удалённого outbox или доставки сохраняет локальный журнал. Следующий ход сначала восстанавливает его; пока восстановление не завершилось, нового upload/provider run нет. Автоотчёт сообщает о неудачном ходе; специального фонового ретраера не добавлено.
- Восстановление после замены/удаления файла и после Git commit учитывает уже выполненную работу. HEAD проверяется по содержимому, включая sparse/ignored пути. Последующая локальная правка не попадает в коммит возврата.
- Отмена ждёт завершения уже запущенной операции записи/коммита. Восстановленный старый отчёт не подавляет автоотчёт о следующей успешной работе.
- Старые WorkspaceState без `pending_sync` загружаются как раньше. Снимок удаляется после завершения транзакции и при штатном release workspace. Архив остаётся в локальном data-хранилище; его не импортируют в рабочую ветку.
- Снимок на той же FS атомарно перемещается `downloaded → .sync.tar`, сохраняя inode: второй полной копии нет. Только при EXDEV перенос идёт через `.sync.tmp` с буфером 64 KiB и fsync перед публикацией; промежуточный файл удаляется при ошибке, источник сохраняется. Перемещение/перенос и сохранение существующего import-журнала составляют один шаг, который дожидается отмены. Ненужный архив без журнала удаляется до следующей загрузки.

## Объём

Менялись broker lifecycle (`backend_hub`, внутреннее поле `WorkspaceState`, внутренние параметры `HubBridge`/outbox delivery), совместимость старой копии транспорта с V-1206, тесты и changelog. Внешняя схема трёх инструментов не менялась. Проверки данных/секретов/квоты и routing не ослаблялись; настройки Sleep V-1209 не менялись.

Интеграция с уже принятым V-1206 (`ef5cc8268`): `_sync_back` передаёт `ssh.get(..., max_out=None)`, summary не содержит старого `transport limit`. В предоставленной worker-copy ещё были старые `get`/`run`, поэтому им добавлен optional `max_out` с обработкой None. Вывод в файл читается порциями не больше 64 KiB; явные конечные ограничения сохранены. Тестовый FakeSsh принимает тот же keyword и соблюдает конечный cap. При переносе на main нужно сохранять уже принятый транспорт V-1206, не возвращать старую версию этой копии.

Два прежних теста обновлены под требуемый контракт частичного результата: отказ импорта теперь означает `turn_end.ok=False`; проверка доставки outbox ищет событие `text`, поскольку следом появляется событие `error`. Проверки сохранения разрешённых файлов, исключения запрещённых путей и количества доставок оставлены.
Проверка release дополнена реальными сохранённым и промежуточным файлами снимка и утверждениями об их удалении.

## Приёмка интеграционной поправки V-1206 / место на диске

Оба замечания закрыты в коде этой копии. Поля и фазы `pending_sync` не расширялись; нового runtime, фонового процесса или зависимости нет. Сохраняется принятый на main контракт V-1206 (`ef5cc8268`): sync-back вызывает `get(downloaded, max_out=None)`, чтение в файл ограничено порциями 64 KiB, старого `transport limit` в summary нет. Явный конечный cap проверяется отдельно и остаётся рабочим.

Сохранение архива: same-FS — один `os.replace`, тот же inode, никаких copyfile/copyfileobj. EXDEV — только тогда копирование буфером 64 KiB в `.sync.tmp`, flush/fsync, атомарная публикация и удаление источника. Ошибка записи/публикации сохраняет источник и очищает промежуточный файл. Перенос и запись import-журнала выполняются одним shielded шагом; повторный Stop дожидается его завершения. Осиротевшие `.sync.tar` и `.sync.tmp` без журнала удаляются перед новой загрузкой, поэтому не занимают место рядом с новым полным архивом.
