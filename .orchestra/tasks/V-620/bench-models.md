# Сравнение пяти моделей на одной задаче (V-616…V-620), 23.09.2026

Одно и то же задание дословно выдано пяти воркерам: развязать воркера, запертого после
`merge_worker(task_outcome="continue")`. Развилку решений владелец закрыл по ходу (вариант C:
чинить `switch_worker_branch`, мерж не трогать; по умолчанию задача возвращается в очередь,
явный аргумент закрывает её как done с обязательным основанием) — уточнение ушло всем пятерым
дословно одинаковым текстом.

Цена в долларах для GPT-6 берётся из `app/models.py`, где эти модели заведены без цен
(Codex считается в `backend_codex.py`), поэтому нули в колонке — отсутствие ставки, а не
бесплатность. Число ходов — строки `turn_usage`, то есть ходы с расходом, а не сообщения.

## Почему смержен Opus 5.5

Решающее — где хранится основание закрытия задачи, потому что это то, что читают потом:

* **Opus 5.5** — в самой строке прогона (`verdict_value`, `worker_head` у `task_run`), рядом с
  остальной судьбой прогона.
* **GPT-6 Luna** — в `failure_code` с префиксом `completed_by_switch:`, то есть причина успеха
  лежит в поле причины ОТКАЗА.
* **GPT-6 Sol** — в `kv` отдельным ключом; сам же отчёт признаёт, что восстановление только из Git
  тогда невозможно.
* **GPT-5.6 Luna** — отдельного поля нет, основание возвращается в ответе тула и нигде не хранится.
* **GPT-5.6 Sol** — реализация полная, но заодно правит модуль промпта `task-management`, то есть
  выходит за границы задачи.

Отрицательные плечи у всех: грязное дерево и несмерженные коммиты блокируют снятие привязки.
У Opus 5.5 они прогнаны как матрица {незакоммиченный файл, несмерженный коммит} × {обычный,
force, явное закрытие} — 8 тестов на реальном git; остальные покрыли 4–6 случаев.

Моя проверка мутацией на принятой ветке: `release_previous=None` при назначении новой задачи →
краснеют ровно два теста (освобождение и закрытие с основанием), без мутации 8 passed.
Автоматический гейт мержа независимо дал 4 красных под мутацией.

## Что это НЕ доказывает

Одна задача одного класса (правка платформенного lifecycle с готовым воспроизведением). Вывод о
маршрутизации моделей по одному наблюдению не делается: три модели из пяти справились за один ход
с рабочим результатом, и разница между ними — в качестве решения, а не в способности его дать.
Ветки четырёх не смерженных вариантов остаются в истории под `task-V-61{6,7,8,9}/bench-*`.
