## 1. LaTeX

**Поправка к V-684.** Там написано «LaTeX не ставили, MathTex не работает». На самом деле
системный TeX Live 2023 стоит на VPS с 07.08.2026 (apt: `texlive-base`, `-latex-extra`,
`-lang-cyrillic`, `-xetex` и др., `/var/log/dpkg.log`). `MathTex` с латиницей на нём работал. Не
работала кириллица: шаблон Manim по умолчанию — `\usepackage[english]{babel}` + amsmath, и
`\text{цена}` падал с `LaTeX Error: Unicode character ц (U+0446) not set up for use with LaTeX`.
Попытка просто дописать `babel[russian]` в преамбулу давала `Option clash for package babel`.

**Что сделано.**
- TinyTeX v2026.10 (TeX Live 2026, pdfTeX 1.40.29, dvisvgm 3.6) поставлен без apt и root в
  `~/.local/share/orchestra-manim/tex/` рядом с `env/`, 220 МБ. Пакеты: `standalone preview dvisvgm
  babel-english babel-russian cyrillic lh` и остальное, что нужно стандартным шаблонам Manim
  (`doublestroke setspace rsfs relsize ragged2e microtype wasysym physics jknapltx wasy mathastext`).
  Скрипт — `install-tex.sh`, логи — `install.log`, `install-extra.log`. Первая попытка упала на
  `curl: (22) … 503` от GitHub (`install-attempt1-503.log`), минутой позже тот же адрес отдал 200,
  поэтому в рецепте стоит `--retry`. Без `babel-english` TinyTeX падал на шаблоне по умолчанию
  (`Unknown option 'english'`).
  Зачем свой TeX, если есть системный: чтобы связка Manim не зависела от чужого apt и чтобы
  рецепт «если у тебя нет» в скилле был проверен, а не написан по памяти.
- `scripts/explainer_video/manim_voice.py` при импорте добавляет `tex/bin/x86_64-linux` в PATH
  (если папки нет, остаётся системный `latex`) и ставит `config.tex_template`: T2A,
  `inputenc utf8`, `babel[english,russian]`, amsmath, amssymb. Пробы (`probe/probe.py`): `MathTex`
  с суммой и дробью, `Tex` «Запись кеша: $0{,}6$ п.п. за миллион», `MathTex(r"\text{кеш}")`.
  Все три рендерятся и на системном TeX, и на TinyTeX.
- Скилл `explainer-video`: где лежит, как поставить, если нет; пример с подстановкой чисел через
  `TransformMatchingTex`; как разбирать `latex error converting to dvi`; приём `0{,}6` для
  десятичной запятой.

## 2. Ролик

`video/compact55.mp4`, 60.4 с, темп по умолчанию 1.25, 9 шагов, Manim + LaTeX.
Абсолютный путь: `/home/kesha/orchestra/worktrees/home-kesha-orchestra/feat-latex-video/.orchestra/tasks/V-685/video/compact55.mp4`.

**Сюжет.** У агента длинный разговор, и модель перечитывает его каждый ход. Кеш живёт час.
Формула подписки: чтение ≈ даром, запись — 0,6 % недели за миллион. Владелец вернулся через два часа,
кеш остыл, и 362 тыс. токенов записываются заново: 0,22 %. На 55-й минуте разговор сжимается в
пересказ на 84 тыс. токенов, и две его записи стоят 0,10 % против одной длинной за 0,22 %. За две
недели это 14,8 % против ≈7,1 % недели. Итог: 60 − 5 = 55 мин.

**Факты и откуда они:**
- `app/session.py`: `PRECOMPACT_DELAY_SECONDS = 55 * 60`, `CLAUDE_CACHE_WINDOW_SECONDS = 60 * 60`.
- KB `models-and-quotas.md`, раздел «ФОРМУЛА подписочного расхода» (V-605, обновление V-660):
  запись кеша 0,604 п.п./М (95% 0,196…1,233), чтение — ноль совместим. В ролике «по нашим замерам
  чтение почти бесплатно». Это и есть вывод KB, а не доказанный ноль.
- `compact_stats.py` → `compact_stats.out`, `data/orchestra.db` read-only, события
  `precompact timer outcome` у Claude с `compact_result.ok`, `pre_tokens` и `next_activity`:
  **70** компактов с 20.09 по 03.10 (всего успешных у Claude 109; у ранних нет полей токенов или
  возврата). Медиана 362 178 → 84 310 токенов (36 % → 8 % окна), медиана простоя 121 мин, 65 из 70
  возвратов пришли после 60 мин.
- Счёт: без сжатия возврат после ≥60 мин от последней активности перезаписывает `pre_tokens`.
  Итого 24,5 М → 14,8 п.п. Со сжатием свежая сессия пишет `post_tokens` сразу и ещё раз, если
  возврат пришёл позже 60 мин от самого компакта: 11,0 М → 6,6 п.п. Плюс пересказ как выход модели:
  784 тыс. знаков ≈ 261 тыс. токенов × 1,81 ≈ 0,5 п.п. Итого ≈ 7,1.

**Ограничения толкования.** Только коэффициент записи надёжен; выход (1,81) взят из той же
регрессии, где он ненадёжен, а «3 знака на токен» — грубая прикидка. Поэтому «≈ 7,1» точнее
читать как «около половины». Возврат до 60 мин без сжатия считается бесплатным, хотя каждый ход
чего-то стоит. Это одинаково в обеих ветках и в разницу не входит. Потерю памяти от сжатия ролик
называет словами («помнит пересказ, а не каждое слово»), но не измеряет. «Обычно 362 тысячи» —
медиана у тех сессий, которые сжимались, а не у всех агентов.

**Проверка.**
- Deepgram (`video/compact55.check.json`): сдвиг начала звука фраз ≤ 0,03 с, первого слова
  ≤ 0,12 с. Дословность по фразам 0,75–1,00, недобор — только числа: в сыром транскрипте они
  есть цифрами («362000 токенов», «06% недельного лимита», «02%», «55-й», «70», «15»).
- Кадры (`video/compact55-contact.png`) просмотрены. В первой сборке (`build-1.log`) были
  дефекты: «362 тыс. токенов» обрезалась правым краем, подписи под скобками формулы наезжали
  друг на друга, «% недельного лимита» налезал на Δq после подстановки, а сравнение читалось как
  «0,10 < Δq ≈ …». Полоса укорочена, подписи выровнены по краям скобок, «%» перенесён в формулу,
  справа теперь «0,6·0,362 ≈ 0,22 %». Во второй сборке (`build.log`) наложений и обрезки нет.
- `tests/test_explainer_video.py` — 4 passed; `scripts/check_instruction_contract.py` — OK.
