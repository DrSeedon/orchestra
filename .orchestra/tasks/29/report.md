# #29 — незащищённый Jinja-глобал больше нельзя смержить

## Мина, воспроизведённая целиком

Шаблоны читаются с диска живьём (`templates.env.auto_reload = True`, проверено), Python
живёт в памяти до рестарта, а рестарт делает человек руками. Значит между мержем и
рестартом **новый шаблон исполняется старым процессом**, где нового глобала ещё нет.

Воспроизведение по HTTP: `TestClient` поверх настоящего `app`, из
`templates.env.globals` удалены `static_url` и `build_id` («старый процесс»), загрузчик
шаблонов переключается между версией из HEAD и версией из ветки.

```
ДО   (шаблоны из HEAD):    {'/': 500, '/login': 500}
ПОСЛЕ (шаблоны из ветки):  {'/': 200, '/login': 200}
```

Падало на первом же вызове: `UndefinedError: 'static_url' is undefined`,
`login.html:6`. То есть в этом окне юзер не мог даже **залогиниться** — не «дашборд
подглючивает», а вход закрыт до тех пор, пока человек не перезапустит сервис.

`build_id()` уцелел только потому, что #15 обернул его в `{{ ... if ... is defined }}`.
У `static_url()` страховки не было; сегодня пронесло по случайности — глобал приехал в
13:44, рестарт был в 13:48.

## Решение

**1. Один владелец запасных значений — `app/templates/_globals.html`.**

```jinja
{% macro asset(path) -%}
{{ static_url(path) if static_url is defined else '/static/' ~ path }}
{%- endmacro %}

{% macro build() -%}
{{ build_id() if build_id is defined else '' }}
{%- endmacro %}
```

Оба шаблона импортируют его первой строкой; 14 вызовов `static_url(...)` (13 в
`dashboard.html`, 1 в `login.html`) переведены на `g.asset(...)`, `build_id()` — на
`g.build()`. Инлайн-страховка в каждой из 14 точек означала бы 14 копий запасного
значения — ровно то, что в этом проекте потом расходится.

Запасное значение честное, а не заглушка: `/static/js/app.js` без версии — это ровно
поведение до #9, старый процесс такой путь отдаёт.

**Рендер с глобалами не изменился ни на байт**: 23 533 символа `dashboard.html`,
2 843 `login.html`, сравнение с версией из HEAD при одинаковом контексте.

**2. Класс закрыт проверкой, а не дисциплиной — `tests/test_template_window.py`.**

Тест рендерит КАЖДЫЙ `*.html` из `app/templates` в окружении **без единого глобала
приложения и без контекста роута**. Это и есть худший случай окна: процесс не знает
ничего из того, что появилось после его старта.

- Параметризация идёт по файлам на диске, а не по списку внутри теста: добавят шаблон —
  он проверится сам. Отдельный тест следит, что параметризация не выродилась в пустую.
- `Undefined` берётся дефолтный, а не `StrictUndefined`: в проде именно он, и разница
  принципиальна — `{{ var }}` от неизвестной переменной даёт пустоту и живёт, а вот
  ВЫЗОВ и обращение к атрибуту бросают. `StrictUndefined` покрасил бы половину живого
  шаблона и научил бы игнорировать этот тест.
- Сообщение при падении называет файл, имя и что делать.

Почему рендер, а не grep по `{{ имя( }}`: grep рассуждает о синтаксисе, рендер
воспроизводит окно. Любая новая форма вызова (фильтр, атрибут, макрос из другого файла)
grep обойдёт, а рендер поймает.

Мутация: добавил в `dashboard.html` `data-new="{{ some_new_global() }}"` —
```
Failed: dashboard.html не пережил рендер без глобалов: UndefinedError:
'some_new_global' is undefined. Вызов глобала в шаблоне обязан идти через макрос из
_globals.html с запасным значением — иначе окно между мержем и рестартом даёт 500.
```
После отката — зелено.

## Что рассматривал и отверг

**`auto_reload = False`** — одна строка, и класс исчезает у корня: процесс держит те
шаблоны, с которыми стартовал, поэтому шаблон и Python всегда согласованы. Отверг по
двум причинам.

1. Это молча ломает документированное свойство («фронтенд обновляется без рестарта»,
   `CLAUDE.md`), и первый же агент, правящий шаблон, получит новый режим отказа: правка
   не применяется, причина невидима.
2. Рассинхрон не исчезает, а **переезжает**: статика по-прежнему отдаётся свежая, и
   старый шаблон встретится с новым `app.js`. Класс «новый клиент против старого
   сервера» этим не лечится (см. #22), а новый класс «старый DOM против нового JS»
   появляется.

Если владелец решит, что цена приемлема, правка тривиальна — но это отдельное решение
про режим разработки, а не про эту мину.

## Побочный улов: четыре теста, приколоченных к форме

Правка обёртки вызова уронила четыре чужих теста — тот же класс, что и три находки #22.
Все чинились одинаково: матчер переводился с ФОРМЫ на СМЫСЛ.

| тест | был приколочен к | стал проверять |
|------|------------------|----------------|
| `test_build_signal::test_body_has_data_build` | литералу `build_id` в `dashboard.html` | атрибут в шаблоне + страховку в `_globals.html` |
| `test_build_signal::test_survives_a_process_that_does_not_know_build_id` | `Environment().from_string(одна строка)` — импорт так не резолвится | рендер шаблона через `FileSystemLoader`; проверяет РЕЗУЛЬТАТ (`data-build=""`), в отличие от моего стража, который проверяет сам факт выживания |
| `test_usage_analytics_frontend::test_template_uses_wide_analytics_shell_and_leaf_script` | строке `static_url('js/analytics.js')` | факту подключения скриптом: `<script src="{{ … 'js/analytics.js' … }}"` |
| `test_static_js_globals::_page_scripts` (мой же, из #22) | регулярке по `static_url\('(js/…)'\)` | тегу `<script src=...>` независимо от обёртки |

Последний — показательный: мой собственный страж из #22 был написан устойчиво к списку
файлов, но не к форме вызова, и на первой же смене обёртки честно упал на
`assert len(scripts) >= 3` вместо тихого «коллизий нет». Fail-loud сработал, но урок
записан: путь к скрипту за сутки обернули дважды (`/static/js/x.js` →
`static_url('js/x.js')` → `g.asset('js/x.js')`).
