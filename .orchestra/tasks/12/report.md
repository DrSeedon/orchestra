# #12 — спавн не оставляет следов в дереве воркера

## Симптом
`merge_worker` → `FAILED — worker working tree is dirty (2 file(s): .claude/skills/codex-debate/SKILL.md, .env)`
в проекте seedon, шесть веток подряд. Воркер этих файлов не трогал.

## Корень (перепроверен, подтверждён)
Два независимых дефекта одного класса — **платформа пишет в рабочее дерево воркера**.

1. **Трекнутый скилл.** `prompting.inject_skills_to_worktree` копирует `pipelines/default/prompts/skills/<n>.md`
   → `worktree/.claude/skills/<n>/SKILL.md` безусловно. Если репозиторий сам версионирует этот путь
   (seedon: 14 файлов в индексе; orchestra/dnd-game-master/kesha-tg-bot: 0), копия = модификация
   отслеживаемого файла. `info/exclude` тут бессилен **по определению**: правила игнорирования
   не применяются к файлам в индексе. Дерево грязное навсегда → «чистое дерево перед DONE» невыполнимо.
   Для соседнего механизма (`sync_agents_md`) такая проверка была, для скиллов её просто не перенесли.
2. **Untracked `.env`.** Копируется из корня репо в worktree, в `_WORKTREE_EXCLUDES` его не было →
   в любом репо без `.env` в `.gitignore` он висит как `?? .env`. Лечилось руками в seedon и
   dnd-game-master; следующий новый репозиторий наступил бы снова.

Тот же класс бьёт и по копиям `CLAUDE.md`/`.mcp.json`, если репозиторий их трекает и в главном
чекауте они изменены: копия перезаписала бы версию ветки воркера.

## Решение
Одно правило вместо трёх частных: **платформа никогда не пишет поверх файла, который репозиторий
отслеживает, и всё, что она кладёт untracked, сама же и исключает.**

- `workspace.tracked_paths(worktree, rels) -> set[str]` — единственный способ задать вопрос
  «этот путь в индексе?». Git не смог ответить → `RuntimeError`, догадок нет. Вызывающий решает
  политику: `create_worktree`/`inject_skills_to_worktree` падают (спавн откатывается),
  `sync_agents_md` логирует и пропускает зеркало (как и раньше — устаревшее зеркало переживаемо).
- `create_worktree`: трекнутый файл из `copies` не копируется (лог `copy skipped`); реально
  положенные копии и таргеты симлинков уходят в `info/exclude` якорем `/<path>`.
- `inject_skills_to_worktree`: трекнутый `SKILL.md` не перезаписывается; остальные скиллы кладутся
  как раньше.
- `_exclude_claude_dir` → `_exclude_worktree_artifacts(wt, extra)` (старое имя врало: там уже
  были `AGENTS.md` и codex-артефакты).

### Почему «не трогать отслеживаемое», а не «класть инъекцию вне дерева»
Инъекция вне worktree означает свой механизм загрузки скиллов: Claude CLI читает
`.claude/skills/` относительно cwd — пришлось бы либо симлинчить (тот же untracked-мусор), либо
дублировать резолвер. В репо, который трекает скилл, агент теперь читает **версию репозитория** —
и это правильнее: файл по этому пути и так native-скилл Claude CLI, его положил владелец проекта,
а `prompting._project_skill_files` уже относится к таким файлам как к источнику истины для Codex.
Мы получаем один контракт для обоих бэкендов вместо двух разных.

## Цена / что изменилось в поведении
- Репо трекает `CLAUDE.md`/`.env`/`.mcp.json` → в worktree теперь версия **ветки воркера**, а не
  копия из главного чекаута. Для `CLAUDE.md` это скорее фикс (воркер видел чужую версию).
  Для трекнутого `.env` (плохая практика, но встречается) машинный `.env` больше не подставляется.
- Parent-fallback (`repo.parent/CLAUDE.md`) работает только для нетрекнутых файлов.
- В `info/exclude` общего git-dir добавляются строки вида `/.env` — они видны и главному чекауту.
  Файл, который платформа скопировала, уже лежал там untracked; после этого `git add <файл>`
  потребует `-f`. Осознанный размен: альтернатива — ручная правка `info/exclude` в каждом новом репо.

## Проверка
Скретч-репо с **отслеживаемым** `.claude/skills/codex-debate/SKILL.md` и untracked `.env`
(`/tmp/repro12.py`, живые worktree не трогались):

```
=== ДО (код из main) ===
 M .claude/skills/codex-debate/SKILL.md
?? .env

=== ПОСЛЕ ===
(clean)
SKILL.md content: # repo's OWN codex-debate skill
.env present in worktree: True
```

Тесты (по затронутым файлам, полный сьют не гонялся — глобальный лок у оркестратора):
`tests/test_workspace.py` 104 passed, `tests/test_manager.py` + `tests/test_session.py` 274 passed,
`tests/test_prompting.py` + pipeline 151 passed.
Четыре новых теста проверены мутацией — со стэшнутым фиксом падают все четыре:
`test_tracked_project_file_not_overwritten`, `test_spawn_into_repo_tracking_skills_leaves_clean_tree`,
`test_copied_untracked_file_does_not_dirty_tree` (workspace), `test_tracked_skill_not_overwritten` (manager).

## Не сделано (осознанно)
- Уже существующие worktree живых воркеров не чинятся задним числом: инъекция происходит на спавне,
  повторно не случится, а seedon/dnd-game-master поправлены руками. Реконнект (`sync_agents_md`)
  обновляет только статический список исключений — списка `copies` там нет.
- `_scaffold_role_docs` тоже пишет в дерево (`docs/tasks/<id>/…`), но это ожидаемые артефакты
  работы воркера, которые он и должен коммитить. Не трогал.
