# V-913 — Bash для Claude-задач в `wf_adapters`/`dynamic_workflow` и перепрогон T для Sonnet

## Починка
`scripts/wf_adapters.py`: при `tools="all"` и `network=True` Claude получает `Bash`, а в argv добавляется `--settings` с PreToolUse command-хуком (matcher `Bash`) → `scripts/wf_bash_hook.py`. Скрипт читает JSON из stdin и вызывает тот же `_make_pretooluse_hooks(_classify_bash_payload, cwd=…)` из `app/backend_claude.py`, что и обычные воркеры (V-773): те же причины отказа. Любое исключение → exit 2 (CLI блокирует вызов), то есть сбой хука не открывает шелл. Выбран command-хук, а не Agent SDK: `claude -p` и остальной адаптер (JSON-вывод, `parse_claude_output`, учёт токенов) остаются как есть; SDK потребовал бы переписать весь адаптер. `tools="read"` и `network=False` остаются без Bash: у CLI нет песочницы, и шелл мог бы `curl`-ить (отклонение от буквы «без сети — закрыто» нет, это его прямое следствие).

Живая проверка (haiku, `claude -p` 2.1.293, `--setting-sources ""`): `echo hello_ok` выполнен; `rm -rf /tmp/v913/victim` → «PreToolUse:Bash hook error: Recursive rm is blocked; move targets to trash instead.», каталог остался; `mkdir && ls` выполнен. Значит `--settings` работает вместе с `--setting-sources ""`.

Тесты (`tests/test_wf_run.py`, 86 passed вместе с `tests/test_dynamic_workflows.py`): хук как настоящий подпроцесс блокирует `rm -rf` и пропускает `echo hi && ls`; мусор на stdin → rc 2; для `read/True`, `read/False`, `all/False` нет Bash и `--settings`; для `all/True` есть Bash и хук. Мутации: хук всегда разрешает → красный `test_claude_bash_hook_blocks_…`; возврат закрытия Bash → красные 2 теста набора инструментов. Настоящий CLI в тестах не вызывается.
