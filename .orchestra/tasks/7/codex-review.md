## Ключевой факт, который переопределил задачу

Задача формулировалась как «`capture_output=True` прочитал stderr и выбросил, проверяется
только `returncode`». Замер показал, что дело хуже: **`git show-ref --verify` БЕЗ `--quiet`
возвращает `exit 128` и на отсутствующую ветку тоже.**

```
git show-ref --verify refs/heads/nope          → exit 128, "fatal: 'refs/heads/nope' - not a valid ref"
git show-ref --verify refs/heads/main (root)   → exit 128, "fatal: detected dubious ownership ..."
git show-ref --verify --quiet refs/heads/nope  → exit 1,   stderr пуст
```

То есть «ветки нет» и «git отказался работать» неразличимы по `returncode` **в принципе**,
и чтение stderr здесь не перестраховка, а единственный рабочий способ. Правильный образец
уже был в файле — `_inspect_branch_ref` (`--verify --quiet`, `exit 1` = нет ветки, прочее =
ошибка с текстом git). Второй помощник не заводил, слепые места перевёл на него.

  `elif target_now.returncode != 1:`.

### Почему 1323/1757/1815 оставлены

Эти три написаны в расчёте на семантику `--quiet` (`returncode == 1` = ветки нет), но
вызывают `show-ref` БЕЗ `--quiet`, где отсутствующая ветка даёт 128. То есть они уже
сегодня misclassify — но в обратную сторону: реально отсутствующую ветку считают сбоем git.
Это зеркальный дефект, менее опасный (шумит, а не молчит).

Чинить их **нельзя тем же приёмом**: все три читают `.stdout` ради OID, а `--quiet` его
подавляет; переход на `_inspect_branch_ref` меняет control flow внутри rollback-верификации
`merge_worker` — самого опасного кода в проекте. Ошибка там = потерянная работа воркера,
поэтому это отдельная задача со своим стендом, а не довесок к этой.

## migrate_agent.py — три дефекта одного корня

Скрипт считал, что ssh-юзер (`root@`) — это и есть юзер службы.

1. **D1 (заказанный)** — worktree и файлы создавались root'ом → git отказывается работать.
2. **D2** — `~` раскрывался в `/root`, а не в домашку юзера службы, **на обоих концах**.
3. **D3** — `enc_cli_dir` делал `.lstrip('-')`, а CLI ведущий дефис сохраняет.

D2+D3 вместе означали, что перенос транскриптов не работал никогда, а в лог писался успех:
в `/root/.claude/projects` три каталога и **ноль файлов**.

**D3 починен не подгонкой под имена каталогов.** Пары `(cwd → имя каталога)` вынуты из
первой строки самих `.jsonl` (поле `cwd` пишет CLI): со `lstrip` совпало **0 из 23**, без
него — **23 из 23**. Тест повторяет этот замер на живой машине и скипается там, где
`~/.claude/projects` нет.

Обратимость: схема CLI лossy by design (`fix-reboot` и разделитель дают один и тот же `-`),
поэтому «обратимо» здесь = воспроизводить имена CLI ровно; это и проверяется парами.

Владельца берём из владельца каталога установки (`stat -c %U`), а не из логина, и после
`chown -R` **перепроверяем** `find ! -user` — иначе это была бы ровно та же ошибка
«поверили в успех, не проверив».

## Три теста пришлось поправить — и почему это не ослабление

Полный прогон дал 3 падения, все от моей правки. Разбирал каждое, а не «подгонял под зелёное».

1. **`test_standalone_non_git_raises`**, 2. **`test_not_git_repo_raises`** — ждали дословного
   `"repo_path is not a Git repository"`. Это ровно та формулировка, которую задача просила
   убрать: она называет причину от себя. Тесты переведены на новый текст и **усилены** —
   теперь требуют, чтобы в сообщении был настоящий ответ git (`not a git repository`).
3. **`test_unobservable_final_target_snapshot_is_partial_unknown`** — считал вызовы с
   ДОСЛОВНЫМ argv `["git","show-ref","--verify","refs/heads/main"]` и ронял третий,
   имитируя отказ финального снимка. После правки первые два зонда идут в форме
   `--verify --quiet`, argv не совпадает, счётчик дошёл только до 1 → сбой не инжектился.

   Проверил инструментом, а не рассуждением: временная копия теста напечатала реальную
   последовательность —
   ```
   #1 ['git','show-ref','--verify','--quiet','refs/heads/main']
   #2 ['git','show-ref','--verify','--quiet','refs/heads/main']
   #3 ['git','show-ref','--verify','refs/heads/main']
   ```
   То есть все три инспекции на месте, изменилась только форма первых двух, а финальный
   снимок (строка 1323) не тронут вовсе. Матчер в тесте переведён с argv на ref — ordinal 3
   снова попадает в финальный снимок, и тест по-прежнему требует `partial` / `unknown`.
   Верификация не ослаблена: она и не менялась.

## Слабые места, которые оставляю осознанно

1. **`give_to_service_user` не делает снимок владельцев пофайлово** — только считает
   количество чужих до/после. Полный снимок на дереве воркера дорог, а число + проверка
   «после = 0» даёт fail-loud, которого не было вовсе.
2. **Ошибки самого `chown` не отделены от «частично не применилось»** — `ssh(check=True)`
   уронит миграцию с текстом ssh/chown, что для скрипта миграции приемлемо.
3. **Сквозной прогон миграции не выполнен** — нужны два хоста; проверены единицы
   (кодирование на живых парах, fail-loud ветки, назначение каталога) и компиляция.
