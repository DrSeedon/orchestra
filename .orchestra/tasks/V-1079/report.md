- The reader now reduces compact errors, completion and lifecycle immediately through one backend-owned operation record. The former private queue and delayed lifecycle drain are removed. Non-retryable errors wake the caller even before ACK/S; retry hints permit recovery, but a definitive failed/interrupted/unsupported terminal fails the operation. Terminal-embedded error text is retained. Success requires ACK, a started lifecycle, a recognized compact notification and a completed terminal. Both S/C/T and S/T/C remain supported, including notifications before ACK. A successful terminal alone never proves compaction.
- Root review found a missing combination in the first implementation: pre-ACK S/C/T resolved the compact future successfully, then EOF released the local owner while the coroutine still awaited the missing ACK and process exit remained pending. The caller consequently timed out instead of reporting transport closure. Success-future resolution now requires ACK as well as S/C/T, and readiness is checked from both ACK handling and the notification reducer. Thus the pending future can still receive a transport error before ACK, without changing ordinary startup stderr draining or adding a new RPC/disconnect policy. An RPC rejection after pre-ACK S/C/T also remains a failure.
- Ownership lasts through the complete operation, including the interval after C and before T/ACK. The first eligible compact turn is pinned. Explicit foreign thread/turn events are rejected before they can mutate compaction evidence or usage. Retired turn/item identities survive for the transport lifetime and are cleared on a new transport, preventing identified duplicates and old queued turns from claiming a retry. Their memory use grows with observed identities during that lifetime; message bodies are not retained in these sets.
- Timeout and caller cancellation cancel only local waiters. The remote outcome remains unknown until a terminal or transport closure reconciles it. The old operation continues to own late notifications; late results are recorded separately and cannot turn the failed/cancelled call into success. Another native compact is refused until reconciliation. A known terminal without C permits a later retry after the caller's failure because remote work has ended; a missing ACK still prevents success even when C/T were observed.
- Ordinary user `turn/start` remains available after the compact caller leaves. Notifications arriving before its ACK are buffered and then routed with the ACK's user-turn ID. Late compact events remain with the old owner. Old tagged compaction events already in the ordinary queue are filtered by the next listener; ID-free idle compaction statuses carry an internal idle marker instead of appearing as a new user-turn compact. Existing deferred-control behavior, including its separate ordinary message visibility contract, is retained.
- EOF/read failure/disconnect wakes compact ACK/completion/terminal waits immediately, before waiting for process exit or stderr. The ordinary startup-error path still drains stderr and preserves its existing sanitized error contract. A reader captures its transport generation, process and notification queue; old reader data/finalization cannot fail or contaminate a new generation.
- Native interrupt selects a compact turn when known. Session manual interrupt can still reach a detached unresolved compact. An unacknowledged compact-only interrupt does not disconnect a live provider as a recovery shortcut or claim remote interruption. The pre-existing manual interrupt fallback for an actual ordinary RUNNING turn remains intact, including when a detached compact record also exists.
- Session `_compacting` still releases in `finally`, queued messages/durable deliveries are woken, and hibernation also checks backend `compact_pending`. This avoids hiding unknown remote work behind local idle without permanently blocking ordinary delivery. Successful compaction with no fresh usage clears the old percentage to unknown; the backend no longer returns an old rollout snapshot as new compact usage. Failure/cancellation preserves the previous context snapshot.

Diagnostics contain a local operation number, transport generation, caller stage, elapsed/stage timestamps, separate caller/remote outcomes, compact/terminal presence, late reconciliation, known error-info names, retry flag, and mismatch/invalid-JSON/legacy counters. They omit prompts, summaries, error bodies and native thread/turn IDs. Provider error text is exposed separately through the existing error result path, not copied into diagnostic metadata. Session failure results include diagnostics; cancellation remains `CancelledError` and logs its stage metadata.

## Missing-ID policy and recovery limits

Legacy `context/compacted`, `thread/compacted`, and contextCompaction items are all supported. Missing thread/turn IDs can succeed only in the exclusive started/terminal compact lifecycle; an actionable failure is allowed earlier in the exclusive request window. A matching explicitly known turn is never replaced by a foreign start or completion. With a concurrent ordinary user turn and a detached compact, ID-free C/error/usage events are ambiguous and are suppressed from both owners, with an overlap counter; positively identified ordinary events continue normally. Normal tagged terminals resolve the old operation.

ACK is `{}` and supplies no compact request/turn correlation ID. Completely ID-free duplicates replayed inside a later legitimate S..T window cannot be distinguished perfectly from that window's own legacy C. The compatibility boundary is an exclusive lifecycle and a successful terminal, not an invented wire correlation guarantee. No extra RPC, forced restart, automatic live-provider disconnect or new durable recovery architecture was introduced to conceal this protocol limit. If an unresolved compact never supplies any terminal, its compact/hibernate gate remains reserved; ordinary user and queued work still proceed. An explicit existing disconnect/transport closure releases the owner. State persistence across a real process restart and real native cancellation were not simulated as stronger guarantees than the current process owner provides.

Out-of-scope follow-up: ordinary non-compact RPCs retain their existing process-exit/stderr-drain behavior on EOF; this change only guarantees immediate failure for every compact stage. Stronger wire correlation for entirely ID-free legacy replays needs a provider contract, rather than another timeout heuristic.
