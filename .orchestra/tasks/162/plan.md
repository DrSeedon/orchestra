# #162 — план: показать реальный потолок 5h с учётом остатка недельного

Основание — `research.md` (курс r = 0.1379 в текущем режиме, N = 7.25 окон, формула
проверена вне выборки). Гейт Phase 2 пройден без отдельного ожидания (решение оркестратора).

## Что делаем

Одно вычисление на сервере, один потребитель на фронте, никаких новых индикаторов.

```
r             = Σ max(0,Δ7d) / Σ max(0,Δ5h) по usage_snapshots за трейлинг-72 ч
available_pct = min(100 − p5, (100 − p7) / r)     ← в п.п. пятичасового окна
locked_pct    = (100 − p5) − available_pct        ← показано свободным, взять нельзя
windows_left  = (100 − p7) / (100 · r)            ← ЕДИНСТВЕННОЕ число для подписи
```

Мало данных за 72 ч (Σd5 < 30 п.п. или Σd7 = 0) → `quota_headroom = null` и вид как сегодня.
Подставлять последнее известное r запрещено: курс дважды менялся вдвое, протухшее число
соврёт молча.

## Чего НЕ делаем

- Не трогаем шкалу 7d (она не врёт), Codex, Grok, стоимость и соседние индикаторы.
- Не добавляем третью копию описания окон: `_PROVIDER_META.windows` (`utils.js:22`) и
  `_normalizeUsageWindows` (`usage.js:391`) остаются единственными владельцами формы окна,
  `quota_headroom` приходит отдельным полем ответа и ни одну из них не расширяет.
- Не трогаем ховер-панель Usage control: она печатает сырые проценты, и они верны.
  Врёт именно ПОЛОСА в верхнем баре — пустое место на ней читается как «свободно».
- Не пишем производное поле в `usage_snapshots.provider_usage`: это вычислимое из истории,
  хранить его — заводить второго владельца одной мысли.
