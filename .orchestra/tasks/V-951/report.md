# V-951 — gzip в Claude Code: что сделано, получает ли Orchestra, видно ли в данных

## Короткий вывод
Orchestra этого ускорения сейчас **не получает**, причём по двум независимым причинам: CLI на VPS старше нужной версии (2.1.293 < 2.1.300), а наш запуск ставит `DISABLE_TELEMETRY=1`, из-за чего в 2.1.293 gzip выключен флагом. В наших данных ожидание до первого токена не измеряется вообще; грубый прокси не показывает сдвига после 14.10.

## 1. Что сделано на самом деле
- Первоисточник: официальный CHANGELOG anthropics/claude-code (скачан целиком, 1 046 331 байт; последняя версия в файле 2.1.302). Единственная запись про gzip запросов, **2.1.300**: «Changed large requests to api.anthropic.com to use gzip compression even when telemetry is disabled; set `CLAUDE_CODE_GZIP_REQUEST_BODIES=0` to turn it off». `npm view`: 2.1.300 опубликована 2026-10-14T14:27Z, 2.1.302 — 2026-10-16.
- Сжимается **тело запроса клиента → api.anthropic.com** (большие запросы `/v1/messages`). Ответ и SSE-поток этой правкой не затронуты. Это следует из текста записи и из кода бинаря (ниже), не из пересказа маркетинга.
- Важный нюанс: сам механизм **уже был** в 2.1.293. Читал бинарь 2.1.293 (`strings`, функция выбора `SEt`): gzip включается, если (а) хост `api.anthropic.com`, (б) нет прокси/mTLS/custom CA, (в) тело ≥ 4096 знаков (≥ 524288 для режима «блоков»), (г) серверный флаг `tengu_atomic_ocean` или `tengu_gzip_request_bodies` включён, либо env `CLAUDE_CODE_GZIP_REQUEST_BODIES` = true. Без флага — `reason:"flag_off"`. Фраза «even when telemetry is disabled» в 2.1.300 означает, что раньше при отключённой телеметрии флаги не приходили, и gzip не включался.
- Нет первоисточника для цифр 4,07→1,33 с и т.д.: картинку/пост Anthropic я не открыл (t.me не отдаёт текст, WebFetch вернул только обёртку). Цифры нашёл только в новостных пересказах (cryptobriefing, techcityauthority, pasqualepillitteri — не открыты, `socket hang up` / только сниппеты поиска); считай их **неподтверждёнными**. Там же утверждается, что часть выигрыша в cloud даёт отдельное изменение «cloud-сессия стартует при наборе» — не только gzip. Нужен оригинал пост @ClaudeDevs от 16.10.2026.
- Что именно ускоряет gzip — гипотеза (UNCERTAIN): меньше байт на аплинке для длинных контекстов (тело сотни КБ), эффект тем больше, чем хуже канал. Прямого измерения нет.

## 2. Получает ли Orchestra
- Запуск: Claude Agent SDK (`claude-agent-sdk` 0.2.164 в окружении, на PyPI 0.2.168), `app/backend_claude.py:_make_client`: `cli = shutil.which("claude") or $CLAUDE_CLI_PATH`; для не-оркестраторов `cli_path` = обёртка `agent_cli_exec.py`, которая зовёт этот бинарь. Бинарь, который идёт из SDK, не используется.
- На VPS: `/usr/bin/claude` → `/usr/lib/node_modules/@anthropic-ai/claude-code/bin/claude.exe`, версия **2.1.293** (файл от 8 окт). В npm есть 2.1.300–2.1.302. Глобальная установка root-овая (`npm ls -g`), обновление — `npm i -g` от root/через ssh kesha@localhost; агенту без прав не сделать, и это инфраструктурное решение владельца, не моё.
- `backend_claude.py` ставит `DISABLE_TELEMETRY=1` и `DISABLE_NON_ESSENTIAL_MODEL_CALLS=1`. На 2.1.293 это гасит флаги → gzip выключен. После обновления до ≥2.1.300 gzip включится сам даже при `DISABLE_TELEMETRY` (это и есть запись в changelog). В окружении сервиса `HTTPS_PROXY` не задан (проверено по /proc/<pid>/environ), то есть условие «proxy» не мешает.
- Обходной путь без обновления: задать `CLAUDE_CODE_GZIP_REQUEST_BODIES=1` в `env` клиента — код 2.1.293 при `true` пропускает проверку флага. **Не проверено на деле**: gzip применяется только к хосту `api.anthropic.com`, локальная заглушка не подходит, а подмена TLS ради проверки — отдельная работа. Риск: сервер мог бы отвергать gzip для части аккаунтов; в коде есть «latch off» после отказа.

## 3. Видно ли в наших данных
- Прямой метрики ожидания до первого токена **нет**. В `turn_usage` (всего Claude: авг 4111, сен 7505, окт 7618 строк) поля `api_duration_ms`, `turn_duration_ms` заполнены только с октября (4351 строк claude), за август–сентябрь — 0. Эти поля — длительность хода целиком, не TTFT.
- `logs` (742 005 строк, 2026-07-27…2026-10-18) не содержит событий «первый байт/первый токен»; stream-delta не хранится.
- Прокси, который я всё же посчитал: от `user_message` до первой строки `text|thinking|tool` в той же сессии (только сессии, где есть Claude-ходы; без промежуточного user_message; отброшено <0 и >600 с). Охват и результат (половины месяца по дате):

Ожидаемая выгода рассчитывается только после этого.

## 4. Что забрать в Orchestra
| Кандидат | Решение | Основание / цена |
|---|---|---|
| gzip запросов Claude CLI (≥2.1.300) | **Брать**, после решения владельца об обновлении CLI | Цена: `npm i -g @anthropic-ai/claude-code@2.1.302` на VPS + перезапуск CLI-сессий у воркеров (без рестарта Orchestra). Выгода на VPS с хорошим каналом неизвестна; замер по п.3 нужен до и после. Альтернатива — env-флаг, но без проверки не рекомендую. |
| Сжатие JSON/HTML дашборда | **Уже есть** | `GZipMiddleware(minimum_size=1024)` в `app/main.py:684` (#197: app.js 814→221 КБ); nginx `gzip on`, уровень 6, `application/json` включён. |
| Сжатие SSE (`/events`, `StreamingResponse` в `routes/sessions.py:840`) | **Не брать** | Starlette исключает `text/event-stream` намеренно: gzip буферизует и задерживает кадры; нужен flush на каждое событие, выигрыш мал (события — десятки байт), риск задержки вместо ускорения. |
| Тело запроса harness → OpenRouter (`backend_harness.py`, `harness/oneshot.py`) | **Не брать без проверки** | Сервис OpenRouter может не принимать `Content-Encoding: gzip` у запроса (не проверял, внешний контракт). Заметный выигрыш лишь при больших контекстах; harness — малая доля ходов (63+41 строк `turn_usage` за сен–окт). Цена проверки — один тестовый запрос на `:free` маршруте. |
| Доставка в TG | **Не брать** | Telegram Bot API не принимает сжатые тела; наш трафик — мелкие сообщения и файлы, уже сжатые (mp4/jpg). |

## Оставшаяся неопределённость
- Неподтверждены цифры Anthropic (нет первоисточника-картинки/поста) и вклад именно gzip.
- Эффективность `CLAUDE_CODE_GZIP_REQUEST_BODIES=1` на 2.1.293 выведена из кода, не из запроса.
- Прокси-метрика п.3 не измеряет TTFT.
