## Findings

### F1. Заявка «бесплатный доступ ко всему интернету» — НЕ формулировка автора. REFUTED (как цитата)
Заявка из постановки задачи не совпадает с репозиторием. Фактический headline README: *«给你的 AI Agent 一键装上互联网能力»* («в один клик повесить агенту интернет-возможности»). GitHub-описание перечисляет **шесть конкретных площадок**: «Read & search Twitter, Reddit, YouTube, GitHub, Bilibili, XiaoHongShu — one CLI, zero API fees».
Формулировка «бесплатный доступ ко всему интернету» — из сторонних агрегаторов, не из репозитория. `zero API fees` — заявление более узкое и, как показано в F4, в основном правдивое.
*Тиер: прямое чтение README + GitHub API. CONFIRMED.*

### F2. Под капотом — установщик и роутер, а НЕ краулер. CONFIRMED
Ключевой факт, определяющий всё остальное: **в CLI нет команд `read` и `search`**.
Полный список подкоманд (`agent_reach/cli.py`): `setup`, `install`, `configure`, `doctor`, `uninstall`, `skill`, `format`, `transcribe`, `check-update`, `watch`, `version`.

Из 17 модулей в `channels/` метод `read()`/`search()` есть только у трёх — `web.py`, `v2ex.py`, `xueqiu.py`. Остальные реализуют только `can_handle()` и `check()` — то есть проверку «установлен ли апстрим-тул».

Docstring базового класса (`channels/base.py`) говорит прямо: *«After installation, agents call upstream tools directly»*. README дублирует: *«负责选型、安装、体检、路由，不负责底层读取本身»* — «отвечает за выбор, установку, диагностику и маршрутизацию, не за само чтение».

Объём: **6 282 строки** в `agent_reach/`, из них `cli.py` — 2 115. Это размер инсталлятора, не движка сбора.

**Что реально читает контент** (внешние процессы, ставятся отдельно): `yt-dlp`, `gh` CLI, `opencli` (npm `@jackwener/opencli`), `rdt-cli`, `twitter-cli`, `bili-cli`, `xiaohongshu-mcp`, `mcporter`+Exa, `r.jina.ai`, `feedparser`.
*Тиер: чтение исходников. CONFIRMED.*

### F3. Главный механизм — угон собственной залогиненной сессии, а не обход антибота
Два несущих механизма:

1. **OpenCLI** (`backends/opencli.py`) — сторонний npm-пакет + **расширение Chrome** (`ildkmabpimmkaediidaifkhjpohdnifk`) + локальный демон на `127.0.0.1:19825`. Управляет **реальным Chrome пользователя**, переиспользуя живые логины. В докстринге прямо: *«desktop-only (no headless)»*.
2. **Извлечение cookie из браузера** (`cookie_extract.py`) через `rookiepy`/`browser_cookie3` из Chrome/Firefox/Edge/Brave/Opera. Целевые площадки и куки заданы явно: Twitter/X (`auth_token`, `ct0`), Bilibili (`SESSDATA`, `bili_jct`), Xueqiu (`xq_a_token`), XiaoHongShu (только ручной экспорт).

**Ответ на «за чей счёт»: за счёт ВАШЕГО аккаунта и вашей IP-репутации.** Ни зашитых ключей, ни общего прокси-пула автора в коде нет — H3 опровергнута. Платите вы: своей учёткой, своим трафиком и риском бана.
*Тиер: чтение исходников. CONFIRMED.*

### F4. «Бесплатно» правдиво, но потолок низкий и измерим. CONFIRMED (измерено)
Бесплатность обеспечена free-тирами чужих сервисов, а не магией:

- **Jina Reader** (`r.jina.ai`, канал `web` — единственный универсальный путь). **Замер 2026-08-02:** заголовок ответа `x-ratelimit-limit: 20, 20;w=60` → **20 запросов/мин анонимно**. Документация Jina: 20 RPM без ключа, 500 RPM с бесплатным ключом. Дополнительно тело ответа содержит `Warning: This is a cached snapshot of the original page` — то есть отдаётся **кеш, не живая страница**.

## Вердикт

**Заявка в присланной формулировке — неверна, но виноват пересказ, а не автор.** «Бесплатного доступа ко всему интернету» нет: есть установщик 15 адаптеров, где универсален ровно один (Jina, 20 RPM, кеш), платите вы своим аккаунтом и IP-репутацией, а десктопный Chrome обязателен для самого ценного.

**Не берём.** Причины: требует GUI-Chrome (у нас headless/VPS), ставит системные пакеты, привязывает риск бана к личным аккаунтам, и главное — **нашу конкретную боль (403 на Reddit) он не решает, а подтверждает, отсылая к платному residential-прокси**.

**Топ-3 применимого — заимствуем идеи, не код:**
1. **Доказательство готовности вместо флага** (`backends/opencli.py`): «файлы на диске не доказывают, что расширение включено; только живое соединение доказывает». Это ровно наш принцип из CLAUDE.md («проверять артефакт, а не рассказ») и `_verify_mcp_isolation`. Их формулировка строже нашей и стоит переноса на проверки готовности воркеров.
2. **`doctor --json` как машинночитаемый контракт готовности:** одна команда возвращает, какой бэкенд обслуживает канал прямо сейчас. У нас проверка живости прокси размазана по скиллам — единый `doctor` с `active_backend` дал бы агенту одну развилку вместо угадывания.
3. **Отказ от побочных эффектов в health-check:** они специально не используют `opencli doctor`, потому что тот авто-стартует демон. Хорошее правило для наших проб: health-check не должен менять состояние проверяемого.

**Немедленное действие вне agent-reach:** поставить `yt-dlp` (тривиально, закрывает YouTube). Reddit — отдельное решение, не команда: см. поправку в F10, поднятие Hiddify его не чинит, потому что блокируются датацентровые IP как класс.

**Главный практический итог задачи — не вердикт по репозиторию, а диагноз своего стека:** пока мерил чужую заявку, обнаружилось, что у нас сломан собственный доступ к Reddit (скилл указывает на мёртвый порт) и отсутствует `yt-dlp`.
