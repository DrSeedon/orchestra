Основание — `docs/tasks/77/research.md` (коммит `2713bc8`). Фаза 1 установила: мешает не

## Что меняется по существу

Одна строка `CLAUDE.md:164`. Всё остальное в плане — доказательства и проверка того,
что эта строка будет исполняться.

**Было** (`CLAUDE.md:164`, дословно):
```
- Мутационная проверка на УЖЕ ЗАКОММИЧЕННОМ фиксе → откатывай файл через `git show <commit>^:<file>` и подтверждай откат маркером (`grep -c`). `git stash push` стэшит пустоту, даёт ложное «7/7 passed» и целится `pop` в чужой стэш
```

**Станет** (кандидат, фиксируется ДО прогона — иначе A/B проверяет не тот текст):
```
- Мутационная проверка — три клаузы в ОДНОЙ команде: `cp F F.bak` → мутация → `mv F.bak F`, и `grep -c` маркера после отката. Любой git-откат (`checkout`, `show <ref>:F >`, `stash`) уничтожает НЕЗАКОММИЧЕННУЮ правку в F ровно так же, как мутацию: замер — три воркера за двое суток, один потерял работу за задачу
```

Что именно поменялось и зачем — по одному пункту, чтобы правку можно было оспорить по частям:

| Изменение | Почему |
|---|---|
| условие «на УЖЕ ЗАКОММИЧЕННОМ» убрано | в момент трёх инцидентов оно ложно → правило молчало. Условие, которое надо оценить, — класс, замеренный на 4% (`rm -rf`) |
| появился шаг отката (`mv F.bak F`) | шаг, на котором происходил ущерб, правилом не был описан вовсе; агент закрывал дыру идиомой `git checkout` (21 эпизод из 51) |
| `git show` больше не рекомендуется | замер: уничтожает незакоммиченное наравне с `checkout` (эксперимент в research.md) |
| `.bak` рядом с файлом, восстановление через `mv` | `mv` одним действием и восстанавливает, и убирает бэкап → оборванный прогон оставляет `F.bak` в `git status`, то есть fail loud. `/tmp` не годится: он общий для всех агентов хоста, два воркера с одинаковым базовым именем файла затрут бэкапы друг друга |
| три клаузы «в ОДНОЙ команде» | 17 из 21 откатов и так пишутся в одной команде с мутацией. Правило ложится на существующую привычку, а не воюет с ней |
| `git stash` не пропал, но ушёл в общую скобку | его отдельный разбор («стэшит пустоту, целится `pop` в чужой стэш») — хроника одного случая; действующая часть накрыта общим «любой git-откат» |
| `grep -c` маркера сохранён дословно | единственная часть старого правила, которая работала: именно `grep -c` показал feat-charts, что правка исчезла |

**Порядок фаз в промпте трогать не нужно.** Старое правило требовало коммита ДО мутации и
этим противоречило `full-cycle.md` Phase 3 (commit пятым шагом). Новое не требует коммита
вовсе — конфликт исчезает сам, вместо того чтобы его разруливать правкой промпта.

## Риски

1. **Внешняя валидность прогона.** Haiku ≠ Opus 5, на котором случились инциденты. Митигация:
   ограничение названо в AC T3 явно; при желании добавляется плечо 5+5 на Opus отдельным
   решением после того, как станет видно расход.
2. **Стенд может оказаться проще боевой ситуации** (у агента там одна задача и один файл,
   а не 20 ходов контекста). Тогда выживаемость завышена в ОБОИХ плечах — разница между
   плечами страдает меньше, но абсолютные доли читать буквально нельзя. Скажу в результатах.
3. **`.bak` остаётся в дереве при обрыве хода** → грязное дерево. Это осознанный выбор в
   пользу видимого следа против тихой потери; `git status` показывает untracked-файл, а
   правило про чистое дерево перед DONE его поймает.
4. **Правка `CLAUDE.md` ждёт юзера** — до его «да» контур продолжает работать со старым
   текстом. Если A/B даст сильный результат, это аргумент для него, а не для меня.
