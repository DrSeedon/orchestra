# V-662: OpenScience Autoresearch — исходники, сравнение и вердикты

Дата среза: 29.09.2026. Только чтение внешнего репозитория и наших исходников; реализация не начиналась.

## Вывод

Autoresearch — рабочая функция, а не один длинный промпт: `StudyDriver` опрашивает задания, получает метрики, завершает прогоны, применяет остановку/бюджет, рендерит журнал и будит сессию. Но научные решения — какие идеи пробовать и что оставить — принимает модель по навыку и текущему состоянию; четыре неудачи лишь вызывают её пересмотреть класс идей. Файлы `study.md`, `ideas.md`, `results.tsv`, `lessons.md` — производная проекция SQLite, не каноническое хранилище.

Большая часть примитивов у нас уже есть в других формах: устойчивые фоновые задания, лимиты и восстановление, сборка workflow с журналом/manifest, измерение качества и цены, отчёты задач. Не хватает продуктового контура «исследование по метрике» — схемы baseline/ideas/runs, привязанной метрики эксперимента и интерфейса серии. Переносить полный study-loop ради сравнения моделей или `error watch` не следует: он оптимизирует один изменяемый объект и адаптивно меняет гипотезы, тогда как сравнение моделей требует фиксированных, парных условий, а `error watch` сейчас только сигнализирует повторяемые ошибки.

## Что делает Autoresearch в исходниках

`backend/cli/src/experiments/driver.ts` задаёт цикл на проект: тик каждые 3 секунды; чтение метрик из лога, закрытие остановившихся compute jobs, kill criteria, лимиты по числу запусков/часам/USD/целевому значению, затем одно коалесцированное сообщение модели. Есть лимит 12 пробуждений в час, минимум три идеи в очереди и напоминание после четырёх завершённых прогонов без улучшения. Каждые шесть прогонов модель получает step-back напоминание перечитать lessons, назвать опробованные классы идей и переоценить очередь. Код не выбирает новый класс за модель и не меняет эксперимент автоматически: он только кладёт инструкцию в её следующее пробуждение. [Driver, таймеры и правила 26–40, 365–400](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/experiments/driver.ts#L26-L40)

Шаги с метрикой поступают из SDK в помеченных строках stdout, которые follower читает из compute-log; источник истины — отдельная SQLite-база на проект с таблицами study/idea/run/point/event. Сетевой приём метрик не нужен для локальных sandbox-задач; для Modal поток метрик приходит лишь после завершения задания. Невалидные kill-условия отклоняются при создании, а не молча игнорируются. [Техническая заметка о хранении и транспорте](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/docs/notes/experiments-and-studies.md#L7-L88), [модель данных](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/experiments/index.ts#L12-L72).

Файлы — читаемый журнал/проекция: `study.md` содержит цель, правила, бюджет, baseline/best; `ideas.md` — приоритет и EV; `results.tsv` — run, verdict, метрика и delta; `lessons.md` — накопленные выводы. Рендер идёт из базы после изменений, обратно файлы не разбираются. У идеи есть `queued/running/kept/reverted/failed/dropped`; `study record` связывает решение модели с анализом и уроком. Повторное `start` блокируется пока идея не в статусе `queued`; повторяющаяся конфигурация не ставится в очередь. Исключение — dispatch failure до запуска команды: код возвращает идею в очередь, так как эксперимент не состоялся и не расходует бюджет. [Ledger](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/experiments/ledger.ts#L5-L14), [цикл в ledger](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/experiments/ledger.ts#L126-L150), [ограничение повторов](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/tool/study.ts#L336-L371), [возврат идеи после ошибки до запуска](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/experiments/driver.ts#L293-L310), [record verdict](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/tool/study.ts#L500-L529).

Навык `backend/cli/skills/core/autoresearch/SKILL.md` описывает постановку бюджета, одну метрику и направление, чтение кода/данных, baseline с приоритетом 1000, не менее трёх разнотипных начальных идей, один запуск на идею, разбор keep/revert и lessons. Бюджет пользователь подтверждает для каждой серии; при отсутствии бюджета навык требует спросить. Значит, агент предлагает и оценивает идеи, но очередью и запуском управляют инструмент/хранилище, а не автономный batch из одного промпта. [Навык](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/skills/core/autoresearch/SKILL.md#L1-L75), [создание с согласуемым бюджетом](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/tool/study.ts#L223-L288).

### Навыки и лицензии

На этом commit в репозитории находится **372 файла `SKILL.md`** (мой подсчёт по рабочему дереву), а не 295, указанных в пересланной новости. README корректно говорит «hundreds»; возможно, число в новости относится к более раннему срезу или иному способу подсчёта. Навыки ищутся из нескольких корней, могут быть встроенными, пользовательскими, проектными и установленными; отдельный catalog описывает capability/status/requirements/upstream, а загрузка тела навыка происходит по запросу. [Skill discovery](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/skill/skill.ts#L150-L165), [каталог](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/skill/catalog.ts#L1-L52).

«Около 40 научных баз» также нельзя буквально выводить из размера общего registry. На указанном срезе дерево содержит отдельные REST-коннекторы, сгруппированные по литературе, genomics, proteins, chemistry, pathways и omics; архитектурный документ отдельно называет **54-entry scientific capability registry**, куда входят compute/inference capabilities, включая experimental и blocked записи, а не только базы данных. Поэтому README-формулировку о connector breadth подтверждает наличие реальных модулей-коннекторов, но число 54 не является числом подключённых баз. [Connector registry](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/science/connectors/index.ts#L16-L32), [architecture/capability inventory](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/ARCHITECTURE.md#L76).

Код репозитория — Apache-2.0, но это не означает, что каждое включённое тело навыка Apache-2.0. Сам Autoresearch skill помечен MIT. Атрибуция OpenScience фиксирует отдельные источники/условия: K-Dense MIT, Hugging Face Apache-2.0, Anthropic document skills на условиях отдельных `LICENSE.txt`, NVIDIA BioNeMo skills CC-BY-4.0; NOTICE и исходные license-файлы следует сохранять при заимствовании. ### Вход по подписке Codex

Это отдельный OpenAI OAuth provider `openai-codex`, а не обычный OpenAI API key: CLI запускает ChatGPT/Codex OAuth flow, plugin принимает только OAuth, обновляет credentials, удаляет фиктивный API-key header и отправляет запрос через Codex transport. Для выбора синтезируется отдельный provider из поддерживаемого набора Codex-моделей; его token cost ставится в ноль, поскольку это подписочный маршрут без per-token цены в их модели учёта. Разделение `openai` BYOK и `openai-codex` сохраняет два пути. [Codex OAuth flow/CLI](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/cli/cmd/auth.ts#L663-L724), [OAuth plugin](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/plugin/codex.ts#L473-L505), [provider synthesis and zero cost](https://github.com/synthetic-sciences/openscience/blob/f1bdf2524cd28f5e0f33641fc5cd38eee2a7ca58/backend/cli/src/provider/provider.ts#L2504-L2570).

Важное отличие: опубликованные benchmark-конфиги запускали `openai/gpt-6-astra` и `openai/gpt-6-sol` через модельный каталог, а не `openai-codex`; trace cost рассчитан каталогом OpenScience. Следовательно, benchmark $ нельзя трактовать как измеренный расход подписки Codex или её долю. Codex OAuth — отдельная возможность продукта, не источник опубликованной цифры бенчмарка.

## Что фактически показывают бенчмарк-артефакты

README benchmark repo сообщает 53/70 (75,7%) и явно помечает результат как **best of one**; Terminal-Bench Science использовал Astra lead и Sol `xhigh` workers, с лимитом 8 часов на trial. Это максимальный wall-clock бюджет каждого задания, а не длительность каждого прогона. Из 70 task `result.json`: 68 содержат интервал `agent_execution` (суммарно 123,27 ч; медиана 1,01 ч; p90 4,41 ч), один из интервалов — ровно 28 800-секундный timeout; две записи не имеют этого интервала (одна priced result, одна послепрогонный regrade). У timeout README указывает, что Harbor не скачал логи агента, поэтому для него нет траектории или usage/cost; нельзя утверждать, что известно, чем именно агент занимался все 8 часов.

У 68 файлов с записанной `cost_usd` сумма оценок OpenScience составляет **$3 256,72**: 54 файла помечены `usage_complete=true` ($1 705,87), у 14 стоимость неполная ($1 550,85); timeout и regrade стоимость не содержат. Один из 68 оценённых результатов не имеет временных меток `agent_execution`. Это не счёт OpenAI: сами результаты называют источник `openscience_catalog_estimate`; usage-компоненты — записанные model steps root+children, а неучтённые auxiliary model calls и внешние/compute расходы исключены. Полная стоимость кампании неизвестна; API-equivalent оценки нельзя принимать за фактический счёт.

Что видно в доступных траекториях:

- `noisy-blackbox-optimization`: 2 ч 56 мин, $47,48 оценочно, 265 шагов lead, два child sessions. Lead менял собственную реализацию `/app/solver.py`, многократно запускал public scorer/evaluation и вспомогательные проверки; в траектории 139 `bash`, 69 `read`, 67 `python`, 55 `apply_patch` calls. Финальный отчёт даёт smoke 0.842057, public 0.812714 и 344 проверки. Это серия локальных итераций и сохранение лучшего кандидата внутри одной кодовой задачи, но в трассе нет `study create/propose/start/record` или Autoresearch-реестра.
- `ambient-rna-correction`: 56 мин, $21,00 оценочно, 96 шагов lead, два child sessions, 47 compute jobs, 26 Python calls и итоговые четыре файла с проверкой формата/содержимого.
- `3x2pt-inference`: 2 ч 36 мин, $75,34 оценочно, 205 шагов lead, восемь child sessions и 127 compute jobs; агент сначала отладил инференс на practice data, затем записал graded результаты и прогнал валидатор.

Все три реальные трассы значительно короче 8 ч; наиболее долгий известный пример в них — не timeout. В полном README указано, что trace каталоги включают `result.json`, конфигурацию, траектории lead/workers, сжатый поток событий и вывод нативного grader-а; task artifacts и host logs исключены. [Benchmark README: правила, лимит и ограничения trace](https://github.com/synthetic-sciences/benchmarks-openscience/blob/61328d97bf51dd35143f41c61f91eebe19270aee/README.md#L163-L182), [таблица 70 результатов](https://github.com/synthetic-sciences/benchmarks-openscience/blob/61328d97bf51dd35143f41c61f91eebe19270aee/README.md#L183-L256), [пример оптимизационной трассы](https://github.com/synthetic-sciences/benchmarks-openscience/tree/61328d97bf51dd35143f41c61f91eebe19270aee/terminal-bench-science/noisy-blackbox-optimization/noisy-blackbox-optimization__6onNcY7), [пример 8-часового timeout](https://github.com/synthetic-sciences/benchmarks-openscience/tree/61328d97bf51dd35143f41c61f91eebe19270aee/terminal-bench-science/frustrated-heisenberg-nqs/frustrated-heisenberg-nqs__uMhCfhF). Для сравнения, Snorkel leaderboard показывает GPT-6 Astra + Codex 68,1% ±3,2 с $4 997 и Opus 5.5 + Claude Code 63,3% ±3,3 с $4 874; это отдельные строки leaderboard, а не контрольная группа той же OpenScience-трассы. [Snorkel Terminal-Bench-Science](https://snorkel.ai/leaderboard/terminal-bench-science/).

## Сопоставление с Orchestra и решение по переносу

Стоимость переноса ниже дана качественно как размер работ по исходникам (низкая / средняя / высокая), не как измеренные инженерные часы.

Фиксированный набор task × model × effort, одинаковая стартовая revision и независимые повторы позволяют сравнивать причины. V-656 содержит только одну попытку на часть ячеек, а разброс прямо отмечен как неизвестный: следующую итерацию следует планировать как фиксированные повторы, не как hill-climb.

### Отдельные вердикты по алгоритму «baseline → очередь → keep/revert → смена класса»

- **Для сравнения моделей:** baseline полезен как фиксированная исходная revision/контрольная ячейка; очередь полезна как заранее утверждённая полная матрица. Keep/revert и «лучшая модель» не являются подходящими операциями над сравнимыми результатами — baseline кода не меняется, а менять класс задач после четырёх неудачных измерений нельзя. Verdict: **частично брать дисциплину baseline и журналирования, не брать hill-climb/адаптивную смену класса**.
- **Для error watch/autofix:** «оставить или откатить» становится meaningful только после готового оракула, который ловит ошибку до/после. Нет метрики или стабильного regression test — решение агента о keep не имеет опоры. Смена типа идеи может помочь исследованию причины, но не должна автоматически менять код в рабочем дереве или коммитить его. Verdict: **не брать как автоматический фиксатор**; гипотезы о причинах — только отдельный разрешённый исследовательский шаг.

Внешнее исследование основано на репозитории, его закреплённом срезе исходников и опубликованных trace data; `result.json` поля и указанные там scope/usage flags использованы как определение подсчёта стоимости.
