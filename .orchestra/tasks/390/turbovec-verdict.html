Turbovec нам полезен — 4-bit как следующий vector backend

На реальных 34 411 векторах Orchestra он сохранил результаты frozen holdout, сжал project payload в 6.95 раза и ускорил retrieval-stage медианно в 2.63 раза. Это кандидат для shadow rollout, не разрешение немедленно менять production.

Что именно измерено

Corpus

19 123 file vectors + 15 288 log vectors, bge-m3 1024d, project Orchestra.

A/A control

Порядок baseline/candidate/control вращался. 4-bit paired gain 213.5 ms при median A/A noise 77.6 ms.

Quality

Exact sqlite-vec ranking сравнивался с Turbovec top-20; затем неизменённые FTS и RRF собирали итоговый top-5.

Не измерено

Production API after integration, RSS/page cache, cold-agent task success и crash recovery.

Как внедрять без поломки truth/freshness

Projection contract

Сначала #388: target_head/indexed_head, canonical fallback и rebuild.

Separate 4-bit indexes

Один IdMapIndex на project × files/logs; chunk_id остаётся стабильным ID.

Shadow reads

sqlite-vec отвечает production, Turbovec сравнивается на расширенном blinded corpus.

Mutation gates

Add/update/delete/sync/crash/restart/cross-project isolation и clean rollback.

Cutover

Только после generation parity и live API A/B; exact sqlite-vec остаётся rollback.

Ограничения

  • Релиз 1.0.0 вышел шесть дней назад; v7 новый, хотя audit выглядит серьёзно.
  • Присланный график снят на AVX-512, наш VPS использует AVX2; переносить 3.4× напрямую нельзя.
  • Отдельный .tvim создаёт Git/SQLite/index generation seam, которого сейчас нет.
  • n=18 подтверждает отсутствие наблюдаемой регрессии, но не общую эквивалентность quality.
  • Correctness knowledge architecture важнее ANN speed; Turbovec не должен обгонять #388.
