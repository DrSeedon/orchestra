# V-1047 — доработка после приёмки

Исправлены отказ из-за параллельного сканера и последующий отказ импорта в минимальной копии гейта. Результаты предыдущего отчёта заменены описанием текущего кода и проверок ниже. Установка в реальные репозитории, push и рестарт не выполнялись.

## Текущая реализация

1. `scripts/publication_gate.py` удалён. Все три `scripts/hooks/*` и генератор `scripts/install_git_hooks.py` снова вызывают `scripts/secret_scan.py`. Генерируемые хуки используют абсолютный путь к сканеру Orchestra. Существующий `secret_scan.py` не изменялся и остаётся единственным владельцем форм для Git-публикации, включая точные длины, упоминания и тела PEM. `scripts/orchestra_backup.py` не изменялся.
2. Существующий вызов сканера `forbidden_strings.load_rules(forbidden_strings.list_path(os.getcwd()))` теперь загружает также `publication_secrets.literal_rules()` для переданного репозитория. Это работает и при отсутствующем стоп-листе, и при `ORCHESTRA_FORBIDDEN_STRINGS`. Возвращаемый Path хранит контекст проекта: общий путь списка не смешивает значения двух проектов при чередующихся вызовах; глобального изменяемого контекста нет. Обычный явно переданный Path сохраняет прежнюю семантику загрузки только списка.
3. `scan_text()` и `scan_range()` проверяют исключительно стоп-лист и буквальные локальные значения. Грубые hub-формы в Git-проверках не участвуют, включая очистку их диагностик. Входящие коммиты, сообщения, пути и добавленные строки проверяются на буквальные значения. Диагностика содержит правило/имя переменной и источник; буквальное значение скрывается и в именах файлов. `merge_worker` блокирует буквальные значения до изменения refs, но пропускает упоминания форм: ими занимается канонический pre-commit воркера.
4. В `publication_secrets.py` формы явно названы `HUB_SECRET_SHAPES` и используются только hub_workspace. Для PEM требуется перевод строки после заголовка и минимум 40 base64-символов тела; переносы строк тела допускаются. Один заголовок, тело из 39 символов и обычное пояснение после заголовка не исключают файл из загрузки на hub. Hub upload planning проверен на файле с таким упоминанием.
5. Установщик сохраняет `--registered`, обработку Orchestra и `include_scopes`, идемпотентное обновление, атомарную замену и восстановление executable-бита. Чужие хуки, симлинки и перенаправления `core.hooksPath` не перезаписываются; отказ содержит причину. Проверена установка из корня временного репозитория с существующим `scripts/secret_scan.py` и запуск всех трёх генерируемых и версионируемых hook-shim.
6. Реестр буквальных значений по-прежнему читает окружение, `.env` проекта/его основного checkout, `.env` Orchestra и её `data/secrets/`. Имена переменных и минимальная длина теперь принадлежат `app/publication_secrets.py`; `secret_mask` и `hub_workspace` используют их оттуда; короткие значения, пути и явные шаблоны исключаются. БД, журналы, локальные `.env` и отображение не переписываются и не маскируются.


## Минимальный импорт и выбор Python

- `forbidden_strings` импортирует только `publication_secrets` из пакета app. Сам `publication_secrets` импортирует исключительно stdlib. Его `_MIN_LEN` и `_SECRET_WORDS` — единственный источник этих констант; `secret_mask` импортирует их, не меняя поведения маскирования. Зависимость маскировщика от runtime_history больше не входит в цепочку хука.
- Минимальный пакет для хука состоит из пустого `app/__init__.py`, `app/forbidden_strings.py` и `app/publication_secrets.py`. Подпроцесс с `-I -S` проверил загрузку именно этих двух подмодулей app, поиск ключа проекта и отсутствие значения в диагностике. Другие файлы app и site-packages в этом прогоне недоступны.
- Генерируемый хук выбирает исполняемый `.venv/bin/python` Orchestra по абсолютному пути. Если его нет, используется абсолютный системный `python3`, найденный через `os.defpath`, без доверия к PATH и `sys.executable` вызывающего процесса. Venv чужого проекта не используется. Оба выбора проверены запуском хука с импортом минимального пакета; отдельный тест подставляет чужие PATH и sys.executable.
- Четыре существующие функции из `tests/test_secret_mask_tg_proxy.py` дополнительно выполнены напрямую через `runpy`: все прошли. Это офлайн-проверка функций, не pytest-прогон.

## Единственная вставка в отсутствующую фикстуру на хосте

`tests/test_secret_commit_gate.py` в копии отсутствует и не создавался. В `scratch_repo` после полного выражения копирования `forbidden_strings.py` добавить с тем же отступом:

```python
(root / "app" / "publication_secrets.py").write_text(
    (Path(__file__).resolve().parents[1] / "app" / "publication_secrets.py").read_text()
)
```

Тот же блок сохранён в `scratch-repo-fixture-insertion.txt`. Это единственное необходимое изменение отсутствующего файла; остальную фикстуру менять не требуется. Настоящий реестр остаётся обязательным, опционального пропуска импорта или проверки нет. Проверку канонического pre-push в нашем тесте также сужено до копирования только минимального пакета из трёх файлов.

## Команда установки на хосте после merge

Из основного checkout Orchestra:

```sh
uv run --frozen python scripts/install_git_hooks.py --registered
```

При чужом хуке установщик отказывает с указанием репозитория и причины, сохраняя файл. Необходимо явно решить цепочку вызовов или конфигурацию этого репозитория; автоматической перезаписи нет.

## Тесты и результат

- `nice -n 15 python3 tests/test_publication_gate_v1047.py -v`: **28 тестов рассмотрены, 27 прошли, 1 явно пропущен**, 11.439 с. Журнал: `revision-tests.log`.
- Единственный skip — проверка настоящего pre-push через неизменённый `secret_scan.py`: сканер не поставлен в эту копию. На хосте при наличии файла тест выполнится автоматически. Для проверок маршрутизации установщика использован только sentinel с записью аргументов и фиксированным exit-code; он не эмулирует распознавание секретов и не считается интеграционной проверкой канонического сканера.
- Двенадцать независимых мутаций вызвали именно падение поведенческого assertion: отключение загрузки локальных значений через существующий API; потеря контекста проекта; отключение буквального поиска; удаление требования тела PEM; возврат грубых форм в `scan_text`; возврат грубых форм в merge_worker; неверный путь сканера в установщике; неверный путь в версионируемом pre-push; отключение отказа на чужом хуке; возврат зависимости от secret_mask в минимальную цепочку; выбор Python вызывающего чужого venv; игнорирование venv Orchestra.
- Проверены merge_worker на запрещающем и разрешающем плечах, сохранение refs при запрете, источники значений и свежая загрузка, отсутствующий стоп-лист, независимые проекты с одним override, linked worktree, шаблоны/пути/кавычки/интерполяция, многострочные значения, двоичный файл, секрет в имени пустого файла, сообщения коммитов, удаление старой утечки и секрет в промежуточном коммите истории.

В существующем `test_publish_guard.py` ожидание для отсутствующего списка уточнено: оно теперь равно локальному реестру проекта, а не обязательно пустому списку. Проверка явного отсутствующего файла без контекста остаётся прежней. Адреса мутаций в `test_publish_guard_mutations.py` соответствуют перенесённой реализации.

## Что здесь не проверено

- Требуемый запуск `uv run --frozen python -m pytest tests/test_publication_gate_v1047.py tests/test_secret_commit_gate.py tests/test_secret_mask_tg_proxy.py -q` был вызван и завершился кодом 127: заглушка сообщает, что `uv` отсутствует и удалённое перенаправление недоступно. У Python 3.12.3 отсутствует pytest. Указанный выше unittest-прогон — альтернативная офлайн-проверка, не проверка через требуемый runner.
- `scripts/secret_scan.py` и `tests/test_secret_commit_gate.py` по-прежнему отсутствуют в поставленной копии. Они не восстанавливались вслепую. Поэтому исходный `test_hook_blocks_commit_of_a_secret`, точные канонические формы/упоминания, прежние pytest-наборы и полный прогон остаются для хоста. Ошибка установщика «publication scanner is missing» устранена возвращением проверки и вызовов к существующему `secret_scan.py`; CLI-путь с этим именем файла проверен локально.
- Полный instruction-contract и Git diff здесь недоступны: поставленная копия без собственного `.git`, полного `.orchestra` и `CLAUDE.md`. Изменённые участки просмотрены; исключённые файлы не перезаписаны. Временные репозитории и мутационные копии создавались внутри каталога задачи и удалены. Живые БД, реальные репозитории и CLI провайдеров не использовались.
- Реальные scopes, права и настройки хуков проверит команда установки на хосте. Старый журнал предыдущего решения удалён, чтобы не смешивать проверки разных реализаций.

**Для активации Python-изменений merge_worker и hub_workspace нужен разрешённый владельцем рестарт Orchestra после merge.** Здесь он не выполнялся. Для установки/работы Git-хуков рестарт сервиса не нужен; локальный реестр перечитывается при проверках.
