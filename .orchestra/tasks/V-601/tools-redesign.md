## Что именно значит «токены в каждом ходу»

`count_tokens.py` считает реальную схему, полученную `await mcp.list_tools()`, сохранённую в [schemas.json](schemas.json). Для каждого инструмента отдельно сериализован объект `{name,description,inputSchema}`: JSON UTF-8, `ensure_ascii=False`, без пробелов-разделителей. Токенизатор `tiktoken==0.13.0`, `o200k_base`; определение и проверяемый hash словаря — [исходник OpenAI](https://raw.githubusercontent.com/openai/tiktoken/main/tiktoken_ext/openai_public.py). Токенизатор запущен как изолированная измерительная утилита через `uv --no-project --with`; зависимости проекта и lockfile не менялись. В предложение новых runtime-зависимостей нет.

`D` — отдельно токенизированное описание, `S` — отдельно inputSchema, `T` — весь входной объект с именем/ключами/JSON. Поэтому D+S не обязано равняться T. Сумма T=7 323; весь JSON-массив=7 325, дополнительные 2 токена относятся к границам массива. Полный wire-объект MCP, включая outputSchema, даёт 8 673; это транспортный размер, его нельзя автоматически назвать размером промпта. По реальному преобразованию `app/harness/mcp.py:_to_openai_schema` (строки 294–304) объект `{type:function,function:{name,description,parameters}}` даёт 7 593 → 6 130, ту же разницу 1 463. Числа по каждому инструменту сохранены в [tokens.json](tokens.json) и [modes.json](modes.json).

Утверждение «каждый тул в каждом ходу каждого агента» буквально неверно. `app/mcp_stdio.py:_apply_access_mode` оставляет 14 инструментов read-only или 4 reducer; full оставляет 45. `DISABLED_TOOLS` в `call_tool` запрещает выполнение, но сам по себе не удаляет схему из `tools/list`. Codex строит allowlist из реестра (`app/backend_codex.py:_orchestra_full_mcp_tools`); Harness передаёт `self.tool_schemas` каждому запросу модели (`app/harness/loop.py:239`). В managed/native клиентах возможны собственная сериализация, deferred loading и prompt cache. Доступ к schema ≠ доказанная передача полного текста на каждом provider request.

Поэтому ниже точные числа **на повторное предъявление выбранной сериализации**, а не фиктивные точные биллинговые токены Claude/Grok/Codex. Реальные provider input/cache tokens и скрытую обёртку здесь не измеряли; для них нет единого публичного токенизатора в нашем runtime. Экономия по N запросам с full-каталогом = 1 463×N контекстных proxy-токенов, а не 1 463×2 477 вызовов MCP; стоимость cache-read и экономия долларов из этого не следуют.
