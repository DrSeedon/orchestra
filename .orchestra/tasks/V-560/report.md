# V-560 — локальный переиспользуемый benchmark runner

**DONE.** Добавлен `scripts/local_bench`: JSON-конфигурация вопроса, clean snapshot,
одинаковый prompt, параллельные плечи, внешний оракул и JSON/Markdown-результат.
Приложение Orchestra, MCP, маршруты, runtime и сервисы не изменялись. Новых зависимостей
Python нет. Реальных прогонов моделей не было; все исполнительные проверки — локальные
контрольные процессы, а provider-протоколы проверены заглушками.

## Как воспользоваться

```bash
python -m scripts.local_bench run scripts/local_bench/examples/repair/bench.json --output /tmp/bench-question-001
```

На текущем VPS вместо `python` доступен
`/opt/orchestra/runtimes/20260817-b0b72d65-py312-rag-v2/bin/python`.
Пример намеренно возвращает exit 1: таблица PASS/PASS/FAIL подтверждает отрицательный
контроль. Отчёт лежит в указанном новом каталоге; существующий каталог не перезаписывается.
Полный контракт — `scripts/local_bench/README.md`.

Другой вопрос требует только своего source/prompt/oracle/arms в JSON, а не нового
контроллера. Проверены три формы: исправление Python-кода, сортировка файла, оценка
текстового ответа через `{response}` и `{transcript}`. Git-история не передаётся моделям;
тесты и эталон можно брать по точному коммиту через mapping repo/revision/path.

В каждом результате сохраняется `replay.json`, указывающий на замороженные входы,
задание, оракул и эталон. Проверен повтор без правок runner: тот же входной SHA и те же
PASS/PASS/FAIL. Старое значение стоимости авторской подготовки в повтор не переносится.
Внешние инструменты и fixture-скрипты должны оставаться доступными; это не образ всей ОС.

## Что закрыто из V-558

| Дефект | Реализованное поведение | Доказательство |
|---|---|---|
| Последовательная очередь | Все плечи подготовлены до общего барьера; затем параллельный запуск | Пересечение интервалов процессов; ошибка подготовки не запускает соседей |
| Счётчик пропадает на лимите | Streaming receipt → SIGINT/grace → TERM/KILL; финальное событие читается до завершения | Graceful-контроль сохранил final cost 0.2 и output_tokens=5 |
| Нет финального события после hard kill | Explicit partial/missing/unpriced/invalid, никогда ложный ноль/полный счёт | Hard-контроль: наблюдение 0.1, полный счёт null; дочерний PID reap-нут |
| `TMPDIR` не решает явный `/tmp` | Provider sandbox требует отдельную tmpfs `/tmp` и PID `/proc`; unsafe fallback отсутствует | На этом хосте preflight честно отказывает до модели |
| `.pyc` считается кодом | Классификация по исходникам, generated cache исключён | Fixture намеренно создаёт bytecode; лишних source-изменений нет |
| `--bare` отключает OAuth | Флаг отсутствует, используется подписочный OAuth, не API-key | Проверка argv/auth environment, без настоящего CLI-вызова |
| Дорогая подготовка не видна | Отдельные preparation_seconds, атрибутированная стоимость и доля подготовки | При 6+2 доля 75%; при неизвестном слагаемом null |

Физически отсутствующий финальный счёт не объявляется восстановленным. После grace
неотвечающий процесс принудительно завершается, а отчёт остаётся неполным по стоимости.
Это явная граница измерения, не спрятанная ошибка. `oracle_pass`, completion и accounting
независимы: код после дедлайна может пройти, хотя ход или счётчик не завершены.

Учет Claude включает `message_delta`: output завершённого ответа сохраняется до финала
всего хода; повторные assistant-сообщения не удваиваются. Позднее сообщение не затирает
закрывающий счётчик. Codex cache_read не суммируется с input повторно. При отсутствии
цен Codex маркируется unpriced; тарифы не копируются из платформы и не выдумываются.
Резерв проверяется до параллельного старта и по доступному прогрессу; native Claude
получает --max-budget-usd. Гарантии hard dollar cap при задержанном usage не заявлены.

## Фактическая проверка

Команда:

```text
nice -n 15 /opt/orchestra/runtimes/20260817-b0b72d65-py312-rag-v2/bin/python -m pytest tests/local_bench --confcutdir=tests/local_bench -q -p no:randomly
```

**38 passed**, полный вывод — [tests-final.log](tests-final.log).
`--confcutdir` исключает фикстуры приложения и работу с его БД.
Фактический импорт: [imports.json](imports.json) — абсолютный путь runner и `app_imported=false`.

Отдельно выполнены три пользовательские команды CLI, без pytest-обёртки:
[acceptance-commands.json](acceptance-commands.json).

- [repair-report.md](repair-report.md): PASS/PASS/FAIL, одинаковые исходники, полные synthetic receipts.
- [replay-report.md](replay-report.md): повтор сохранённого рецепта, тот же результат без переписывания стенда.
- [deadlines-report.md](deadlines-report.md): оба оракула PASS; graceful — complete, hard-kill — partial;
  полный итог стоимости неизвестен, наблюдаемые части показаны отдельно.

Дополнительно тестами проверены неизменность оракула при подмене submitted test, отказ
на зелёном baseline/красном reference до плеч, symlink escape (включая промежуточный
симлинк), пересечение runtime mount с эталоном, отмена с сохранением receipt, большой
stdin у не читающего его процесса, отказ на рекурсивном output внутри входа, отсутствие
перезаписи результата и работа обоих provider-протоколов через только Python-заглушки.
Diff формируется Python-кодом: model-controlled `.git/config` не исполняет external diff
вне sandbox. Сам submitted checkout и hashes сохраняются вместе с patch.diff.

## Ограничение хоста и границы готовности

[doctor.log](doctor.log) содержит фактический отказ:

> приватный /tmp недоступен: запрещены непривилегированные user namespaces
> (kernel.apparmor_restrict_unprivileged_userns=1)

Vendor-bwrap найден, но не может настроить uid map. Снятие защиты — решение владельца;
владелец выбрал сохранить её. Ничего не устанавливалось, sysctl/AppArmor не менялись.
Offline — основной полностью проверенный рабочий путь на этом VPS. Provider-путь требует
рабочих namespaces, Landlock ABI >=4 и libseccomp; на поддерживаемом хосте перед
дорогим прогоном нужен успешный `doctor`. Положительная настоящая namespace-ветка здесь
не запускалась успешно; её нельзя выдавать за проверенный live-provider прогон.

Поддерживаемые native provider runtime — Codex и Claude. Новый тип вопроса задаётся
конфигурацией, новый CLI-протокол потребует отдельного адаптера. Fixtures — доверенные
локальные программы, а не обход provider sandbox; смешивать их с provider-плечами в
одном сравнении конфигурация не позволяет. Raw результаты приватны и git-ignored;
их намеренная публикация требует отдельной проверки секретов.

Подготовка в отчёте отделена от исполнения, но снижение реальной долларовой доли
авторской работы после повторного использования ещё не измерено. Доказано, что готовый
рецепт повторяется обычной командой без нового модельного проектирования; валютная
атрибуция остаётся явным входом, а не догадкой из времени или общего счётчика пула.

## Передача результата

Изменения: новый пакет `scripts/local_bench/`, его offline-примеры и README;
`tests/local_bench/`; артефакты V-560; добавление факта о namespace в существующую KB.
Ни платформенных дочерних workers, ни платных модельных сессий не создавалось.
Работа в прежнем изолированном worktree; привязку/merge платформы не обходил.
При копировании в main KB нужно применить дельтой, не затирать весь чужой актуальный файл.

Перед коммитом: `git diff --check` чист; raw/task-артефакты не дали совпадений
app.secret_mask. Два совпадения в исходниках разобраны отдельно: выражение чтения
OAuth и явно синтетическое значение теста, не рабочие секреты ([secret-scan.json](secret-scan.json)).

Финальная проверка также исполнила генерируемый Python-probe под настоящим сетевым
Landlock/seccomp-фильтром: TCP отвергнут, дочерний `/proc/self/fd` читается. Для этого
контроля только mount-setup заменён заглушкой; полного namespace это не доказывает.
Этот тест поймал и закрыл ошибку вложенного quoting в положительной ветке preflight.
