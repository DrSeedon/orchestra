# V-1184 — Daily hub idle watch

The active job runs daily at 03:00 UTC with pattern `HUB_IDLE`, currently invoking the ignored copy `/home/kesha/orchestra/data/hub_idle_watch.py 60`. Its existing message gives `katya-work` candidates a 72-hour exception and instructs the orchestrator to tell each named orchestrator to merge and kill. The ignored script also excludes game-design candidates and groups by the top-level ancestor. Both exceptions came from earlier owner instructions and are superseded by this task.

The tracked replacement `scripts/hub_idle_watch.py` infers a strict 24-hour idle anchor from known state events. `turn ended` starts an idle interval unless `waiting for bg jobs` follows; context-refresh and auto-report bookkeeping logs preserve the prior state; repeated manual-stop logs preserve an existing idle anchor. Activity, waiting, server shutdown, and unrecognized events clear the anchor. Candidates must currently be `idle`, use a `hub-` model, and resolve to their nearest owning orchestrator. No game-design or per-orchestrator age exceptions remain. Empty output means no proven candidates; missing, malformed, schema-incomplete, or empty databases emit `HUB_IDLE_ERROR` and return nonzero.

The code prepares candidate notices only. It does not merge, delete, kill, create tasks, send messages, or call a provider. The recipient flow remains the existing one: the cron wakes `Orchestra-orchestrator`, which sends one direct instruction to each named owning orchestrator. Each recipient must inspect `worker_wip`; merge only accepted work, then kill only after the existing clean/accepted merge gate passes. Unaccepted, dirty, or unmerged work stays alive. Repeated daily notices can still recur for a candidate whose work remains unresolved; no task records are created.

## Event lifecycle audit and coverage (2026-11-01 08:05 UTC)

The live process path was read from its environment and matched the DB used below. The snapshot contained 1,549 sessions across 10 scopes and 361 hub sessions; 8 were currently `idle` across 4 scopes. Every one of the 361 hub sessions had at least one `turn ended` record and nonzero `total_turns`; the never-ended class therefore has zero live examples. All 8 idle-hub latest log timestamps were timezone-aware and parseable. Their latest log type was `status` in every case: 4 `stopped (manual interrupt)`, 2 `auto-report skipped`, 1 `context unknown`, and 1 `turn ended`. This explains why the latest-log-only rule dropped seven rows.

The event-aware inference retained a timestamp for all 8 current idle hub sessions: 2 anchors were strictly older than 24 hours and 6 were not. The two qualifying rows had an older `turn ended`, followed only by status records classified from source as state-neutral (`auto-report skipped`) or a repeated manual stop; there was no later `waiting for bg jobs` or user/tool/text event. It returned 2 candidates across 2 owning orchestrators. Against the old 60-minute watchdog, the live output contained 5 candidates across 4 owners; the inferred 24-hour set was a subset of 2, with 3 old-only and 0 new-only. Outputs were parsed in memory; no worker names or identifiers were recorded.

The state classes are supported as follows. `turn ended` is emitted by `TurnManager.handle_turn_end` (`app/session_turns.py:564-568`), then `finish_turn_status` sets either idle or waiting; the waiting case emits `waiting for bg jobs` after the turn-end row (`:582-595`). `context unknown` is logged by the asynchronous context refresh without changing session status (`app/session.py:4060-4070`). `auto-report skipped` is a bookkeeping log in the auto-report path, not a session-state update (`app/session_turns.py:260-278`). `manual interrupt` is logged before `stop()` sets `IDLE` when the pre-stop status was not `RUNNING`; preserving an existing idle anchor across repeated stop events avoids resetting an already-idle worker (`app/session.py:4887-4895`). `server shutdown` means the pre-stop status was `RUNNING` and the row is written as `INTERRUPTED`, so a later startup reset to `IDLE` must not inherit the old timestamp. Startup performs that reset in SQL and restores waiting only while an active background job remains (`app/manager.py:2501-2502, 2526-2530`).

The persistent `sessions` schema has `created_at` and `finished_at`, but no status-change or idle-start timestamp (`app/schema.sql:327-355`). `created_at` is set when `AgentSession` is constructed (`app/session.py:437`); creation calls `session.start()` later (`app/manager.py:898`), which sets idle (`app/session.py:1077`). Thus it cannot prove the exact idle boundary for an untouched worker. The current DB has no never-ended hub sessions to validate that class against. Synthetic coverage does include a never-ended session with an explicit manual-stop transition (age is measured from that stop) and an unlogged session (no candidate). Thus no claim is made that the current DB can timestamp every transition class.

The real `list_agents` call is scoped to the caller's project: it returned 13 agents and 3 idle hub workers. The real `list_orchestrators` call covers all projects and returned 10 orchestrators, matching the DB's 10 scopes. The watcher queries the process DB without a scope filter and resolves parent ownership across all scopes. The exact current live candidate owners were not copied into this report.

Remaining unknown cases include unrecognized status events, sessions whose last idle transition occurred during startup's SQL normalization, and never-ended sessions with no logged transition. The watcher clears its inferred anchor on unrecognized events and on server shutdown, which can miss candidates but avoids asserting age from a stale turn-end or a restart. Complete coverage needs a persisted `idle_since` field updated atomically on every transition: set it when an IDLE state begins (including initial no-task creation and recovery from waiting/interrupted), preserve it on IDLE→IDLE bookkeeping, and clear it when leaving IDLE. Backfill only state transitions proven by existing logs; leave unknown rows NULL until the next recorded transition. Add transition tests for idle→idle, waiting→idle, interrupted→idle recovery, and no-turn-start creation. This schema/lifecycle change is a separate architectural step; it is not implemented here and the live cron remains untouched.
