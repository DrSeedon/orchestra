## 2. Воспроизведение (выполнено, бесплатно, 1 CPU-секунда)

Скрипты и вывод лежат рядом: `repro_seed.py`, `check_b.py` (+ `.out`). Запуск `python3 -I`.

- Алгоритм из статьи: `x=(t<<16)|0x330E; x=(0x5DEECE66D*x+0xB) mod 2^48; байт=x>>40`, кандидат = 20 подряд идущих байт, непересекающиеся блоки; `t` = 1997-08-16 01:52:34 UTC = 871696354.
- Результат: блок с нулевым индексом **1841** (то есть 1842-й при счёте с единицы, как в статье) равен `C49D360886E704936A6678E1139D26B7819F7E90` — опубликованному seed P-256. Скользящее окно даёт тот же блок на байте 36820 = 20·1841, то есть совпадение не случайно из-за выравнивания.
- Независимая проверка связи с кривой: по ANSI X9.62 из этого seed через SHA-1 получаю c = `0x7efba166…04fa0d`, и для опубликованного b P-256 выполняется `c·b² ≡ −27 (mod p)`: **True**. Значит, seed действительно порождает официальный параметр b, а совпадение с lrand48 не артефакт.
- Не проверено: остальные 13 seed, кандидат 876 (критерий порядка кривой), базовые точки, код Valsorda на Go, утверждение о 1/5810. Вывод в тексте: утверждение «seed P-256 = lrand48-поток от 16.08.1997» подтверждено моим расчётом; «и это единственно возможное происхождение» — нет (метка времени подобрана по статье, а не найдена мной с нуля: для обратного поиска нужен LLL-шаг, я его не делал).
