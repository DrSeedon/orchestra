# V-568 — исследовательский протокол

Цель: разложить фактический контекст Claude-оркестратора, отделив размер одного API-запроса от суммы запросов за ход Orchestra. Срез: живая read-only БД и нативная сессия; тела и секреты остаются в игнорируемом local/, в Git — размеры, хеши и агрегаты.

Гипотеза H1: большая часть повторного чтения — накопленная история и повторные API-запросы, а не один огромный статический промпт. Опровержение: измеренная статика занимает большинство реального тела запроса.
H2: сокращение сериализации ответов инструментов уменьшает вход и стоимость при том же содержании. Альтернатива: экономия незначительна либо теряется из-за cache miss/output. Проверка: тот же Claude и задача, идентичный JSON после json.loads, pretty/compact сериализация; cold и повторные запросы. Память, обратная связь, приёмка и защитные правила сохранены побайтно.

До прогона: правильный результат — точные counts/statuses по fixture; все ключи и значения обоих входов равны. Метрики: реальные input/cache-write/cache-read/output, total_cost_usd и точность ответа; никаких переводов в недельные проценты. Не делать вывод о полном качестве оркестрации из одной закрытой задачи. Если запросы не доходят или кеш не читается, это ограничение замера, не нулевая стоимость.

Цена кандидата заранее: одна длинная строка ухудшает чтение человеком, grep/line-based диагностику и цитирование; форматирование не должно менять канонический объект или доступ к полным данным. Это предложение для модельной сериализации, не разрешение менять dashboard/логи. Если сравниваемая форма уже компактна в реальном пути Claude — кандидат там неприменим.

Действующие prompts/app не меняются. Для внешнего review прочитан codex-debate; отдельный модельный review пока не выбран.

Первичная проверка H2 до модельного прогона дала 0 байт экономии: JSON уже compact. Для обязательного before/after выбран другой обнаруженный кандидат — дедуп одинаковых nested CLAUDE.md по SHA256 с сохранением всех scope paths и обеих уникальных версий. Конкретный вход, последовательность и oracle зафиксированы в experiment-protocol.json до отправки шести запросов. Итог и границы переноса — research.md.
