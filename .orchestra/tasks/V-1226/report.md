# V-1226 — unslop: что полезно Orchestra (только исследование)

**Вывод.** unslop (commit `a6f121e`, CC BY 4.0, коммерция разрешена при атрибуции) — это
чек-лист «признак → место → исправление» плюс порядок проходов и набор вкусовых токенов. Для
дашборда Orchestra ценны 4 механизма: аудит с местом дефекта, триаж «насколько менять»,
проверка контраста по реальной поверхности и сверка результата с тем же списком аудита.
Эстетику (нейтральная палитра, отказ от индиго, эмодзи → line-иконки, «мир/сигнатура»,
генерация картинок, story-видео) переносить не стоит: она либо противоречит решениям
владельца в `docs/design-system.md` и нашем `html-artifacts`, либо субъективна. Влияние skill на
качество НЕ измерено; пара скриншотов ниже — иллюстрация, а не замер.

Источники, SHA, хэши и лицензия — `sources.md`. Сырьё — приватно на хабе `/tmp/v1226-src/`.

## Что в skill на самом деле (пересказ закреплённых файлов)

- `SKILL.md` «Run it»: посмотреть экран (скриншот, а не только код) → аудит по `signs.md`,
  «одна строка на признак, где он живёт» → решить объём: много/мало/нет «слопа» → записать
  направление (5 строк) и ждать согласия → 9 проходов в порядке spacing, color, icons, copy, type,
  layout, details, visuals, motion → чек-лист + повторный рендер, сверка со списком аудита →
  отчёт. Лимит: не больше трёх рендеров за прогон.
- Инварианты «Do not»: не менять, чем продукт является (функции, контент, порядок разделов),
  не выдумывать данные и утверждения, не заменять снятый декор новым трендом.
- `signs.md` — ~60 признаков в 9 группах, каждый с исправлением. `tokens.md` — шкала 4 px,
  нейтральные рампы, контраст 4,5:1, радиусы, одна кривая анимации.
- `visuals.md`/`effects.md`/story — генерация картинок, glyph-эффекты, 10-секундное видео
  (Playwright + ffmpeg). Скрипты прочитаны статически, не запускались.

## Игрушечный пример (собственный, вымышленные данные)

`toy/task-card.html` — одна карточка задачи, обе версии рендерят **один объект `TASK`**
(`?v=before` / `?v=after`). «После» сделан по нашему `html-artifacts` (светлая тема, системный
шрифт, акцент `#0066d6`), а не по токенам unslop. Встроенная самопроверка пишет контраст,
горизонтальный overflow, фокус и список действий в `body[data-check]`. Действия заданы одним
списком `ACTIONS` (Открыть, Чат, Перезапустить, Удалить) — **все 4 есть в обеих версиях**;
в «после» они спокойнее (основная, две вторичные, «Удалить» — сдержанный danger справа), но не скрыты.

| Скриншот | Viewport | Что видно / замер |
|---|---|---|
| `toy/shots/before-1280x720.png` | 1280×720 | градиент, свечение, капс, «!!», 4 кнопки (`actions: open,chat,restart,delete`); 12 текстовых узлов на градиенте/полупрозрачном фоне — контраст **не измерен** (честно n/a), 2 бейджа 3,96 < 4,5 |
| `toy/shots/after-1280x720.png`, `after-1280x720-focus.png` | 1280×720 | 4 кнопки (`actions: open,chat,restart,delete`); мин. контраст 5,07, ниже 4,5 — 0; на `-focus` кольцо видно на «Открыть» |
| `toy/shots/pair-390x844.png` (PNG 780×844, `toy/narrow.html`: два iframe `flex:none; width:390px`, диагностический `<pre>` скрыт) | 390×844 каждый; в DOM у обоих `contentWindow.innerWidth = 390`, ширина рамки 390, `check.width = 390` | «до»: при настоящих 390 px плитки помещаются (прежний «вылет» был артефактом сжатого до ~300 px iframe), кнопки переносятся в 2 строки; «после»: столбец, 4 кнопки сеткой 2×2, overflow нет; в обоих по 4 действия |

Ограничения проверки: headless Chrome не даёт окно уже 500 px, поэтому узкий вид — через iframe;
эмодзи без шрифта = «тофу» (ограничение снимка); фокус — программный `.focus()`, а не реальный Tab:
в режиме `--dump-dom` страница не в фокусе, и пробник 3 из 3 раз даёт `:focus-visible = false`,
`outline: none`; кольцо подтверждено только скриншотом `--screenshot`; reduced-motion
включён флагом (анимации «до» на скриншоте статичны); пробник overflow смотрит только страницу,
не вылет внутри карточки (его видно глазами). Chrome закрыт, профиль `/tmp/v1226-chrome` удалён.

## Применение (3–6 пунктов, без реализации в этой задаче)

1. **Контраст мелкого текста по реальной поверхности** (п.3) — кандидат, не подтверждённый
   дефект: расчёт по токенам, а реальное отображение активного текста надо подтверждать отдельно.
   Продуктовых правок не инициирую; решение — за оркестратором.
2. **В `html-artifacts.md` → Check and deliver**: аудит «признак → место → исправлено», сверка
   после рендера и триаж «насколько менять» (п.1, 2, 4). При адаптации текста — атрибуция из `sources.md`.
3. **Чек-лист доступности при касании экрана** (п.6): `:focus-visible`, reduced-motion, никакого
   пульса на неживом — уже наш принцип, добавить в тот же аудит.
4. Остальное (п.7–10) не переносить; эмодзи-статусы остаются по решению V-876.
