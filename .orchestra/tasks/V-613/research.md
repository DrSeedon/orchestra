## Вывод одной строкой

Брать нечего в виде готового кода. Одна идея стоит того, чтобы сделать её у себя без Jev: **гейт
«DONE без прошедшей проверки после последней правки»** (идея Canny). Наш журнал `logs` уже
хранит все нужные факты, так что это чистый Python в нашем коде. Компакция через Jev и winnow
в нашей валюте (запись кеша + выход) не окупаются, и оба работают только через ранний доступ
к function hooks Claude Code.

## 2. Кандидаты

### 2.1 Canny → идея гейта «DONE только после проверки»

**Проблема есть — замер.** `done_gate_probe.py` по снимку БД: для каждого `send_message` воркера
(не оркестратора) с текстом `DONE…` берётся окно от предыдущего DONE этой сессии, в нём —
последняя правка файла с кодовым расширением (Edit/Write/MultiEdit/FileChange/apply_patch) и
Bash-команды из списка проверок (pytest, tsc, ruff, npm test, node --check, py_compile…) с
результатом без ошибки.

| Метрика (весь журнал, 27.07–22.09) | Значение |
|---|---|
| DONE-отчётов воркеров | 1 283 |
| из них с правкой кода в окне | 734 |
| нет ни одной успешной проверки после последней правки | 262 (36%) |
| то же, и последняя правка вне `.orchestra/` и `docs/` | 145 |
| нет «строгой» проверки (без `\| tail`, `\|\| true`, `; echo`, как в Canny) | 402 |
| по проектам (262): seedon / katya-work / comfy / orchestra / cog / dnd | 81 / 66 / 51 / 41 / 12 / 10 |
| по рантайму: codex / claude | 150 из 527 / 112 из 207 |

Точность эвристики невысока: из 41 случая в Orchestra вручную примерно 9 — правки `app/`, остальные —
скрипты замеров в `.orchestra/tasks/` и `docs/`, где «проверкой» служит запуск самого скрипта.
Один случай проверен целиком: **V-556 (queued-send, 12.09)** — последняя правка `app/mailbox.py`
в 15:02:51, после неё только `git status`, DONE в 15:03:26; мерж в 15:06 упал с
`TEST_GATE_FAILED`, успешный — в 15:15. Всего в `merge_operations` 41 `TEST_GATE_FAILED` и 25
`TEST_GATE_INCONCLUSIVE` (16.08–21.09): это DONE, которые гейт мержа развернул.

**Чем это отличается от нашего гейта.** `app/merge_test_gate.py` срабатывает при мерже и
выбирает `tests/test_<stem>.py` для изменённых `app/*.py` — то есть работает для репо Orchestra, а
для seedon/katya/comfy без такого отображения отдаёт `SKIPPED no_mapped_tests`. Canny ловит
раньше, на Stop, и в любом проекте. Пересечение с V-607 частичное: мутационный гейт проверяет
качество тестов, Canny — факт запуска.

**Как встраивается, если брать как есть.** Хуки `PostToolUse`/`PostToolUseFailure`/`Stop` в
`settings.json` CLI (у нас `/usr/bin/claude` 2.1.278) и `hooks.json` для Codex 0.153.4 (фича
`hooks` = stable). Ledger пишется в `~/.canny/`. Минусы: запускается `node` на каждый вызов тула
(~40 мс по README), Stop-гейт блокирует конец хода, а наш DONE — это `send_message` до конца хода,
то есть блок придёт после уже отправленного отчёта. Правка `settings.json` живых CLI — вне
полномочий этой задачи.

**Лучше — реализовать у себя без внешнего API.** Ledger уже есть: таблица `logs` (`tool`,
`tool_result`, `tool_is_error`, `tool_use_id`). Место — обработчик `send_message` для текста,
начинающегося с `DONE` (`app/mcp_stdio.py` / `app/manager.py`): вернуть воркеру предупреждение
(не отказ) «после последней правки X не было успешной проверки», как Canny делает на шаге 3.
Цена — порядка сотни строк Python и тест на две ветки. Jev не нужен: в Canny Jev только
ослабляет гейт («это не заявление о готовности»), а у нас DONE — явный маркер. Без Jev ничего не
ломается, наружу ничего не уходит. Список проверок должен быть настраиваемым по проекту: для
seedon/katya проверка — это сборка документа, иначе ложные срабатывания.

Фича новая, поэтому это предложение владельцу, а не решение.

### 2.2 fast-jev-compaction → нет

Что делает: удаляет или обрезает устаревшие пары вызов/результат, а не пересказывает (код:
`src/compact.ts`, `decideCall`: `keepResult ≥ 0.5` → оставить, иначе `keepCall ≥ 0.5` → обрезать
результат до 300 символов, иначе удалить оба). Без ключа Jev бросает исключение, плагин
откатывается на встроенный summary — режима без Jev нет.

Почему не подходит:
1. **Не сработает на нашем пути.** Хук висит на `session.compact` в CLI. Компакция Claude у нас —
   режим `handoff` (`app/session.py`, `_precompact_policy` → `"compact_mode": "handoff"`): агент
   пишет сводку по `_compact_prompt`, сессия переподключается заново. CLI-компакция не
   вызывается, хук не выстрелит.
2. **Хуже в нашей валюте.** Формула V-605: `0,811×cache_create + 1,81×output` п.п./М. Сводка
   handoff — медиана 10 552 символа ≈ 2 638 токенов выхода (комментарий V-606 в `app/session.py`).
   Jev-компакция не тратит выход Claude, но оставляет K токенов дословного контекста, которые
   придётся заново записать в кеш. Выгодно только при `1,81×2638 > 0,811×(K−2638)`, то есть
   K < ~8,5 тыс. токенов (при верхней границе коэффициента выхода 3,79 — K < ~15 тыс.). Сам плагин
   требует сокращения хотя бы на 25% (`minReductionRatio`), а таймер V-606 срабатывает от 5%
   окна, так что оставшийся контекст на порядок больше этого порога.
3. **Рычаг маленький.** За 15–22.09 таймер компакции отработал 16 раз (`precompact timer
   compacted`), а запись кеша Claude за неделю — 74,4 млн токенов (`turn_usage`). Компакция не
   то место, где горит пул.

Можно взять идею без Jev: при обрезке *нашей* handoff-сводки не пересказывать дословные ошибки и
пути. Но это правка промпта, её эффект не измерен.

### 2.3 winnow → нет

Что делает (код `hooks/winnow.ts`, `on('tool.call', …)`; сайдкар `sidecar/src/winnow/`):
результаты Read/Bash/Grep длиннее ~1 500 символов режет на блоки, прячет уверенно ненужные
(p ≤ 0,1) за заглушку с ключом для `winnow_recall`.

Эффект по замеру самого автора (`docs/WRITEUP.md`): на безопасном пороге прячется **~4,6%**
текста больших результатов, 97 разметок сделаны моделью, человеческий аудит на 20 блоках дал 38%
согласия.

Перевод в нашу валюту. Большие (>1 500 симв.) результаты Read+Bash у Claude за 15–22.09 — 23,4 млн
символов (с обрезкой по 30 тыс.; Read 14,7 млн, Bash 8,8 млн). При 3,5–4 символах на токен это
5,9–6,7 млн токенов; 4,6% от них — ~0,3 млн токенов записи кеша ≈ **0,25 п.п. недельного пула**.
Даже при предположении, что каждый токен перезаписывается на каждом истечении кеша, потолок —
4,6% от 74,4 млн = 3,4 млн ≈ 2,8 п.п./нед. Сюда надо добавить вызовы recall и потерю, если
спрятано нужное.

Режим «без Jev на Haiku» (`AdapterJudge`, `system_one_adapter`) и сводки в заглушках
(`summarize.py`, `anthropic.Anthropic()`) ходят в **платный API Anthropic по
`ANTHROPIC_API_KEY`**, не в подписку. По правилам проекта нужно отдельное разрешение. Keyless-судья
`lexical` есть, но автор сам показывает, что он не судья (ECE 0,31 против 0,14 у Jev).

## 4. Контраргументы и риски

- **Ранний доступ.** По README winnow, Jev в early access с листом ожидания. Function hooks, на
  которых стоят fast-jev-compaction и winnow, — тоже early access Claude Code за флагом; их
  README предупреждают, что интерфейс «may change between releases». Правило проекта держит CLI
  на точной версии (`CLAUDE_CLI_HISTORY_VERSION` в `app/backend_claude.py`), и привязка к
  нестабильной поверхности идёт против этого.
- **Лимиты.** `docs.typesafe.ai/models`: цена $0,042/М входа, выход бесплатный; 250 тыс.
  токенов/с и 1 200 запросов/мин, «adjusting dynamically… can change without notice». Лимит 64k на
  запрос, 32k на state + вопрос — поэтому компакция режет состояние по стадиям.
- **Данные уходят наружу.** Canny с ключом шлёт диффы (до 4 000 символов), правила из
  CLAUDE.md/AGENTS.md и последнее сообщение агента; winnow — содержимое каждого большого
  Read/Bash/Grep; компакция — весь разговор. Политика TypeSafe: «not trained on customer
  requests», но нулевое хранение — только по enterprise DPA, стандартный срок хранения не указан.
  Для наших проектов (документы seedon, данные katya-work) это внешний получатель всего, что
  читает агент.
- **Хайп звёзд.** fast-jev-compaction: 6 167★ и 346 форков при 13 наблюдателях и 30 коммитах,
  все за 17.09; jev-ultrafast: 17 255★ при 3 коммитах. Canny с работающим кодом и бенчем —
  32★. Подлинность звёзд не проверена: `GET /repos/…/stargazers` вернул 404, GraphQL один раз
  отдал пустой список при `stargazerCount` 6 167. Звёзды здесь ничего не говорят о полезности.
- **Возраст.** 16 из 20 репо созданы 15–18.09, то есть им меньше недели; Canny — 11.09. Исключения —
  json-render, agent-desktop и prism, к ним Jev прикрутили отдельными коммитами 16–18.09.
- **Цена Jev не наша валюта.** $0,042/М — это деньги сверх подписки, а экономию по контексту
  выше мы оцениваем в п.п. пула. Любое внедрение с Jev добавляет новый платный API, что требует
  разрешения владельца.

## Предложение

1. (Нужно решение владельца.) Предупреждение в `send_message` на DONE без успешной проверки после
   последней правки кода, по журналу `logs`, без Jev. Сначала — тень: писать статус и считать
   срабатывания неделю, сверить с `TEST_GATE_FAILED`, потом решать про видимость воркеру.
2. Остальное из списка не брать. Если когда-нибудь понадобится калиброванный судья, ставить
   `jev-mcp`/`typesafe-mcp` имеет смысл только под конкретную измеренную задачу.

Ограничения: точность эвристики §2.1 оценена вручную по 41 случаю, не размечена; перевод символов
в токены (3,5–4) — допущение, не токенизатор; тест-сьют Canny не запускался.
