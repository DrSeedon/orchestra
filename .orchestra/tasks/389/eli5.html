#389: курс Vercel нам полезен как техосмотр

Он учит собирать «коробку», внутри которой модель думает, вызывает инструменты и проверяет результат. Такая коробка у Orchestra уже есть.

Переписывать Orchestra не надо

Из 11 тем курса примерно 7 уже закрыты нашим harness — часто глубже, чем в учебном примере.

7/11

Но техосмотр нашёл одну настоящую дыру

Orchestra
проверяет внешние действияворкеры, worktree, MCP, роли
→
Внутренняя модель harnessсама зовёт bash / write / edit внутри Python
→
Действие сразу выполняетсявнешний охранник этот вызов не видит

Простая аналогия: охранник стоит у главной двери, а внутри цеха осталась боковая дверь без пропуска.

Что предлагается сделать

Модель просит действиеточное имя + все аргументы
→
Серверный пропускной пунктразрешить / запретить / спросить человека
→
Исполнить ровно один рази сохранить квитанцию

Это не «ещё один промпт». Это проверка в коде прямо перед исполнением каждого внутреннего инструмента.

Берём из курса

  • место для проверки каждого tool-вызова;
  • пауза и продолжение после одобрения;
  • эксперимент с очисткой старых тяжёлых результатов;
  • автопоиск подходящих тестов проекта.

Не берём

  • переписывание на TypeScript;
  • Vercel AI SDK, Gateway и Workflow;
  • новую облачную песочницу без нужды;
  • наивный список «безопасных» shell-команд.
Итог: курс подтвердил, что наш путь нормальный.

Практическая польза #389 — один узкий предохранитель для внутреннего harness. Остальное либо уже есть, либо сначала надо измерять.
