# V-1115: промежуточные повторы хаб-наблюдения

В `app/error_watch.py` добавлен один класс `_NOISE`: `hub watch read retry`.
Шаблон ограничен началом сообщения `hub t3_thread_wait/read failed; retrying
in ...s: ...`, принимает числовую задержку и `<N>`, не зависит от причины
транспортного сбоя. Другие классы шума и `app/backend_hub.py` не изменены.
Добавлена запись CHANGELOG по образцу V-1111.

Нюанс нормализации: числа рядом с буквой `s` могут остаться числами из-за
границ слов в `_NUMBER`. Поэтому проверены обе формы задержки и снятие
префикса `WARNING:app.backend_hub:`. Поддерживаются оба вызова, задержки
1/2/4/8 секунд, RemoteProtocolError, ReadError, ReadTimeout, ConnectError,
HTTP 503. Окончательные исключения, общий таймаут 60 секунд и вызовы
send/launch остаются находками; смешанная серия повторов и отказов проверена
через `aggregate`. Состояние и формат сохранённых данных не менялись.

Проверки выполнены provisioned uv 0.11.28 в стандартном `.venv`:

- До добавления шаблона: `uv run --frozen python -m pytest
  tests/test_error_watch.py -q -k hub_watch` — 51 failed, 16 passed,
  96 deselected. Все падения относятся к новым ожиданиям шума.
- После: `uv run --frozen python -m pytest tests/test_error_watch.py -q` —
  163 passed in 15.17s.
- Отдельным assert подтверждён импорт `app/error_watch.py` именно из текущей
  рабочей копии. Абсолютный путь опущен по ограничению задачи.

Тесты использовали локальные фикстуры, без живых CLI, сети и боевой БД.
Живой журнал и восстановление хаб-соединения не проверялись: логика повторов
не входит в эту правку. Незавершённых проверок из задания нет.

Предлагаемый заголовок коммита: `#V-1115: ignore intermediate hub watch read retries`.
Коммит и перенос результата выполняет платформа.
