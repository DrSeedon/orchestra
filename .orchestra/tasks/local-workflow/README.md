# Локальная работа, V- и простая передача контекста

Реализовано по одобрению владельца 08.09.2026. Ветка `codex/local-workflow`, база `8209b2b9`. Отдельный runner и новые типы воркеров не добавлялись. Сервисы и удалённый Git не изменялись.

## Изменения

- `ORCHESTRA_TASK_PREFIX=V-` задаёт префикс НОВЫХ задач узла. На ноутбуке значение пустое. Префикс записывается вместе с задачей, а не вычисляется при отображении из сегодняшнего конфига. Старые номера, каталоги, назначения и история не переименовываются; счётчик не сбрасывается.
- Полная ссылка проходит через API задач, публикацию/восстановление назначения, worktree, squash commit, приёмку, закрытие задачи и привязку расхода. `task-V-42/worker`, заголовок `V-42:` и `.orchestra/tasks/V-42/` не превращаются в `42`. Чужая `V-1` в истории Git не связывается с местной задачей `1`; при разборе коммитов остаётся явно неизвестной ссылкой.
- Префикс сохранён в SQLite и в канонической записи задачи. Чтение канонического списка/карточки не требует открытия legacy-владельца. Миграция добавляет поле до восстановления старых назначений. Существующие режимы хранения сохранены: массовой миграции/объединения баз или переименования исторических задач нет. Префикс не разрешает содержательные конфликты при изменении одного файла с двух машин.
- При смене runtime в обе стороны новая нативная сессия получает историю обычным сообщением на первом реальном ходе. Из БД берутся последние 100 записей user/assistant/tool/tool_result, без служебного шума, плюс доступные вызовы для результатов на границе окна. Большие записи явно сокращаются и содержат ID полного лога; общий текст ограничен. Это исходные сообщения, без модельного пересказа, canary-вызова или записи в приватный формат истории CLI. Смена модели внутри одного runtime сохраняет существующее нативное продолжение; восстановление старых незавершённых handoff сохранено.
- Создание, восстановление и повторная сборка промпта используют `assemble_prompt`. Общие шаблоны — `.orchestra/pipelines/<pipeline>/prompts`; индивидуальные дополнения и полные overrides остаются в настройках агента. Промпт ребёнка использует его указанного родителя, а не первого оркестратора того же проекта. Неоднозначный выбор без parent отказывает явно.
- Сообщения из restart inbox переходят в обычную долговечную очередь по устойчивому ID. Повтор после сбоя сохранения ACK не создаёт новую отправку и не сбрасывает UNKNOWN. Подтверждение inbox означает передачу в очередь, а не завершение работы модели. Протокол первоначального создания исполнителя и его старые записи сохранены.
- Ошибка подключения runtime показывается в API/UI/MCP. Если после неудачного connect адаптер ещё владеет процессом, он не используется для следующей отправки до переподключения. Писатели CLI не убиваются и их приватные блокировки не сбрасываются автоматически. Это исправление видимости/повторной отправки, не обещание автоматического лечения любого upstream active-writer.
- Из инструкций убраны предложения RULE, обязательный RULE TRIAGE, отчёты Memory updated/none и самостоятельное редактирование общих правил. Полезное наблюдение записывается в личные заметки; перенос в KB — отдельная последующая работа.

## Включение

Код пока в рабочей ветке. Для VPS при согласованном обновлении добавить `ORCHESTRA_TASK_PREFIX=V-` в его `.env`; на ноутбуке оставить пустое значение. После загрузки нового Python потребуется разрешённый владельцем рестарт и переподключение MCP. В этой задаче ни настройка боевого `.env`, ни выкладка, ни рестарт не выполнялись. Индивидуальные prompts не переносились в новые файлы: существующая возможность настройки сохранена.
