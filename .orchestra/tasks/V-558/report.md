# V-558 — пять моделей написали проходящий код; полное сравнение цены не получилось

**RESEARCH DONE.** На одной реальной backend/API-задаче Orchestra все пять моделей
написали код, прошедший **93/93 независимых теста**. Три Codex-плеча сами завершили
работу; Opus и Fable к установленному дедлайну тоже имели проходящий код, но продолжали
локальные проверки и были остановлены через 600 секунд. Они не дали финальный usage/cost.
Это доказательство способности всех пяти восстановить заданное поведение. Это не общий
рейтинг программирования и не доказательство равенства качества вне этих 93 сценариев.

## Изоляция и способ запуска

Это **не динамический wf_run**: внешний run_arms.py запускает одноразовые native CLI,
используя канонические parsers scripts/wf_adapters.py и readiness из wf_run. Обычные
Orchestra-workers не создавались. Codex 0.153.4, Claude Code 2.1.263; точные model/effort
и argv — invocation.json каждого плеча. Astra medium, остальные high, согласно pipeline.
Разные native system/tool prompts сохраняются: сравниваются модель+CLI, не только веса.

У каждого плеча свой обезличенный repository с одним seed-коммитом, без remotes и
старых objects, и собственный linked worktree. Никакой общей Git object database между
плечами. Snapshot включает app/tests/scripts/pyproject/uv.lock, но не .orchestra, AGENTS,
CLAUDE, TODO, CHANGELOG или docs. Доступ к исходному репозиторию, task/KB, соседним плечам,
БД и /proc-обходам запрещён Landlock; сеть — provider-only CONNECT relay, прямой TCP
запрещён кроме порта relay. Seccomp блокирует процессную память/handles и host AF_UNIX.
Перед стартом каждого из пяти плеч прошли пробы boundary-*.json; GitHub и dashboard
через relay получили 403, provider CONNECT — 200. Сырые relay-решения сохранены.
Файловый запрет охватывает весь внешний data/, включая фактическую live DB из
ORCHESTRA_DB_PATH и её merge_operations. Это не только просьба модели не искать ответ.

V-543 сначала отвергнут по проверенному ограничению: baseline 7 failed/84 passed/1 skipped,
reference 91 passed/1 skipped, но Landlock привязывает разрешённый /proc/self к PID
родителя и закрывает его детям. unshare отказал и внутри exec, и у bg-исполнителя.
Такой стенд ломал бы предмет pidfd-задачи. Эти измерения сохранены, в модельную таблицу
V-546 не входят. Смена кандидата подтверждена родителем до модельных запусков.

## Ошибки организации и пределы вывода

1. Я начала последовательную очередь. По прямому требованию владельца оставшиеся
   Opus/Fable переведены в параллель; Luna/Sol уже закончились, Astra продолжалась.
   Их время поэтому нельзя трактовать как контролируемый замер скорости при одинаковом фоне.
2. Начальный Claude --bare отключает OAuth (прямо сказано в локальном --help).
   Оба первых старта дали Not logged in, duration_api_ms=0, usage=0, $0, без relay-запросов.
   После удаления флага OAuth проверен в sandbox; это первые модельные попытки этих плеч.
3. Лимит 600 секунд одинаков для всех, но обрезал финальную телеметрию обоих Claude.
   Я сохранила streaming вывод, однако он не заменил total_cost_usd. Полное сравнение
   затрат не выполнено; повторные платные попытки не запускались.
4. Sandbox ограничивал явный /tmp при рабочем TMPDIR. Claude-плечи попробовали /tmp
   и получили Permission denied; они также выбрали более широкие тесты с отсутствующей
   инфраструктурой. Эталонные 93 теста внутри sandbox проходят, но эти дополнительные
   затруднения не позволяют объявлять наблюдённый timeout чистым недостатком модели.
5. Первый classifier ошибочно посчитал Luna __pycache__ изменением production. Исправлена
   классификация generated bytecode, исходный result.json сохранён; canonical source_pass
   в final-results.json — true. Модель и oracle для этого не перезапускались.

Следующий полноценный сравнительный замер должен сохранять завершающий usage при лимите,
иметь приватный рабочий /tmp и запускать плечи параллельно с самого начала. Это вывод
о недостатках этого стенда, не начало новой работы и не новая постоянная политика.
Для общего ответа о программировании нужны несколько разных заранее выбранных задач и
повторы: здесь одна backend-задача показала 5/5 проходящих исходников, без различения
качества выше порога оракула. Вероятность успеха моделей по одному запуску не оценивалась.
