Реализуй в этом репозитории отдельные жёсткие потолки квот для полос моделей.

Критерий приёмки: при завершённом окне квоты расход Codex 96% блокирует Sol и Astra
(полоса sol), но допускает Luna; на 99.5% блокируются обе полосы, на 94.9% все три
модели допускаются. По умолчанию потолок sol равен 95%, остальные используют общий
потолок 99%. Claude и Spark сохраняют прежнее поведение.

Потолки задаются QUOTA_LANE_HARD_STOP_PCT в формате sol=95,luna=90 через окружение
или .env с существующей горячей перечиткой. Указанный набор заменяет предыдущий:
исчезнувшая полоса возвращается к общему потолку. Пустая строка означает отсутствие
специальных потолков. Неверные элементы (например sol, sol=abc, sol=101, =95, sol=95,)
дают ValueError с именем переменной. Проценты конечные, допустимый диапазон 1..100.
Общий потолок всегда ограничивает потолок полосы сверху.

Совместимый контракт: QuotaPolicy принимает и предоставляет mapping lane_hard_stop_pct;
hard_stop_for(lane) возвращает действующий потолок, включая lane=None. Решение допуска,
его hard_limit_pct, порог линии, прогноз времени освобождения и rule ответа карты квот
согласованы с потолком полосы; rule содержит lane_hard_stop_pct. Остальное действующее
поведение допуска, неизвестной квоты, сбросов, кривых и API должно сохраниться.

Это задача только backend/API: UI менять не требуется. Изменения production-кода допустимы
в app/quota_gate.py и app/routes/system.py. Можно добавлять собственные тесты; окончательная
проверка использует неизменяемые независимые тесты. Старые локальные тесты могут ожидать
прежний общий потолок: требования выше заменяют именно эти ожидания.
Не ослабляй проверки, не отключай функциональность и не подменяй результат тестирования.
Работай только в своём checkout. Внешние репозитории, другие агенты и сервисы недоступны.
Порядок работы, инструменты, реализацию и локальные проверки выбирай самостоятельно.
