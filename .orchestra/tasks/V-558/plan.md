# V-558 — план и смета до запуска

Состояние: ожидается согласование сметы; модельные плечи не запускались.

## Что измеряем

Первый пилот: самостоятельное исправление утечки pidfd на историческом коде Orchestra.
Одна задача × пять моделей × один независимый запуск. Это сравнение пяти попыток
на конкретном asyncio/resource-ownership баге, не рейтинг общего умения писать код.
Результат оценивается поведением, не сходством diff с принятой реализацией.
Модель + её штатный CLI — единица сравнения; эффект модели отдельно от рантайма не выделяется.

Выбран V-543: baseline `1fc6beb677cbe7455df801607f7694fb6131963b`,
эталон `180a5a4f1c9372ebf557ee72d859fb2308bd4966`.
Изменены два production-файла, 37 и 8 строк по git stat; новая проверка 149 строк.
Оракул `tests/test_pidfd_leaks.py`: девять сценариев, 12 итераций каждый,
сравнение реальных `/proc/self/fd` и fdinfo до/после. Нового имени
`_await_owned_spawn` в тесте нет: альтернативная реализация может пройти.
Семь дефектных сценариев и два разрешающих контроля; дополнительная защита от регрессий —
исторические `tests/test_bg_jobs.py` и `tests/test_harness_tools.py`.
Предыдущий отчёт зафиксировал 91 passed, 1 skipped; это ещё не свежая валидация стенда.
V-546 отвергнут для первого пилота: шире поверхность (UI/API/config), тесты вводят
новые внутренние имена. V-536 не исследован дальше: подходящий кандидат уже найден.

## Изоляция и контроль до первого платного плеча

Обычный worktree недостаточен: git objects, соседние checkout, task/KB и MCP раскрывают ответ.
Подготовить отдельный обезличенный репозиторий из исторического snapshot с одним начальным
коммитом; убрать историю, remotes, `.orchestra`, локальные инструкции/память и отчёты.
Пять собственных worktree создаются уже от этого чистого репозитория.
Эталон и новые тесты остаются снаружи доступной плечу файловой системы.
Плечу доступны исходный код и прежние тесты; новые проверки применяет измеритель после
завершения, в копии результата, куда возвращаются неизменяемые оригиналы тестов.

Нужна проверенная граница доступа к ФС, а не просьба не заглядывать: запрет чтения
основного checkout, других плеч, логов/БД, домашней памяти и эталона; без MCP Orchestra.
Транспорт модели обслуживает внешний процесс; исполняемые моделью команды видят только
стенд, runtime/dependencies и временные данные. Метод ещё не реализован: bwrap в PATH
не найден, unshare есть. До запуска проверить поддерживаемый механизм, положительный доступ
к стенду и отрицательные пробы доступа к эталону. Если надёжная граница недоступна,
запуск остановить, а не объявлять prompt-запрет изоляцией.

До моделей: выполнить одинаковый оракул на baseline и reference в том же окружении.
Должны воспроизвестись дефектные сценарии и зелёный эталон. Сохранить полный stdout/stderr,
exit code, импортированный абсолютный путь app, версии, hashes исходников и тестов.
Никаких тестов на живой БД/провайдере; тестовые процессы только собственные.

## Задание плечам

Один и тот же текст описывает требуемый результат: устранить утечки собственных pidfd
при завершении/повторе/отмене command watcher, отмене при получении дескриптора и повторной
отмене spawn в менеджере и bash; сохранить успешное выполнение, отмену и повторный cleanup.
Не подсказывать helper, порядок чтения, инструменты или способ исправления.
Границы: production-изменения только в собственном стенде, нельзя ослаблять тесты,
подменять ядро/счётчик fd, отключать функции ради прохождения; никакого доступа к сервисам.
Точный текст и hash заморозить до первого плеча. Обратную связь скрытого оракула
во время попытки не выдавать. Собственные локальные проверки и исправления свободны.

## Продолжение после согласования

Владелец одобрил пять плеч и резерв $15 через Orchestra-orchestrator («бенч апрув»),
включая дополнительное Astra-плечо. Ни одного модельного запуска пока нет.
Контроли воспроизведены: baseline 7 failed / 84 passed / 1 skipped; reference
91 passed / 1 skipped. Доказательства в evidence/controls-results.json и отдельных логах.

Landlock ABI 4 доступен; unshare -Urnm внутри Codex exec отвергнут на uid_map,
sudo отвергнут флагом no_new_privs. Прототип sandbox.py подтвердил 15 проб доступа
(evidence/boundary.json), включая запрет основного Git, отчёта, KB, TODO, соседнего
плеча, БД, /proc alias и прямых сетевых соединений. Но разрешение /proc/self
привязано к PID родителя, поэтому дочерняя Python-проба не может читать свой
/proc/self/fd. Такой стенд для выбранной задачи НЕ принят. Фоновый исполнитель
проверяет unshare отдельно: его контекст может отличаться от tool sandbox.
transport.py — ещё не проверенный CONNECT-only relay для provider endpoints;
модели через него не запускались.

## Зафиксированный запасной пилот перед платными запусками

Фоновый unshare также отказал. Выбран backend/API V-546, без UI: baseline
9948ab52542a52bb189cec6f84bb5b45a4729351; reference 084a989edad3164192311669080d9aba6af9e6da.
Широкий первый контроль включал e2e с отсутствующим pipeline и браузеры — они исключены
из критерия backend/API ДО запуска моделей, исходные логи сохранены. Финальный критерий:
tests/test_quota_gate.py + tests/test_quota_map_api.py. Baseline: 13 failed / 80 passed;
reference: 93 passed. Тот же эталон внутри Landlock/seccomp: 93 passed.

Пять независимых обезличенных Git-репозиториев, по одному seed-коммиту и собственному
linked worktree внутри файловой границы каждого плеча. Их tree hash одинаков, remotes
пусты. Нет .orchestra, CHANGELOG, TODO, AGENTS/CLAUDE или полной истории. Проверки
boundary-*.json закрывают все внешние источники, включая живую БД merge_operations.
Сеть ограничена CONNECT-only relay к provider API: GitHub и dashboard отвергаются,
прямой 443 запрещён Landlock; AF_UNIX и процессная память ограничены seccomp.

Исполнитель run_arms.py использует одноразовые штатные CLI и канонические парсеры
scripts/wf_adapters.py (тот же runtime слой wf_run), без Orchestra-сессий и MCP.
Внешняя изоляция требует своей обёртки; полноценный wf_run не добавляет нужной границы.
Пять запусков последовательны, без ретраев: Luna, Sol, Astra, Opus, Fable. Effort
соответствует текущему pipeline: Astra medium, остальные high. Таймаут 600 секунд
на попытку; Claude ограничен min($5, остаток резерва), Codex не обещает hard dollar cap.
Стоимость проверяется перед следующим плечом; после ошибки рантайма очередь останавливается.
Native tool/system prompts отличаются между runtime: это сравнение модель+CLI, а не
чистая абляция весов модели. Текст prompt.txt и его SHA зафиксированы в arms-manifest.json.

Очередь пяти плеч запущена фоновым заданием `bg-2ce4f8612c`. Подготовка и замороженный
стенд закоммичены до запуска. Проверка secret_mask на всех артефактах до запуска:
совпадений нет. `git diff --check` отмечает пробелы в сырых pytest stdout; они намеренно
сохранены дословно, а не вычищены из доказательств. Файлы исходного кода проекта не менялись.

Владелец потребовал параллельный запуск (22:38). На этот момент Luna и Sol завершились,
Astra уже выполнялась. Через `parallel_handoff.py` запущены одновременно Opus и Fable,
job `bg-4096671e78`. Исходный контроллер продолжает Astra; эксклюзивный mkdir каталога
результатов не даст ему повторно запустить Opus/Fable. Его FileExistsError на Opus после
Astra будет ожидаемой остановкой очереди при передаче управления. При итоговой сводке
читать пять отдельных result.json, не принимать этот ожидаемый handoff за сбой моделей.

Первичная автоматическая оценка Luna ошибочно посчитала созданные Python `__pycache__/*.pyc`
изменениями production-кода. Oracle прошёл. Классификатор исправлен: собственный bytecode
не является изменением исходников; исходный result сохранён для прозрачности, финальная
приёмка должна учитывать это исправление. Последующие проверки не требуют повторного
модельного запуска. Методика запуска — прямые native CLI с внешней границей и каноническими
парсерами wf_adapters, а не динамический workflow; это явно объяснено владельцу.

Claude preflight поправлен после нулевого старта: локальный `claude --help` явно говорит,
что `--bare` принимает только API-key auth и НЕ читает OAuth. Оба отказа показали
`Not logged in`, duration_api_ms=0, total_cost_usd=0, все usage=0 и пустой relay.
API-ключ вместо подписки не использовался. Убран `--bare`, приватный OAuth передан
через штатный CLAUDE_CODE_OAUTH_TOKEN (значение не сохраняется в evidence).
Auth status внутри той же файловой границы: loggedIn=true, authMethod=oauth_token.
Private HOME, пустые setting sources/MCP, явно ограниченные tools и файловая граница
сохраняются. Прогон двух Claude-плеч начат параллельно job `bg-feea00468f`; результаты
в opus-authenticated/fable-authenticated. Это первые модельные попытки этих плеч,
нулевые отказы запуска сохранены отдельно. Исходная очередь после Astra остановилась
на ожидаемом mkdir для opus, дубликатов не было.
