# V-732: сдвиг линии недельной квоты Claude

## Изменение

`QuotaPolicy.claude_weekly_shift_hours` задаёт горизонт сдвига (по умолчанию 8 часов). Только для полосы `claude` функция `line_limit` вычисляет норму и допуск в точке `progress + hours * 60 / WEEKLY_WINDOW_MINUTES`. Полоса Claude выбирается из недельного окна `anthropic` в `deciding_window`; короткое окно Claude не становится источником данных. Линии `sol`, вызовы без `lane` и прочие полосы не сдвигаются. Инверсия прямой в `line_release_progress` вычитает тот же горизонт, поэтому расчёт `opens_in` согласован с текущим порогом. Там, где линия уже достигла потолка, любое значение ниже жёсткого стопа считается уже разрешённым; фактическое использование на жёстком стопе по-прежнему блокируется до сброса. Override по-прежнему снимает линию, но не общий жёсткий стоп.

При параметрах по умолчанию прибавка там, где потолок ещё не достигнут, равна `91 * 8 / 168 = 4.333333…` п.п. При progress `0.5` линия Claude — `59.8333%`, базовая — `55.5%`; линия Sol и вызов без полосы остались прежними.

## Уточнение времени достижения потолка

Указанные в задаче «около 8 часов до сброса» не совпадают с заданной формулой вместе с текущим допуском `10 → 1` п.п. Старая прямая уже касается потолка 99% при `progress = (99−10)/91 = 89/91`, то есть примерно за 3 ч 41 мин до сброса. После сдвига на 8 часов она впервые касается 99% при `progress = 89/91 − 8/168`; это примерно за 11 ч 42 мин до сброса. При этом новая линия ровно на 8 часов опережает старую во всём незажатом участке, как задано. Утилизация на фактических 99% остаётся жёстко заблокированной до сброса, даже когда сама линия достигла 99% раньше.
