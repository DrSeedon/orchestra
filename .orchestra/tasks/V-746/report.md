# V-746 — review of `writing-for-agents`

Research only; no prompt or policy edits were made. Source checked on 2026-10-07: [`SKILL.md` at the inspected upstream main snapshot](https://github.com/mattpocock/skills/blob/f3fc5632f401156837ee3872f14fe33ccf1024ea/skills/productivity/writing-for-agents/SKILL.md), with its only referenced file, [`SKILL-MECHANICS.md`](https://github.com/mattpocock/skills/blob/f3fc5632f401156837ee3872f14fe33ccf1024ea/skills/productivity/writing-for-agents/SKILL-MECHANICS.md). `main` was `f3fc5632f401156837ee3872f14fe33ccf1024ea` at inspection. GitHub's file history API identifies `321658273cb1d20b76026717d027d505790106d4` (2026-08-19) as the latest commit touching `SKILL.md`; the same pinned tree was used for the referenced mechanics file. The repository declares MIT in `package.json` and `LICENSE` (Copyright 2026 Matt Pocock).

The source is an authoring framework for agent-facing documents, not a skill that restructures a repository by itself. It proposes a set of lenses: contextual pointers; separate agent-context and human-navigation costs; a hierarchy of steps and reference, including conditional disclosure; co-locating rules and caveats; explicit, checkable completion criteria; splitting only where a real sequence or invocation boundary earns the extra pointer; familiar compact vocabulary (“leading words”); careful positive instructions alongside necessary prohibitions; one authoritative owner per meaning; consulting runtime/configuration instead of copying cheap facts; pruning stale or irrelevant text; and identifying no-op instructions by observing model behavior. `SKILL-MECHANICS.md` adds model-invoked versus user-invoked skill descriptions and router skills.

The Telegram prompt is a proposed operation, not the skill's prescription: it asks for three increasingly radical subagents and one PR. Neither source file requires three agents, radical alternatives, `CODING_STANDARDS.md`, or even a multi-agent review. Those are choices in the forwarded prompt, and their cost would need its own justification.

## Exact wording and evidence behind the claim

To preserve the source wording without reproducing the 81-line work wholesale, three short rules are quoted exactly: “One trigger per branch.”; “The strongest criteria are both checkable and exhaustive.”; “settle it by running the document, not by debate.” The remaining source rules are represented in the comparison below.

The skill argues that overexplaining things the model already knows is a common waste and says to test no-op status against the model's default behavior. Neither `SKILL.md` nor `SKILL-MECHANICS.md` gives a measurement establishing “the most frequent source of wasted tokens”: no corpus, frequency denominator, model/task sample, token accounting, or comparison is reported. That ranking is absent from the two inspected skill files; from these sources it can only be treated as an authorial hypothesis, not a measured fact. Whether a line is a no-op is expressly model-relative in the skill; static inspection cannot establish it.

These are conditional paths, but not a general auto-loader for arbitrary linked documents. | **Already have the mechanism; take the wording lens selectively.** Reviewing a pointer when touching it is cheap. Runtime does not automatically follow every Markdown link or fetch an arbitrary target. | **Already have the structural equivalent; take branch-based placement as an editing heuristic.** Moving rules out of delivered modules costs more than adding a file: someone must make the target reachable, write and maintain its trigger, and verify delivery. ## Local measurements and limits

Measured with the current `app.pipeline.build_system_prompt('default', role)` using the checked-in manifest and prompt files. The KB index was measured separately with `app.kb_index.kb_index_block()` for this worktree. These are exact source-text bytes/chars, not provider token counts.

| Role | Assembled static prompt bytes | Characters | KB index characters | Static + index characters |
|---|---:|---:|---:|---:|
| orchestrator | 81,370 | 80,839 | 1,793 | 82,632 |
| sub-orchestrator | 74,447 | 74,025 | 1,793 | 75,818 |
| worker | 39,001 | 38,827 | 1,793 | 40,620 |
| full-cycle | 66,978 | 66,664 | 1,793 | 68,457 |
| reducer | 24,132 | 24,024 | 1,793 | 25,817 |

The largest static role prompt is 3.37× the reducer's. Root `AGENTS.md` is 14,044 bytes against its 16 KiB limit. These counts are not full request size: the pipeline uses `inherit_claude_md: true`, and session assembly can add worker memory, ownership blocks, stored overlays, dynamic role/context blocks, and skills/runtime material. Those additions vary by agent and request. No compatible tokenizer for all configured providers was available locally, so no token totals are claimed; adding a tokenizer or asking providers for counts would be a different measurement. The file-size spread shows that selective role delivery exists, but does not show which rules have behavioral effect.

**What can be called a no-op from current evidence:** no particular natural-language policy line was proved behaviorally inert by this audit. The assembly code proves which static text is delivered, not whether a model follows or needs it. The committed #490 check guards module wiring; it does not assert literal sentences. Determining per-line effect would require controlled comparisons with a success/preservation metric, for each relevant model/runtime; V-666/V-548/V-550 do not license broad deletion.

## Disposition

No prompt edit is proposed. Orchestra already has the core architecture advocated by the skill: a small, size-limited root rules file, per-role base/role/module composition, skill files, and an injected KB index. The portable value is as a selective editorial checklist—especially checking real branch triggers, single ownership, context/cognitive cost, and stale/no-op claims with evidence. It does not justify three increasingly radical subagent rewrites or a move into `CODING_STANDARDS.md`; those add delegation, context, navigation, and delivery costs before any specific failure has been established.

This is consistent with our evidence limits: V-548/V-550 tested one bounded task on five models and found a 7.5–8.8× cost penalty for two models under the combined prompt intervention; it cannot attribute the effect to either sentence alone. V-666 separately measured generic reasoning/certainty wording in its benchmark, not every Orchestra policy or provider. #490's durable finding is that role delivery must be mechanically checked because a whole module had silently been omitted from reducer. The 06.09 decision rejects literal-phrase tests; no tests were added.
