# V-960 — фреймворк tester-army/e2e: нужен ли Orchestra

Только исследование. Источники: клон репозитория (HEAD ef977f4, 2026-10-17, `packages/e2e` v0.21.2), его `docs/*.mdx` (поставляются в npm-пакет), `gh api`, реальный прогон. Пост Telegram не открывался (нужен вход), заявления из задачи сверены с README и docs.

## Что это на самом деле

TypeScript-раннер (Playwright внутри для web, agent-device для iOS/Android) с API в духе Playwright. Тест — обычный код с `locator`-проверками, плюс опциональные шаги `agent.act / assert / waitFor / extract` на естественном языке. Лицензия Apache-2.0. Зрелость: репозиторий создан 2026-07-22, 11 213 звёзд, 76 открытых issues, коммиты ежедневно (последний 2026-10-17), версия 0.21.2, README прямо говорит «на пути к 1.0, API и конфиг меняются между minor-версиями». Делает TesterArmy — продукт-платформа вокруг этого OSS (есть телеметрия, отключается `E2E_TELEMETRY_DISABLED=1`).

## Устройство ИИ-шага (docs/agent-steps.mdx, cache.mdx, models.mdx)

- Модель **не задана по умолчанию** («There is no default»): любая модель AI SDK (gateway, OpenRouter, ключ провайдера, локальный сервер) с tool calls и картинками.
- `act`: цикл «модель видит текстовый снимок страницы (роли, имена, состояния; без HTML/куки), просит действие, получает дельту экрана». Лимит `maxModelCalls` по умолчанию 25 на шаг, таймаут шага и 15 с на действие. `assert`/`extract` — один вызов + один ремонтный; `waitFor` — без вызовов, пока экран не меняется. Скриншот добавляется только при `vision` или когда текста мало. Точных токенов на шаг в документации нет, есть только итоговая строка прогона вида «4.1k tokens · 2 model calls».
- **Платный API или подписка:** подписочные входы — ChatGPT Plus/Pro (`e2e login openai`, OAuth), GitHub Copilot, OpenCode Console, SuperGrok. Для Claude Max/Team подписочного входа **нет**: «Claude plans have no sign-in for other apps», нужен API-ключ, оплачиваемый из месячных API-кредитов плана. Подписочного Claude-CLI-режима нет (в executors.mdx нет упоминаний Claude Code/Codex как исполнителя; свой executor писать самим). Про то, допускают ли условия OpenAI использование ChatGPT-OAuth вне Codex, я не проверял.
- Для нас это значит: Claude-вариант упирается в правило «API-кредиты $200 — только отдельные задачи, не обычный воркер»; ChatGPT-вариант возможен, но съест Codex-пул, а он на Plus мал.

## Что значит «детерминированный» и как работает кэш

Два разных смысла. (1) Тест без agent-шагов — обычный детерминированный код, модель не нужна. (2) Кэш воспроизведения: после `act` должна пройти проверка (локатор-матчер, `toHaveURL`, `agent.assert`) — тогда runner сохраняет **записанные действия**, и следующий прогон повторяет их без модели; если контрол или итог не совпал, агент «подхватывает» с текущего экрана, запись вытесняется. Ключ — тест, цель, текст инструкции, параметры, агент, движок; смена модели промах не даёт. `agent.assert/waitFor/extract` **всегда идут живьём** — детерминированными они не становятся. Итого «детерминизм» = кэш успешного пути + обычные локаторы, не гарантия вердикта.

## Реальный прогон (без модели, без боевых данных)

Окружение: системный Node 20 не подходит (пакету нужен ≥22.22), поставил `node@22.23.3` в `/tmp/e2e-v960/run`, там же `e2e@0.21.2` и `@e2e-dev/web`. Целью взят публичный `http://127.0.0.1:8888/login` (корень отдаёт 302 на /login, дашборд закрыт паролем; ни данных, ни кредов не трогал). Ни одного вызова модели и платного API.

Файлы: `e2e.config.ts`, `login.e2e.ts`, эталон `login-web-linux.png` в этой папке.

1. Первый прогон: `no stored screenshot ... wrote this run's there` → провал (так задумано). `--update-snapshots` → 2 passed, 1.2 с. Повтор без флага → 2 passed, 1.18 с. Проверка `toHaveURL(/\/login/)` на редирект с `/` — прошла, 146 мс.
2. Мутация (клик на EN перед сравнением с RU-эталоном): `2241 pixels (0.24% of the image) differ ...`, плюс `-diff` (красные пиксели), `-actual`, `-expected` в `.e2e/results/.../screenshots/`. Визуальная регрессия ловится, рендер стабилен между прогонами на одной машине.
3. Тест с `agent.assert` без модели: сразу `MODEL_UNAVAILABLE ... agents.default has none`, ничего не вызывается.

Ограничения прогона: проверен только публичный экран логина, не залогиненный дашборд; агентные шаги и кэш-повтор не запускались (нужна модель, платная или подписочная).

## Сравнение с нашим стеком

Наш стек: Python pytest + playwright (`tests/conftest.py`, маркер `browser`, ~30 файлов `tests/test_*frontend*`, `*_browser.py`), вне merge-gate; V-874: полный browser-прогон 201 passed за 310 с при `-n 2`.

| Механизм e2e | У нас | Вердикт |
| --- | --- | --- |
| Детерминированные локатор-тесты | Есть, богаче: фикстуры, fake microphone, IndexedDB | **Уже есть**, переписывать на TS незачем |
| Сравнение со скриншотом (`toHaveScreenshot`, `--update-snapshots`, diff/actual/expected) | **Нет.** Python-Playwright не имеет такого матчера (проверено: у `PageAssertions`/`LocatorAssertions` ни одного метода со `screen`). Тесты V-860/V-874 лишь пишут скриншоты в `.orchestra/tasks/V-xxx/screenshots` (`tests/test_frontend.py:5984,5996`) — это артефакты для человека, ничего не сравнивают | **Реальная дыра**, но закрывается без нового фреймворка (см. ниже) |
| Агентные шаги `act/assert` | Нет; скилл webapp-testing — ручной сценарий агента | **Не брать** для CI: цена и недетерминизм при том, что у нас интерфейс известен и стабилен для локаторов |
| Кэш воспроизведения | Нет | **Не брать**: смысл только при наличии агентных шагов |
| Web+iOS+Android единый API | Не нужно, у дашборда нет мобильного клиента | **Не нужно** |
| Telegram/CI-репортёры | Свои | Не нужно |

Где болит на деле: (а) визуальные регрессии дашборда не проверяет никто — подтверждается отсутствием какого-либо сравнения пикселей в `tests/`; (б) «перезапись отслеживаемых скриншотов» из постановки — это запись PNG в каталоги задач, а не эталоны; конфликт с эталонами появится только когда эталоны заведём.

## Цена переноса и контраргументы

- Целиком на e2e: вторая экосистема (Node ≥22.22 на сервере, где стоит 20), переписать ~30 файлов с pytest-фикстурами и серверными моками, нестабильный API до 1.0, телеметрия, нет подписочного Claude-пути. Цена высокая, выгода только в одном механизме.
- Контраргумент «агент сам ходит по дашборду и находит поломки» (`e2e explore`): это отдельная ценность, но требует модели на каждый прогон; у нас такую роль уже играют воркеры со скиллом webapp-testing, а их токены считаются отдельно.
- Контраргумент в пользу e2e: готовые diff-картинки и политика CI «не писать эталоны без флага» продуманы; но их воспроизводимо повторить в pytest за малый объём (см. ниже).

## Рекомендация

1. **e2e целиком — не брать.** 
2. **Единственный механизм, который стоит позаимствовать — идею эталонных скриншотов.** Вариант без новой зависимости: маленький помощник на pytest (`page.screenshot()` + сравнение через Pillow/pixelmatch-аналог, эталоны `tests/__snapshots__/<name>-<project>-linux.png`, обновление флагом `--update-snapshots`, при провале сохранять actual/diff в каталог результатов, не в отслеживаемое дерево). Ограничение: пиксельные эталоны зависят от шрифтов и ОС, поэтому снимать на одной среде (VPS) и проверять локально не стоит; начинать с 2–3 стабильных экранов (login, пустой дашборд) и маскировать динамику. Это новая работа и потребует отдельного одобрения владельца — здесь не внедрено.
3. Если владелец хочет именно агентное исследование UI — единственный бесплатный путь через ChatGPT-OAuth (не проверено на допустимость условиями), иначе платный ключ, а это запрещено без разрешения.
