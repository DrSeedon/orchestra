# #522 — платформа вставляет оглавление KB в системный промпт

## Что сделано

Список тем базы знаний перестал быть текстом внутри корневых `AGENTS.md`/`CLAUDE.md`.
Теперь платформа собирает его при каждой сборке системного промпта из
`<scope>/.orchestra/kb/README.md` — того проекта, в котором работает агент.

Один владелец разбора: `app/kb_index.py`. Его читают оба потребителя —
`ROLE_SYSTEM_PROMPT` (промпт) и `scripts/check_instruction_contract.py` (CI-проверка).
Второго парсера того же README в коде нет.

## Где именно вставляется блок

`app/manager.py:ROLE_SYSTEM_PROMPT` — сразу после статики слоёв пайплайна
(`build_system_prompt`) и до динамики оркестратора (каталог ролей, список воркеров):

```python
kb = kb_index_block(scope)
if kb:
    base += f"\n\n{kb}"
```

Эта функция — единственная точка сборки базы промпта, и её зовут оба пути:

| путь | вызов | когда |
|---|---|---|
| спавн | `_create_session_locked` → `ROLE_SYSTEM_PROMPT(pipeline, role, scope)` | создание сессии |
| переинжект | `session.py:1512` → `manager.assemble_prompt` → `ROLE_SYSTEM_PROMPT` | первый ход после resume/compact |

Из-за этого блок обновляется тем же механизмом, что и `<worker-memory>`, без рестарта.
Чтобы это работало у воркеров, им теперь тоже передаётся `scope` (раньше
`ROLE_SYSTEM_PROMPT(pipeline, role)` без него). Блоки других оркестраторов и воркеров
остались под `if is_orch` внутри функции, поэтому воркер их по-прежнему не получает.

Роли не участвуют в решении: блок не лежит ни в одном `prompts/modules/*.md`, поэтому
роль с коротким списком `modules:` (reducer) не может его потерять — это и есть дефект,
на котором #490 молча терял вынесенные блоки.

## Кто теперь ловит незаиндексированную тему

`check_instruction_contract.py:check_kb_index` — тот же общий парсер. Тема-файл без строки
в README отбивается как раньше (`KB topics missing from README`), но исправляется теперь
правкой ОДНОГО файла: корень трогать не нужно.

## Отказы (негативное плечо)

| ситуация | поведение |
|---|---|
| нет `.orchestra/kb/` | блока нет вообще (не пустой заголовок) |
| нет `README.md` | блока нет |
| README без единой строки-темы | блока нет |
| `scope=""` (ad-hoc/legacy сессия) | блока нет |
| строка ведёт на несуществующий файл | `ValueError: KB index points outside its topic inventory` |
| символическая ссылка из `kb/` наружу | тот же отказ |
| тема указана дважды | `ValueError: KB topic indexed more than once` |
| пустое описание | `ValueError: KB topic needs a description` |
| README нечитаем (права) | предупреждение в лог, блока нет — спавны проекта не падают из-за бита доступа |
| `- [...](../guides/...)` | пропускается: это указатель, а не тема (строка реально есть в нашем README) |

## Остаточный риск

Источник индекса — `scope` (корень проекта), а пути в блоке относительные, то есть агент
открывает их от СВОЕГО каталога. Для воркера в worktree, чья ветка старше свежей темы,
строка в блоке будет, а файла в его worktree ещё нет. Выбор сознательный: требование
называет источником scope, а KB коммитится, поэтому расхождение живёт ровно до первого
мержа/ребейза. Альтернатива (читать README из worktree воркера) даёт обратный дефект —
агент не увидит темы, добавленной в main.
