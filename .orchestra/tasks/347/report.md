## Приёмка (механическая)

**1. Ни один триггер не потерян.** Скрипт бьёт оба файла на пункты, берёт первые 14 значимых
слов каждого СТАРОГО пункта как триггер и ищет лучшее совпадение среди НОВЫХ. Было 210 пунктов,
стало 216 (шесть слипшихся разделены). Совпадение <0.5 дали 5 пунктов:

- `Тест приколочен к дословному argv / тексту кода / имени вызова` — **настоящая потеря, правило
  восстановлено** (`#154`/`#58`);
- `греп МАРКЕРА без границы слова` → «Грепаешь МАРКЕР → якорно: точный путь, граница слова»;
- `Предохранитель цикла ... условие остановки зависит от продуктивности` → «Потолок раундов
  безусловный и по ТИПУ предмета ... "3 раунда БЕЗ ПРОГРЕССА" на порождающем предмете не
  срабатывает никогда»;
- `Под NoNewPrivileges=yes sudo не работает` → «`sudo` под `NoNewPrivileges=yes` отбит …»;
- `Выбрал ПОРОГ (или любое значение параметра) по замеру` → «Выбрал ПОРОГ по замеру → до прода
  три проверки».

Последние четыре — переформулировки, каждая подтверждена грепом (`grep -c` = 1 на файл).

**2. Ни одна ссылка не битая.** Все пути `docs/…`, `app/…`, `tests/…`, `pipelines/…`,
`scripts/…` из `CLAUDE.md` прогнаны через `test -e`: 24 существуют, 4 «MISS» — плейсхолдеры
(`docs/tasks/<id>/`, `docs/workers/<`, `pipelines/*/prompts/`), не пути.

**3. Доказательства не потеряны.** Маркеры, исчезнувшие из `CLAUDE.md` (72 пункта отдали
детали), выборочно проверены в базе знаний: `contaminated-run-evidence.txt`,
`manager.py:2093,2124`, `60-runtime-isolation.conf`, `remote_fetch=false`, `caught=14, MISSED=22`,
`asyncio.events._get_running_loop()`, `_ADMISSION_WATCHDOG_S=120` — все нашлись в `docs/kb/`.

**4. Артефакты не в `.gitignore`:** `git check-ignore -v` для `docs/tasks/347/*`, `docs/kb/*`,
`docs/workers/*` → rc=1.

## Почему не 60–70 КБ

Ориентир не достигнут: 97 КБ. Причина не в «недожали», а в том, что после первых двух проходов
каждый оставшийся пункт — это уже «триггер → действие + одно число». Два прохода замерены:
первый дал `Грабли` 69 538 Б (−28.5%), второй, с потолком «≤2 предложения на правило», — 58 984 Б
(−39.4%); третий проход дал бы ещё ~10 КБ только за счёт удаления якорей замера, а якорь и есть
аргумент правила: без «#345 — занижение в 2.6 раза» правило читается как вкусовщина и будет
отменено следующим агентом.

Оставшийся рычаг — не сжатие, а **удаление правил целиком** (~40 пунктов с самой узкой
применимостью). Это решение владельца файла, не исполнителя.

Длиннее прочих намеренно остались (их нельзя резать без потери исполнимости): мутационная
проверка «три клаузы» (порядок команд + `touch` + git-откат — каждый пункт закрывает
отдельный способ получить ложно-зелёное), `uv run` в юните (два дословных прогона с
`MATCH=False/True` — иначе нечем отличить рабочую конфигурацию от сломанной), выбор порога
по замеру (три независимые проверки), приоритет пулов (дословные решения юзера).
