# Дизайн-галерея и владение ревью

Запрос владельца от 2026-09-07: ограничить запуск ревью исполнителями; сначала собрать
локальные и глобальные дизайн-скиллы, применить их в примерах и получить оценки перед
объединением HTML-скилла. Ветка: `codex/design-skill-gallery`.

## Готово для просмотра

`artifacts/design-skill-gallery/index.html` — самостоятельная офлайн-галерея. Включает
десять новых HTML-примеров, выбор узкого экрана, оценки, комментарии и экспорт оценок
в JSON. Каждый пример можно скачать отдельно. Все числовые данные — явно помеченные
учебные фикстуры из `data.json`, а не измерения Orchestra.

1. `apple-design` + указанный владельцем референс: плотный белый дашборд.
2. Проектный `html-artifacts`: отчёт с двумя шрифтовыми семьями.
3. Глобальный `html-artifacts`: тёмный инструмент с графиком и таблицей.
4. Глобальные Claude/Agents `frontend-design`: выразительная обложка.
5. Официальный marketplace `frontend-design`: сдержанный интерфейс принятия решений.
6. `diagram-design`: схема ответственности с ортогональными связями.
7. `eli5`: интерактивное объяснение очереди через четыре рабочих места.
8. `playground`: настройка плотности и экспорт инструкции словами.
9. `3d-frontend`: настоящая сцена Three.js с камерой, управляемой скроллом.
10. `page-cro` + frontend: страница с одной основной кнопкой и ответами на возражения.

Рядом показаны двадцать ОРИГИНАЛЬНЫХ превью Office-шаблонов из кеша OpenAI Templates.
Они не выдаются за новые применения шаблонов: DOCX/PPTX/XLSX здесь не генерировались.
Форматные PDF/DOCX/PPTX/XLSX, растровый imagegen, учебный teach-me и процессный udesign
попали в инвентаризацию как смежные инструменты, а не самостоятельные стили HTML.

`inventory.json` содержит пути, SHA-256 и размер каждого различающегося SKILL.md.
Обследованы проектные .codex/.claude и канонические prompts/skills, глобальные
.codex/.agents/.claude/skills, кеши плагинов и локальные marketplace, Projects/skills.
Наличие в кеше не означает, что скилл подключён к текущей сессии.
Полные тексты источников сохранены локально в игнорируемом `skill-sources.json`.
Копии с одинаковым содержимым объединены. Проектные HTML-копии отличаются только
путём вывода, две глобальные frontend-копии — финальной фразой; отдельных макетов
для этих косметических различий нет.

Канонический HTML-скилл Orchestra: `.orchestra/pipelines/default/prompts/skills/html-artifacts.md`.
Нативные `.codex/.claude/skills` — проекции; будущая консолидация должна менять владельца,
а не создавать очередную независимую копию.

## Изменение ревью

- Из skills оркестратора и суборкестратора исключён codex-debate.
- В codex_review перед созданием квитанции, проверкой квот и запуском job проверяется
  текущая роль из API сессии. Разрешены worker/full-cycle без is_orchestrator.
  Неизвестная роль, reducer, обе оркестраторские роли и is_orchestrator отказываются.
- Проверка действует на все режимы и resume. Старое значение ROLE процесса не может
  переопределить текущую роль сессии.
- Непустой target_worker отклоняется. Старый путь запуска ревью чужой ветки удалён
  из инструмента; read-only API получения снимка оставлен, он сам ревью не запускает.
- Исторические квитанции, их подписи, review-skip и проверки покрытия при merge сохранены.
- Инструкции отправляют вопросы обратно исполнителю и запрещают оркестраторам обход
  через shell или подставного ревьюера. Передача работы не обнуляет историю раундов.
- Канонический скилл приведён в соответствие с default Luna и implementation-режимом.
  Проверка манифеста теперь запрещает возвращать review-скилл оркестраторам.

Это ограничение штатного MCP-инструмента, а не песочница против агента с произвольным shell.
Код находится только в отдельном worktree: merge, push, деплой, рестарт и обновление
живых MCP-процессов не выполнялись. Для активации требуется интеграция и обновление
MCP-процессов; никаких самовольных перезапусков.

## Следующий этап после оценок владельца

Не утверждать единый визуальный стиль до оценок галереи. Собрать короткий канонический
HTML SKILL.md с загрузкой нужных references; выбранные темы, композицию, схемы,
интерактив и экспорт держать отдельно. Учитывать лицензию и происхождение заимствований.
Офисные форматы и растровую генерацию не превращать в обязательные зависимости HTML.
Проверить выбранную комбинацию на отчёте, схеме и объяснении, затем согласованно
обновить проекции. Авторизация на работу есть; недостающий вход — оценка примеров.
