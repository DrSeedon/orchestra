    6	# Laptop access
    7	
    8	The only route for platform agents is SSH through the reverse tunnel. The laptop maintains the
    9	connection to the VPS; its system-level `ssh-tunnel-vps.service` was checked active/running on
   10	2026-09-13. The `run_on_laptop` tool is unavailable to platform agents.
   11	
   12	## Check the connection
   13	
   14	On the VPS, check the local listener:
   15	
   16	```bash
   17	ss -ltnH 'sport = :2222'
   18	```
   19	
   20	Working command (2026-09-13, host `maxim-911aird`, user `maxim`):
   21	
   22	```bash
   23	ssh -i /home/kesha/.ssh/tunnel_laptop -o IdentitiesOnly=yes -o BatchMode=yes -o ConnectTimeout=5 -p 2222 maxim@127.0.0.1 'hostname; pwd'
   24	```
   25	
   26	For authorized work, replace only the remote command; quote paths containing spaces. The laptop
   27	user is `maxim`, not the VPS user `kesha`. Empty successful `ss` output means no listener; an
   28	error from the check does not prove that none exists. Refused/timeout means the connection is
   29	unavailable: report the observed failure to the owner. Sleep, shutdown, and network loss are
   30	possible, but one error does not establish the cause. Permission denied means an authentication
   31	problem, not proven sleep: check the user and specified key. The tunnel is raised from the
   32	laptop; do not reconfigure or restart it from the VPS.
   33	
   34	## Actual boundaries
   35	
   36	This is a remote shell with the `maxim` account's rights, not a command whitelist or metacharacter
   37	filter. SSH maintains authentication and protects transport; the laptop OS limits object access.
   38	The assignment and project rules determine what is allowed, not the existence of a working
   39	connection. Installation, restart, and configuration changes are allowed only when explicitly
   40	included in the agreed assignment. Handle the laptop carefully — see [AGENTS.md Orchestra,
   41	"Authority boundaries"](/home/kesha/orchestra/AGENTS.md). Do not copy those rules into this skill.
   42	Access alone does not authorize spawning agents or continuing other sessions. Long authorized
   43	commands follow the platform's background-jobs rules.
