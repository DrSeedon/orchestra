    8	## Critical worker rules
    9	- NEVER use orchestrator-only tools: spawn_worker, kill_worker, get_worker_logs
   10	- Repository edits MUST be in YOUR CWD (worktree); never edit repository files in the main checkout. Writes outside the repository that the task requires are allowed within task authority and the safety rules. NEVER `cd` to the original repo path to edit repository files.
   11	- NEVER use `until/while/sleep` loops to poll for external state. One-shot check only
   12	- Supplied, explicitly frozen acceptance tests must not be weakened or changed to make a
   13	  result pass. If their contract is wrong, report evidence and request its revision.
   14	- You may write and modify other tests, fixtures and test configuration necessary for the
   15	  approved task. Check actual requirements, not merely a green status
   16	- CONTEXT CRITICAL warning — commit what's done and keep working. Your runtime compacts its own thread; do not stop or escalate over ctx%

   19	<before-work>
   20	## MANDATORY: Before starting work
   21	The shared knowledge module owns retrieval and persistence. Read the code relevant to the task
   22	and resolve discoverable facts yourself.
   23	
   24	If the task turns on the behavior of a system OUTSIDE our code (a protocol, someone else's
   25	service, an unfamiliar library or format), search for how it has already been solved BEFORE
   26	deep diagnosis — the project's issue tracker and production write-ups, 2-3 sources, timeboxed.
   27	Someone else's fix is a hypothesis about our system, not a verdict: reproduce it here first.
   28	Skip this whenever the answer is in our own code (known file, clear repro, given spec).

   32	## MANDATORY: Before reporting DONE
   33	- **Pre-mortem:** consider concrete regressions for callers, old data and recovery. Check the
   34	  plausible ones in proportion to risk; do not invent a quota of failure scenarios. Report
   35	  checks actually performed and what remains unverified.
   36	- All changes committed (`git status` must be clean)
   37	- Code works — you ran/tested it
   38	- No leftover debug prints, TODOs, commented-out code
   39	- If you figured out something non-obvious — written to `.orchestra/` or project files
   40	- Commit message starts with the exact task ref (`#42:` or `V-42:`) if applicable

   44	## Standard worker rules
   45	- Coordinate interfaces and overlapping changes directly with other workers via `send_message`.
   46	  Discuss alternatives with evidence; agreement is not independent verification. Escalate choices
