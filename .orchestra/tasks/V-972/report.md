## Вопрос, метод и предел доказательства

Контекст — инструкции, которые платформа собирает для пяти ролей default pipeline и выдаёт через MCP/skills/project rules. Проверяемая гипотеза — разные действующие источники предписывают разные действия при одном входе. Альтернатива — кажущаяся пара относится к разным ролям, разным операциям или уже разрешена авторизацией/приоритетом. Единица счёта задана владельцем: **одна пара правил и один различимый сценарий действий**. Повторные копии и дополнительные ссылки той же стороны перечислены в одной строке. Само наличие двух формулировок не считается доказательством дефекта.

Просмотрены полностью все 28 файлов в `.orchestra/pipelines/default/prompts/**`: base, 15 modules, 5 roles, 6 skill entrypoints, 1 skill reference. Из `app/mcp_stdio.py` AST извлечены и полностью прочитаны **все 45 зарегистрированных MCP tool descriptions**; незарегистрированный `codex_review()` отдельно не считается действующим tool description. Проверены сборка, ownership, временные правила, KB index и перечисленные ниже пути доставки. Связанные личные skill-указатели прочитаны read-only. Первая стадия ограничена конечным inventory; после неё проверка кандидатов ограничивалась адресными чтениями и детерминированными локальными пробами. Провайдеры, model review, платные API, Luna control runs не запускались. Модельное поведение ниже нигде не выдано за измеренное.

`collect.py` сохраняет нумерованные источники, SHA-256, AST-описания tools и raw stdout/stderr команд. `probe.py` вызывает настоящий `build_system_prompt`, `resolve_role`, `validate_spawn`, `kb_index_block`, `own_catalog_path`; две функции manager исполняет из AST с локальным fake-session и без БД. Это проверка конкретных веток кода, **не end-to-end тест живого сервиса**. `capture-evidence.py` сохраняет дополнительные нумерованные участки и команды. Исследовательские скрипты пишут только в каталог V-972.

Первый запуск probe импортировал `app` из main из-за editable-install окружения uv. Его вывод сохранён отдельно как `raw/probe-first-main-import.txt` и не используется для выводов. `app/manager.py:261–294` добавляет **KB topic index**, затем для orchestrator kind — **каталог разрешённых child roles**. `assemble_prompt:1912–1962` после этого добавляет custom overlay/ownership, personal memory, **последним temporary-rules**. Полный legacy/operator override может сохранить старое тело вместо пересборки (`1940–1944`); такой override не обследовался как универсальное правило платформы. Ownership генерируется только при непустом owned_dirs (`411–420`).

Skills — отдельный канал. `app/prompting.py:340–362,462–506` и `app/session.py:1733–1779`: pipeline skills копируются при connect/reconnect в `.claude/skills` или `.codex/skills`, tracked repo-owned файлы не перезаписываются. `prompting.py:610–660,731–778` строит progressive index; тело читается при применении skill. Здесь установленная `.codex`-копия каждого из трёх skills worker/full-cycle побайтно совпала с каноном. Поэтому строки skills в таблице означают **условную co-delivery при указанном сценарии применения**, не обязательное присутствие всего skill в каждом ходе.

Codex получает собранный платформенный текст как `developerInstructions` (`app/backend_codex.py:720–727`), правила проекта читает CLI; в этой беседе AGENTS доставлен user-сообщением. Claude получает platform append к preset (`backend_claude.py:1125–1136`) и `setting_sources=[user,project,local]` при inherit=true (`1151–1153`). Harness явно конкатенирует **platform → project rules → tool guidelines** (`app/harness/prompts.py:65–82`), читая AGENTS перед CLAUDE и с общим бюджетом 32 KiB (`35–61`). Поэтому физическое положение позже не тождественно более высокому системному приоритету во всех runtime. Никакого универсального «последняя строка побеждает» в выводах нет.

Обновления имеют ещё один канал: `app/session.py:1543–1609` на resume/изменение temporary rules может вложить свежий промпт в user-сообщение с platform note. Это не доказательство, что каждый уже работающий агент немедленно заменил первоначальный developer/system текст. Живые prompt overlays, personal memory всех агентов, сторонние project AGENTS и профили всех Claude-инсталляций не выгружались.

Обычный staged `git diff --check` отметил trailing whitespace в нумерованных raw-выгрузках: пустая исходная строка у `nl` заканчивается табуляцией после номера. Поэтому отдельно проверены обычный staged diff авторского отчёта/скриптов без raw и полный staged diff с временным `-c core.whitespace=-blank-at-eol,-blank-at-eof` (raw-протоколы команд также заканчиваются пустой строкой). Первый более узкий вариант опции и его отказ на двух EOF сохранены в `raw/validation-first-whitespace.txt`. Это только параметр проверяющей команды, ни Git-конфиг, ни source не изменены. Проверяются также неизменность 40 source hashes и девять колонок/20 уникальных строк таблицы.
