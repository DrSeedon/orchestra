## 1. Что такое evals-from-sessions (по исходникам)

**Лицензия.** Скилл — MIT (© 2026 Ibragim Badertdinov). Harbor — Apache-2.0 (по странице репозитория `harbor-framework/harbor`, там же Terminal-Bench). Задачи автора не опубликованы: «The tasks remain private for now» — ни из поста, ни из лидерборда повторить его замеры нельзя; открыт только метод и скилл.

**Состав скилла.** Один `SKILL.md` (17 КБ), `references/harbor-contract.md`, шаблон задачи (Dockerfile, `instruction.md`, `provenance.md`, `task.toml`, `tests/test.sh`+`verify.py` — только stdlib и функция `same()` для сравнения JSON по смыслу, `solution/solve.sh`), `leak-probe.sh`, `please-hack.j2`. **Исполняемого кода майнинга нет**: правило прямо запрещает парсеры («No parsers for trajectory formats. Read raw JSONL with `jq`»), то есть вся «автоматизация» — это инструкция агенту. Единственный скрипт — `leak-probe.sh`: собирает образ и ищет в нём строки решения, git-метаданные (коммитов ровно 1, ни remote, ни тегов, ни stash).

**Отбор сессий.** Шаг 0: копия сессий, `gitleaks dir --redact`. Шаг 1: агент читает копию и пишет `candidates.md` (сессия, строки JSONL, цель, «решающая правка пользователя», исход, режим, решение). Берётся эпизод, если результат проверяется по файлам/git/выводу команды, человеку на него ≤1 часа, после удаления сервисов остаётся реальная работа, не тривиален (одной командой по тексту не решается), это повторяющаяся работа. Предпочитаются эпизоды с решающей правкой пользователя или реальным провалом исходного агента. Метка `discovery` (есть вывод, который агент должен сложить из улик) или `routine` (все правила названы). **Чекпоинт 1** — человек утверждает `candidates.md`.

**Из сессии в задачу.** `provenance.md` до остальных файлов: требования (3–8), failure modes, список «must be discovered» (заморожен после чекпоинта 2; каждый пункт обязан ловиться near-miss решением). Private-режим: `git archive <родитель коммита>` в `environment/repo/`, в образе один свежий коммит (`git init`), эталон = `git diff parent episode` в `solution/fix.patch`, тесты эпизода переносятся в `tests/`. Shareable-режим: переписанная с нуля. Расследовательские задачи — закрытый набор ответов JSON (enum + id записей), свободный текст не оценивается ключевыми словами.

**Изоляция ответа.** Нет будущей истории (ни коммитов, ни веток, ни reflog), `tests/` и `solution/` в образ не копируются (монтируются только на проверку), офлайн-проверка, для кода из публичных репозиториев — `network_mode=allowlist`, иначе агент найдёт апстрим-фикс. Проверка leak-probe. Ловушка «please-hack»: дополнительный прогон с просьбой взломать верификатор, любой `1.0` без правильного состояния = дефект верификатора.

**Запуск.** Сам скилл останавливается на смоук-прогоне одним агентом и необязательной калибровке 2 сетапа × 3 прогона («слишком просто», если все проходят меньше чем за ~15 вызовов инструментов; «аудит», если не проходит никто). Сравнение сетапов — `harbor run -p tasks/ ... -k 3` вручную, «вне скилла». Метрики: reward 0/1 из `reward.txt`, токены/cost/шаги из `result.json` Harbor. Не более двух повышений версии задачи после первого смоука, третье — отказ.

**Гайд (teletype).** ~1270 сессий за 3 месяца; начато 15 задач, 3–5 итераций, оставлено 10 (одну в 90 минут чистки выбросили как решаемую за минуту); проверки: oracle ×5, nop, near-miss, alt-correct; детерминированные проверки, не LLM-судья; траектории читает второй агент на предмет лазеек. Главный вывод поста: Pi+GPT-6.1 Sol medium решает то же, что Codex, за $0,070 против $0,138 за задачу.

**Лидерборд (core10-v1.3, обновлён 08.10.2026).** 10 задач × 3 прогона = 30 попыток на конфиг, 31 конфиг, Harbor 0.21.0, харнессы Pi 0.85.1, Codex 0.118.0, Claude Code 2.1.281, Oh My Pi. Столбцы pass@1/pass@3/pass-all-3, $/task, время, шаги, токены, cache hit. **Дисперсии, интервалов и тестов нет**; автор сам оговаривает «10 tasks is a small sample». Из 31 конфига **15 имеют 100% по всем трём метрикам** — набор насыщен для различения качества, ранжирование идёт по цене/времени (максимум 100% при $0,0145 у Pi+Luna xhigh и $0,3546 у Claude Code+Opus 5.5 high). Один прогон на задачу меняет pass@1 на 3,3 п.п., так что 96,7/93,3/90% неразличимы. Цены — API-эквивалент; про учёт кеша и подписку страница ничего не говорит. Кэш-хит у GLM-5.3-Flash 0%, у Qwen 97% — он показывает расхождение учёта по провайдерам, а у нас платными считаются только запись кеша и вывод (V-660).

## 4. Постоянный набор: стоит ли, и как

Да, потому что сейчас каждый вопрос «помогает ли фраза/модель» (V-895, V-896, V-906) платит три вещи заново: выбор задач, драйвер/анализ (~70% копия), правила оракула. Но набор бесполезен как «лидерборд на 100%»: нужен срез сложности и ≥3 повтора.

Рекомендация (это архитектурная развилка → владельцу до реализации):
- **Вариант 1, минимальный (рекомендую):** не строить новую систему. Завести `scripts/evals/` (или каталог `.orchestra/evals/`) с (а) майнером F2P — скрипт ~60 строк по образцу `f2p.sh`, который по `main` выдаёт индекс `{commit, parent, test_files, f2p, priv_names, mock_count}`; (б) одним общим `run.py`/`analyze.py` вместо копий V-895/V-896 (вытащить общее; различающееся — только `tasks.py` и оракул); (в) «ядром» из ~30 задач, отобранных калибровочным прогоном. Новые вопросы тогда решаются прогоном с готового ядра: ориентир — 30 задач × 2 модели × 3 повтора × плечи.
- **Вариант 2:** довести `local_bench` до рабочего provider-режима (нужно снять `apparmor_restrict_unprivileged_userns` — решение владельца, он сознательно оставил защиту). Дороже и зависит от хоста; выигрыш — изоляция чтения (закрывает ограничение №7 V-895). Не рекомендую делать ради одного набора.
- **Вариант 3:** Harbor/Docker. Не рекомендую (см. таблицу).

**Цена калибровки (оценка, не замер):** закрытая задача A в V-895 стоила ≈ 72 354 / 16 ≈ 4,5k платных токенов на прогон. 100 кандидатов × 2 модели × 3 повтора × 4,5k ≈ **2,7 млн платных токенов подписки**, порядка одного V-896 (A+B+C 2,43 млн). Из них отобрать ~30 с принимаемостью 30–60% и зафиксировать версию. Работа сборки, по аналогии с V-895/V-896: ≈ день воркера, три шага (майнер, общий драйвер, ядро).

**Что это даст:** следующий спор о фразе решается запуском на ядре (минуты на подготовку плечей + прогон) вместо нового набора. **Чего не даст:** различимости малых эффектов — при 30 задачах × 2 модели и принимаемости 30–60% различима разница порядка ≥15–20 п.п. (по аналогии: V-895 различал ≥5 из 8; пересчитывать при калибровке), творческие и исследовательские вопросы (V-896) по-прежнему требуют ручных чек-листов.

## 5. Минимальный пилот (описание, не запущено)

1. **Без моделей, ~1–2 часа CPU:** прогнать `f2p.sh` по всем 485 (параллельно 4, `ssh kesha@localhost`, вне cgroup платформы; на 24 коммитах у меня ушло ≈25 мин последовательно) — получить точные 485 → N F2P вместо оценки 67%±17. Выход: `index.jsonl`. Решает, существует ли ядро вообще.
2. **На подписке Luna (по слову владельца):** 20 задач из индекса с `priv_names ≤4` и `mock ≤8`, по одной формулировке задания из сообщения коммита (без внутренних имён), плечо A, 1 повтор, существующий `V-895/run.py` без правок. Критерий: у скольких принимаемость 30–60%; ≈ 20 × 4,5k ≈ 90k платных токенов. Если таких меньше 5 — набор слишком лёгкий, остановиться.
3. Проверять только там, где пилот решает: после пилота — предложение по варианту 1.

## Ограничения этого исследования
- Выборка F2P: 24 из 485, один seed; причины 4 красных на коммите не разобраны; таймаут 240 с мог занизить число.
