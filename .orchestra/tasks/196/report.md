# #196 — правило «сообщение воркеру заканчивается действием» переехало в промпт оркестраторов

## Что просили
Правило из `CLAUDE.md` (коммит `1eb7dc90`) действует только в своде проекта Orchestra, а нужно во
всех проектах. Найти владельца в `pipelines/default/prompts/`, убрать дубль из `CLAUDE.md`.

## Выбор владельца — по аудитории

| кандидат | кто читает | вердикт |
|---|---|---|
| `modules/orchestration.md` | `orchestrator`, `sub-orchestrator` (`pipeline.yaml:25,41`) | **владелец** |
| `roles/orchestrator.md` | только top-level (578 Б, чистая рамка «кому отчитываешься») | нет — суб-оркестратор правило не увидит |
| `base.md` | ВСЕ роли, включая 4 роли воркеров | нет — правило про отправку воркерам, воркерам оно не адресовано |

Критерий из задания («читают все, кто отправляет, и никто больше») выполнен: правило видно ровно
двум ролям, которые управляют воркерами.

**Известный зазор, оставлен сознательно.** `full-cycle` имеет `can_spawn: ["*"]`, но
`orchestration` не грузит (`pipeline.yaml:73`). Затащить туда весь модуль — +17 КБ промпта ради
одного абзаца на роль, которая спавнит воркеров только под research-слайсы; общая формулировка
про ack-сообщения у неё уже есть в `base.md:63`. Если full-cycle начнёт будить воркеров пустыми
сообщениями — правильный ход не копировать абзац, а вынести гейт в отдельный микромодуль.

## Не добавил новое, а усилил существующее
Читал `orchestration.md` целиком (263 строки). Та же мысль там уже была ДВАЖДЫ, обе — слабее:

1. `### Pre-send gate` (строка 153) — отвечал на «какую задачу можно слать», но не на
   «а есть ли вообще что слать»: ветка `idle` разрешала «a new task or required RULE TRIAGE reply»
   и молчала о том, что при отсутствии и того и другого писать нельзя.
2. Критическое правило (строка 224) — `NEVER send empty/acknowledgment messages to workers
   ("good job", "stay idle")`. Чистый запрет; по замеру #188 запреты работают в 5–15 раз хуже
   предписаний при побайтово одинаковом тексте.

Сделано:
- Гейт разбит на два шага. **Check 1 — content** идёт ПЕРВЫМ (дешевле статуса: не о чем писать —
  не тратишь и `list_agents`): назови одной фразой действие, которое воркер совершит при получении
  («he will X»); не назвал → закончи ход без отправки. Туда же перенесены из `CLAUDE.md` три
  разбора: `RULE TRIAGE`/гейт/ответ/исправление — законное действие, хвост «а новых задач нет» к
  ним не приписывать, похвала только меняющая будущее поведение и одной фразой. Цена хода ≈$1.92
  и «отсутствие задачи сообщается молчанием» сохранены дословно.
- **Check 2 — status** — прежний текст про `list_agents`/`idle`/`running` без изменений.
- Критическое правило переписано в указатель на гейт («Put every message to a worker through the
  pre-send gate above — name the action it triggers, check status, then send. Nothing to name →
  stay silent»). Примеры «good job»/«stay idle» из него убраны — они теперь живут в гейте, две
  копии разошлись бы.

Единственная другая ссылка на гейт (`worker-management`, строка 156 «a new task or required
`RULE TRIAGE` reply») цела; ссылок по старому заголовку секции в репозитории нет
(`grep -rn "pre-send gate" pipelines/ CLAUDE.md docs/workers/` — два вхождения, оба учтены).
