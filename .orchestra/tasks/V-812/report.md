# V-812: проверка иконок статуса Telegram

## Вывод

Дефект отображения иконок не подтверждён. Иконка 📆 на активных оркестраторах означает реальное ожидание квоты `WAITING_QUOTA`; это состояние по замыслу V-804/V-805. Определение ожидания и отображение текущих активных состояний не менялись.

Проверка live `getForumTopicIconStickers` вернула 112 иконок и подтвердила все три ID из кода: running `5312016608254762256 → ⚡️`, waiting `5433614043006903194 → 📆`, idle `5350392020785437399 → ☕️`. Значит, неверного соответствия ID и эмодзи нет.

## Журнал и архивные топики

Проверен журнал живого PID 912872 от старта 10.10.2026 11:19 UTC до последней доступной записи 11.10.2026 04:08 UTC (запрос `journalctl` до текущего времени 04:56 UTC). Найдено 44 строки `TG topic_status` — это 22 отдельных перехода, поскольку каждый переход дублируется в stdout и `INFO:tg-bridge`; среди них 10 отдельных переходов в `waiting` (20 строк). Статусные события относятся только к шести именам активных оркестраторов. **Журнал не содержит доказательства, что архивный или иной незагруженный топик получил 📆.** Для видимых переходов в журнале также есть `forum_topic_edited` с соответствующим thread ID.

В живом конфиге было 69 topic IDs; API показывал 10 загруженных оркестраторов и одну загруженную non-orchestrator-сессию, остальные 58 имён были архивными (56) или без строки сессии (2). Само наличие этих топиков не доказывает, что они отображались с 📆. У Bot API нет read-only метода, возвращающего текущую иконку конкретного топика, поэтому проверить их фактические иконки без редактирования нельзя. Ни одной ручной правки топика не выполнялось.

## Стоимость editForumTopic

Bot API описывает `editForumTopic` как изменение имени и иконки, возвращающее `True` при успехе; документация не обещает чтение состояния или бесплатную проверку без расхода лимита ([Bot API](https://core.telegram.org/bots/api#editforumtopic)). MTProto указывает, что совпадающие с текущим состоянием данные приводят к `TOPIC_NOT_MODIFIED` — «ничего не изменено» ([`messages.editForumTopic`](https://core.telegram.org/method/messages.editForumTopic)). Прямой запрос с неизменившимися данными не выполнялся, поэтому поведение конкретного Local Bot API ответа отдельно не измерялось. При фактической смене live-журнал показывает `forum_topic_edited`, соответствующий Telegram `messageActionTopicEdit` ([`messageActionTopicEdit`](https://core.telegram.org/constructor/messageActionTopicEdit)). Массовая сверка 69 топиков могла бы занять общий бюджет группы и создать сервисные сообщения при реальных изменениях; оснований выполнять её не найдено.
