# Model text control flow — результат

Запрос владельца: упростить механизмы со скриншота #504 после согласованного разбора. База: `d4e3028c`; ветка `fix/model-text-control-flow`, отдельный worktree `/mnt/data/Projects/Python/orchestra-model-text-control-flow`.

## Изменения

- Обычный ответ больше не включает лимит подписки и не запускает откат истории. Автоматический safeguard-fork удалён: SDK здесь не даёт отдельного доказанного события для такого восстановления. Ошибки и исходная история сохраняются.
- Claude `RateLimitEvent` передаётся отдельным `provider_limit`; блокировка только по первичному `status=rejected`, не по `overage_status`. Сырые измерения `RATE_LIMIT_RAW` сохранены. Новая служебная запись не рисуется в чате. Ожидающий повтор проверяет отказ после задержки и повторно под lifecycle-lock, включая возвращение из проверки квоты. Планировщик пробуждения не читает прозу модели; старые записи использует только при наличии серверного сообщения о лимите.
- Компакт принимает непустой текст только после успешного `turn_end` и при отсутствии ошибки. Слова `rate limit`, `api error` и т. п. допустимы в сводке. Вывод инструментов остаётся в журнале, но не подменяет сводку. Неудача и обрыв сохраняют прежнюю сессию и сводку; прежние тесты отмены и rollback ack остаются зелёными.
- Round guard добавляется только в запрос соответствующего раунда, учитывается при оценке контекста и не попадает в `history/new_messages`. Удаления сообщений по префиксу больше нет.
- Ревью: финализатор обязательно проверяет события завершения CLI и наличие ответа, а не слова ревьюера или вывод команд. Старый явный контракт `## Verdict` сохранён, добавлен явный `INCOMPLETE`; читается последний раунд. Проверка результата общая для финализатора и фоновой задачи. Частичные находки при сбое/INCOMPLETE сохраняются вместе с предыдущими; отсутствующий вердикт оставляет прежний артефакт и текущий `.round`. Квитанция сразу получает failed, без промежуточного completed. Shell fallback не перетирает точную причину уже завершённой квитанции.
- Удалён ярлык «НЕ ВЫПОЛНЕНО» по XML из Telegram, чата и стенограммы субагента; осиротевший `tool_call_guard.py` удалён. События настоящих инструментов сохраняют прежнее отображение.

Новых зависимостей, сервисов, таблиц или миграций нет. Существующие фикстуры, имитировавшие ошибку прозой либо успешный запуск без событий завершения, приведены к реальному контракту. Тесты удалённого автоотката заменены проверками сохранения истории.

## Границы первоначальной реализации

Успешное завершение CLI и оформленный вердикт не доказывают качество ревью: его содержание всё равно требует оценки. Маркеры статуса внутри оговорённого `## Verdict` остаются явным протоколом, не эвристикой по произвольной прозе. Старые статусы квоты без надёжного источника не реконструируются из слов ассистента.

Работа в отдельной ветке, основной checkout не изменён. Коммит не смержен и не выложен; Orchestra и telegram-bot-api не перезапускались. Живые обращения к провайдерам и реальная отправка в Telegram не проверялись; для применения Python-изменений требуется отдельный разрешённый рестарт.

Продолжение после разрешения владельца на мерж и выкладку: [integration.md](integration.md).
