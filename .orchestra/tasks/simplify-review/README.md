# Упрощение ревью и приёмки — 2026-09-07

Реализовано по одобрению владельца. Для новых назначений модельное ревью — необязательное приложение к результату. Единственная приёмка фиксирует полномочного принимающего, итоговый commit и его пояснение; предусмотренные тесты и защита точного commit остаются обязательными на пути merge.

## Поведение

- `worker_wip` показывает `work-review-v2`, точный HEAD, попытки ревью и изменения после последнего code-review.
- `merge_worker(expected_head=..., acceptance_note=..., task_outcome=...)` принимает указанный результат. Новые коммиты после решения требуют новой приёмки.
- Для новых задач не нужны `record_review_outcome`, аттестация или skip-квитанция. Завершение ревью не означает одобрение реализации.
- Бюджет: три попытки на задачу, включая ошибки, одна активная попытка. Смена имени отчёта или исполнителя не сбрасывает бюджет. Повтор HTTP-запроса возвращает уже созданное задание.
- Оркестратор принимает работу, ревью запускают worker/full-cycle. Full-cycle родитель может принять ребёнка в свою ветку, но не разрешить себе merge в main.
- Старые назначения, включая принятую при запуске legacy_inflight работу, сохраняют прежний контракт. Его policy-файл сохранён побайтно в `.orchestra/guides/review-legacy-v1.md`; старые данные не переписаны. Удаление legacy-кода отложено до завершения этих задач.

## Применение и пределы

Код интегрируется в локальный main. Живой сервис не перезапускался, VPS не обновлялся. Python-изменения вступят в силу после разрешённого владельцем рестарта; MCP-клиентам требуется переподключение для новой сигнатуры инструмента. Уже начатая работа остаётся legacy.
Бюджет защищает штатный путь MCP/фоновых review jobs, а не произвольный shell на машине с полным доступом. Исторические записи и код прежней приёмки сохранены намеренно.
