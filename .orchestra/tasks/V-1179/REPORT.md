# V-1179 — Codex: чтение usage из rollout без полного разбора файла

## Дефект (воспроизведён по коду и замером)
`app/backend_codex.py`: `_read_rollout_context` / `_read_rollout_totals` читали rollout треда
целиком, `json.loads` на каждую строку, синхронно в общем event loop Orchestra.
- `send()` — первый ход после connect/resume (`_thread_usage_total is None`) → `_runtime_totals()`,
  который сначала вызывал `_runtime_context()` (полный проход, результат выброшен — только ради
  поиска пути), затем второй полный проход.
- `_turn_completed()` без уведомления `thread/tokenUsage/updated` (ошибка/квота/прерывание до
  вызова модели) → `_runtime_totals()` + `_runtime_context()` = три полных прохода.
- Попутно: строка rollout с JSON не-объектом (`[..]`, `"..."`) или `payload`-строкой давала
  `AttributeError` из `_turn_completed` (forward-reader ловил только JSONDecodeError/TypeError);
  одна строка totals с нечисловым полем обнуляла totals всего файла (ValueError → None).

## Исправление (минимальное, контракты сохранены)
- Обратное чтение файла чанками 256 KiB до последней валидной строки `token_count`
  (`_iter_token_count_rows_reversed`); строки без литерала `token_count` не декодируются и не
  парсятся (Codex пишет rollout через serde_json, ASCII-буквы не экранируются — это допущение).
- Правила валидности строки вынесены без изменений в `_rollout_context_from` / `_rollout_totals_from`;
  сигнатуры и результаты `_read_rollout_context` / `_read_rollout_totals` прежние.
- `_locate_rollout()` — поиск/кэш пути; `_runtime_totals()` больше не парсит файл ради контекста.
- Не тронуто: steer/requeue/failed-turn/compact (V-1160, V-1150), квоты, авторизация, сессии.

Первый вариант без префильтра в худшем случае был МЕДЛЕННЕЕ (turn end 400 → 495 ms: split +
json.loads каждой строки) — исправлено префильтром до принятия. Шум между прогонами «до» ~±25%.
Реальные размеры rollout на боевых сессиях не измерялись (запрет на реальные сессии).
