## Демо

Сценарий — `demo-steps.txt` (8 ходов), тема — подготовка программы к включению в реестр российского ПО. Итоговый прогон — `demo/run.log` (`STEPS WITH PROBLEMS: 0`), скриншоты по ходам `demo/step01.png` … `demo/step08.png`, вид владельца после входа — `demo/final/` (`1-вход-чат-оркестратора.png`, `2-чат-1…6.png`, `3-задачи.png`, `4-воркер-analitik.png`).

Что видно на стенде после входа:
1. Оркестратор изучил окружение (список агентов, файлы папки).
2. В трекере три задачи: «Составить перечень требований к ПО для реестра», «Проверить лицензии компонентов программы», «Подготовить сводку для эксперта» (вкладка «Задачи»), плюс задача №4 воркера — её завёл сам движок при спавне.
3. Оркестратор сам записал `требования.md` (пять требований ПП РФ № 1236 — текст задан в сценарии, модель его не выдумывала) и `компоненты.csv`.
4. Заспавнен воркер `analitik` на GigaChat-2-Max, он в своей рабочей копии написал `проверка_лицензий.py`; оркестратор перенёс скрипт и **действительно запустил** его: вывод «FastAPI — MIT — допустима … Итог: допустимых компонентов — 5, требующих проверки — 0» (повторный запуск на стенде дал тот же вывод).
5. `сводка.md` составлена по выводу скрипта; последний ход — краткий отчёт о задачах и агентах.
Файлы демо закоммичены в `/workspace/project` (коммит «Проверка ПО для реестра: …»), чтобы рестарт стенда их не спрятал (см. «Что осталось»).

Сценарий упрощён относительно первой версии, и это честно: GigaChat-2-Max на стенде не справился со свободными формулировками. Попытки `demo-try1` … `demo-try4`, `demo-aborted`, `demo-final-aborted` показывают, что он делал: спавнил воркера там, где просили сделать самому; слал `send_message` самому себе по кругу; просил воркера «подтвердить» вместо ожидания; присылал Python с экранированными кавычками и в кодовом блоке с литеральными `\n`; выдумывал итог проверки, не запустив скрипт. Код починен там, где виноват движок (таблица выше). Со стороны сценария: в сообщениях прямо сказано «сам создай файл», для скрипта заданы `csv.reader` и номера колонок, копирование и запуск скрипта — отдельный ход. Оркестратору стенда сняты `send_message`, `task_get`, `task_update`, `get_worker_logs`, `kill_worker`, `review`: для демо они не нужны, а модель ими промахивалась. Писать уже созданному воркеру в этой конфигурации оркестратор не может; отчёт воркера приходит автоматически.

Английского служебного текста в интерфейсе после правок не осталось. Латиница, которая остаётся, — это содержимое работы: названия лицензий и библиотек, код, пути, вывод `ls`, имена агентов (`orchestrator`, `analitik` — имена ограничены `[a-zA-Z0-9._-]`) и название модели GigaChat-2-Max.

## Что осталось

- **Потеря файлов при рестарте стенда (не чинил, в TODO.md):** при старте миграция раскладки проекта прячет незакоммиченные файлы `/workspace/project` в `git stash` и не возвращает их, если сама падает (`ORCHESTRA_LAYOUT_MISSING` / `ORCHESTRA_LAYOUT_GIT_ERROR`). Так после одного рестарта пропали `bubble.py` и `README.md` (лежат в `stash@{0}` стенда). Демо-файлы поэтому закоммичены.
- Перед записью файла GigaChat иногда сначала читает его — в чате это видно как нейтральное «Файла пока нет».
- Имена агентов (`orchestrator`, воркеры) — латиница: имя агента ограничено `[a-zA-Z0-9._-]`, оно же имя ветки.
- Командный вывод (`ls -la`, `total 20`) и названия инструментов (Bash, Write) остаются как есть — это содержимое работы, не служебный текст.
- GigaChat-2-Max слабо держит инструкции: иногда спавнит воркера там, где просили сделать самому, пишет себе сообщения. Промпт стенда это сдерживает, но не гарантирует.
