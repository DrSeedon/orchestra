Что ещё ограничивает уверенность
  • Окно короткое: 9.74 дня. Это 16 orchestrator и 103 worker sessions, но не сезон поведения.
  • Последний gap каждой сессии right-censored и не входит в primary по условию задачи. 115 idle Claude-сессий на snapshot уже молчали >60m; их включение увеличило бы tail, но исход неизвестен.
  • Gaps внутри одной сессии зависимы. Wilson CI (orch 95.7–99.9%, worker 96.0–99.9%) описывает события, не независимых агентов.
  • Два самых активных оркестратора дают 55/127 long gaps; fleet-wide rate не равен «среднему агенту».
  • False-rate считает стоимость, но не semantic loss от summary. Поэтому policy требует natural break, idle state и сохранённую память.
08

Политика, которую трудно сломать

Экономика говорит «да». Guardrails решают, не превратится ли экономия в потерю незавершённой работы.

Только Claude Max + TTL=60m.
Codex, API-credit mode и forced 5m TTL — другой режим.
Только после завершённого turn и при status=idle.
Не compact во время долгой команды, background job, subagent или running turn.
T=55m для обеих ролей; ctx ≥5%.
Ниже порога cost-only EV близок к нулю, semantic loss доминирует.
Один compact на idle episode.
Lifecycle status не должен re-arm timer. Сбрасывать флаг только новой user/agent activity.
Persist before compact.
Orchestrator пишет session notes/TODO; worker фиксирует gate/report state. Summary не считается долговременной памятью.
Логировать trigger и outcome.
Через 30 дней пересчитать false-rate по реальной feature telemetry, отдельно по role/backend/hour.

Финальный вердикт

Да: preventive compact внедрять. Оптимум production — 55 минут и одинаков для orchestrators/workers. Включать при ctx≥5%, только в idle state и ровно один раз. Данные не подтверждают необходимость role-specific T; они подтверждают необходимость role-agnostic guardrails.
