# 4. 信頼の境界（セキュリティ）

## L4-1. その値はどこから来て、誰が書き換えられるか
- 問い: この値は、どの信頼の境界を越えてここに来たか。その境界で、誰が何を検証したか。社内の API、キュー、保存済みのレコードから来た値も、境界を越えるなら検証したか。
- 兆し: 新しいハンドラで入力の型の検査がない、Webhook やキューのペイロードを信じる、フロントエンドだけの検証、拒否リスト型の検査。
- 十分な場合: 入口にスキーマでの検証があり、新しい項目もそこに入っている。

## L4-2. 他人の ID を渡したら、他人のデータが返らないか（認可）
- 教訓: OWASP Top 10 で、アクセス制御の不備は 2021 年、2025 年とも 1 位（2021 年の「94%」は、何らかのアクセス制御の不備についてテストされた応用の割合で、94% が脆弱だったという意味ではない）。
- 問い: この新しいエンドポイントやクエリは、ID を別の利用者のものに書き換えられたら、他人のデータを返すか。権限の確認は、毎回の要求で、サーバ側で行われているか。
- 兆し: URL やボディの ID でそのまま `find(id)`、利用者やテナントで絞らない新しいクエリ、既存の認可の仕組みの外にある新しいルート、クライアントが送った role や owner_id を信じる。
- 十分な場合: クエリが常に利用者やテナントで絞られる仕組みがあり、新しいコードがそれを通っていることを確かめた。

## L4-3. 要求の中身を、そのままモデルに流し込まない
- 問い: このモデルに後から role や owner_id の列が足されたら、この代入はそれも受け付けてしまうか。
- 兆し: `Model.new(params)`、`update(req.body)`、`Object.assign(user, body)`。モデルに権限や所有者の列を足す差分。
- 十分な場合: 必要な項目だけを持つ専用の入力の型で受け、明示的に詰め替えている。

## L4-4. 利用者の値が、SQL やコマンドの構文になる経路はないか
- 問い: この文字列に、利用者の値が構文の一部として入る経路はあるか。
- 兆し: 文字列の連結やテンプレートで作るクエリやシェルのコマンド、ORDER BY に利用者の値、自前のエスケープ。
- 十分な場合: 連結しているのが、定数やコード内の候補から選んだ値だけだと追って確かめた。
- 補足: 入力の検証だけでは注入は防げない。値のバインドと、出力時のエスケープを使う。

## L4-5. 利用者が指定した URL をサーバが取りに行くと、内部への入口になる（SSRF）
- 問い: この URL に `http://169.254.169.254/` や `http://localhost:6379/` を入れたら何が返るか。
- 兆し: 利用者の入力を fetch に渡す、リダイレクトの追従が既定のまま、ホスト名の文字列だけを検査する。
- 十分な場合: 宛先が設定で固定され、利用者は URL のどこも変えられない。

## L4-6. 秘密や内部の情報を、ログや応答に出さない
- 問い: このログ行や失敗の応答に、トークン、パスワード、個人情報、SQL、スタックが入らないか。要求や利用者のオブジェクトを丸ごと出していないか。
- 兆し: `log(request)`、構造体を丸ごと出力、`err.message` や `err.stack` を応答に返す。
- 十分な場合: ロガーの側でマスクする設定があり、その場所を見せられる。利用者が直せるエラー（検証に失敗した項目名）は返すべき。

## L4-7. 利用者の入力に当てる正規表現は、CPU を食い尽くしうる
- 問い: この正規表現に、長くて「あと少しで一致する」文字列を入れたら、時間は文字数に比例するか、爆発するか。
- 兆し: 入れ子の量指定子、`.*` の連続、入力の長さの上限なし、利用者が正規表現を指定できる。
- 十分な場合: 線形時間のエンジン（Go の regexp など。Go の regexp は線形時間を文書で保証している）。入力が短く固定。
- 実例: Cloudflare の 2019 年の障害の原因は、この種の正規表現だった。

## L4-8. 新しい依存は、自分たちと同じ権限で動く他人のコード
- 問い: この依存は誰が保守し、インストール時に何を実行し、版は固定されているか。小さな機能のために大きな依存を入れていないか。既にあるもので代わりが利かないか。
- 兆し: 新しいパッケージ、ロックファイルの大きな変化、`^` や `latest` の版指定、`curl | sh`。
- 十分な場合: 組織が既に採用している、広く使われた依存で、ロックファイルで固定されている。

## L4-9. 誰から届くか（公開の範囲）
- 問い: この口（ポート、エンドポイント、管理用の機能、ファイル）には、誰が届くか。内部向けのつもりのものが、外から届かないか。
- 兆し: listen するアドレス（`0.0.0.0` やホストの指定なし）、CORS や公開範囲の設定、新しい管理用のルート、認証の仕組みの外にあるルート。
- 十分な場合: 届く範囲を決めている場所（設定、プロキシ、認証の適用）を見せられる。
