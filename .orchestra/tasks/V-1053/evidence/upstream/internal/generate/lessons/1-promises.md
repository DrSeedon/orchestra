# 1. 約束を守っているか（正しさ）

## L1-1. 変更前のコードが守っていた約束を、変更も守っているか
- 問い: 状態や値の意味、不変条件、失敗の扱い、既存のテストが守る振る舞いは、変更後も成り立つか。
- 兆し: 状態の追加や意味の変更、分岐の条件の変更、既存のテストの期待値の変更。
- 十分な場合: 約束を確かめた場所と結果を見せられる。

## L1-2. 約束していない振る舞いにも、誰かが頼っている（Hyrum の法則）
- 問い: 外から見える振る舞い（並び順、エラーの文言やコード、null と空の違い、既定値、時間）が変わっていないか。それに頼る呼び出し元はいないか。
- 兆し: ORDER BY の削除や追加、map への置き換えや並列化、エラーの文言の変更、null と空配列の入れ替え。
- 十分な場合: 呼び出し元がすべて同じリポジトリにあり、grep で全部を確かめた。

## L1-3. 消されたものは、何を守っていたか（Chesterton の柵）
- 問い: 消された行、緩められた条件、消されたテストは、もともと何を守っていたか。消したあと、それを守る別の仕組みはあるか。
- 兆し: 消された条件分岐、再試行、null の確認、ソート、ロック、sleep。「不要なコードを削除」というコミットメッセージ。
- 十分な場合: 守っていた理由が、もう成り立たないこと（呼び出し元がない、型で表せなくなった）を確かめた。
- 補足: 同じ教えは逆向きにも使う。残っている一見冗長なコードにも、理由があることが多い。Spolsky は、古いコードの奇妙な行はたいていバグ修正だと書く。

## L1-4. 手順で守っている約束を、型や制約で守れないか
- 問い: 「確かめてから書く」「この順で呼ぶ」で守っている約束を、型、DB の制約、データの持ち方で守れないか。意味のない組み合わせ（完了なのに完了日時が空）を作れてしまわないか。
- 兆し: 互いに関係する bool の並び、状態と nullable な列の組み合わせ、同じ確認が複数の層にある、`isValid(x)` のあと x を緩い型のまま渡す。「まだない」を本物に見える値（0、空文字、`new Date(0)`、`-1`）で表す。
- ツアーへ: 守れるなら、選ばなかった設計として比べ、何を得て何を払うかを書く。
- 十分な場合: 言語やスキーマで表すのが重すぎる。確認が 1 か所でしか使われない。

## L1-5. 「確かめてから書く」の隙間に、別の要求が入らないか
- 問い: 確認と書き込みの間に、同じ要求がもう 1 本来たら、両方とも通るか。
- 兆し: `if !exists { insert }`、一意索引のない `find_or_create`、残高をアプリで計算して保存、ロックなしの SELECT → UPDATE。
- 十分な場合: どこで直列化されているか（1 本のワーカー、FOR UPDATE、一意制約、条件付き更新）を見せられる。

## L1-6. 宣言しただけで効いていると思い込まない（接続や設定で決まる振る舞い）
- 問い: 書いたコードや宣言が実際に効くかを、接続や初期化の処理、設定、環境変数、ライブラリの既定値が決めていないか。
- 兆し: 外部キー、トランザクション、タイムアウト、キャッシュ、ログの設定に頼る変更。
- 十分な場合: それを有効にしている（または無効にしている）場所を見せられる。

## L1-7. たまたま動いているのか、保証されて動いているのか
- 問い: これが動くのは仕様の保証か、いまはたまたまそうなっているだけか（並び順、タイミング、ライブラリの内部の振る舞い）。
- 兆し: map の反復順への依存、sleep での待ち合わせ、ドキュメントにない振る舞いへの依存。

## L1-8. 現実のデータは、思い込みより複雑（時刻、お金、文字、名前）
- 問い: この時刻は「起きた瞬間」か「未来の現地の予定」か。日付をどのタイムゾーンで区切るか。金額は何の型で持ち、どこで丸めるか。長さの上限は文字数かバイト数か。名前に形の決まりを置いていないか。経過時間を戻りうる時計で測っていないか。
- 兆し: UTC の時刻をそのまま利用者向けの出力（画面、CSV、メール）に出す、日付の区切りを `toISOString().slice(0, 10)` などで UTC のまま切る、タイムゾーンなしの保存、`86400` 秒を 1 日として足す、金額を float で計算、`VARCHAR(n)` の新設、名前の正規表現、壁時計での経過時間。
- 十分な場合: 単一の国のサービスで、その簡略化を明記している。表示だけの概算。機械が作る識別子。
- 実例: Cloudflare の 2017 年のうるう秒の障害（時刻が戻り、負の経過時間で panic）。
