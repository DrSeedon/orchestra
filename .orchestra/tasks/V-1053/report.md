## 2. Как это работает по коду

### Программа и вызов моделей

Это самостоятельная **Go TUI**, не skill-файл и не команда MCP. `go.mod:1–12` требует Go 1.27.2; интерфейс — Bubble Tea v2, подсветка — Chroma, схемы SQLite — modernc.org/sqlite. Входная точка `cmd/tour/main.go:88–215`: настройка языка/LLM, выбор ветки, одного коммита, диапазона или сохранённого JSON. Один commit превращается в `<commit>^` → `<commit>` (`:218–244`); диапазон сравнивается от merge-base, что не всегда совпадает с прямым двухточечным diff.

`internal/generate/workspace.go:31–107` экспортирует в cache-каталог `base/` и `head/` через `git archive`, добавляет `change.diff`, `commits.txt`, встроенные `lessons/`. Это снимки двух деревьев, включая неизменённые файлы, а не только текст diff и не вся история Git. Для WORKTREE отдельно копируются tracked и неигнорируемые untracked файлы. Симлинки из архива не экспортируются. После генерации export удаляется; готовый тур хранится в cache.

Выбранная CLI запускается через Go `os/exec` в export-каталоге. Поддержаны Claude Code, Codex, Gemini, OpenCode v2, Copilot; рассматриваемые в задаче два адаптера:

* **Claude**, `internal/generate/claude.go:45–54,71–138`: `claude -p --restricted --strict-mcp-config --tools Read,Grep,Glob --permission-mode dontAsk --permission-prompts none --no-session-persistence --output-format stream-json --verbose <prompt>`. Промпт передаётся аргументом. Из JSON stream берутся чтения/поиск, финальный result, `total_cost_usd` и ошибки.
* **Codex**, `internal/generate/codex.go:51–74,211–259`: `codex exec --json --color never --ephemeral --ignore-user-config --ignore-rules --skip-git-repo-check -C <export> ... -`. Промпт идёт через stdin. Задаётся профиль `diff_tour_read`: чтение workspace, минимальных системных путей и исполняемого пакета Codex; writable-путей нет. `approval_policy="never"`, `web_search="disabled"`, `history.persistence="none"`; отключены apps/plugins, multi_agent, memories, image generation, browser/computer tools и ряд других features. Сетевой доступ команд sandbox выключен; соединение самой CLI с провайдером, разумеется, нужно. Комментарий указывает проверку флагов на codex-cli 0.160.1 и Linux; macOS здесь не проверен. Неизвестный wrapper может не работать в sandbox, и адаптер отказывает при `bwrap: execvp`.

Модель напрямую в этих адаптерах не выбирается: используются настройки/default соответствующей CLI. Сам diff-tour не имеет своего inference API, сервера или телеметрии. Ограничения чтения/записи задаются флагами внешней CLI, а их исполнение в этой среде я не проверял. Read-only export не означает запрета отправки исходников выбранному провайдеру.

### Настоящие промпты и дословные выдержки

`internal/generate/generate.go:67–90` собирает **один основной запрос** в порядке `common.md` → строка с base/head → `planC.md` → `format.md` → `output-C.md`. Внутри одного ответа требуются предварительное исследование, затем JSON. Промпты и lessons преимущественно японские; подстановка для английского вывода дословно: `Write all text in English. Use short, plain sentences.` (`generate.go:59–64`). Это не готовый английский модуль для Orchestra.

Ниже оригинальный текст, без исправлений; русский текст рядом — мой перевод смысла. Полные оригиналы лежат в `evidence/upstream/internal/generate/prompts/` и `lessons/` с MIT notice.

**Не оправдывать AI-код; требовать основания для успокоения** — `internal/generate/prompts/common.md:28–30`:

> - **AI が書いたコードを正当化するだけにしない**。シニアなら手が止まる場所があれば、はっきり指摘する。見つからなければ「確かめた場所とその結果」を見せる。問題を作り出さない。
> - 見つけたことは、重さを付けて全部挙げる。手順を厚く使うのは、一番効く数個にする。残りは落とさず、短く挙げる。
> - 「十分」「気にしなくてよい」と言うときは、このリポジトリのどこで確かめたかを示す。示せないなら問いとして出す。

Смысл: не фабриковать проблемы, но и не оправдывать автоматически; перечислить найденное с весом; «достаточно/можно не беспокоиться» подкрепить местом проверки, иначе оставить вопросом.

**Читать прежние обещания и неизменённые зависимости** — `internal/generate/prompts/planC.md:7`:

> 3. `base/` を読み、**変更前のコードが守っている約束**を書き出す。変更で触られるファイルだけでなく、それと関わる変更していないファイル（呼び出し元、バッチ、設定、接続や初期化の処理、テスト、ドキュメント、データの定義）も読む。

Смысл: изучить базовую версию и её контракты, включая callers, batch, конфигурацию, инициализацию, тесты, документацию и определения данных, даже если они не менялись.

**Вопрос до ответа** — `internal/generate/prompts/common.md:32–33`:

> - 問いの手順（question: true）を章に 1 回程度入れる。問いだけを出し、答えは次の手順に置く。ジュニアが自信を持って答えそうで実は違う問いを選ぶ。
> - 問いの答えを、問いより前の手順で言わない（タイトルや図で先に答えを見せない）。

Смысл: примерно один вопрос на главу; ответ только на следующем шаге, без раскрытия в предыдущем заголовке/диаграмме. Это обучающая пауза при перелистывании, не запрос разрешения на merge и не обязательный ввод ответа человеком.

**Почему → карта → механизм → риски → вывод** — `internal/generate/prompts/common.md:49–53`:

> 2. 何のための変更か（誰が何に困らなくなるか。ユーザーから見た振る舞い。コードはなるべく見せない。ここで立てた仮説を、以降の章で確かめる）
> 3. 全体の地図（処理の流れ。変更していない部分も含む。この差分のどこに時間を使い、どこは短く済ませるかを宣言する）
> 4. 仕組み（変更の中身と、その設計の理由。良くできているところも）
> 5. シニアならここで手が止まる（指摘と、その重さ。読者が気にしそうだが気にしなくてよいところと、その根拠）
> 6. まとめ（まず、この変更は全体としてコードベースを良くしたか。次に、シニアならこの変更にどうコメントするかを、重さの札（必須 / 提案 / Nit / 問い / 良い点）を付けて 2〜4 個。最後に、追体験したことの箇条書き）

**Что возвращает CLI** — `internal/generate/prompts/output-C.md:4–6`:

> 1. 1 行目に `=== 下調べ ===` と書き、そのあとに段階 1 の下調べを日本語の箇条書きで書く（簡潔でよい）。
> 2. 下調べのあとに、1 行だけの `=== ツアー JSON ===` を書く。
> 3. そのあとに、ツアーの JSON だけを書く。```json などの囲みは付けない。JSON のあとには何も書かない。

То есть предварительные заметки на японском и JSON разделяются маркером; это не Markdown-отчёт. `extractJSON` отбрасывает заметки при сохранении тура. Сборка и файлы проверяются по [generate.go](https://github.com/init-co-jp/diff-tour/blob/eeaf897ce18e37018540d6b425accbed4945389c/internal/generate/generate.go), цитаты — по [папке prompts](https://github.com/init-co-jp/diff-tour/tree/eeaf897ce18e37018540d6b425accbed4945389c/internal/generate/prompts).

`planC.md:13–16` требует пройти все восемь областей lessons: старые контракты, отказы, эксплуатация/выкатка, границы доверия, масштаб, дальнейшие изменения, доказательная сила тестов, типичные ошибки AI-кода. Отдельные lessons раскрывают повторный вызов, конкурентность, старые данные и rollback. Наличие такой инструкции не доказывает её выполнение моделью.

Для исправлений используется `fix.md` + список ошибок + `format.md` + `fix-output.md`: исправлять только названные ошибки, не менять содержание/порядок. Максимум два repair-запроса. Если первый ответ вообще без JSON, допускается ещё одна полная генерация, поэтому верхняя граница обычного пути — четыре вызова CLI, а не один (`generate.go:155–215`).

Для `?` берутся `ask.md`, оглавление тура, текущий шаг, вопрос, base/head, `format.md`, `ask-output.md`; весь тур дополнительно записывается в `tour.json` в новом export. Ответ становится следующими шагами и тоже проходит repair-путь (`internal/generate/ask.go:25–103`). Это отдельный модельный расход.

### «Каждая строка из git»: точная гарантия и её граница

В `internal/tour/tour.go:30–40,96–107` блок настоящего кода содержит **путь, сторону base/head, номера строк**, но не текст кода; diff содержит путь и номера hunks. `internal/render/blocks.go:52–97,100–169` получает код через `Repo.Show` и `Repo.Diff`, а `internal/git/git.go:66–87` вызывает `git show <ref>:<file>` / `git diff --no-ext-diff ...`. Таким образом LLM выбирает, что показать; текст реального code/diff-блока извлекает программа. `snippet` с модельным примером отдельно получает видимую метку Example (`blocks.go:172–177`). Для WORKTREE читаются текущие допустимые файлы, включая untracked; универсальная формулировка «всегда из commit» для этого режима неверна.

После JSON decode с запретом неизвестных полей `generate.go:108–126` подменяет base/head на запрошенные значения и вызывает проверки формата и ссылок. `internal/render/check.go:12–78` проверяет существование файлов, границы строк, hunks, роли изменённых файлов и доступность схем. **Не проверяются истинность объяснений, полнота найденных дефектов, обоснованность “безопасно”, либо то, что тест реально запускался.** `basis=fact/inferred/opinion` — метки, назначенные самой моделью. Валидатор разрешает даже пустой basis (`tour.go:265–271`).

JSON version 1 содержит `title`, `base`, `head`, главы и шаги, `question`, `asks`, blocks: абзацы, цитаты, списки, таблицы, code/diff, examples, flow, timeline, file map, target, schema/rows. Данные code/diff/target/files извлекаются из Git; текст, подписи и диаграммы остаются модельными. SQLite schema строится применением SQL-миграций к in-memory SQLite, не исполнением Python-миграций Orchestra.

Просмотр — TUI со стрелками, Enter/Space, `q`; `?` задаёт новый вопрос, `o` открывает editor. `DropRevealingAsks` механически удаляет подсказки с вопроса и предыдущего шага, но не распознаёт утечку ответа в прозе. `tour saved.json --dump --plain` печатает все шаги без TUI; это воспроизведение готового тура, не документированный headless-генератор (`cmd/tour/main.go:139–181`). Cache key включает resolved base/head, язык, PromptVersion v6 и имя backend, но не конкретную модель (`generate.go:225–232`). Готовый JSON сохраняется в cache, обычно `~/.cache/tour/tours/`.

Установщик `install.sh:45–66` скачивает release-архив и `checksums.txt`, сравнивает SHA-256 **до** распаковки/установки. Это проверка совпадения с манифестом того же release, а не независимая подпись издателя. Прочитанный скрипт выполнен из файла, без `curl | sh`.

## 4. Как Orchestra принимает работу сейчас

Канонический decision-tree — `.orchestra/pipelines/default/prompts/modules/orchestration.md:85–100`: исследование останавливается на findings; до merge оркестратор проверяет результат и настоящий diff; модельное review заморожено, подменный reviewer тоже запрещён; основание — diff, тесты, собственная mutation-проверка. По каждому заданию нужен `worker_wip`, затем одна приёмка `merge_worker(expected_head=..., acceptance_note=..., task_outcome=...)`; при смене HEAD нужно читать обновление. `:295` запрещает принимать красивый рассказ без конкретного артефакта.

`app/mcp_stdio.py:3111–3168` выводит WIP, точный worker_head в review summary, uncommitted/unmerged, changed files и статистику; review помечен advisory, не permit. Список файлов сокращается после первых десяти, это не карта всех зависимостей. Docstring `merge_worker` (`:2744–2756`) описывает полный SHA и содержательную note не короче 15 символов; сам серверный валидатор приёмки в выданную копию не входит, поэтому его runtime-исполнение не подтверждаю. `app/workspace.py:1575–1592` принимает pinned worker/target heads и note; `:1649–1654` проверяет несовпадение worker HEAD. `_build_squash_message` (`:1288–1316`) берёт **только первую строку note** как заголовок squash: нельзя рассчитывать, что весь подробный разбор попадёт в текст Git-коммита. Подробности уместны в существующем task report.

Это существенное пересечение с diff-tour, не пустое место.

## 6. Контрсвидетельства и риски

1. **Убедительный рассказ не равен проверке.** Истинность `fact` и “fine” не валидируется; даже существующие строки могут не доказывать сказанное. Read-only CLI читает тесты, но не исполняет их в Claude-режиме. Поэтому объяснение «тест подтверждает» нельзя переносить в проверку оркестратора без результата теста и mutation evidence. Заморозка после V-918 остаётся в силе; сам V-918 в этой копии не доступен, числа про пропуски взяты из постановки, не перепроверены.

2. **Собственные опубликованные неудачи авторов.** `experiments/generate/README.md:400–408` сообщает, что ранний v2 в обоих соответствующих турах хвалил тесты, неспособные упасть; v3 в обоих order-export турах отнёс проблему масштаба к «можно не беспокоиться»; у всех версий остались пропуски. Это история настройки, не доказательство, что нынешний v6 воспроизводит тот же промах. Но она прямо опровергает предположение, что структура “senior tour” сама гарантирует полноту/верное успокоение. `:443–445` описывает отсутствие выигрыша средних оценок от lessons на небольшом наборе при большей стоимости.

3. **Ещё один reviewer не решил проблему даже в upstream-опытах.** `experiments/generate/README.md:447–461`: для трёх методов брали два новых сюжета, по две генерации на сюжет/метод, всего двенадцать туров; два оценщика видели скрытую версию. Дополнительный reviewer v5r не улучшил оценки проблемного изменения, ухудшил оценки хорошего и не попал в продукт. Это малая искусственная выборка авторов с субъективными оценками, не независимый benchmark и не оценка Orchestra. Это дополнительный аргумент не восстанавливать модельное review под новым названием. [Первичные материалы опытов](https://github.com/init-co-jp/diff-tour/blob/eeaf897ce18e37018540d6b425accbed4945389c/experiments/generate/README.md).

4. **Время и токены.** `README.md:30–33` говорит о времени **генерации**, не длительности чтения человеком. Основной prompt просит примерно 12–18 шагов; авторы отмечают затянутость и раскрытие ответа заголовком (`experiments/generate/README.md:461`). Обязательное чтение всех lessons, повторные поколения/repairs и каждый `?` расходуют подписочную квоту. Моего замера токенов нет; токены на один тур и доступный остаток квоты неизвестны. Нельзя получить токены или стоимость подписки пересчётом долларов из FAQ.

| Публикация авторов о стоимости | Что именно измерено/заявлено | Что нельзя из этого заключать |
|---|---|---|
| FAQ: $1.00–1.50 API-equivalent | пример Claude-тура изменения около 250 строк, без полноценного описания выборки в FAQ | это не счёт владельцу и не универсальная квота/стоимость любого тура |
| Опыт v5: $1.23–1.51 на тур | четыре генерации, два искусственных сюжета, `experiments/generate/README.md:451–457` | это не замер Orchestra, Codex или реальной подписочной цены |
| Опыт v5r: $2.18–2.35 на тур | четыре генерации с дополнительным reviewer на тех же двух сюжетах | это не основание запускать reviewer; авторы отказались от варианта |

5. **Подлинность кода уже, чем подлинность тура.** Модель пишет подписи, `marks`, flow/timeline и примеры данных. Строки `git show` могут быть настоящими при неверном объяснении. Branch names сохраняются как запрошенные refs (`generate.go:120–121,274–286`), а не обязательно как неизменяемые SHA; открытие старого сохранённого JSON после движения ветки может совместить старый рассказ с новым кодом. Это вывод из кода, отдельно не воспроизведённый. Для проверяемого артефакта предпочтительны явные commit SHA. Cache key также не учитывает смену default-модели внутри одного backend.

6. **Export и секреты.** `.gitignore` не исключает уже tracked файл из `git archive`. Обещание README «ignored .env никогда не экспортируется» нельзя считать универсальным, если секрет уже попал в Git. В WORKTREE попадут также неигнорируемые untracked файлы; публичного shape-based secret scanner перед отправкой в этих export-функциях нет. На Orchestra data/ не должна быть в Git; из этого не следует, что любая история безопасна для стороннего провайдера. Это ограничение модели экспорта, не обнаруженная утечка в нашем репозитории. Секреты не искал и не читал.

7. **Границы изоляции и интеграции.** Одна CLI-версия и Linux-проверки автора не подтверждают совместимость с shims hub, будущими флагами и системными настройками `/etc/codex`. Запуск отдельного `tour` из Orchestra также может пройти мимо обычного учёта quota/model-routing. Из этого не делаю вывода о фактическом обходе здесь: модель не запускалась. Для read-only объяснения не требуется давать право merge или записывать код.

8. **Неподходящий адресат.** Исходный `common.md:4–6` адресован junior developer, который хочет сам понимать код. Владелец Orchestra не читает diff и не открывает отчёт. TUI и кодовые маршруты могут быть полезны разработчику, но не доказано, что они помогают владельцу понять итог быстрее короткого связного пересказа. Русский `--lang ru` сейчас отвергается. Нового обязательного обучения/ритуала приёмки задача не оправдывает.

## 7. Артефакты, проверки и что осталось

* `evidence/upstream/`: 40 неизменённых файлов первоисточника, включая все runtime prompts и lessons, ключевой Go-код, README, эксперименты, installer и MIT license. `source-files.json` содержит SHA-256 каждого файла; `source-pin.txt`, `hashes.json` фиксируют источник/архив/binary. Воспроизводимый scratch с остальными upstream-файлами и binary удалён после проверки; бинарники в результат не включены.
* `evidence/repository.json`, `latest-commit.json`, `commits-headers.txt`, `issues.json`, `latest-release.json`, `release-tag*.json`, `checksums.txt`: первичные публичные metadata и release manifest.
* `evidence/*.output.txt` и `*.command.json`: дословные результаты установки и запуска/отказов. Программа тур не сгенерировала; файла с выдуманным «готовым туром» нет.
* `run_experiment.py`: исследовательский harness установки и offline startup checks; не код интеграции. Python был нужен для сохранения сырых stdout/stderr и metadata. Инструменты проекта `uv`/`go` недоступны, обязательные suites не запускались.
* `evidence/artifact-integrity.output.txt`: проверены хеши всех 40 сохранённых исходников, точное совпадение пяти блоков цитат с оригиналами и десять пар command/output. Финальная версия harness выполнена заново с удалённым scratch: скачивание, распаковка с проверкой source SHA-256 и установка прошли; archive и binary совпали с исходными хешами. `harness-replay.output.txt` сохраняет итоговые коды каждой команды.
* `evidence/secret-shape-scan.output.txt`: проверены 75 task-local текстовых файлов по шести формам секретов, совпадений нет. Это ограниченная проверка формы, не гарантия отсутствия любого возможного секрета. Production-файлы, credentials и данные вне task directory не сканировались. Git diff недоступен без `.git`; все записи результата выполнялись только по путям задачи.
