## Observed boundaries and leaf work

The default manifest declares full-cycle **kind worker**, with child roles `[worker, full-cycle, reducer]`; worker has no children. The full-cycle description covers research, planning, implementation and verification. Its native role body says to implement directly by default, delegate bounded independent work, and respect research-only/approval boundaries (`.orchestra/pipelines/default/pipeline.yaml:125`; `prompts/roles/full-cycle.md:4`, `:16`, `:23`, `:51`, relative to that pipeline). The hub path replaces the whole native prefix with the generic hub worker contract; it does not reproduce those full-cycle modules. Stored role still participates in effort selection and broker identity (`app/backend_hub.py:358`; `app/session.py:916`).

Research and implementation **leaf execution remain available paths**: task text reaches `_prompt`, ordinary files can be edited/tested in the copy, `_sync_back` returns files to the worker branch, and parent reporting exists. That fact does not demonstrate task quality, completeness of supplied context, or preservation of the native full-cycle prompt. The offline trimmed-prompt/import test exercised a sample `calc.py` change and excluded the outbox from imported files (`tests/test_hub_workspace.py:1442`). No management operation was needed for that leaf result.

Mechanisms currently enforce the outbox allowlist, parent-only outbox destination, scoped identity, proof-bound acceptance, full-cycle child/branch/scope predicate, model gates/reasons/capacity, and archive boundaries. **Task scope, research-only versus implementation, “delegate only when worthwhile,” and ordinary-worker “never use spawn_worker” are prose at these inspected seams.** Ordinary worker spawn is separately refused by manifest validation, but native tools remain registered in full access unless explicitly disabled. Native same-project messaging is broader than hub parent-only messaging; the prose “report only to your own orchestrator” is not a parent-only predicate in native keyed ingress (`app/routes/sessions.py:1186`).

`RuntimeCapabilities.subagents=False` is present for hub and serialized in `/api/models` (`app/runtime_registry.py:416`; `app/routes/system.py:525`). The traced create, model-change, role-catalog and hub-preamble paths do not use it to reject management roles or constrain assignments. It is not an advertised four-operation Orchestra-management contract. This statement comes from those callable paths, not a claim of absence based on an empty search.

For nested acceptance, the exact code predicate is proof-valid full-cycle parent, target.parent_id matching parent id, different target id, equal scope, nonempty parent branch outside `{main, master, parent.base_branch}`, and merge target equal to parent branch (`app/mcp_proof.py:78`). The ordinary authenticated orchestrator/owner path returns earlier. That early path does not impose this full-cycle predicate; it is not evidence that every orchestrator action is universally parent/project-bound. Task acceptance-command project checks and message scope checks are distinct contracts.

Outbox timing matters: it is consumed after the remote turn, after file application and **before commit_sync** (`app/backend_hub.py:776`). A parent message can therefore precede the final imported commit; its receipt is not proof of a successful import/merge. Clear-before-execute can lose an entry on later execution failure; it prevents replay of the cleared file, not all delivery ambiguity. Unknown-operation rows do not queue an automatic management fallback. A parent can still receive ordinary final text through worker auto-report when its guards permit it. No new fallback is implemented here.
