# #453 — гейт, не пускающий секрет в git

Владелец списка форм: `scripts/secret_scan.py`. Хуки — тонкие шимы без собственных шаблонов:
`scripts/hooks/{pre-commit,commit-msg,pre-push}`. Установка: `scripts/install_git_hooks.py`.
Оракул: `tests/test_secret_commit_gate.py` (28 тестов).

## 1. Где стоит гейт: ТРИ рубежа, и ни один не «закрывает полностью»

| | ловит | не ловит |
|---|---|---|
| `pre-commit` | момент, когда значение ВХОДИТ в историю; после отказа чинить нечего — коммита нет | `--no-verify`, `git am`, `git rebase`, чужой чекаут без установленных хуков |
| `commit-msg` | секрет в СООБЩЕНИИ коммита — `pre-commit` его не видит вовсе, git отдаёт текст только этому хуку | то же `--no-verify` |
| `pre-push` | публикацию: всё, что легло в историю мимо первых двух, по КАЖДОМУ публикуемому коммиту | к моменту срабатывания секрет УЖЕ в локальной истории — чинится только переписыванием ветки |

От чего НЕ защищает ни один, честно:

- **`--no-verify` снимает оба.** Клиентский хук — это соглашение, а не запрет; технически
  недостижимо запретить его на своей машине. Оракул это воспроизводит явно
  (`test_pre_push_catches_what_no_verify_committed`: `commit --no-verify` проходит, `push`
  отбивается) — то есть второй рубеж и заведён ровно под обход первого.
- **Чужой клон без установки.** Хуки не версионируются, они не приезжают с `git clone`
  (см. пункт 2). Единственный рубеж, который нельзя обойти локально, — серверный
  `pre-receive` на GitHub, а его на бесплатном плане нет. Здесь его нет и не будет.
- **Секрет, собранный из кусков** (`"AIza" + key_part`), в тексте файла не существует —
  сканер работает по литеральному тексту блоба и такое не увидит.
- **История.** Гейт закрывает будущее. Прошлое (единственная фикстура
  `sk-or-v1-…` в `.orchestra/tasks/315/`) не трогалось по постановке.

## 2. Как гейт попадает к воркерам: одной установкой, факт проверен

**Linked worktree берёт хуки из ОБЩЕГО git dir.** Проверено прямым экспериментом на git 2.53.0
(скретч-репозиторий вне рабочего дерева): хук положен только в `main-co/.git/hooks/pre-commit`,
коммит делался в `../wt`; хук отработал:

```
HOOK-RAN-FROM-COMMON-DIR pwd=/mnt/data/tmp/hooktest-592808/wt \
  GIT_DIR=/mnt/data/tmp/hooktest-592808/main-co/.git/worktrees/wt
COMMIT_RC=1
```

Каталога `hooks/` в `.git/worktrees/wt/` нет вовсе (`ls` даёт `HEAD ORIG_HEAD commondir gitdir
index logs refs`). Это же плечо закреплено тестом
`test_hook_from_common_dir_covers_linked_worktree`.

Отсюда прямой ответ: **одна установка защищает и главный чекаут, и ВСЕ рабочие деревья
воркеров — существующие и будущие.** `git worktree list` в этом репозитории даёт 22 записи,
по всем контурам их 37; отдельная установка на каждое не нужна.

Чего установка НЕ покрывает: другой КЛОН репозитория (VPS, ноутбук, чужая копия) — там свой
common dir и свою установку надо повторить. Поэтому команда добавлена в `CONTRIBUTING.md`
рядом с `uv sync`. `core.hooksPath` в репозитории не задан (`git config core.hooksPath` → rc=1),
конкурирующего владельца хуков нет.

Хук зовёт сканер из ГЛАВНОГО чекаута (`dirname $(git rev-parse --path-format=absolute
--git-common-dir)`), а не из своего дерева: ветка воркера может быть старше гейта.
`--show-toplevel` для этого негоден — внутри worktree он возвращает сам worktree (#419/#420).

## 3. Как отличить секрет от его ОПИСАНИЯ: по ПОЛЕЗНОЙ НАГРУЗКЕ, а не по префиксу

Признак: совпадением считается только **нагрузка провайдерского формата** — точная длина и
точный алфавит после префикса. Упоминание пишет форму (`y0_`, `gh[pousr]_`, `Bearer <25+>`)
или регулярку (`y0_[A-Za-z0-9_-]+`), то есть либо не имеет нагрузки вовсе, либо после
префикса стоит символ вне алфавита (`[`, `)`, `<`). Второй слой — слова-заглушки внутри
нагрузки (`secret`, `example`, `test`, `xxxx`, …) и вырожденный алфавит (< 8 различных
символов).

**Мера того, зачем это нужно.** Наивный гейт «греп по форме», как он записан прозой в
`CLAUDE.md`, на 17 520 отслеживаемых файлах даёт **138 срабатываний в 63 файлах**, и ни одно
из них не секрет (топ: `.orchestra/tasks/106/q5/results/primary.jsonl` — 13,
`.orchestra/tasks/kb-extract/report.html` — 8, `CLAUDE.md` — 3). Такой гейт выключили бы на
второй день. Гейт с проверкой нагрузки на тех же 17 520 файлах даёт **0**.

Отбор по ПУТИ (пропускать `tests/`, `.orchestra/tasks/`) отвергнут сознательно: единственная
реальная утечка проекта — `docs/tasks/sol-efficiency/calls_strict.tsv`, 12.08.2026, два боевых
OAuth-токена в публичном `origin` — лежала ровно в каталоге задач. Путевой аллоулист пропустил
бы её.

Какой слой что несёт (замер, а не рассуждение): с выключенным фильтром заглушек полный обход
дерева даёт 3 находки в 2 файлах — `.orchestra/tasks/315/.../t5_recovery_records.json:32` и
`tests/test_runtime_handoff_v2.py:116,133`, все три — `Bearer` с 38–47-символьной нагрузкой.
То есть формат несёт всё, кроме `Bearer`: у него формата нет по определению (любая строка
25+), и там работает только слой заглушек.

## Формы (9 правил, `scripts/secret_scan.py:RULES`)

`y0_` (40+ base64url) · `sk-or-v1-` (ровно 64 hex) · `sk-ant-(api|oat)NN-` (80+) · `ya29.` (50+) ·
`gh[pousr]_` (ровно 36 base62) · `github_pat_` (70+) · `AIza` (ровно 35) · `Bearer` (25+) ·
`BEGIN … PRIVATE KEY` + тело base64 40+ символов, считая экранированные `\n`.

Заголовок PEM без тела — упоминание: именно так он написан в `tests/test_secret_mask.py:157`
и `app/runtime_history.py:183`.

Слой заглушек применяется ТОЛЬКО к `bearer` и телу PEM — двум правилам без провайдерского
формата. К остальным он не применяется намеренно (правка по ревью): `ghp_` + 36 base62,
внутри которых случайно оказалось слово `test`, — валидный токен, и глушить его словом
внутри нагрузки нельзя.

## Ревью

Маршрут: Luna (`gpt-5.6-luna`), 1 состоявшийся раунд + 2 несостоявшиеся попытки (обе убиты
рестартом сервиса, `turn.completed` в jsonl отсутствует, находок не было). Вердикт раунда —
**❌ Incorrect, 6 blocking + 2 suggestion**. Артефакт: `.orchestra/tasks/453/codex-review-impl.md`.

Сам артефакт оказался первым посторонним срабатыванием гейта: ревьюер выписал примеры
ПОЛНОЙ провайдерской формы, и `pre-commit` их отбил. Значения вырезаны, текст находок цел —
отличить выдуманный ключ правильной формы от настоящего гейт не умеет и не должен.

Каждое blocking проверено запуском до принятия — четыре формы прогнаны через `scan_text`
напрямую, и все четыре подтвердились как обход:

| находка | проверка | решение |
|---|---|---|
| PEM в JSON с экранированным `\n` (ключ Google service-account) | `scan_text` → `ПРОПУЩЕН` | ACK, `_SEP` теперь считает `\\n` разделителем |
| `ghp_` + 36 base62, содержащих `test`, глушится слоем заглушек | `scan_text` → `ПРОПУЩЕН` | ACK, слой заглушек снят со всех форматных правил |
| формы `github_pat_` нет в списке | `scan_text` → `ПРОПУЩЕН` | ACK, правило добавлено к тому же владельцу |
| `pre-push` смотрит итоговый дифф диапазона → секрет в СООБЩЕНИИ коммита и файл, добавленный и удалённый соседними коммитами, не сканируются | подтверждено тестом `test_pre_push_scans_every_published_commit_not_the_net_diff` | ACK, обход по каждому коммиту + сканирование сообщений + отдельный хук `commit-msg` |
| `--diff-filter=ACM` не содержит `T`/`R` → токен уезжает в цель симлинка | подтверждено тестом `test_typechange_to_symlink_is_scanned` | ACK, `--diff-filter=d` (всё, кроме удалений) + `--no-renames` |
| установщик игнорирует `core.hooksPath` → «успех» при том, что git зовёт другие хуки | `git config core.hooksPath` в репозитории не задан (rc=1), но глобальный сломал бы молча | ACK, установщик сверяет `git rev-parse --git-path hooks` и отказывает |
| suggestion: gitlink и не-UTF8 имя ломают `git show :<путь>` и отбивают честный коммит | подтверждено тестом | ACK, чтение переведено на `--raw` + `cat-file blob <sha>`: путь для чтения больше не нужен, gitlink отсеян по режиму `160000` |
| suggestion: `Bearer` + 26 символов подряд идущего алфавита — правдоподобная документация, а гейт её отобьёт | в репозитории таких строк 0 (полный обход 17 520 файлов) | **DISAGREE**: `bearer` — самое слабое правило и единственное без формата провайдера; ослаблять его ради гипотетической строки в документации дороже, чем одна правка контрибьютора. Цена ложного срабатывания — один edit, цена пропуска — публичный токен |

## Мутации — по каждому плечу отдельно

Протокол: `cp F F.bak` → мутация → прогон → `mv F.bak F` → `touch F`; счётчик маркера мутанта
до и после отката. У всех строк ниже маркер **1 / 0**.

| мутация | что стало |
|---|---|
| **A0** — гейт выключен целиком (`RULES` пуст) | **17 failed, 11 passed**: покраснели все формы, все обходы и все хуки; негативный контроль зелен |
| **B1** — выключен слой заглушек | **1 failed, 5 passed** на негативном контроле: `t5_recovery_records.json:32: bearer` |
| **E1** — PEM снова без экранированных разделителей | 1 failed: `known_evasions[escaped-pem]` |
| **E2** — слой заглушек возвращён на формат `github` | 1 failed: `known_evasions[placeholder-inside-valid-token]` |
| **E3** — удалено правило `github-pat` | 1 failed: `provider_format[github-pat]` |
| **E4** — `--diff-filter=d` → `ACM` | 1 failed: `typechange_to_symlink` |
| **E5** — `pre-push` снова по одному tip-коммиту | 1 failed: `every_published_commit` |
| **E6** — снят пропуск gitlink | 1 failed: `gitlink_and_non_utf8` |
| **E7** — снят гейт `core.hooksPath` | 1 failed: `installer_refuses` |
| **D** — снят fail-closed на пропавший сканер | 1 failed: `missing_scanner_fails_closed` |
| без мутаций | **28 passed in 2.54s** |

Отдельно про **B2** (ослабление формата OpenRouter до `[A-Za-z0-9]{20,}`): на прежней версии
мутация НЕ краснела — фикстуру ловил слой заглушек. После правки по ревью этот слой к
форматным правилам не применяется, то есть формат остался единственным защитником фикстуры,
и подпорки под ним больше нет.

Положительный контроль сканера отдельно: 9 значений провайдерских форматов + 2 известных
обхода → находки по всем, `EXIT=1`; 17 520 отслеживаемых файлов → 0 находок, `EXIT=0`
(тот же ноль и до, и после правок по ревью).

Значения-приманки в оракуле собираются генератором с фиксированным seed, а не пишутся
литералом: литерал секретного формата в тесте отбивался бы собственным гейтом при коммите.

## Пре-мортем — регрессии за пределами постановки

1. **Гейт блокирует ВСЕ коммиты во всех 37 деревьях, если сканер пропал из главного чекаута**
   (главный чекаут отмотан на ветку без гейта). Закрыто: хук проверяет наличие файла и
   отказывает с названной причиной и командой снятия, а не падает `exit 127`. Тест +
   мутация D.
2. **`merge_worker` делает `git commit` (`app/workspace.py:1138,1705`) — отказ гейта ломает
   мерж.** Это желаемое поведение; проверено, что причина не теряется:
   `_commit_failure_result` (`app/workspace.py:1065`) склеивает stdout+stderr коммита в
   `error`, и дальше идёт откат целевой ветки. Текст находки доедет до оркестратора.
3. **Стоимость `pre-push`**: обход идёт по коммитам диапазона, для каждого — дифф против
   родителя, то есть цена пропорциональна публикуемым изменениям, а не размеру дерева.
   Прежний fallback «просканировать дерево целиком» (17 520 блобов ≈ 115 с) удалён вместе с
   `_changed_names`. Патологический случай остался один: новая ветка в remote, у которого
   локально нет ни одной ссылки, — тогда `--not --remotes` перечислит всю историю.
4. **Двоичные файлы** декодируются `errors="replace"` и сканируются наравне с текстом —
   отдельной ветки «пропустить как бинарь», врущей в сторону «всё чисто», нет. Проверено
   тем же полным обходом 17 520 файлов (в них есть `.png`, `.woff2`) — 0 ложных.
5. **Сообщение гейта само публикует секрет.** Закрыто: печатается правило, файл, строка и
   длина, значение — никогда. Тест `test_findings_never_print_the_value`.
6. **Установка ДО мержа заблокировала бы коммиты во всех 37 деревьях**: хук зовёт сканер из
   главного чекаута, где его ещё нет. Закрыто конструкцией — установщик берёт шимы оттуда же
   и отказывается ставить, пока их там нет. Ставить гейт после мержа:
   `uv run python scripts/install_git_hooks.py`.

## Одной строкой: чего гейт НЕ ловит

`git commit --no-verify` и `git push --no-verify` снимают все три хука одной опцией — клиентский
гейт останавливает ошибку, а не намерение; серверного `pre-receive` у публичного репозитория
на бесплатном плане нет.
