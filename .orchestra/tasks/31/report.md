# #31 — Отчёт: путь к codex разрешается на месте

## Что было

`app/mcp_stdio.py`: `_CODEX_BIN = "/home/maxim/.local/bin/codex"` — константа с ноутбука,
использовалась в четырёх местах при сборке shell-команд. После переезда контура на VPS
(пользователь `kesha`) каталога `/home/maxim` не существует вовсе, поэтому КАЖДЫЙ вызов
`codex_review` падал так:

```
/bin/sh: 26: /home/maxim/.local/bin/codex: not found
Process exited with exit code 127
```

Мина двойная: exit 127 приходил из фоновой джобы, где его никто не связывал с путём, а
MCP-вызов при этом возвращал бодрое «Codex exec started». Не прочитав статус джобы, ревью
можно было считать пройденным, не имея ни строчки вердикта.

## Что сделано

| Файл | Что | ± |
|---|---|---|
| `app/mcp_stdio.py` | `_codex_bin()` — разрешение в момент вызова: `CODEX_BIN` из окружения → `shutil.which("codex")` → пусто. Константа удалена, все 4 места собирают команду из разрешённого пути. Гард с внятным текстом до сборки команды | +25 / −2 |
| `tests/test_codex_bin_resolution.py` | новый файл, 8 тестов | +75 |

Текст отказа при отсутствии бинарника:
> codex не найден: ни CODEX_BIN в окружении, ни `codex` в PATH. Поставь Codex CLI или задай
> CODEX_BIN=/путь/к/codex в .env сервиса. Проверить: `which codex`

## Проверено (и чего проверить НЕЛЬЗЯ)

Сквозного прогона Codex нет и быть не может: квота провайдера исчерпана до 08.08.2026
(«You've hit your usage limit … try again at Aug 8th, 2026 7:53 AM» — прогон оркестратора).
Изображать сквозную проверку не стал. Доказано ровно следующее:

- **зовётся существующий бинарник:** `_codex_bin()` → `/usr/bin/codex`, `codex --version` →
  `codex-cli 0.146.0` (запущен реально, из кода);
- **порядок разрешения:** `CODEX_BIN=/opt/codex/bin/codex` перебивает `which`; пустая
  строка/пробелы в `CODEX_BIN` не маскируют рабочий `which` (частый случай в `.env`);
- **отсутствие бинарника даёт текст, а не exit 127:** тест вызывает `codex_review` при
  `which → None` и проверяет, что в ответе есть «codex не найден», `CODEX_BIN`,
  `which codex` и НЕТ «127»;
- **разрешение никогда не выдумывает путь:** возвращает либо существующий файл, либо пусто;
- **регресс на саму мину:** модульной константы `_CODEX_BIN` больше нет.

Тесты: `tests/test_codex_bin_resolution.py` 8 passed; вместе с соседями
(`test_mcp_stdio.py`, `test_mcp_codex_review.py`) — 84 passed. Полный прогон не брал: диф
не трогает shared runtime данных, только сборку одной команды; лок держать ради этого не стал.

**Мутационная проверка гарда:** подменил `return _CODEX_MISSING_HINT` на несуществующее имя →
`test_missing_binary_gives_actionable_text_instead_of_exit_127` покраснел. Тест ловит
отсутствие гарда, а не рисует галочку.
