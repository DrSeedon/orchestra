# V-1189 — error-watch

Исправлены `app/error_watch.py`, `tests/test_error_watch.py`, `CHANGELOG.md`.

## Поведение

- Оба стандартных разделителя цепочки Python traceback классифицируются как
  `traceback chaining line` только целиком. Обёртка logger и краевые пробелы
  проходят прежнюю нормализацию. Дописанная ошибка, префикс другой ошибки и
  многострочное сообщение с реальным исключением остаются кандидатами.
- Разделители не считаются повторением зарегистрированного исправления.
- В `ClientConnectorError: ... [Multiple exceptions: ...]` сортируются полные
  errno-причины. Запятые кортежей адресов не разделяют причины; повторяющиеся
  причины не удаляются. Перестановка IPv4/IPv6 больше не дробит счётчик.
- Сетевой отказ остаётся actionable. Другая причина, exception class, hostname,
  SSL mode или окружающий текст ошибки не объединяются этой сортировкой.
  Неподдержанные/незавершённые формы списка не переписываются.
- На scan старые ключи alerts канонизируются без повторного уведомления.
  Старые ключи fixes сохраняются вместе с метаданными и сопоставляются с новой
  сигнатурой в finding/post-fix. Повторный scan после загрузки state молчит.
- Исходные события и сообщения не изменяются. Числовая нормализация, включая
  прежнее `<N>` для errno/адресов/портов, остаётся существующим контрактом;
  задача меняет только порядок причин, не расширяет точность этих полей.

исходники приложения. Fallback подставляет только DB_PATH и identity
mask_secrets и отключает корневые фикстуры; это **не обязательный gate**.

**240 passed**, импорт `app` из рабочего worktree (сообщение оркестратора при
возврате задачи). Это результат принимающей стороны, а не isolated fallback.
Полный набор проекта и CI здесь не запускались. Проверенные сравнения используют синтетические сообщения
без секретов; production-заглушек или ослабления тестов в проекте нет.

Live БД, journalctl, провайдеры, сервисы и рестарт не использовались.
В этой копии нет `.git`; commit/push не запускались по контракту worker.
Изменения передаются платформе для коммита в `task-V-1189/fix-error-watch`;
hash до завершения передачи недоступен.
