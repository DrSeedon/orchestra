# Личная память оркестратора

Как вести память: modules/knowledge.md. Старые записи лежат в kb/history.md. Роутинг моделей, рестарт и секреты регулируют только AGENTS.md и model-routing, сюда их не дублировать.

## Ловушки
- Боевую БД и хранилище задач определять по живому процессу: `/proc/<MainPID>/fd` и `environ` (`ORCHESTRA_DB_PATH`, `ORCHESTRA_TASK_REPOSITORY`). Путь к БД менялся, поэтому замер по старому файлу молча обрывается. 28.09 я удалил живое хранилище задач, приняв его за копию (V-655). Перед удалением в `data/` грепать все пути `ORCHESTRA_*`. Перед `trash <каталог>` смотреть `git ls-files` и удалять ровно путь из `git status`.
- Переменные из `.env` протекают в тесты и в гейт мержа. Гасить их в `tests/conftest.py` до импорта `app`. Дочерний uvicorn через `load_dotenv` дочитывает боевой `.env` (V-576). Проверять по журналу и `git log`, а не по докладу воркера.
- Гейт мержа тестирует ветку воркера, поэтому воркер должен подтянуть main. `PENDING` от `merge_worker` означает «принято», мерж не повторять.
- Работу воркера принимать мутацией фикса. Задание воркеру: результат, критерий приёмки, границы, без предписанного маршрута (V-548/V-550).
- Новый id модели писать в pipeline.yaml только после рестарта, который загрузил этот id.
- Расход мерить по `turn_usage.cost_usd`. Проценты пула сравнимы, только если не было параллельной активности. В расход подписки входит и Кеша (`kesha-bot-vps`, `response_usage`, V-1061).
- Прежде чем назвать задачу открытой, сделать `task_get`. Прежде чем сказать «ключа нет», выполнить `grep` по `.env`.
- Лимиты памяти orchestra.service 14G/16G ставить через `set-property` без `--runtime`. Drop-in'ы применяются по алфавиту, и `oom.conf` перебивал значения. После правки сверять `systemctl show -p MemoryHigh,MemoryMax`.
- Рестарт режет только running-агентов, waiting не режет. На ноутбуке рестарт без sudo: TERM, затем INT (`Restart=always`), только по слову владельца.
- Ошибка «не работает openssl с X25519MLKEM768» на зеркале означает только, что nginx не поддерживает MLKEM. Это не блокировка; проверять через `curl -sk` и tcpdump.

## Решения владельца
- Пересланная новость или ссылка — это сразу исследование. Ответ по пунктам: взять / уже есть / не брать, применение в Orchestra, польза (в процентах только с измерением, иначе «не измерено»), важность, цена переноса. Реализация — по его слову (V-1097).
- Пушить main в origin всегда, после проверки секретов по форме и по значениям из `.env`. Синхронизация: ноутбук делает merge origin/main и push, VPS — `ff-only`.
- Промпты Оркестры пишутся по-английски, без цитат, с пометкой «owner decision, <дата>». Правила про конкретных агентов этой установки туда не писать: роль агента хранится в описании его сессии. katya-work не трогать.
- Сам правлю только md-файлы (память, TODO, задачи, решения в правилах) и делаю merge/push. Код, конфиги и промпты отдаю воркеру.
- Хаб-воркера после влитой работы: `worker_wip`, затем `kill_worker`. Исключение — геймдизайн (rule-e402924620).
- Идею владельца, которую я оценил как хорошую, делать сразу. Баги чинить самому. Без вопроса: исследования, улучшения, подписочные ресурсы. Спрашивать: удаление данных, платное, архитектурные развилки, чужие проекты.
- Любая цифра для владельца должна быть проверена (n, шум, контроль). Незначимую не поднимать или помечать «шум».
- Всё делается для личного использования: некоммерческие лицензии кандидата не отсекают. Для голоса и изображений нужны реальные образцы. В роликах допустима любая музыка, титры не нужны, стиль светлый «бумажный» (по образцу NIST).
- Модельное ревью перед мержем не предлагать без новых данных (V-918).
- Claude Code и Codex CLI обновлять самому по цепочке: changelog → канарейка (`~/.cache/canary-scripts/cc.py|cx.py`) → `sudo npm i -g` через `ssh kesha@localhost choom` → проверка → короткое сообщение владельцу. Если версия ломает SDK или app-server, не ставить. Сторож обновлений — `bg-a32f0e70d8`. На ноутбуке сам: `ff-only`, `claude install`, codex через npm без sudo.
- Автообновления VPS выключены, needrestart стоит в режиме `l`. Перезапуск служб после ручного apt — отдельное решение.
- Строку `iguana_necktie` в лимитах Anthropic не упоминать.
- Стенд reestr-demo.seedon.ru заморожен до решения Минцифры. Ничего не делать без команды seedon; при падении поднять минимальным вмешательством.
