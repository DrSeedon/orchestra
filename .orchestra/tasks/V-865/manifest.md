# V-865 preregistered pilot manifest

Frozen before model runs; commit contains all 12 inputs, questions, candidate instruction, score rubric, pair order, and X/Y anonymization. All cases derive from recorded Orchestra work; evidence below is intentionally a compact snapshot, not the prior report's conclusion text.

## Experimental arms and execution

- A: exact case prompt only, with dynamic_workflow's current default system modules.
- B: same case prompt plus the exact text in [`candidate-rule.md`](candidate-rule.md).
- Model alias: `luna`; billing: `subscription`; no API-credit route. Same workflow tool, model alias, case prompt and run settings in both arms. Dynamic workflow currently assembles `communication-style`, `user-values`, `knowledge`, and `code-quality` by default; it does not assemble the role-specific prompt bundle of a normal orchestrator/full-cycle session. The pilot therefore estimates this route, not every Orchestra role.
- 12 pairs, 24 primary calls; one separate Luna subscription call to blind-score all 12 pairs (25 expected calls). `budget_usd=15`, `max_calls=36`, `max_concurrency=3`. The run must stop on the tool's budget/call cap. No API credits.
- `od -An -N24 -tu1 /dev/urandom` before the runs yielded: `6 135 67 189 114 216 243 218 198 215 33 135 111 91 202 145 105 134 225 45 16 231 191 108`. Per case, byte parity 0/1 from the first 12 values determines A/B order (0=A then B; 1=B then A); parity from the next 12 assigns the opaque assessor labels (0=A=X/B=Y; 1=A=Y/B=X). The judge sees only X/Y. Mapping is retained here for post-score unblinding.
