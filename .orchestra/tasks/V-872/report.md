# V-872 — append conflicts in `.gitignore`

## Причина

В `merge_worktree_to_main` предварительный `git merge-tree --write-tree` возвращал конфликт до записи журнала и до squash merge. Поэтому обычный append/append конфликт `.gitignore` немедленно становился `CONFLICT`, даже когда обе стороны только добавили строки к общей базе. Исправление живёт в Orchestra и не требует `.gitattributes` в репозиториях проектов.

## Изменение

Перед принятием результата предварительной проверки код сравнивает содержимое `.gitignore` в merge-base, target и worker. Автоматическое объединение разрешено только когда обе стороны имеют точный построчный префикс merge-base; строки добавок объединяются в порядке target, затем worker, с удалением повторов среди добавок. Если совместное дерево содержит другой конфликт, операция возвращает `CONFLICT` только по конфликтующим обычным файлам и не начинает squash.

Для чистого `.gitignore` append-конфликта ожидаемое дерево журнала строится через временный Git index и новый blob, без изменения refs или рабочего индекса до `prepare`. После начала squash та же проверка разрешает индексный конфликт `.gitignore`; остальные неразрешённые конфликты ведут к прежнему `git reset --merge` и `CONFLICT`. Изменения существующих строк, удаление файла, отсутствие общего файла или не-построчное продолжение префикса автоматически не объединяются.

## Проверка

`uv run --frozen python -m pytest -q tests/test_merge_conflict_report_423.py` — 6 passed. Зафиксированы три сценария: две append-ветки с общей дублирующей строкой дают успешный squash без дубля; конфликт обычного файла остаётся конфликтом; конфликт `.gitignore` вместе с обычным файлом показывает только обычный файл. Mutation-check закоммиченного успешного теста: временный unconditional `return None` в `_appended_lines_union` дал 1 failed на `assert result["ok"] is True`; после восстановления кода тот же файл тестов снова дал 6 passed.

Прогон выполнен на Git-репозиториях в `tmp_path`, боевые репозитории не менялись. Требуется рестарт Orchestra после мержа, так как изменён Python-код `app/workspace.py`.
