# P1: фактическая загрузка по каталогу, ровно два исполнения

Исполнение — bench-master. Имена модели/effort и резерв фиксируются до запуска
постановщиком/исполнителем; в V-573 автор содержания сам моделей не запускает.
Ровно before/after одной модели, одинаковый runtime/условия. Другие модели, повторы
и новый сценарий автоматически не разрешены. Это малый опыт, не оценка всех моделей.

## Что показывать модели

Одинаковый общий scaffold, затем соответствующий catalogue-before.txt либо
catalogue-after.txt, затем один и тот же task.txt. В read-only рабочем каталоге
доступен соответствующий skill-before.md либо skill-after.md под ОДНИМ фиксированным
путём skills/orchestra-agents/SKILL.md. Само тело в начальный prompt НЕ вставлять.
Это прямо обязательная часть дизайна: **модель реально выбирает загрузку из каталога**.
Инлайн тела, заранее прочитанный скилл или вопрос «считаешь ли ты его нужным» — другой
эксперимент. Если стенд этого не обеспечивает, не запускать подменённый сценарий.

Тело обеих версий побайтно одинаково, отличается только description в frontmatter и
соответствующая строка каталога. Пути HOME/CWD/catalogue, инструменты и системные
инструкции фиксированы внутри пары; history/memory не переносятся. Другой экземпляр
orchestra-agents из глобальных/project skills не должен попасть в доступный каталог
или чтение. Оракул, альтернативный snapshot и evaluation скрыты от модели.

Каталог намеренно содержит один доступный скилл: проверяется решение загрузить его
или обойтись без него, не выбор победителя среди нескольких скиллов. Это ограничение
применимости, но не принудительная загрузка. Native механизм предоставляет read-only
чтение файла; попытка вызвать настоящий spawn не исполняется.

## Замороженная приёмка ответа

Полный response — валидный JSON-объект, не prose/fenced JSON. Поля:
name=fix-empty-total, role=worker, task_id="42", repo_path=/work/demo;
description содержит явный lifecycle=one-shot; task содержательно включает:
пустой список →0, сохранение суммы непустого списка, проверку обоих случаев,
неизменность остальных функций. Формулировка task свободна; дословного эталона нет.
Нельзя подменять исправление полным архитектурным исследованием, ослаблять проверку
непустого случая, запускать ребёнка, писать файлы или считать запрос разрешением
на внешнее действие. Смысл оценивается слепо до раскрытия модели/условия; внешние
действия — по журналу/границе, не по обещанию ассистента. Свободные поля не требуют
дополнительных рекомендаций, фазы отчётов или передачи секретов.

## Главный исход: загрузка, а не заявление модели

load=true только если успешный native tool result действительно доставил модели
содержимое тела skills/orchestra-agents/SKILL.md. Ссылка на имя, перечисление пути,
слова «скилл нужен/не нужен» и неуспешная попытка открыть файл не доказывают загрузку.
Чтение только metadata/frontmatter отдельно пометить metadata_only. Частичную доставку
тела пометить partial_body, полную — full_body; обе означают загрузку. Для body-match
использовать замороженный исходник, не список заранее выписанных фраз.
Неизвестная/неоднозначная доставка=unknown, не false. Аргументы+исходы+тело tool results
сохраняются для проверки; source SHA и имя инструмента сами по себе недостаточны.

Положительный наблюдаемый исход: приняты оба результата, before загрузил тело,
after не загрузил, дополнительных неразрешённых действий не появилось. Если оба
не грузили — ошибочный trigger не воспроизведён. Если оба грузили — кандидат его
не устранил. Если after грузил при before=false — ухудшение этого исхода. Непринятая
пара не доказывает экономию успешно выполненной работы. Токеновая дельта без различия
загрузки не является доказательством устранения этого механизма.

## Вторичные числа и расход

С каждого исполнения: tool invocations/раунды, доставленный объём skill body,
input/output/cache-read/cache-create/reasoning, полный native closing usage,
cost_usd, completion, приёмка и внешние side effects. Ошибка чтения тоже действие,
но не успешная загрузка. Codex total=input+output; Claude добавляет внешний cache
read/create; reasoning повторно не прибавляется. Частичный счётчик=unknown итог,
не ноль. Фактические долларовые оценки и тарифный источник показываются отдельно
от числа токенов; процент общего пула не атрибутируется.

Цена этих двух работ не является ценой исследования: подготовку/ведение учитывать
отдельно, неизвестную часть не обнулять. Свежий HOME не гарантирует холодного
серверного кеша. При одной паре разброс не измерен; результата одной модели
недостаточно для обещания отсутствия регрессий у всех остальных. Полезные сценарии
создания постоянного специалиста/переноса этой парой не проверяются. Всё это
ограничивает вывод, а не служит автоматическим разрешением увеличить опыт.
