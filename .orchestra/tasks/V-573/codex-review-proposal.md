# Личный codex-review: отдельное предложение владельцу

Прочитаны все272строки ~/.claude/skills/codex-review/SKILL.md. SHA17951байтного
источника повторно снят непосредственно перед построением diff и совпал с исходным
чтением — [codex-review-source.json](codex-review-source.json). Внешний файл не менялся.
Нативный Codex CLI не объявляется отсутствующим или запрещённым для любых задач;
конфликт относится к самостоятельному обходному маршруту ревью внутри Orchestra.

| Дословное предписание личного файла | Конфликт с каноном платформы |
|---|---|
| «АВТОМАТИЧЕСКИ после каждого фикса/изменения кода»; «не пушить без хотя бы одного раунда Codex» | codex-debate: ревью доступно, но не обязательно; исполнитель решает полезность, оркестратор не запускает его через shell |
| «Повторять шаги 1-4 пока Codex не скажет APPROVED»; ниже «7+ раундов без прогресса» | Канон не требует одобрительной надписи, серверный бюджет — три попытки на задачу. Повторный CLI вне сервера не становится четвёртой разрешённой попыткой |
| «Codex ВСЕГДА запускается в background (run_in_background: true в Bash)» | Base запрещает этот механизм; долгие процессы используют серверные bg jobs |
| «Users: ~10 active, NOT millions. No horizontal scaling needed» в обязательном PROJECT CONTEXT | Проектный масштаб нельзя переносить из чужого шаблона; актуальные поля собираются по текущему проекту |
| «Хочешь чтобы я вступил в дебаты с ним?» и «НЕ спрашивать юзера ... и итерировать» | Внутренне расходящиеся указания одного скилла о том же переходе |

Скилл также закрепляет GPT-5.5/старые модельные настройки, личные /tmp-сессии и
папку docs/<feature>/CODEX_REVIEW.md. Эти сведения не доказывают актуальный маршрут
модельного ревью Orchestra. Проверку замечаний через код из скилла не отвергаем:
она уже есть в каноне. Старые заявления о100%accuracy не проверялись заново.

**Предлагаю короткий указатель** на канонический codex-debate с узким description,
без CLI-команд, схемы бесконечного debate, старых моделей и собственной приёмки.
Ревью остаётся доступной функцией платформы, с единственным владельцем правил.
[Предложенный файл](proposed/codex-review-SKILL.md), [diff](codex-review-proposal.diff).
Это не самостоятельное одобрение внешнего применения.

Удаление из активного каталога тоже устраняет приглашение, но ломает привычный
личный trigger /codex; оставить как есть сохраняет все перечисленные конфликты.
Если владелец использует этот скилл для ручного CLI вне Orchestra, выбор указателя
означает отказ от прежней самостоятельной инструкции на VPS — это должен решить он.

При одобрении оркестратор ещё раз проверяет SHA, сохраняет оригинал рядом с уникальным
суффиксом и метаданными, затем заменяет файл атомарно. При сменившемся SHA сначала
пересобирается diff. При отказе новая версия не устанавливается; откат — оригинал
из backup. Я личные файлы и references не удалял и не заменял.
