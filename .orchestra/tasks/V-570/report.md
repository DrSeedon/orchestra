## Что оказалось важнее сокращения текста

Текущий managed Codex использует отдельный CODEX_HOME. В 53 проверенных каталогах
AGENTS.md отсутствует; `_prepare_codex_home` переносит auth/config, не глобальные
инструкции. Значит, синхронизация ~/.codex/AGENTS.md сама по себе не исправляет их
доставку этим агентам. Факт относится к текущему коду/проверенному состоянию;
«никогда во всей истории» не доказано. В default Claude при inherit_claude_md включены
user/project/local источники. Сам факт доставки в конкретный уже открытый native
диалог этим файловым обследованием не проверен.

По решению оркестратора второй канал в managed homes не добавляется. Общие нормы
доставляются модулями pipeline, личный AGENTS нужен ручному Codex владельца.
Ниже именно недостающие конкретные нормы, а не утверждение, что Codex раньше
вообще не имел безопасности: общие рамки полномочий/сохранности уже были в ролях.

| Норма глобала, не доходившая этим путём до managed Codex | До пакета | После пакета |
|---|---|---|
| rm-r/rf запрещены, trash/rm-i; недоступный инструмент не обходить молча | Только глобал Claude, в общих модулях нет | safety, все роли |
| Точные границы ~/.config, ~/.ssh, .env, прочих dotfiles; запрет удаления вне проекта | Существовали общие рамки worktree/полномочий, но не эти перечисленные запреты | safety, все роли |
| Запрет chmod777 и curl-pipe-shell | Только глобал | safety, все роли |
| Перед деструктивным показать команду и спросить | Общий gate разрешения был, явный показ команды — глобал | safety, все роли |
| Проверить читаемость/успех/stderr прежде чем трактовать пустоту | История sudo в глобале | safety, все роли |
| Service user для Git/login/config; ownership snapshot и сохранение modes | Глобал | safety, все роли, условие — соответствующая операция |
| TODO/сообщение о найденных неустранённых проблемах | Частично orchestration/корень Orchestra; не едино всем меняющим роли | project-maintenance, четыре роли |
| Ручной CHANGELOG, не генерировать из внутренних отчётов, trigger case, версии/секции | Глобал | project-maintenance |
| Обновление существующего architecture.md, не создавать самостоятельно | Глобал | project-maintenance |
| Четыре ступени перед кодом, плотность комментариев | Часть общих code-quality уже была у worker/full-cycle; эти детали только глобал | code-quality дополнен; получают все четыре способные менять код роли |

Личные настройки, включая Git-авторство/watermark, тоже не доходят через отсутствующий
managed AGENTS. Они сознательно остаются личными по прямому решению владельца.
Цены/предпочтения моделей MCP после его ответа сняты из обеих предложенных инструкций;
они не копируются ни в общий промпт, ни в личный справочник. Это ограничение канала
сохранено в [KB agent-control](../../kb/agent-control.md), не спрятано в статусе задачи.
