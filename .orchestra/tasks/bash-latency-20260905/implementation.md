## Что изменено

- `merge_worker` передаёт неизменяемый ID вызывающей сессии. Сервер сохраняет наблюдателя
  в существующем хранилище background jobs и возвращает его ID. Только подтверждённая
  регистрация отменяет синхронное ожидание до 90 с; старый сервер или ошибка регистрации
  сохраняют прежний путь. Наблюдатель не запускает и не повторяет merge.
- Наблюдатель проверяет scope, объединяет конкурентные регистрации для одного адресата
  и операции, восстанавливается после рестарта. Он доставляет terminal state либо
  появившийся блокер: ожидание завершения при блокере могло бы зависнуть навсегда.
- Синхронный fallback теперь ограничивает и зависший запрос статуса остатком своего
  бюджета. Раньше один HTTP-запрос мог добавить ещё до 30 с сверх бюджета ожидания.
- Встроенный Bash **OpenRouter Harness** сохраняет частичный вывод, маркирует ошибки
  и nonzero exit, связывает события через tool_use_id. Вывод накапливается ограниченно;
  после timeout чтение не ждёт уцелевшего владельца pipe. Используется существующий
  pidfd lifecycle; отмена чистит свою группу, нормальный выход сохраняет намеренно
  отделённые процессы. В сообщении названы requested/effective/max timeout и bg_create.
  Это не утверждение об исправлении native Bash всех внешних CLI.
- Ошибки HTTP MCP содержат elapsed_seconds и настройки connect/read/write/pool timeout.
  Общий дефолт 30 с не увеличен и автоматических повторов мутаций не добавлено.
- Full-cycle prompt больше не требует безусловный полный `pytest -x` после каждой задачи:
  сначала exact acceptance и связанные регрессии, полный набор — по области изменения.
  Добавлен батчинг независимых чтений; зависимости и мутации остаются последовательными.
- `pytest-xdist==3.8.0` добавлен в dev/lock. Глобального `-n` нет; параллельность opt-in
  для проверенных наборов. В lock добавлены только xdist/execnet и ссылки на xdist.
- На VPS установлен standalone ripgrep 14.1.0. Проверен `/usr/bin/rg` в PATH живого
  сервиса. apt работал с `NEEDRESTART_MODE=l`; сервис не перезапускался.
