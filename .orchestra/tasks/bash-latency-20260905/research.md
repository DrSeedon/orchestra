## Независимая выборка

`audit.py` читает последние 100000 позиций ID logs на каждом контуре, mode=ro,
query_only. Соединение только по `(session_id, tool_use_id)`, без угадывания старых
пар. JSON содержит границы, непарные события и агрегаты. Команды и секреты не сохранены.
Отдельный срез ниже: с 2026-08-29 до времени снимка 2026-09-05, scope Orchestra.

| Эвристическая группа команд | Ноутбук, вызовы / часы | VPS, вызовы / часы |
|---|---:|---:|
| С упоминанием pytest | 1568 / 2.971 | 513 / 1.721 |
| С упоминанием поиска | 2350 / 0.341 | 855 / 0.653 |
| С упоминанием sleep, после исключения групп выше | 6 / 0.009 | 36 / 0.277 |

Это ориентир, **не точное распределение времени исполняемых программ**: поиск слова
pytest попадает в первую группу, составная команда учитывается целиком, sleep внутри
pytest-команды отдельно не виден. Разные задания и количество вызовов не позволяют
сравнивать производительность машин по этим суммам. Время — интервал поступления
событий, не CPU и не календарный критический путь. У Codex при пропущенном started
оба события могут возникнуть на completed (`backend_codex.py:2195`), занижая интервал.

Во всей выборке около 73%/76% сопоставленных Bash-вызовов уже содержат `&&`, `;`
или перевод строки. Это лишь синтаксический признак, не проверка независимости команд.
Он не поддерживает предположение, что каждый короткий вызов можно сгруппировать втрое.

## Приоритет следующей реализации

1. Разобрать воспроизводимые таймауты и повторные операции: сохранять частичный
   результат и однозначный статус завершения, различать бюджет клиента/сервера/CLI.
2. Для долгих ожиданий использовать существующие durable jobs и доставку завершения.
   Перед сокращением 90 с merge проверить доставку события и отсутствие повторного
   мержа: возврат RUNNING раньше без продолжения способен ухудшить поведение.
3. Проверить xdist в отдельном окружении на одинаковых целевых наборах: последовательный
   запуск против `-n 2 --dist load`, затем 4 при достаточной памяти. Измерять wall/RSS,
   одинаковые passed/failed/skipped и повторяемость. Браузерные, общие порты и файлы
   требуют отдельной проверки. Глобальный `addopts=-n 6` до этого не обоснован.
4. Восстановить доступность standalone rg на VPS; область поиска выбирать по задаче.
   Батчинг ограничить независимыми чтениями и проверить по раундам модели, а не
   умножать число Bash-команд на усреднённые 13.75 с.

`--dist loadfile` держит один файл на одном worker: одиночный целевой файл этим не
ускоряется. Документация: https://pytest-xdist.readthedocs.io/en/stable/distribution.html
Поведение ignore: https://github.com/BurntSushi/ripgrep/blob/master/GUIDE.md

Полный pytest, установка xdist и A/B производительности не запускались: этот этап —
исследование логов и текущего кода. Коэффициенты ×1.38/×5.7 и экономия 88 часов
не подтверждены; для них нужны реальные раунды, зависимости и критический путь задач.
