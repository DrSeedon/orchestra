# Antigravity на ноутбуке — 2026-11-05

Итог: установка, OAuth и рабочий запуск через Contabo выполнены. Gemini
Flash High вернул `OK` в двух отдельных проверках. Установлен запускатель
«Antigravity — Contabo», который управляет SSH-туннелем на время работы CLI.
Подробности и проверка уборки процессов — в [contabo.md](contabo.md).

Источник: просьба Максима в главном треде Orchestra установить Antigravity
на ноутбук и выполнить авторизацию. Отдельное разрешение 2026-11-05:
«на ноуте без ограничений можешь качать все и делай все авторизируй ок».

## История входа

Владелец выбирает Google-аккаунт и подтверждает OAuth в браузере ноутбука.
При первой проверке вход выполнялся, credential ещё отсутствовал.
Затем проверить успешный exit code и доступ к каталогу/квотам без вывода
credential и без платного inference. Тип подписки пока не подтверждён.

Повторная проверка: официальный `agy acp --login` завершился с `exit_code: 1`,
credential не создан, процессов `agy` не осталось. Причина уточняется по
журналу клиента. Установка завершена, авторизация не завершена.

Причина первой ошибки подтверждена журналом клиента:
`token exchange failed: oauth2: "invalid_grant" "Malformed auth code."`.
Запущена вторая ограниченная по времени попытка официального входа с
пояснением в окне терминала: передать только свежий код из браузера.

Пользователь попросил перезапустить вход и автоматически подставить код.
Предыдущий код не повторяется и не используется. Третья попытка запущена
через управляемый PTY (`exec session_id: 20917`), с отключённым echo и
таймаутом 600 секунд. Официальная OAuth-ссылка открыта в существующем
браузере ноутбука. Свежий Google-код из буфера обмена ноутбука передаётся
непосредственно в stdin клиента; содержимое буфера не выводится и не
сохраняется в файлы. Код, который находился в буфере до запуска, игнорируется.

Пользователь сообщил, что браузерное окно не появилось, и попросил вернуть
вход через терминал. Третья попытка остановлена по точно проверенным PID
клиента и обёртки. Четвёртая попытка запущена в отдельном окне Konsole
(`--separate --hold`), с видимой официальной ссылкой и приглашением вставить
свежий код. Таймаут входа — 600 секунд; результат сохраняется без секретов
в тот же status JSON на ноутбуке. Автоподстановка буфера больше не работает.

## Успешный вход и региональный отказ

Четвёртая попытка завершилась успешно (`exit_code: 0`), пользователь подтвердил
сообщение `Logged in` и свой аккаунт в интерфейсе `agy 1.5.1`.
Файловый credential по ожидаемому Orchestra пути не появился; отсутствие
этого файла не означает неуспешный вход в нативный CLI.

Пользователь сообщил точный отказ при отправке сообщения:
`Eligibility check failed: Your current account is not eligible for Antigravity,
because it is not currently available in your location.`
Следовательно, OAuth успешен, доступ к inference пока не подтверждён.

После этого Максим явно попросил применить патч: «вот пора время патча».
Это разрешение на изменение отдельного CLI на ноутбуке; остальные установки
и настройки провайдеров T3 в область этой задачи не входят.

Исходник QNIX-Dev/eligibility-antigravity-patcher установлен на ноутбук:
`/home/maxim/.local/share/agy-manager/manager.py`.
Зафиксирован commit `90498f50353d414232f593dffe88899bc80b6312`,
SHA-256 `aac1d9c2be0eb17820cbea987487173a4165ba67ff2af638747319b211db06f8`.
Проверены код поиска сигнатур, резервного копирования, записи и проверки
патча. Путь изменения задаётся явно; функции управления аккаунтами и квотами
из этого стороннего инструмента не вызываются.

На оригинальном бинарнике проверены две однозначные x64-сигнатуры:
CLI по смещению `0x98b56b2` (4 байта) и embedded auth по `0x91ec90a` (6 байт).
Обе имеют состояние `unpatched`.
SHA-256 оригинала `agy 1.5.1`:
`72738cf0445918483956a5f0da33abdfcfb21a12dd9a421fd57d063782826669`.

Патч применён к промежуточной копии; выполнены проверка всех отличий от
оригинала, проверка обеих конечных сигнатур и запуск `--version`.
Копия атомарно установлена в `/home/maxim/.local/bin/agy`.
Обе сигнатуры имеют состояние `patched`, версия остаётся `1.5.1`.
Оригинал сохранён в `/home/maxim/.local/bin/agy.1.5.1.agybak`.
SHA-256 патченного бинарника:
`422155a38d305750c35fe8f67d35266a843a0b9cf51939299c14c009ca43fbeb`.
На ноутбуке сохранён технический результат без секретов:
`/home/maxim/.cache/antigravity/orchestra-patch-20261105.json`.
Проверка каталога и квот запущена отдельно; работоспособность inference
этими проверками бинарника пока не подтверждена.

После патча нативный CLI успешно вернул каталог (`SUCCESS`, exit 0):
`gemini-3.8-flash-high`, `gemini-3.8-flash-medium`, `gemini-3.8-flash-low`,
`claude-sonnet-4-6`, `claude-opus-4-6-thinking`, `gpt-oss-120b-medium`.
Запрос `/quota` также успешен (exit 0): `gemini-weekly`, `gemini-5h`,
`3p-weekly`, `3p-5h` имеют `remaining_fraction: 1`.
Argon и Pro в фактическом каталоге этого аккаунта отсутствуют; платный тариф
этими данными не подтверждён.

Первый запуск минимального canary остановился до обращения к модели:
`Error: --settings: unknown setting "security.workspaceTrust.enabled"`.
Версия `1.5.1` не принимает этот ключ в session override. Повторная проверка
будет без этого параметра, в пустом временном каталоге и в режиме plan.

Реальный canary на `gemini-3.8-flash-high` после исправления аргументов
дошёл до сервера и завершился с exit 3:
`FAILED_PRECONDITION (code 400): User location is not supported for the API use.`
Входящие и исходящие токены — 0. Локальные патчи не снимают серверную
проверку сети; успешный каталог не означает успешный inference.

На ноутбуке найден уже настроенный локальный прокси `127.0.0.1:7897`.
Выполнен один дополнительный canary с `HTTP_PROXY`/`HTTPS_PROXY` только для
этого процесса. Настройки системного прокси и VPN не менялись.
Сервер вернул тот же `FAILED_PRECONDITION (code 400): User location is not
supported for the API use.`; входящие/исходящие токены вновь равны 0.
Дальнейшие повторения inference не выполняются.

## Состояние после локального патча, до настройки Contabo

- Установка и OAuth на ноутбуке выполнены.
- Два локальных патча применены и проверены, чистый оригинал сохранён.
- Каталог и данные квот получены успешно.

  inference не достигнут; причину серверного отказа нельзя исправить одним
  локальным eligibility-патчем.

## Границы

Сначала установлен официальный бинарник; после отдельной прямой просьбы
пользователя применены два локальных изменения eligibility. Настройки провайдеров T3,
боевой сервер Orchestra и Telegram не менялись. OAuth URL, коды входа и
credential в артефакт не копируются. Архив и временный каталог установки
удалены автоматически после успешной установки.
