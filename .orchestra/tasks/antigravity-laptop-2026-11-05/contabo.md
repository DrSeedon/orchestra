# Antigravity через Contabo — 2026-11-05

Дополнение: по следующей прямой просьбе Максима обычный `agy` тоже сделан
запускателем через Contabo. Актуальные пути, хеши и проверки Argon/Sonnet/Opus
описаны в [always-proxy-models.md](always-proxy-models.md). Ниже — история
первой установки отдельного запускателя.

Источник: Максим попросил попробовать прокси через Contabo, разобраться
в бинарнике или найти публичные способы решения серверного location-отказа.

## Проверенные исходные данные

- На ноутбуке `agy 1.5.1` с двумя уже проверенными локальными патчами.
- Прямой inference и inference с существующим прокси 127.0.0.1:7897
  ранее получили `FAILED_PRECONDITION: User location is not supported`.
- Публичный issue описывает похожее игнорирование proxy env для model calls:
  https://github.com/google-antigravity/antigravity-cli/issues/875
  Это пока гипотеза для нашей версии, а не результат нашего измерения.
- SSH к `kesha@158.220.127.161` с ноутбука работает штатным ключом по умолчанию.
  Хост проверяется через существующий known_hosts. Ключи не копируются.
- Алиас `orchestra-vps` на ноутбуке отсутствует и дал DNS-ошибку.
  Явная попытка с ключом `tunnel_vps` получила `Permission denied (publickey)`;
  стандартный выбор ключа успешен.
- На Contabo перед пробой доступно около 20 млн КиБ RAM, loadavg 0.34.
- На ноутбуке уже есть `strace` и `proxychains4`; `graftcp` и Go отсутствуют.

## План проверки

Временный SOCKS-туннель SSH только на loopback ноутбука; проверить фактический
выход через Contabo, затем один короткий canary Flash с proxy env. С помощью
trace только `connect` проверить, не идёт ли модель напрямую. Туннель и все
тестовые процессы останавливаются в finally. TLS не расшифровывается,
credential из системного хранилища не извлекается.

## Дополнительное исследование

Поиск нашёл NakishN/antigravity-cli-unlocker, однако GitHub API для указанной
ветки вернул 404; этот исходник не установлен и не выполнялся.

## Успешная проверка

Временный SSH SOCKS-туннель с ноутбука поднят штатным ключом к Contabo.
Cloudflare trace через SOCKS сообщил `loc=FR`. Проверка ожидаемого IPv4
`158.220.127.161` с фактическим адресом выхода не совпала; конкретный адрес
выхода в артефакт не копировался. Это не отменяет подтверждённую SSH-цепочку;
сопоставление выходного IPv4/IPv6 отдельно не выполнялось.

Переменные `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` и их lowercase-варианты
заданы как `socks5://127.0.0.1:<эпhemeral-port>` только для процесса `agy`.
На `gemini-3.8-flash-high` получен настоящий ответ `OK`, status `SUCCESS`,
exit 0, время CLI 3.753 с, 6964 входных и 41 выходной токен (40 thinking).

`strace -f -e trace=connect` этого запуска показал IPv4-соединения только к
127.0.0.1:53 и loopback-порту SOCKS. Прямых внешних TCP:443 не наблюдалось.
Следовательно, гипотеза об игнорировании SOCKS env на этом пути в `1.5.1`
не подтвердилась. Ранее проверенный локальный прокси не обеспечивал успешный
доступ; точная причина его отличия от Contabo не устанавливалась.

Временный туннель и trace-каталог удалены в finally. Технический JSON без
секретов на ноутбуке:
`~/.cache/antigravity/orchestra-contabo-probe-20261105.json`.

Следующий шаг: отдельный запускатель, который держит loopback SSH SOCKS
только пока работает Antigravity и закрывает его при выходе. Настройки
T3, VPN, системного прокси и сервисов Contabo для этого не меняются.

## Установленный запускатель

Канонический исходник рядом с этим файлом: `antigravity-contabo.py`.
На ноутбуке установлен в:
`/home/maxim/.local/share/antigravity-contabo/launch.py`.
SHA-256 исходника:
`32f92721300a33d3339f127b6d4ca1285f7769d9e5dd86087aea371e2d6d3a5d`.
В меню приложений добавлен «Antigravity — Contabo»:
`/home/maxim/.local/share/applications/antigravity-contabo.desktop`.

Установленный файл отдельно проверен полным запуском Flash High:
exit 0, status `SUCCESS`, ответ `OK`, время 3.620 с, 6954 входных,
79 выходных токенов (78 thinking). После завершения status `closed`,
SSH и CLI завершены, loopback-порт закрыт. Это второй успешный ответ
после первого диагностического запуска — всего 2/2 через Contabo.
Никакие фоновые сервисы и автозапуск не устанавливались.

Технический результат проверки без секретов на ноутбуке:
`~/.cache/antigravity/orchestra-installed-launcher-check-20261105.json`.
После проверки открыто отдельное рабочее окно Konsole с этим запускателем.

Ручной запуск из любой папки, дополнительные аргументы передаются в agy:

```sh
python3 ~/.local/share/antigravity-contabo/launch.py
```
