Владелец разрешил проверить один простой проект нативным Codex Luna, затем дал «гоу» на
остальные. Пилот WebView: две темы из четырёх отчётов; родитель проверил источники и попросил
уточнить отсутствие документированного Windows-теста, поправку mimetypes.add_type и различие
плана/исполнения. После этого выполнялись ограниченные проектные задания Luna с проверкой Astra.

## Проверка качества Luna

Первый ответ агента не принимался за доказательство. Родитель исправил:
- COG: переставленную полярность гипотезы requests/urllib (источник: curl работал, urllib нет;
  предсказание отказа requests опроверглось 200 OK), лишнюю обязательную preregistration.
- Sensar: совпадение init-файлов/одной Qt-библиотеки не исключает различия фактического env.
- Parsing: восстановлено несвязанное правило Git/deploy, которое агент удалил сверх задачи.
- kesha-tg-bot: отменена лишняя правка probe и добавлена содержательная KB вместо одного отчёта.
- Малые проекты: untracked layout-marker не означает dirty tracked; ложный блокер снят.

Это свидетельство пригодности Luna для подготовки с содержательной проверкой, а не
безошибочного автономного извлечения/удаления. Полное извлечение каждого исторического
тезиса из всех отчётов не заявляется. Исходные tasks/workers/docs/records намеренно сохранены;
кандидаты на дальнейшую чистку и ограничения перечислены в каждом проектном отчёте.
Product manuals, GDD, контракты, CRM, брендбуки и machine runbooks не объявлены мусором.

Сервисы, модели, Windows/GPU, торговые программы и клиентские устройства не запускались.
На VPS выполнены только scoped Git/document операции; отдельная итоговая проверка ниже.

## Границы результата

Это исправление обнаружения, адресов и отобранных содержательных конфликтов, а не доказанная
полная выжимка всех исторических документов. Сохранены большие root-справочники и operational
темы, используемые текущей работой; дальнейшее удаление требует предметной проверки.
Изменения на ноутбуке и VPS зафиксированы по месту; единый Git sync всех сторонних репозиториев
не выполнялся, поскольку push может запускать их автоматический deploy.

Сопутствующая диагностика Codex UI: npm Codex 0.153.4 не имеет managed standalone path,
необходимого codex agents/shared daemon. /agent этой версии тоже требует shared server.
Установщик скачан и изучен, но установка/PATH/daemon не менялись без отдельного подтверждения.
Это не ошибка исполняющихся collaboration-агентов и не останавливало их работу.
