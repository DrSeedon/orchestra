# V-1110: search_logs — фильтр по типу, regex, метод поиска

## Что сделано
- `app/db.py`: `search_logs(..., kinds=None)`. По умолчанию `l.type IN ('user_message','text')` (в SQL, до лимита 10 000; agent messages — это `user_message` с `origin='agent'`, голос — тоже `user_message`). `kinds` = список типов через запятую или `all`; неизвестный тип → `ValueError` (HTTP 400). В ответ добавлено `oldest_scanned` (ts самой старой просмотренной строки).
- Regex без учёта регистра (`a|b`). Простой текст (без метасимволов) идёт прежним путём casefold (ß/ss, İ — тесты V-1089 сохранены). Паттерн >200 символов, синтаксическая ошибка или «квантификатор после группы» (`(a+)+`, `(a|aa)*` — экспоненциальный откат) → поиск подстрокой через `re.escape`. Regex смотрит только первые 200 000 символов строки; простой текст — всю строку (контракт V-1078 «rare match searches complete payload» сохранён). Остаточный риск: ReDoS-форма без скобок-группы не отсекается эвристикой, но на таких паттернах откат полиномиальный и ограничен 200k символов.
- HTTP `/api/logs/search?kinds=`, MCP `search_logs(kinds=)`, описание инструмента содержит метод; `knowledge.md` — абзац «Search method».
- Тесты `tests/test_log_search_v1110.py` (по умолчанию tool_result не находится, `kinds` находит; `kinds` расширяет окно скана; альтернатива и битый паттерн; `(a+)+$` на строке 4 МБ не виснет, регекс не заглядывает за предел; HTTP). Мутация «по умолчанию включить tool/tool_result» краснит 3 теста. В `test_log_search_v1078.py` два места, намеренно использовавшие tool_result как «tool», теперь передают `kinds="all"` / ожидают scanned=3.
