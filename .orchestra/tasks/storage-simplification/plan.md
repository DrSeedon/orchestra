# Упрощение хранения и офлайн-синхронизация

Разрешено владельцем: реализовать предложенные упрощения, VPS-префикс V-, независимую офлайн-работу с Git sync; старые слои и ненужные копии удалить. Историю задач и результаты сохраняем в оставшемся хранилище до удаления прежних.

База реализации: b1c7583e. Отдельный worktree /mnt/data/Projects/Python/orchestra-storage.

## Контракт результата

- Префикс обозначает происхождение задачи. Локальная `#123` и `V-123` различимы в данных, ссылках, API, привязках, коммитах и UI. После синхронизации V-номер остаётся V-номером.
- Задачи — один Git-канон и одна SQLite-проекция в runtime-БД. Нет task-current.db, общего task+knowledge current.db и очереди согласования этих проекций.
- Знания и evidence остаются файлами проекта; тяжёлый общий knowledge runtime и переходные режимы удаляются после перевода потребителей.
- Git sync не требует соединения для обычного чтения/создания/изменения задач. Конфликтующие изменения одной задачи явно останавливают синхронизацию; история не перетирается.
- Синхронизация приватных задач не публикует их в публичный origin репозитория программы.
- Собственные подключения SQLite закрываются; заимствованные транзакции сохраняют своего владельца.
- Миграция сохраняет ID и связи, имеет проверенный backup/restore и явную карту номеров. Исторические таблицы/файлы удаляются только после успешного переноса.

## Этапы

1. TDD и исправление владения SQLite-подключениями.
2. Канонический формат задачи, V-префикс, независимая нумерация, тест двух Git-клонов и конфликтов.
3. Одна проекция, перевод task API/lifecycle/UI и поиск по файлам, удаление старого knowledge/task glue.
4. Нумерованная схема и миграция с проверкой старых данных, общих UUID и связей.
5. Проверки, самопроверка diff, применение согласованной миграции и настройка VPS-префикса; фиксация фактического состояния.

## Обнаруженные условия миграции

Read-only инвентаризация: 896 canonical task state на ноутбуке, 744 на VPS; общих UUID — 33. Есть исторические варианты проектных идентичностей. Нельзя превращать совпадающие UUID в новые задачи только из-за добавления префикса. Полные пользовательские записи не выгружены в трекаемые артефакты; метаданные для сопоставления лежат в игнорируемом data/storage-migration основного checkout.

## Прогресс

- Собственные SQLite-соединения закрываются через OwnedConnection; borrowed save_session остаётся в транзакции вызывающего. 124 теста DB/доставок прошли. Первое RED-плечо содержало 3 настоящих падения и неполную фикстуру borrowed session (исправлена).
- Новый Git TaskStore и TaskRef реализованы отдельно от старого IA. 18 тестов проверяют V/без префикса, два офлайн-клона, Git merge, CAS, идемпотентность, защиту ручных правок. Пока не подключены к боевым API.
- Следующий этап: одна проекция tm_tasks с task_origin/stable_id/task_revision/task_commit, компактный TaskRuntime; перевод tm API и удаление старого IA glue. При публикации обновления Git-first, SQL — проекция; сбой между ними восстанавливается по Git HEAD, без второй файловой очереди.
- Для начальной миграции сравнить 33 общих UUID по бизнес-содержимому; не переименовывать общую задачу по месту чтения. Политика origin: существующие общие задачи сохраняют общий ref; VPS-only и новые VPS задачи получают V.
