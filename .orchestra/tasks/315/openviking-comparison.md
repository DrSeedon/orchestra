# #315 — OpenViking mechanism comparison

Fetched 2026-08-24 from the official documentation and `volcengine/OpenViking` repository only.
The table records mechanisms, not promised product benefits. Any token/quality/latency statement in
OpenViking documentation is labelled **claim**, never treated as an Orchestra measurement.

Official context: latest GitHub release v0.4.16 (2026-08-21), repository active (2,071 commits, 169
issues, 332 PRs at fetch), main project AGPLv3; CLI/examples Apache-2.0. Recheck before implementation.

## Transfer verdict

The useful OpenViking pattern is **typed address + content/index separation + progressive projection
read + explicit session archive + validated packs**. The non-transferable parts are its assumption that
LLM-generated summaries and extraction can update memory automatically, the absence of a Git merge/CAS
contract for Orchestra task/evidence writes, and the operational cost of adopting a standalone daemon.
OpenViking's own docs and current issues show why official product claims cannot replace local proof.

## Required local proofs before implementation cutover

1. Frozen #299 migration manifest and replay parity, including stable ID and preserved project `#N`.
2. #256 18-query exact/current/rejected holdout with zero stale contradiction and source-linked facts.
3. 12 promotion scenarios: identical idempotence, conflict, supersedes, disputed, rejected, TTL,
   missing evidence, duplicate topic, stale head, rollback and two-contour sync.
4. projection read-after-write and direct canonical fallback probes; vector remains async and measurable.
5. pack export/import/restore checksum and failure rehearsal; no assumption of atomic backup.
6. privacy secret-form scan across canonical, FTS, vector metadata, prompts and logs.
