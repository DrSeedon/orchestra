# V-810 — Release or cancel quota-held initial tasks

## Findings and changes

The durable initial-delivery row already records the worker's session ID. `quota_queue.release_waiting()` resolves that session's current persisted model for each sweep, so a later sweep uses the model after a runtime change. The defect reproduced on the retry path: `/api/sessions/{name}/initial-deliveries` successfully preflighted the new model, but `accept_initial_delivery()` treated the existing `WAITING_QUOTA` row as an immutable receipt and returned its stale Claude refusal instead of releasing it.

The idempotent accept path now rechecks its caller-provided quota decision. If the current preflight passes, it atomically transitions the same row `WAITING_QUOTA → QUEUED` and wakes the existing runner. If it remains blocked, the row keeps `WAITING_QUOTA` but stores the latest reason/ETA. A successful model change also performs an immediate quota queue sweep after the new model is persisted. The sweep lock and conditional state update preserve the existing race behavior: a sweep that sampled the old model before the model change may leave the row waiting for that pass, but the post-change sweep rechecks it against the current model; a subsequent periodic pass remains the fallback if release fails.

`cancel_message_delivery` now falls back to the initial-delivery table when the direct-message ID is absent. It cancels initial tasks only in `WAITING_QUOTA` or `QUEUED`, checks the original sender for agent callers, commits the state transition atomically, and wakes the target's direct-message runner so messages queued behind the initial task can proceed. `PREPARING` and later states return `NOT_CANCELLABLE`; the provider boundary is left intact. A cancelled spawn receipt says the worker has no task and points to `send_message` or `kill_worker` for subsequent action.
