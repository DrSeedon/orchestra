# #227 — серверный model gate для worker spawn

## Результат

После активации `spawn_worker` больше не полагается на соблюдение текстового model-routing.
Политика типизированно грузится общим pipeline loader и проверяется в `SessionManager` до
создания worktree, старта backend и публикации сессии. Финальный YAML сейчас намеренно целиком
закомментирован: включение выполняется снятием `# ` с готового блока одновременно с разрешённым
рестартом Orchestra, без редактирования значений.

- Всегда разрешены `gpt-5.6-sol`, `gpt-5.6-luna`, `gpt-5.3-codex-spark`.
- Явно запрещены `claude-fable-5[1m]` и `gpt-5.6-terra`; прочие не перечисленные worker-модели
  тоже отклоняются.
- `claude-opus-5[1m]` читает только `anthropic.seven_day`. Условия независимы и соединены OR:
  темп блокируется, когда utilization опережает прошедшую долю окна на `>=11` п.п., и открывается
  при `<=7` п.п.; абсолютный потолок блокируется при `>=90%` и открывается при `<=87%`.
- Порог темпа следует из решения владельца: 5–10 п.п. опережения — нормальный расход; 11 п.п. —
  первый целый пункт вне допустимой полосы. Возврат на 7 п.п. снова находится внутри нормы и
  оставляет 4 п.п. гистерезиса. Потолок 90% напрямую резервирует последние 10% под
  оркестраторов и прогретый кеш; его deadband — 3 п.п.
- Доля окна: `1 - (resets_at - now) / 7d`. При текущих 64% utilization и 28% прошедшего окна
  опережение 36 п.п., поэтому Opus закрыт по темпу.
- Пустой, malformed, naive, прошлый или лежащий дальше семи суток `resets_at` отключает только
  pace-condition и пишет warning; абсолютный потолок продолжает работать. Codex-телеметрия не
  запрашивается и в решении не участвует.
- Роли с `kind: orchestrator` освобождены от worker policy.
- `model_policy_override_reason` работает только с непустой причиной; причина пишется в warning.
- Недоступная, malformed или зависшая телеметрия пропускает спавн и пишет error. Общий дедлайн
  чтения `/api/usage` — 12 секунд, меньше 30-секундного MCP request budget.
- Битый YAML/типизированный manifest остаётся fail-closed по существующему контракту pipeline
  loader; fail-open относится к runtime model gate и его телеметрии.

## Окно несовместимости MCP ↔ route

- **Новый MCP + старый route.** Обычный спавн не содержит нового поля и идёт прежним путём.
  При явном исключении новый MCP посылает поле, старый Pydantic request его игнорирует как extra;
  старый manager ещё не имеет гейта, поэтому спавн проходит, но причина исключения не логируется.
- **Старый MCP + новый route.** Поля нет, route подставляет `""`; новый manager применяет policy
  как к спавну без исключения. Sol/Luna/Spark проходят, быстрый/исчерпанный Claude и статически
  запрещённые модели получают 409. Исключение недоступно до реконнекта агента на новый MCP.

После мержа код manager/route начнёт действовать только после рестарта Orchestra. До него policy
остаётся закомментированной: живой процесс держит старую Pydantic-схему с `extra='forbid'`, и
новое поле роняет загрузку всего манифеста. Добавление поля в manifest — изменение контракта, не
значения: горячая перезагрузка безопасна только после того, как схема в памяти процесса уже знает
поле. Вместе с разрешённым рестартом готовый блок надо раскомментировать; после этого списки и
пороги меняются горячо, loader перечитывает YAML по `(имя, путь, mtime_ns, размер)`.

## Проверки

- Перезамороженный красный оракул нового критерия: `8 failed, 8 passed`; старый oracle разрыва
  Claude−Codex удалён как измерявший отвергнутый предмет.
- Мутации на зелёном: удаление общего вызова, pace-block и absolute-block по отдельности дали
  красный `DID NOT RAISE`; у каждой `marker-before=1`, после отдельного отката+`touch`
  `marker-after=1` и целевой тест зелёный.
- Финальный узкий регресс: `304 passed in 24.10s`; четыре изменённых Python-модуля проходят
  `compileall`, `git diff --check` чист.
- Codex review, раунд 1: blocking — у telemetry lookup не было общего timeout.
- Раунд 2 подтвердил timeout-фикс: `Re-review status: **FIXED**.` / `New findings: None.` /
  `Verdict: **APPROVED**`; независимый timeout-оракул: `1 passed in 5.73s`.
- Финальный раунд 3 по заменённому pace/reserve-критерию дословно подтвердил логику:
  `Replacement pace/reserve logic: correctly implements elapsed-window math, independent
  hysteresis, cold deadband, reset warnings, override, exemptions, and pre-side-effect
  enforcement.` Затем нашёл blocking: тёплый Anthropic-кеш старый loader ошибочно трактовал как
  недоступную телеметрию и fail-open пропускал Opus. Дословный итог раунда:
  `Verdict: **CHANGES REQUESTED**`.
- Blocking исправлен после раунда: gate теперь использует общий `current_quota_observation`,
  принимает свежий кеш, проверяет его возраст общим 300-секундным порогом и по-прежнему обновляет
  только Anthropic. Реальный warm-cache оракул трижды зелёный; мутация, снова объявляющая тёплый
  кеш недоступным, дала `DID NOT RAISE`, маркеры `before=1` / `after=1`, после отката+`touch` тест
  зелёный. Отдельный stale-cache оракул подтверждает громкий fail-open при неудаче обновления.
  Повторного вердикта нет: безусловный потолок `codex-debate` для исполняемого артефакта — три
  раунда, и он исчерпан.
- Независимый post-review нашёл второй blocking на реальном spawn seam: после fail-open нового
  гейта соседний `get_worker_admission` превращал ту же stale/unavailable телеметрию в
  `QuotaGateError`. Автофикстура тестов подменяла этот второй гейт разрешающим ответом. Исправление
  сделано на общем seam в `SessionManager`: только подтверждённое состояние `blocked` остаётся
  отказом; `unknown` и исключение проверки громко логируются и пропускают спавн. Сквозные тесты
  возвращают настоящий `get_worker_admission` поверх автоподмены и покрывают разрешающее
  warm-cache плечо, stale+failed-refresh, отсутствие кеша, timeout и исключение проверки.
  Мутация удаления обработки `unknown` вернула исходный `QuotaGateError`; маркеры до/после — 1,
  после отката+`touch` тест зелёный.
- Тот же независимый ревьюер повторил прямые `SessionManager.create_session`-пробы без autouse
  quota stub. Дословный вердикт: `APPROVED`. Его focused suite: `21 passed in 16.06s`;
  разрешены warm-normal, stale+failed-refresh, missing и slow telemetry, причём ошибки видны в
  ERROR-логе и Codex refresh равен нулю. Контрольные плечи: быстрый warm-cache расход блокируется
  новым `ValueError`, а подтверждённые 95% downstream-гейта блокируются `QuotaGateError`.

Полный suite не запускался по условию задачи. Попытка полного `tests/test_manager.py` была
остановлена как непропорционально долгая; этот прогон не используется как evidence.
