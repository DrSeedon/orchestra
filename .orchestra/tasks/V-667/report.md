Результаты собственных и oracle pytest — дословные сохранённые выводы из `runs/<метка>/{own_tests.txt,oracle_tests.txt}`. Для проверки красного плеча собственные изменённые тесты повторно запускались локально через `python -m pytest` в одноразовом worktree от соответствующей базы; patch применялся без `app/`, тесты копировались из дерева прогона. Worktree удалены после каждого запуска, исходные деревья не изменялись. Команды, worktree и return code повторных base-прогонов записаны в `.meta`. Импорт приложения шёл из созданного base-worktree; в traceback collection/import failures указан его абсолютный путь.

Контроли oracle на исходных базах и эталонных коммитах не менялись: в V-661 база дала ожидаемые красные результаты, эталон — зелёные (кроме `stall`, где тест вообще не собирается на базе из-за отсутствующего `app.stall_signals`). Использованы те же тестовые файлы и коммиты. `raw/` содержит повторные base-логи и дословные branch/oracle логи второго раунда.

Шкала та же: 0 — нет полезного результата; 1 — чтение/диагноз; 2 — заготовка без проверяемого исправления; 3 — частичное исправление или существенный пробел; 4 — основное поведение есть, но есть незакрытый критерий/проверка; 5 — критерии закрыты требуемыми тестами и отчётом. Неадаптированный oracle сам по себе не снижает балл, если он привязан к внутреннему API и не показывает дефект поведения; измеримый отказ поведения учитывается.

**Opus-high лучше medium, Sonnet наоборот — слабое описательное подтверждение только на сводных средних.** Средние баллы пяти задач за раунд 1: Opus medium 3.2, high 4.0; Sonnet medium 3.8, high 3.4.
