# V-641: что из herdr стоит перенести в Orchestra

Источник: `github.com/ogulcancelik/herdr`, `--depth 1`, клон в `/tmp/herdr-src` (0.9.1, Rust, ~300 тыс. строк, Apache-2.0: `Cargo.toml:7`, текст лицензии в `LICENSE`, файла NOTICE нет). Пути herdr — относительно корня клона; пути Orchestra — относительно `app/`. Читались только перечисленные места; сборка и запуск herdr не выполнялись.

## Главный вывод

Ядро herdr решает задачу, которой у нас нет: агент — это **TUI-процесс в PTY**, у которого нет структурированных событий, поэтому состояние выковыривается из экрана регулярками. Наши агенты идут через Agent SDK / JSON-RPC (`backend_claude.py`, `backend_codex.py`), состояние приходит событиями протокола. Переносить сканер экрана незачем. Проблемы, с которыми пришёл владелец («воркер просто стоит», «срезанные при рестарте»), herdr либо не решает, либо решает иначе и ценой, которую мы уже отвергли (#537). Брать стоит одну малую идею — «промпт без наблюдаемой активности = stalled» (строка 2).

## Ответы на три вопроса владельца

1. **«Ждёт ответа / заблокирован» без хуков.** Так: определяют процесс по foreground process group, читают низ экрана и OSC-заголовок, применяют TOML-правила (`claude.toml`), гасят дребезг working→idle тремя подтверждениями за 700 мс. Хуки нужны только для id сессии (у Claude установлен один — `SessionStart`; хуки working/blocked они **убрали**: `claude_settings.rs:20-70`, список `HOOK_REMOVALS`). У нас это неприменимо: экрана нет, а blocked закрыт авто-разрешением. «Воркер просто стоит» у нас — это RUNNING с живым backend и тишиной, и heartbeat на этом только пишет в лог (`session_hibernate.py:165`); herdr тут ничего не даёт, потому что сам не отличает «завис» от «работает». Отдельная идея вне herdr — эскалация тишины родителю.
2. **Resume после рестарта.** У нас механика уже есть и по сути та же (п.5), сильнее их. Уточнение по номеру: #537 в нашем KB — не про «срезанные ходы», а про осиротевших писателей и отвергнутый «живой adoption»; срезанные ходы обслуживает `auto_resume_all` + уведомление о рестарте. Живой handoff herdr (п.7) — путь, который #537 закрыл, и он тоже не сохраняет in-flight работу.
3. **Что даёт agent-to-agent API сверх `send_message`/`bg_create`.** Только синхронный вердикт «промпт дошёл и агент взялся (working/blocked) или stalled» и блокирующее ожидание статуса чужого агента. Первое — единственное, что имеет смысл взять (п.2). Второе перекрыто нашим авто-отчётом.

## Лицензия: что нужно для заимствования кода (Apache-2.0, `LICENSE`)

Взять код (например, идею таблицы argv или правило из TOML) можно с условиями по разд. 4: приложить копию лицензии, оставить уведомления об авторстве в скопированных файлах, пометить изменённые файлы заметным уведомлением об изменении, перенести содержимое NOTICE (в herdr его нет). Идеи и механизмы без копирования кода условий не создают. Правка лицензии Orchestra не требуется, но нужна проверка совместимости со сторонним кодом, если Orchestra распространяется как офлайн-комплект (V-638) — тогда лицензия и уведомления идут в комплекте. Для рекомендуемой строки 2 копирование не нужно: она реализуется на нашем коде.

## Ограничения

Herdr не собирался и не запускался: выводы — по чтению исходников (регионы/правила манифеста, циклы `pane.rs`, `wait.rs`). Точность самих regex-правил и поведение на живых CLI не проверялись. Цены переноса — оценки по объёму затрагиваемых файлов, не замер. Бэкенды Grok и harness на предмет blocked не читались.
