## Исследование: где проходит admission

**Подтверждено текущим кодом:** quota admission реализован обычными функциями Python внутри процесса. На штатном manager-пути они используются серверным процессом. Эти два утверждения совместимы: «на сервере» не означает «неподменяемая граница сервиса для любого прямого вызова backend».

1. `app/quota_gate.py:1017–1027` — `evaluate_worker_admission()` вычисляет решение и читает локальную policy. `:1227–1261` — `get_worker_admission()` напрямую импортирует `hub_admission` для hub-моделей (`:1231–1234`), а для своего пула импортирует `current_quota_observation` и вызывает его как функцию (`:1241–1246`), затем локально вычисляет решение (`:1256–1260`). В этом участке нет HTTP/RPC-вызова независимого admission-сервиса. Реализации импортируемых функций отсутствуют в копии, их внутренний транспорт здесь неизвестен.
2. `app/quota_gate.py:1264–1267` — enforcement в `require_worker_admission()` сводится к локальному `raise QuotaGateError` при `decision.state == "blocked"`. Это не выдача неподделываемого разрешения, которое видимый код передаёт пулу.
3. `app/manager.py:758–764` — spawn больше не отклоняется по gate собственных подписок: первое задание должно ожидать в durable `WAITING_QUOTA`; hub capacity проверяется отдельным вызовом `require_hub_capacity(model)`. Поэтому успешное создание сессии само по себе не доказывает допуск реального хода.
4. `app/manager.py:1164–1173` — preflight доставки делегируется `session.preflight_delivery_admission()`; `:1155–1158` — реальная отправка делегируется `session.send()`. `AgentSession` импортируется из `app.session` в `app/manager.py:21`, но исходник session не предоставлен. Нельзя по одному manager восстановить все проверки непосредственно перед provider submit.

**Дополнительные свидетельства из текстов тестов, не из выполненных прогонов:**

- `tests/test_mcp_quota_gate.py:47–70, 113–134` описывает клиентские API `/api/sessions` и `/initial-deliveries`, а также отказ сервера. Это поддерживает наличие серверной границы у штатного MCP-пути; реализация `app/mcp_stdio.py` не предоставлена.
- `tests/test_session.py:5103–5116` подменяет `_admission_service` на самой сессии и ожидает блокировку до создания backend. `:5120–5134` описывает разрешённые platform/system-origin ходы с закрытым gate. Backend в этих тестах — `AsyncMock`; это не доказательство реального обращения к пулу и не инструкция обхода.
- `tests/test_quota_admission_e2e.py:200–215, 220–241` описывает положительное и отрицательное плечо hub admission при spawn и смене модели, с подменённым снимком hub-пула. Это не проверяет серверную защиту собственного пула при произвольном прямом backend-вызове.

### Ответ на гипотезу V-1038 §4.2

Monkeypatch в отдельном процессе работника **не изменит** admission уже работающего сервера; штатный API-путь остаётся под серверными проверками. Но утверждение «worker script принципиально не может обойти gate, потому что единственная граница — серверный API» **не доказано**: предоставленный gate является локальным Python-кодом, а реализаций session, backend и транспорта к реальному пулу в копии нет.

Если скрипт запускает собственный backend в своём процессе и имеет прямой доступ к нашему пулу, локальный gate сам по себе не является неподконтрольной скрипту защитой. Наличие такого разрешённого транспортом доступа и отсутствие повторного admission на границе пула — необходимые, но здесь непроверенные условия. Нельзя честно объявить ни успешный реальный обход, ни его невозможность. В данной hub-копии нет полного приложения и credentials; реальный модельный вызов не выполнялся.

Для окончательного ответа нужен read-only проход по отсутствующим `app/session.py`, используемым им backend/transport, `app/hub_pool.py` и маршрутам API/очереди: проверить, существует ли прямой provider-путь и требует ли граница пула отдельный server-issued admission. Это оставшаяся исследовательская часть, без предложения менять защиту в рамках V-1041. Проверка смены модели именно у held delivery также остаётся за пределами доступного кода; наличие теста hub model change не доказывает этот контракт для всех пулов.
