# V-773 — managed Claude Bash classifier

## Изменение

`_make_pretooluse_hooks` теперь вызывает небольшой классификатор прямо в event loop. Он больше не ждёт свободный worker thread и не имеет 100-мс пути, который превращал очередь executor в fail-open. Bash-команда размером более 1 MiB (в UTF-8 байтах) явно запрещается с отдельной причиной. Это верхняя граница входа для лексера и регулярных выражений; обычные команды не получают искусственную задержку.

При ошибке разбора shell-команды и при исключении классификатора hook проверяет исходную строку на известные опасные команды. Обнаруженные `rm`, `find … -delete`, `xargs … rm -r`, `rmdir -p`, `shred`, принудительный `git clean`, `chmod 777`, `curl | sh/bash` и текущий опасный шаблон grep запрещаются. Неопасная, но синтаксически некорректная строка пропускается. Проверка пути для распознанного `rmdir -p` использует `ClaudeBackend.cwd`: цель внутри сессии разрешена, выход за worktree блокируется. Обычный `rmdir` и `git clean -n`/`git clean -nfdx` разрешены.

Проверка `rmdir -p` отслеживает простые литеральные `cd`/`pushd`; переходы через переменные, glob или `cd -` оставляют каталог неизвестным и блокируют `rmdir -p`. При ошибке разбора путь разрешается только если до `rmdir` не было `cd`/`pushd` и цель однозначна. Это сознательно консервативная граница: некорректный shell-текст с неоднозначным cwd не должен обходить проверку worktree.
