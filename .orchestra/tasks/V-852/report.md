## Встройка

Русская озвучка теперь использует Tera по умолчанию (`ru_m1`); `--voice m1|m5|f1|f2` выбирает один из четырёх голосов, Vosk выбирается через `--tts-engine vosk`. Это обновляет первоначальный default `ru_m5` по переслушанному выбору владельца: default `ru_m1`, женский вариант `ru_f2`. Tera принимает `<ru>…</ru>`, выполняет собственную разметку ударений и сохраняет ручной `+`; отдельный процесс RUAccent запускается только для Vosk. `--rate` переводится в `duration_scale = 1 / rate`. Один процесс загружает модель один раз, а две фразы синтезируются параллельно в потоках; ONNX Runtime использует шесть CPU threads. Кэш различает текст, ревизию модели, голос, темп и режим автоматического ударения. На запуске до synth/render Tera-путь проверяет символы по закреплённому `unicode_indexer.json`; `--preview-*` остаётся без загрузки TTS, `--timing-only` использует фактическую длительность WAV.

В pinned source `add_russian_stress()` возвращает `<ru>` span с `+` без автоматической разметки. Поэтому маркер сохраняется и не дублируется внешним RUAccent; при наличии маркера автоударение пропускается для всего предложения, обёрнутого одним `<ru>` span. `--stress-only` показывает нормализованный результат перед сборкой.

Прямая проба Tera-нормализации на `В 2026 году лим+ита обновляется.` вернула `В две тысячи двадцать шесть году лим+ита обновляется.`. Число было расширено, но не получило требуемое для контекста склонение; поэтому Tera-проверка, как и Vosk-проверка, требует писать числительные словами в нужном падеже. После пробы ранняя проверка make стала отклонять цифры. В сохранённой нормализации видны расширение числа и сохранение ровно одного ручного `+`.

Проверка кода: `uv run --frozen python -m pytest tests/test_video_artifact.py -q` — 30 passed. В набор входят default/alias voice mapping, запрет цифровых литералов для Tera, точная Unicode-валидация, один вызов model loader для параллельной пары фраз и сохранение порядка/таймингов для существующего pipeline. `git diff --check` пройден.

## Замер и демо

Оба движка обработали одну [четырёхшаговую HTML-сцену](tera-demo.html) с теми же четырьмя русскими фразами, `--rate 1.15`, `--stills`, `--no-check`, `nice -n 15` и сборочной очередью. В Tera явно передан `--voice m1`. Замер `stage_one_to_plan_s` начинается после чтения сцены и заканчивается готовым планом из реальных WAV-длительностей; он включает Tera-модель и bundled RUAccent либо отдельный RUAccent + Vosk для fallback. Поэтому это сравнение полного холодного пути озвучки, а не только коротких вызовов генератора.

`bench/tera/` хранит первый stills-прогон на `ru_m5`, который завершился до решения владельца о `ru_m1`; он не входит в таблицу и не является финальным голосовым образцом. Итоговое сравнение использует свежий `ru_m1` кэш в `bench/tera-m1/` и Vosk-кэш в `bench/vosk/`.

| Движок | Шаг 1 → план | От старта synthesis → план | Peak RSS по `/usr/bin/time` |
|---|---:|---:|---:|
| TeraTTSv2 `ru_m1` | 17.15 с | 17.15 с | 2,414,312 KiB (2.30 GiB) |
| Vosk speaker 1 + RUAccent | 79.84 с | 65.91 с | 2,274,368 KiB (2.17 GiB) |

Полный cold timing path с Tera занял в 4.65 раза меньше времени. Peak RSS сборки с Tera выше на 136,664 KiB (~6.1%). Это peak всего процесса сборки, а не только ONNX sampler. `pre_stage1_s` составил 16.70 с для Tera и 663.01 с для Vosk; Vosk-лог показывает ожидание сборки `part3`, поэтому wall time до запуска сцены не использую для сравнения синтезаторов. Сырые `timing.log`, `/usr/bin/time` и JSON: `bench/tera-m1/`, `bench/vosk/`.

Обе контрольные команды работали с `--no-check`, чтобы не выполнять платный Deepgram-вызов. Production-код проверки Deepgram не изменён. В этой среде также нет `DEEPGRAM_API_KEY`.

Финальная [MP4](bench/tera-m1/tera-demo.mp4) собрана с `ru_m1` из того же WAV-кэша; длительность — 15.133 с, размер — 479,840 bytes (<10 MB), H.264 + AAC, 48 kHz stereo. `ffmpeg` декодировал ролик целиком; `volumedetect` показал mean −20.3 dB и peak −4.1 dB. Просмотренный [контакт-лист](bench/tera-m1/tera-demo-contact.png) показывает четыре шага без перекрытия маркера и подписей. Полный рендер из кэша занял 154.60 с при `--jobs 2`; WAV повторно не синтезировался.
