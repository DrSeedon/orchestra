Модель выбирается турникетом, а не догадкой

Перед созданием помощника сервер один раз проверяет, что это за задача, не секретна ли она и есть ли готовая проверка результата. Затем проходит первая подходящая ветка — или система заметно отказывает.

Как объяснить это ребёнку

Представьте аэропорт: сначала проверяют билет, багаж и паспорт. Нельзя сказать «я очень тороплюсь» и пройти через другой выход. Для сложного маршрута нужно отдельное разрешение пользователя.

Ключ: подсказка может описать карту, но только серверный турникет может не пустить того, кто вызывает, с чужой моделью или секретом в Ox.

Безопасность

Барьеры, которые нельзя заменить промптом

Каждый барьер должен сработать до внешнего вызова и оставить объяснимый след.

01 / TRUST

Доверенный вход

Caller передаёт задачу, но не может подделать quota, canary или capability. Production adapter получает runtime state сам; injection — только в pure test seam.

02 / RECEIPT

Sol по пропуску

Receipt содержит task_id, scope, requester, срок, причину и receipt_id. Нет пропуска, он просрочен или для другой задачи — 0 Sol spawn/review/eval calls.

03 / ZERO-SPEND

Ox без платного сюрприза

Атомарная lease берётся до POST. Missing, positive, boolean, строка или неизвестная цена — отказ. Отсутствующая usage.cost не становится нулём.

04 / SCOPE

Рост scope — новая проверка

Если задача стала открытой или сложной, Ox/Luna eligibility сбрасывается до следующего turn. Closed work не эскалирует молча; state не теряется.

05 / ROLLBACK

Отказ виден

Revision, выбранный leaf, fallback и причина сохраняются без secret payload. Откат отключает affected class, не удаляет evidence и не возвращает скрытый Sonnet.

06 / SEPARATION

Review — отдельная поверхность

Review default не превращается в worker default. Единственное исключение — тот же обязательный Sol receipt для явного review с Sol.

Честная точка старта

Карта отделяет исполняемый owner от рекомендации в prompt. Иначе красивая схема создаёт ложное чувство безопасности.

Сейчас — baseline

Исполняется

Модель должна быть передана в spawn_worker; registry и manager проверяют canonical model и admission. HTTP omission имеет свой Sonnet default — это не worker policy.

Остаётся prompt-only

Luna/Sol/Opus рекомендации, Spark-ограничения, sensitivity, oracle и scope не связаны одним trusted decision function.

Выкатка

Не прыжок, а четыре контрольные ступени

Числа ниже — proposed acceptance gates для Phase 2, не измерения, проведённые в Phase 1.

Shadow

Сервер считает маршрут, но не меняет выбранную модель.

  • 100% случаев: ровно один leaf/refusal
  • 0 пропущенных predicates
  • 0 private задач в Ox
  • 0 Sol calls без receipt

Ox canary

Только public, text/tool, immutable oracle; без production secrets.

  • closed oracle 1.0 × 2 batches
  • open audit ≥8/10 × 2
  • 0 empty/tool errors
  • 0 positive/unknown price и cost

Preferred

Ox включается только для прошедших классов.

  • route revision + broker lease на попытку
  • считаем choice/fallback, p50/p95
  • oracle и scope-growth в наблюдаемости
  • никаких глобальных заявлений «Ox default»

Steady

Каждый маршрут объясним задним числом.

  • leaf/runtime/effort/revision
  • gate receipts и acceptance result
  • сверка локального counter с внешним usage
  • неопределённость usage показана явно

Откат сразу, если…

  • secret/private ушёл в Ox/OpenRouter
  • есть paid/unknown cost или platform 429
  • empty Ox response или artifact/oracle mismatch
  • scope вырос, а маршрут не сменился
  • Sol стартовал без scope-matched receipt
  • сломался broker, counter или capability readiness
