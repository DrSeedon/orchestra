# V-572: один SSH-маршрут, свежая карта, два личных указателя

Подготовлен канон `.orchestra/pipelines/default/prompts/skills/laptop-access.md`.
Он подключён orchestrator/sub-orchestrator/worker/full-cycle; reducer не выполняет
операции доступа и не получает новый скилл. Тело читается по необходимости, в описание
вынесен только узкий trigger. Личные файлы не менялись: [proposed/](proposed/) содержит
два коротких одинаковых указателя, а [sources.json](sources.json) — SHA оригиналов.
Внешнее применение выполняет оркестратор после одобрения, с копиями рядом.

## Проверенный сценарий доступа

13.09.2026 на VPS `ss -ltnH 'sport = :2222'` показал listener 127.0.0.1:2222.
Через SSH с ключом /home/kesha/.ssh/tunnel_laptop, IdentitiesOnly=yes,
BatchMode=yes, ConnectTimeout=5, порт2222 и maxim@127.0.0.1 получены:

- hostname maxim-911aird и успешный exit;
- system-level ssh-tunnel-vps.service: loaded/active/running;
- карта каталогов и пользователь maxim, время снимка
  **2026-09-13T14:00:29.258676+00:00** — [laptop-inventory.json](laptop-inventory.json).

Точная команда находится в каноне. Туннель устанавливает ноутбук, не VPS. SSH
даёт shell с правами пользователя; whitelist и запрета метасимволов здесь нет.
Уже успешно выполненная лёгкая составная команда с точками с запятой показывает,
что ограничение старой обёртки не является ограничением этого SSH-маршрута.
Аутентификация/транспорт обеспечиваются SSH, доступ к объектам — правами ОС;
согласованный scope и ограничения операций — инструкциями, не фиктивным sandbox.

Ничего на ноутбуке не устанавливалось, не перезапускалось и не изменялось.
Читались только имена/типы корневых каталогов, наличие .git, hostname, часы,
состояние tunnel unit и разрешение двух путей vault. Туннель не перенастраивался.
Правила бережного обращения не скопированы: в скилле ссылка на AGENTS.md Orchestra.

При отказе скилл требует сообщить наблюдаемый факт недоступности, не заявлять
неизвестную причину. Сон/выключение/сеть не различаются одним timeout/refused.
Permission denied не выдаётся за сон. Отсутствие listener устанавливается лишь
успешным ss без строк; ошибка самой проверки не считается пустым состоянием.
Реальный сон/выключение ноутбука не воспроизводились: это потребовало бы запрещённого
воздействия на рабочую машину. Проверен положительный путь, а не все причины отказа.

## Карта именно сегодняшнего состояния

В Python-корне найдено **60 каталогов и 7 обычных файлов**, в Unity — **8 каталогов**.
Файлы-журналы не названы проектами. Все каталоги перенесены из JSON в таблицы канона
без старых описаний клиентов и предположений о назначении. Маркер .git=file не
объявляется автоматически worktree: им может быть и submodule. Каталоги без маркера
не объявлены не-Git вообще; проверено только его наличие в этой точке.

В старой карте уже были некоторые названия из предварительного описания задачи.
Это не независимое подтверждение: оркестратор уточнил, что взял их из той же карты.
Новый перечень составлен из сегодняшнего снимка, не из сравнения с этим списком.

Старое утверждение «/home/maxim/Рабочий стол/Cursor/COG-second-brain не существует»
**опровергнуто проверкой**: оба пути существуют, os.path.samefile=true;
Path.resolve(home-путь) возвращает /mnt/data/Рабочий стол/Cursor/COG-second-brain.
В каноне оставлен один путь /mnt/data. Это не попытка чинить alias и не его создание.

## Почему личных исходников оказалось два

Назначение называло ~/.claude/skills/laptop-access/SKILL.md. Дополнительно найден
~/.agents/skills/laptop-access/SKILL.md — Codex-адаптация от12.09, видимая в индексе
моей сессии. Две версии расходились по **содержанию**:

- Claude: маршрут через run_on_laptop, whitelist, запрет метасимволов и тут же
  обход через python3 -c; также запуск другой сессии и устаревший background-флаг.
- Codex: уже правильный SSH, но оставлена альтернатива через обёртку, нет полной
  свежей карты. Это опровергает предпосылку «SSH нигде не описан», хотя не решает
  отсутствие единого описания для платформы.

По согласованию оркестратора имя laptop-access сохраняется. Обе личные версии
становятся указателями на канон: frontmatter + четыре строки тела, без команды,
whitelist, обхода и карты. Дубли имени в discovery могут остаться; независимых
описаний маршрута после внешнего применения не останется. До применения старые
личные тела всё ещё существуют, поэтому задача не выдаётся за применённую целиком.

Пересечение личных каталогов обследовано по */SKILL.md и frontmatter name:
18 файлов в ~/.claude/skills и 2 в ~/.agents/skills. Общих имён два:

## Что не перенесено из старых текстов

Whitelist/таймауты обёртки и python-обход отсутствуют в каноне. Run_on_laptop
упоминается лишь как недоступный платформенным агентам. Альтернативных туннелей,
Tailscale/host-alias, восстановления туннеля с VPS или запуска чужой Claude-сессии
скилл не назначает. Старые описания проектов/клиентов не перенесены по памяти.
Синхронизация Git не включена в этот read-only сценарий; SSH-доступ сам по себе
не разрешает push, деплой или рестарт. Личные оригиналы сохранены для diff,
а не как ещё один активно читаемый маршрут.
