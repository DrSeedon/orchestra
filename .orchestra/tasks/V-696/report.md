# V-696 — RUAccent перед локальным Vosk TTS

## Изменения

`make.py` пропускает русские `say` через отдельный `tts_worker_stress.py`, запущенный интерпретатором `TTS_PYTHON`. В worker используются CPU-модель `turbo3.1` и словарь; `sys.path` процесса `make.py` не меняется. Явный `--no-stress` отключает worker, английский Kokoro его не вызывает. Слова, уже содержащие ручной `+`, не отправляются автоматике, поэтому заданная владельцем гласная сохраняется. Ключ WAV-кэша включает фактический текст для синтеза с `+`; прежние записи с другим произношением не совпадают по ключу. Подпись в кадре убирает `+` автоматически; сам marker остаётся только для синтеза и проверки ASR. Если пакет отсутствует, сборка завершается сообщением с командой установки.

## Follow-up: отдельный процесс и экранная подпись

Ручная разметка остаётся в `say` для синтеза, но `VOICE_JS` удаляет `+` из текста, который видит зритель. RUAccent запускается как отдельный subprocess через `TTS_PYTHON`: список фраз передаётся JSON через stdin, размеченный список возвращается в stdout. Отсутствие RUAccent worker сообщает marker на stderr; `make.py` превращает его в прежнюю подсказку по установке. Установка на VPS и ноутбуке остаётся в том же TTS-venv.

Короткая проба на VPS выполнена настоящим процессом (без рендера видео):

| Вход | Результат worker | Проверка |
|---|---|---|
| `Шлюз задерживает запуск новых воркеров до исчерпания лимита.` | `…лим+ита.` | автоматическая метка получена |
| `П+осле проверки продолжаем.` | `П+осле пров+ерки продолж+аем.` | ручной marker сохранён, остальные слова размечены |
| `Вы описываете задачу оркестратору обычными словами.` | `…оркестр+атору…` | OOV получает автоматическую метку |

Логи и команда этой пробы: [live-check.log](live-check.log), [live-check.py](live-check.py).
MP4 V-696 не перерендеривались; ранее созданные копии и Deepgram-отчёт остались без изменений.

## Сравнение ударений для 17 фраз V-690

Позиции — порядковый номер гласной в слове, считая с единицы. Словарь Vosk выбран так же, как в коде `vosk_tts.Model`: максимальная вероятность; при равенстве остаётся первое вхождение. `OOV` означает, что слова нет в словаре.

| Слово | Vosk | RUAccent | Вывод по фразе |
|---|---|---|---|
| `Оркестра` | ударение на 2-й гласной (`е`) | `Орк+естра`, 2-я | совпадают; не включено в различия |
| `репозитория` | 3-я и 5-я гласные (`и`, обе помечены в словаре) | `репозит+ория`, 4-я | различаются; словарная запись Vosk содержит две ударные гласные |
| `оркестратору` | OOV, явного ударения нет | `оркестр+атору`, 3-я | RUAccent добавляет ударение для OOV |
| `Оркестратор` | 3-я (`а`) | `Оркестр+атор`, 3-я | совпадают; не включено в различия |
| `После` | 1-я (`о`) | `Посл+е`, 2-я | ошибка автоматики в этой фразе; для итогового рендера вручную задано `П+осле` |
| `История` | 2-я (`о`) | `Ист+ория`, 2-я | совпадают; не включено в различия |
| `Аналитика` | 3-я (`и`) | `Анал+итика`, 3-я | совпадают; не включено в различия |
| `лимита` | 3-я (`а`) | `лим+ита`, 2-я (`и`) | RUAccent исправляет подтверждённое неверное ударение словаря Vosk |
| `уже` | 1-я (`у`) | `уж+е`, 2-я | различаются; контекст фразы — «уже подключёнными», где ударение на `е` |

Сверка считает именно фонемные маркеры модели и `+` RUAccent; Deepgram измеряет распознанные слова и тайминг, но не правильность ударения. Все строки автоматики сохранены в [stress-differences.json](stress-differences.json); пять фактических различий после учёта регистра перечислены в таблице.

В исходной фразе `После проверки…` RUAccent передвинул ударение с первой гласной на последнюю, хотя Vosk-словарь даёт нормативное `по́сле`. Для итоговой пробы создана копия сцены [orchestra-tour.html](orchestra-tour.html): только в этом слове `say` задано как `П+осле`, а `sub` оставлен без маркера. Остальные слова автоматически обрабатываются RUAccent. Страница использует базовый относительный путь к неизменённым медиа V-690.
