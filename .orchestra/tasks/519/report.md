**83 из 107 якорей вида `app/<file>.py:N-M` в `01`, `02`, `05`, `06` сместились.** Измерено
скриптом: для каждого якоря сравнивался текст строк `N..M` в `fbed73a3` и в `main`; 24 совпали
дословно, 83 нет (часть — чистый сдвиг, часть — переписанный код). Массовое переписывание якорей

каждый якорь проверяемым и честным. Если владелец захочет перевести якоря на `main` — это
отдельная работа с осознанной ценой повторного протухания.

## Самопроверка: собственная ошибка замера, пойманная и исправленная

Первый вариант `04-stack.md` заявлял 18 089 tracked-файлов, 1 433 540 строк и 11 файлов в
`docs/**`. Это неверно: команды счёта запускались ПОСЛЕ `git checkout f0237603 -- docs/portfolio/`,
поэтому шесть файлов самого портфолио уже стояли в индексе и попали в собственный срез.
Сверка с деревом-пином вскрыла расхождение ровно на 6 файлов и 481 строку:

```console
$ git ls-tree -r --name-only a1fd56bb | wc -l
18083
$ git ls-tree -r --name-only a1fd56bb -- docs | wc -l
5
```

Исправлено на 18 083 / 1 433 059 / 5, в текст добавлена явная оговорка, что шесть файлов
портфолио в срез не входят и добавляют к нему 6 файлов и 481 строку. Производное число в
`06-resume-lines.md` поправлено следом.

Урок для самого замера: пересчитывать репозиторий, стоя в дереве, которое ты сам уже изменил, —
значит мерить себя. Пин на `a1fd56bb` (родительский HEAD) снимает это.
