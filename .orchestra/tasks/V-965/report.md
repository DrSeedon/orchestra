# V-965 — shot и Coverage на дашборде Orchestra

## Краткий вывод

`shot` — отдельный инструмент для наблюдения и показа действий на экране Mac: он дополняет браузерные тесты, но не заменяет Playwright. В текущей первой загрузке дашборда Chrome использовал 46,6% JavaScript и 27,8% CSS по покрытию UTF-16-единиц исходника после 6 секунд ожидания; это покрытие только одного маршрута и одного состояния, а не доказательство мёртвого кода. Доля неиспользованного кода указывает на возможную пользу от отложенной загрузки отдельных экранов, но решение об изменении приложения — отдельная работа.

## Что проверено

Исходник `davekiss/shot` клонирован и прочитан на commit [`617bd790217edeb9e237a619bae4ad0d7c37cd50`](https://github.com/davekiss/shot/tree/617bd790217edeb9e237a619bae4ad0d7c37cd50), от 18.10.2026; в `claude-mod/.claude-plugin/plugin.json` указана версия 0.1.9. Лицензия репозитория — MIT. В `Package.swift` задан macOS 13+, а реализация использует AppKit, Vision, ScreenCaptureKit, AVFoundation и `/usr/sbin/screencapture`; это не Linux-инструмент для текущего VPS.

`shot` предоставляет MCP-сервер по stdio и конфигурацию для Codex, а не только Claude Code-плагин. Нужное приложение-оболочка на Mac требует разрешения Screen Recording. Инструменты включают захват экрана/окна/области, OCR, компоновку и аннотации по найденному тексту, затемнение найденных секретов, сравнение двух снимков, короткую запись с раскадровкой, показ указателей поверх живого окна и поиск по библиотеке скриншотов. Опциональное описание скриншотов моделью выключено по умолчанию и может отправлять изображения Claude; его включение добавляет внешний модельный вызов. Первичные источники: [`README.md`](https://github.com/davekiss/shot/blob/617bd790217edeb9e237a619bae4ad0d7c37cd50/README.md), [`Package.swift`](https://github.com/davekiss/shot/blob/617bd790217edeb9e237a619bae4ad0d7c37cd50/Package.swift), [`LICENSE`](https://github.com/davekiss/shot/blob/617bd790217edeb9e237a619bae4ad0d7c37cd50/LICENSE), [конфигурация MCP](https://github.com/davekiss/shot/blob/617bd790217edeb9e237a619bae4ad0d7c37cd50/claude-mod/.mcp.json).

## Измерение Coverage

**Контракт замера:** загрузить `/` дашборда один раз в новом Chromium-контексте с авторизованной сессией, дождаться `load`, затем дать интерфейсу 6 секунд на стартовые запросы. Снять JavaScript precise coverage и CSS rule usage через Chrome DevTools Protocol. Учитывались только CSS/JS, загруженные с `127.0.0.1:8888`; coverage — исполненные диапазоны исходника в покрытии данного экрана за это окно времени. Визуальные панели не открывались и действия не выполнялись.

**Окружение:** 19.10.2026, активная локальная Orchestra на `127.0.0.1:8888`, service user `kesha`; Chromium headless, viewport 1440×900, контекст без прежнего browser cache. Сессионный HMAC вычислялся процессом из локального `.env` и не печатался. После обнаружения сетевого `POST /api/owner-activity/events` в повторном замере он блокировался в браузере до отправки; повторный Coverage зафиксировал один заблокированный POST. Это событие содержит metadata присутствия, а не текст сообщений.

| Тип | Загружено исходника (UTF-16 единиц) | Исполнено/использовано | Не использовано в этом замере |
|---|---:|---:|---:|
| JavaScript | 1 001 672 | 467 226 (46,6%) | 534 446 (53,4%) |
| CSS | 115 143 | 32 043 (27,8%) | 83 100 (72,2%) |

CDP диапазоны индексируются в UTF-16. Первый черновой расчёт использовал индексы Python-кодпоинтов; после обнаружения этой несостыковки скрипт был исправлен и Coverage повторён. Таблица выше использует UTF-16 диапазоны. При отдельном повторном замере navigation timing составил FCP 204 мс, DOMContentLoaded 206,8 мс, load 223,9 мс. Сумма `encodedDataLength` для 22 статических CSS/JS-ресурсов была 330 498 байт; это сетевой размер ответа с gzip, а не сумма исходных байтов.

Большой объём неиспользованного CSS сосредоточен в `style.css` (19 186 из 83 810 UTF-16 единиц использовано) и CSS Tailwind (8 644 из 21 146 использовано). Из JS заметны `analytics.js` (1 049/45 098) и `jobs-timeline.js` (2 374/16 140); это кандидаты на проверку отложенной загрузки, но они могут понадобиться после перехода на соответствующие панели. Само по себе покрытие на одном маршруте не даёт основания удалять код.

Замер выполнен скриптом [coverage.py](coverage.py); числа агрегированы в таблице выше. Исходный JSON с URL внутренних файлов и скриншот панели после чтения удалены из рабочей папки и не входят в коммит.

## Дополнительный неполный эксперимент: перенос синхронных скриптов из `<head>`

Чтобы проверить, даёт ли освобождение HTML-парсера видимый выигрыш, вариант B локально переписывал только HTML-ответ `/`: пять синхронных `<script>` (`i18n`, `marked`, `purify`, `diff_match_patch`, `highlight`) переносились перед `theme.js` в конце `<body>`. Файлы сервера не менялись. Пять холодных контекстов на комбинацию; метрики ниже — медианы из частичного прогона. Сравнение для slow-режима не завершено.

| Профиль (CDP) | A FCP / DCL / load, мс | B FCP / DCL / load, мс | Наблюдение |
|---|---:|---:|---|
| LAN, CPU 1× | 144 / 150 / 152 | 124 / 176 / 178 | FCP −20 мс, DCL/load +26 мс |
| LAN, CPU 4× | 676 / 768 / 795 | 524 / 769 / 799 | FCP −152 мс, DCL/load почти без сдвига |
| 4G 1,6 Мбит/с, CPU 1× | 1 404 / 2 063 / 2 072 | 652 / 1 968 / 1 977 | FCP −752 мс, DCL/load −95 мс |
| 4G 1,6 Мбит/с, CPU 4× | 1 556 / 2 112 / 2 142 | 740 / 2 003 / 2 036 | FCP −816 мс, DCL/load −106 мс |

Это указывает, что блокирующие загрузки задерживают первую отрисовку при эмулированном 4G, но перенос почти не меняет DCL/load: выполнение скриптов всё ещё происходит до завершения загрузки документа. Эффект на FCP заслуживает отдельной проверки; из-за частичного набора условий и возможной нагрузки на живую панель не предлагаю менять шаблон по этим данным.

**Сбой процедуры и побочный эффект:** первый timing-процесс был запущен до добавления блокировки POST и остановлен после четырёх пар профилей (LAN CPU 1×/4×, 4G CPU 1×/4×). В этой версии браузер мог записать события присутствия в рабочую таблицу `owner_activity_events`; точное число не собиралось. Я не удалял строки из живой БД. Timing JSON из отменённого процесса не был записан. После исправления blocker Coverage прошёл с `blocked_presence_posts = 1`; timing повторно не запускался.

## Итог

`shot` стоит рассматривать как Mac-инструмент, чтобы агент видел и объяснял то, что отображается на настоящем экране; для дашборда это вспомогательное средство визуального исследования. Playwright остаётся правильным местом для повторяемых CI-проверок. Замер Coverage выявил крупную долю стартовых ресурсов, неиспользованных на первом экране, а перенос head-скриптов в частичном прогоне улучшил только FCP. Ни зависимость, ни конфигурация, ни код приложения в рамках исследования не менялись.
