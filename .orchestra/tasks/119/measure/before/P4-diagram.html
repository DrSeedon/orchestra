Путь задачи через оркестратор

Задача идёт по одной прямой: пользователь → оркестратор → воркер в своём worktree → ревью → squash в main. Из этой прямой есть ровно два выхода — ревью не прошло (возврат к воркеру, ветка живёт) и воркер упал (оркестратор поднимает работу из worktree). Оба возвращают задачу в ту же прямую, а не открывают новую.

Что держит прямую

  • Один воркер — один worktree — одна ветка task-<id>/<name>.
  • В main пишет только оркестратор и только через merge_worker.
  • DONE возможен лишь при чистом git status: незакоммиченного не существует.

Ревью не прошло

  • Мержа не было — main не изменился, откатывать нечего.
  • Воркер живой и с контекстом: правки дешевле, чем спавн нового.
  • Круг повторяется до зелёного ревью; каждый круг — новые коммиты поверх.

Воркер упал

  • Первым делом квота (/api/usage), а не «сломалась инфраструктура».
  • Worktree переживает падение: сделанное достаётся через worker_wip.
  • Задача возвращается оркестратору целой — потерять её падение не может.
