## 2. Что переносим — принципы, дающие РАЗНООБРАЗИЕ

Правило отбора: берём то, что заставляет артефакты отличаться друг от друга; не берём ни одного
готового набора цветов. Источники: `visualize.css` (Apache-2.0) и `## Frontend guidance` gpt-5.5.

| Переносим | Откуда | Почему это разнообразие, а не второй хардкод |
|---|---|---|
| **Палитра выводится под тему артефакта**: 2 базовых токена (`--bg`, `--ink`) + акцент, подобранный под предмет; всё остальное — `color-mix()` от них | приём `visualize.css` (`--card`, `--muted` выведены из `--foreground`) | сейчас в файле лежит готовый `#7c3aed` на всё; станет — правило выбора |
| **Запрет одноцветных палитр**, дословно перечислены фиолетовый/фиолетово-синий, беж, тёмно-синий, коричневый + «просканируй CSS перед сдачей» | gpt-5.5 | прямо убивает наш дефолт |
| **«Vary themes, type families, and visual languages across outputs»** | gpt-5.4 | единственная фраза, адресующая жалобу «все одинаковые» буквально |
| **Типографская шкала от одной базы** (`h1 = base × 1.714`, `h2 × 1.429`, `h3 × 1.286`) | `visualize.css` | иерархия появляется вычислением, а не подбором на глаз |
| **Шкала радиусов от одного `--radius`** (`sm .6 / md .8 / lg 1 / 2xl 1.6`) | `visualize.css` | то же |
| **Тень = состояние, не украшение**: `box-shadow` только для фокуса/выделения (`inset 0 0 0 1px var(--ring)`), высота — максимум одна `--shadow-sm` | наблюдение из моей таблицы (12 использований, 9 — фокус-кольца) | у нас тень сейчас просто запрещена в anti-patterns; правило «можно, но как состояние» полезнее запрета |
| **`:focus-visible` через `--ring` на КАЖДОМ интерактивном элементе** + `.sr-only` | `visualize.css` | у нас не упомянуто ни разу |
| **`light-dark()` + `color-scheme` вместо дублирующего media-блока**, `:root[data-theme]` для ручного переключателя | `visualize.css` | минус дубль в каждом артефакте |
| **Плотность под жанр**: отчёт/дашборд — «quiet, utilitarian», плотно и для сканирования; без hero-секций и декоративных карточек | gpt-5.5 | |
| **Карточка не внутри карточки; секции не оформляются плавающими карточками** | gpt-5.5 | |
| **Кегль под контейнер; текст обязан влезать на всех вьюпортах; `letter-spacing: 0`; не масштабировать кегль от ширины вьюпорта** | gpt-5.5 | |
| **Серии графиков — ПРАВИЛО**: 6 различимых тонов, разнесённых по кругу, каждый задан для светлой и тёмной темы | `--viz-series-1..6` | берём требование, не их шесть хексов |

**Не переносим:** готовые хексы серий; Floating UI и lucide с unpkg (ломает «работает офлайн»);
`#widget`, `html > body { background: transparent }`, `::codex-inline-vis` (привязка к их рантайму);
правила про лендинги, hero, Three.js, дев-сервер, Playwright; плагин `openai-templates` (Proprietary).

## 3. Лицензия

**Дословный CSS в скилл не попадает вообще** — переносим принципы своими словами, а выражение
(конкретные значения, имена токенов, порядок правил) не копируем. Тогда атрибуция в скилле не нужна,
и чужой бренд никуда не тащится.

Вербатим-копия остаётся ровно там, где она уже лежит и уже атрибутирована:
`docs/tasks/119/extracted/upstream-visualize.css` + источник, URL и лицензия в `research.md`.
**Если при реализации окажется, что какое-то правило без дословных значений теряет смысл** — тогда
и только тогда этот фрагмент едет с шапкой `© OpenAI, Apache-2.0, <URL>, снято 05.08.2026`, и это
отдельно отмечается в отчёте. Названия продуктов OpenAI в тексте скилла не используем.

## 4. Размер — твоя предпосылка неверна, и это меняет бюджет

> «Файл читают ВСЕ воркеры при каждом спавне»

Так было в старой архитектуре (`read_skills_content` вклеивал тело в системный промпт). **Сейчас нет.**
Всегда оплачивается только **description**, тело читается по требованию:

- Codex/Sol — в промпт уходит одна строка индекса; заголовок индекса прямо говорит
  «The entries below are an index, not loaded instructions» (`app/prompting.py:157`).
- Claude — файл кладётся как нативный скилл в `.claude/skills/`, CLI грузит описания, тело читает при срабатывании.

Замер сейчас: **тело 2 335 Б, description 55 символов** (глобальный: 12 046 Б / 801 символ).

**Целевой бюджет:**

| | сейчас | цель | почему |
|---|---|---|---|
| description | 55 симв. | **≤ 250 симв.** | платится в каждой сессии трёх ролей; глобальные 801 — перебор, но 55 не описывают триггеры |
| тело | 2 335 Б | **≤ 6 000 Б** | платится только при срабатывании; 12 046 глобальных не нужны без `references/` |

**Что выкидываем, чтобы влезть** (иначе тело уедет за 8 КБ):
- секция `## When NOT to use` — дублирует description, уходит в него;
- `## Where to save` + `## After saving` — 8 строк схлопываются в 3;
- литеральный CSS-блок `## CSS base` (~350 Б хексов) заменяется правилами вывода — чистый выигрыш;
- дефект нумерации: в текущем файле два пункта «2» подряд (`Single .html file` и `Works offline`), правится заодно.

`references/` через нынешний механизм **доставить нельзя**: `inject_skills_to_worktree` копирует
ровно один `<name>.md` в `SKILL.md`, поддержки каталога нет. Расширять инжектор — правка общего
рантайма ради косметики; **не предлагаю в этой задаче**, выношу как отдельный вопрос к тебе.
