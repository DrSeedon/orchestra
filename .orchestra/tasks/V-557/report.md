## Утверждённый контракт

При постановке задания или уточнения указывай результат, наблюдаемый критерий приёмки,
существенный контекст и явные границы. Закрытая задача определяет правильный результат,
но не обязывает постановщика выбирать инструменты и последовательность. Для открытого
вопроса задай вопрос и нужные доказательства, не подставляй готовый вывод.
Предписывай метод только по требованию владельца, когда исследуется сам метод либо он
необходим для названного ограничения безопасности или внешнего контракта; объясни причину.
В остальных случаях путь выбирает исполнитель. Свобода метода не расширяет полномочия.

В самом модуле следом стоит короткое основание V-548/V-550: все пять моделей завершили
одну проверенную задачу за ход после снятия маршрута и двусмысленности при обрезке;
стоимость Opus/Fable снизилась в 7.5–8.8 раза. Коэффициент относится только к этому опыту.
Полный английский текст для агентов — в активном worker-lifecycle; точный diff сохранён в patch.

## Почему это место и что заменяется

Текущий `pipeline.yaml` и сборка `app.pipeline.build_system_prompt` показывают:

| Роль | Может выдавать задания | Получает worker-lifecycle | Получает orchestration |
|---|---|---|---|
| orchestrator | да | да | да |
| sub-orchestrator | да | да | да |
| full-cycle | да | да | нет |
| worker | нет | нет | нет |
| reducer | нет | нет | нет |

Поэтому владелец правила — существующий раздел постановки в `worker-lifecycle.md`.
Размещение только в `orchestration.md` не достигло бы full-cycle. Base платят все роли;
ещё один модуль, скилл или изменение манифеста для этой задачи не нужны. Это общие
pipeline-промпты, а не корневые инструкции разработчиков одного проекта. Пользовательский
pipeline, который не подключает эти модули, не покрывается этой правкой автоматически.

Предложенные замены:

- `worker-lifecycle`: вводный раздел с длинным пересказом #219 заменён контрактом задания,
  основанием V-550 и коротким сохранением причины задавать схему из #219. Колонки,
  определение подсчёта, границы выводов ребёнка и ответственность родителя сохранены.
- Там же требование `cmd > ... 2>&1` заменено проверяемым результатом: подлинный вывод
  команды дословно в файле, без ручного пересказа. Основание #230 сохранено.
- `orchestration`: удалён Step 1.5 с прямым предписанием закрытой задаче «do X using Y».
  Смысл открытого вопроса перенесён в единый контракт. Строка Step 1 отсылает туда.

В предлагаемом diff `orchestration.md`: 19 780 → 19 305 байт;
`worker-lifecycle.md`: 3 223 → 3 808 байт; суммарно +110 байт. Это модули, не корневые
AGENTS/CLAUDE. Корневые файлы не изменены: каждый 13 460 байт < 16 KiB; base — 5 985 байт.
