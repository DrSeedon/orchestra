# V-674 — claude.dev: идеи и сопоставление с Orchestra

Дата проверки: 2026-10-01. Объём: публикации claude.dev по моделям, агентам, оркестрации, контексту, стоимости, evals и Skills; сопоставление с текущими `app/`, промптами и локальными замерами. Это исследование, изменений кода и промптов нет.

## Выводы

1. **Sonnet 5.5 по умолчанию подтверждён для ограниченных задач — качественно обеими сторонами.** Anthropic рекомендует Sonnet 5.5 для чётко заданной повседневной работы и отдельно оставляет Opus для сложных задач, где нужно суждение. Наши V-667 задачи — трудные и выполнены при medium: Sonnet получил 3,9/5 против Opus 3,6/5 в двух раундах, с 16К выходных токенов против 35К. Это поддерживает текущую маршрутизацию для типичных задач Orchestra и сохраняет исключение Opus для случаев с доказанной нуждой в более глубоком поиске причин.

2. **Проценты экономии Anthropic не подтверждены как универсальные числа.** Их «до 30%» для Sonnet 5.5 относится к сравнению с Sonnet 5; «около 40%» для Opus 5.5 против Opus 5 — оценка типичной нагрузки при medium, включающая предположение о меньшем числе токенов. Наш V-656 увидел на двух ограниченных задачах $2,37 против $9,54 и 21 против 41 минуты для Sonnet 5.5 и Sonnet 5 — экономия в этой выборке составила около 75%, а не 30%. V-667 сравнивал Sonnet с Opus по качеству, выходным токенам и времени, но не даёт сопоставимой полной суммы долларов на задачу. Разные выборки, настройки и способы учёта не позволяют ни подтвердить, ни опровергнуть vendor-оценки напрямую.

3. **Формулу стоимости cache нужно отдельно сверить с режимом тарификации.** Статья Sonnet 5.5 даёт cache-read $0,20/млн для Sonnet и Opus 5.5. Наш `backend_claude.py` рассчитывает его как 10% input для всех Claude-моделей: для Opus 5.5 с input $4/млн это $0,40/млн. Формула cache-create в том же месте использует 125% input — это опубликованная ставка пятиминутной записи, тогда как KB V-656 считает задачи по ставке записи на час (2× input). Значит, расчёт `cost_usd_cached` для Opus может завышать read-rate, а для часового cache-create занижать write-rate. Это различие публичного API-equivalent расчёта; оно не доказывает ошибку отображения подписочной квоты. Перед исправлением нужно установить, какой режим должен отображать поле и к каким рядам usage применяется.

4. **Контекстные рекомендации Anthropic полезны как гипотезы, а не разрешение ослабить наши правила.** У нас уже есть разнесение по ролям, выборочные Skills и отдельные модули. Но системные требования безопасности, полномочий, сохранения данных, поведения при ошибках и lifecycle сформированы владельцем и локальными инцидентами. Их нельзя удалять на основании vendor-замера, сделанного на другом продукте, моделях и eval-наборе. Возможная цена короткого эксперимента с менее обязательными повторами/дублированием в обычных инструкциях — ниже контекстный объём; риск переноса на критичные правила — регрессия поведения, которую нельзя оценивать лишь по длине промпта.

5. **Сильнее всего переносимы процедуры измерения:** репрезентативные задачи, повторяемость, контроль шума, скрытая test-часть, чтение сырых трасс и разделение train/test. V-667 уже показал разброс оценок от −1 до +3 между раундами при близком описании решения; это прямой аргумент за такие меры при будущих сравнениях. Цена — квотные расходы и время на повторные прогоны; автоматическое hillclimbing промптов или harness в этой задаче не проводилось.

## Факты и интерпретации о стоимости

**Опубликовано Anthropic:** [статья о Sonnet 5.5](https://claude.dev/blog/building-with-claude-sonnet-5-5/) даёт Sonnet 5.5 — $2/млн input, $10/млн output, cache-write $2,50 (5 минут) / $4 (1 час), cache-read $0,20; Opus 5.5 — $4/$20, cache-write $5/$8, cache-read тоже $0,20. [Статья о стоимости Opus 5.5](https://claude.dev/blog/what-a-task-costs-on-opus-5-5/) говорит о снижении input/output на 20%, cache-read на 60% относительно Opus 5, и оценивает типичную стоимость задачи примерно на 40% ниже при своих default settings. Это последнее — оценка типичной нагрузки, а не ставка по токенам.

**Наши замеры:** V-656 сравнивал Sonnet 5.5 с Sonnet 5 на двух ограниченных задачах, в изолированном клоне, с официальными тарифами и 1-hour cache writes; V-667 сравнивал Sonnet 5.5 и Opus 5.5 на пяти трудных задачах, двумя раундами и ручной оценкой по критериям. Sonnet medium оказался в среднем равным или выше по оценке, с примерно вдвое меньшим output. У V-667 значительный шум между единичными прогонами; стоимость в $ по ячейкам отдельно не приведена. См. `.orchestra/kb/models-and-quotas.md:684-718`.

**Интерпретация:** Anthropic и Orchestra сходятся в дефолтном выборе Sonnet для хорошо ограниченных задач; V-667 даёт более прямое локальное основание для этой политики, чем vendor statement. Vendor-проценты экономии относятся к другим сравнениям и не служат численным прогнозом для наших задач. Чтобы сравнить общий расход на задачу, нужны одинаковые входные задачи, effort, число попыток и раздельный учёт всех типов токенов/кеша.

## Проверяемое расхождение в нашем учёте cache

`app/models.py:61-74` задаёт Opus 5.5 input price $4/млн и Sonnet 5.5 $2/млн. В `app/backend_claude.py:1457-1460` cache-read формула умножает input price на `0.1` для всех Claude моделей: она выводит Opus cache-read $0,40/млн и Sonnet $0,20/млн. В тарифной таблице [Building with Claude Sonnet 5.5](https://claude.dev/blog/building-with-claude-sonnet-5-5/) cache-read равен $0,20/млн для обеих моделей.

Та же строка формулы оценивает cache-create как 125% input. Это совпадает с пятиминутной ставкой из таблицы (Sonnet $2,50/млн, Opus $5/млн), но не с часовой ставкой (Sonnet $4/млн, Opus $8/млн), которую KB V-656 использует в модельных прогонах. При часовой тарификации формула была бы ниже на $1,50/млн Sonnet cache-create и на $3/млн Opus cache-create. Это может смещать API-equivalent cost reports в обе стороны; сначала требуется определить контракт именно этого поля и фактически применяемый cache TTL. Не менял учёт в рамках исследования.
