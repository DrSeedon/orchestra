#V-620. Дефект платформы, воспроизведён 23.09 в проекте katya-work: после merge_worker(task_outcome="continue") воркер остаётся привязан к задаче навсегда, если новых коммитов больше не будет. Дословно: switch_worker_branch → `domain_error: branch switch rolled back after task assignment failed: ValueError: open task run conflicts with current assignment provenance` (то же с force=True); merge_worker(task_outcome="complete", next_task_id=...) → `FAILED — target branch 'main' and worker branch 'task-V-5/struktura-ege' point to the same commit; refusing to merge the worker branch into its target`. worker_wip при этом чист, expected_head совпадает с worker_head, задача числится in_progress.

Решение выбрано владельцем (вариант C), менять его не нужно: чиним СО СТОРОНЫ switch_worker_branch — он сам закрывает открытую привязку, когда воркер простаивает и дерево чисто (нет незакоммиченного и нет несмерженных коммитов). merge_worker не трогаем: его отказ «ветка равна main» остаётся, пустых служебных коммитов не заводим, новых типов квитанций не добавляем.
По умолчанию перевод ОСВОБОЖДАЕТ воркера: прогон задачи завершается как освобождённый, сама задача возвращается в открытое состояние и остаётся в очереди. Плюс явный аргумент, которым оркестратор говорит «прежняя задача выполнена»: он закрывает её как done и требует непустое основание.

Критерии приёмки: тест воспроизводит клинч (краснеет на коде без правки, зелёный с правкой); тесты на оба плеча (освобождение и закрытие с основанием); отрицательные — грязное дерево и несмерженные коммиты привязку не снимают; обычный complete с реальными коммитами работает как раньше; тесты затронутых модулей зелёные — python -m pytest, абсолютный путь импортированного app в отчёте. Отчёт .orchestra/tasks/V-620/report.md и строка в CHANGELOG.

Границы: боевую БД и боевое хранилище задач не трогать (только временные копии с явными путями); чужие ветки и проекты не трогать; рестарт Orchestra не делать. Закоммить результат.
