# V-775. Возможности API Anthropic для Orchestra

Исследование, без правок кода и правил. Дата 08.10.2026. Источники: docs platform.claude.com (pricing, batch, prompt caching, advisor tool, managed agents, rate limits), живые пробы на ключе `ORCHESTRA_CLAUDE_CREDIT_API_KEY`. Ключ нигде не печатался и не коммитится. Скрипты — `scripts/` рядом с отчётом, сырые результаты — `data/v775/` (gitignored).

## Короткий вердикт

1. **Batch брать**, но как инструмент для разовых больших прогонов, не как каркас платформы. На триаже тендеров Seedon он реально работает (300 строк за 9,4 мин, 300/300 успешно). Экономия в абсолютных долларах мала: все 151k закупок на Haiku batch — около $3,9.
2. **Advisor не брать.** На двух тяжёлых задачах с oracle он не поднял балл, а при вызове советник даёт около 95% стоимости прогона. Исполнитель (Haiku) вызывает советника редко.
3. **Prompt caching работает без каких-либо включений.** Строка «Not enabled» в Console не блокер: проба показала `cache_creation 4819`, затем `cache_read 4819` на этом же ключе. Что именно значит строка — UNKNOWN (гипотеза: «ещё не было кешированных обращений»); Console я не вижу, пусть владелец сверит.
4. Остальное большей частью «не брать» или «уже есть»; исключения — structured outputs, token counting, Usage/Cost API (дёшево и полезно).
5. План трат $200 — в разделе 5. Главная статья — запасной режим воркеров (V-774), остальное мелко: деньги придётся сжигать осознанно.

## 2. Batch

Кейс: база тендеров Seedon (`tender-collector.sqlite3`, read-only): 151 074 закупок, 58 506 в куче «Ключевого совпадения нет; требуется ручная проверка» (45 073 с ценой), около 106k новых за 7 дней. Эксперимент: 300 случайных строк из кучи (цена 30k–10M), один и тот же промпт, ответ да/возможно/нет.

| | Haiku 5.5 batch | Sonnet 5.5 batch |
|---|---|---|
| 300 строк | ≈ $0,008 | ≈ $0,145 |
| результат | 290 нет / 9 возможно / 1 да | 291 / 8 / 1 |
| время | 9,4 мин на оба пакета (08:55→09:04 UTC), 300/300 успешно | |

Совпадение моделей 299/300. Единственное «да» — реальный пропуск ключевого поиска: «разработка раздела корпоративного портала Минэнерго России «Сервис сквозного контр…»». Экстраполяция: вся куча 58,5k — Haiku ≈ $1,5, Sonnet ≈ $28; все 151k на Haiku ≈ $3,9. Без Batch цена вдвое выше.

Вывод: Batch подходит, асинхронность допустима, но экономия в долларах — единицы. Ценность не в деньгах, а в закрытии слепого пятна (сейчас эта куча не читается вообще). Рекомендация: триаж кучи Haiku batch, «возможно»/«да» отдать второй проверкой Sonnet. Сухая экстраполяция показывает точность ~99%, но 1 «да» на 300 — слишком мало, чтобы оценить полноту; нужна ручная разметка выборки (оценка качества не выполнена).

Прочие кандидаты: грейдеры/оценщики замеров Orchestra (V-758 использовал Luna-грейдеров), холодный архив (21 823 лога, 54 МБ), анализ документации тендеров. Не нужен Batch там, где результат нужен сразу, — запасной режим воркеров.

## 3. Advisor — живой эксперимент

Задачи с oracle из V-758: pidfd (V-543, 9 тестов) и ident (V-575, 16 тестов). Ветки: H — Haiku 5.5 low голый; HO — Haiku low + советник Opus 5.5; HS — Haiku low + советник Sonnet 5.5; S — Sonnet 5.5 medium голый. 3 повтора. Цикл агента — минимальный bash-tool на Messages API (`scripts/agent.py`), стоимость по `usage.iterations`. Вне cgroup платформы, по 2 параллельно.

| Задача | Ветка | Passed (3 прогона) | Среднее | Ср. цена, $ | Вызовов советника | Ср. время, с |
|---|---|---|---|---|---|---|
| pidfd /9 | H | 5, 6, 6 | 5,67 | 0,014 | 0/3 | 304 |
| | HO | 5, 5, 5 | 5,0 | 0,125 | 2/3 | 685 |
| | HS | 5, 5, 5 | 5,0 | 0,059 | 1/3 | 294 |
| | S | 5, 5, 5 | 5,0 | 0,130 | 0/3 | 265 |
| ident /16 | H | 14, 13, 14 | 13,67 | 0,024 | 0/3 | 674 |
| | HO | 13, 15, 16 | 14,67 | 0,322 | 3/3 | 778 |
| | HS | 15, 14, 14 | 14,33 | 0,088 | 1/3 | 483 |
| | S | 15, 14, 14 | 14,33 | 0,162 | 0/3 | 556 |

Пилот (Haiku+Opus на pidfd): $0,359, 1 вызов, 5/9; советник $0,344 из них.

Выводы (n=3, шум велик — о качестве моделей не судить):
- pidfd: ни одна ветка не вышла за 5–6 из 9; советник не помог.
- ident: HO чуть выше (14,67 против 13,67 у голого Haiku), единственное полное 16/16 — HO-r3, но ценой ×13 к голому Haiku и ×2 к Sonnet. HS и S равны по баллу, HS вдвое дешевле S только за счёт того, что советника почти не звали.
- Исполнитель недовызывает советника: советник Sonnet вызван в 2 прогонах из 6, советник Opus — в 5 из 6. Когда советник вызван, он даёт ≈95% стоимости прогона.
- Совпадает с данными Anthropic: GPQA с Haiku 5.5 + Opus 5.5 — советник вызван 0 из 198, определение инструмента добавляет ≈12% стоимости.
- Вердикт: **не брать**. Голый Haiku low ($0,014–0,024) по баллу не хуже. Для трудных задач разумнее Sonnet medium голый (≈$0,13–0,16).

Оговорка: oracle pidfd на исходной базе даёт 5/9, то есть прирост относительно «ничего не сделано» у всех веток отсутствует или мал; сравнение по задачам нужно читать как «никто не продвинулся», а не «все равны на уровне решения».

## 4. Prompt caching: «Not enabled»

Проба на этом ключе: первый вызов `cache_creation_input_tokens=4819`, второй `cache_read_input_tokens=4819`, без каких-либо включений. Значит кеш функционирует, строка в Console не блокер. Что она означает — UNKNOWN; Console не видел. Просьба владельцу: после тестовых прогонов проверить, поменялась ли строка, и сверить баланс (проверка: был $199,72 до экспериментов; мой собственный подсчёт трат на эксперименты — около $4, в Console не сверено).
