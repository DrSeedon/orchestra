# V-910 protocol (frozen before any run)

Question (owner, 17.10.2026): does an agent find the right KB / task-report record when the question is worded differently from the record, and does semantic (hybrid) search give a noticeable gain over today's path? Basis: V-898 report §3, §6.

**Corpus** (pinned snapshot, `corpus_manifest.sha256`, commit 789df54d): `.orchestra/kb/*.md` (10 files) + `.orchestra/tasks/*/report.md` (303), 5.3 MB, outside the repo at `/home/kesha/bench910/corpus`. V-910 itself is not in it.

**Questions**: 40 (`questions.py`, committed with `reference.json` before runs): 28 paraphrase (P), 7 direct (D), 5 replaced/withdrawn conclusions (S). Targets were drawn with a fixed seed (`sample.py`, seed 910) from `##` sections; generic sections (no standalone fact) were skipped in sample order. Deviation from the brief (30, half paraphrase): the primary test needs power on P, so P was raised to 28 (sd of paired differences ≈ 0.4 → SE ≈ 0.076; a true +20 pp is detected one-sided at 5% with power ≈ 0.9; a +10 pp gain is not). D and S are controls. Acceptable set per question = every corpus file containing the `gold` regex (README excluded); the hit is file-level. Paraphrase quality is checked mechanically (`check_q.py`: question stems of ≥5 letters shared with ±1500 characters around the gold match and with corpus document frequency ≤ 8); results go to the report, not used to drop questions after runs.

**A (today's path)**: Luna (`luna`) and Sonnet 5.5 (`sonnet`), 2 repeats each, subscription only. Prompt = the KB topic index block rendered by `app.kb_index.kb_index_block` + the search guidance sentence of the knowledge module + the question + the budget rule (≤3 search calls: rg/grep/Grep/Glob/ls/find; reading a located file is free) + output format `FILES: <≤2 paths>` / `ANSWER:`. Tools read-only: Luna `codex exec -s read-only` (shell, rg), Sonnet Read/Glob/Grep. cwd = corpus root. Contamination scan on the raw output (`V-910`, `bench-kb-search`, `questions.py`, `reference.json`, `/home/kesha/orchestra`) → run invalid and repeated.
- hit_strict = a cited file is in the acceptable set AND search calls ≤ 3 (Luna: `command_execution` items whose command runs rg/grep/find/ls/fd/ag; Sonnet: Grep + Glob `tool_use` events from the stream). hit_lenient = file correct regardless of budget. Paid tokens = output + cache write + fresh input (cache read not counted).
- S questions: additionally a blind cross-family judge (Luna answers judged by Sonnet and vice versa) compares the ANSWER to the in-force rubric.

**B (hybrid index)**: `/opt/kesha-bot/rag.py` imported read-only in the bot's venv; `RagMemory` on a separate DB under `/home/kesha/bench910/` with an empty stub messages DB; `index_file` for every corpus file (heading-aware chunks ≤1200 chars, bge-m3 int8 ONNX via fastembed, vec0 + FTS5, RRF k=60, pool = 4×limit, FTS query = prefix-OR expansion `_expand_query`), `search` = the file part of `RagMemory.search` (vec + fts → RRF). Run outside the platform cgroup (`ssh kesha@localhost 'nice -n 15 …'`) after a free-memory check; the bot has priority. Hit = any acceptable file among the top-5 chunks. Ablations (not decision rules): vec-only, FTS-only, top-1, top-10, MRR.

**Decision rule (fixed)**: unit = question. A_q = mean strict hit over the 4 A runs (2 models × 2 repeats; per-model values reported too); B_q ∈ {0,1}. Primary: paired difference d_q = B_q − A_q over the 28 P questions. The proposal "index as an agent search tool" holds iff mean d ≥ +0.20 AND one-sided exact sign-flip permutation p < 0.05 (H0: mean d ≤ 0). Otherwise the layer is not needed. Also reported: bootstrap 95% CI of mean d; the same per A model; the stratum "P questions where A pooled < 1 (A misses)" — this stratum is chosen on the A outcome, so it carries regression-to-the-mean optimism and is secondary; D and S as controls; KB vs report questions split. The pilot (3 questions × 1 rep) only checks the driver and is excluded.

**Not measured**: how often a real agent would call such a tool and how it reads the chunks (B is retrieval only, no answer generation); S questions cannot be answered by B alone.
