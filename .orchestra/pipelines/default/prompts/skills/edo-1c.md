## 3. Быстрый запуск и проверка окружения

Перед любой операцией с ЭДО на `orchestra-vps` запусти скрипт проверки и автоподъёма окружения:

```bash
/home/kesha/projects/seedon/scripts/edo/ensure_edo_env.sh
```

Скрипт идемпотентно проверяет и поднимает:
1. SOCKS5-туннель `127.0.0.1:1080` до ноутбука.
2. Проброс сокета смарт-карты `/run/pcscd/pcscd.comm` до ноутбука.
3. Видимость контейнера Рутокена через `/opt/cprocsp/bin/amd64/csptest -keyset -enum_cont -verifycontext -fqcn`.
4. Виртуальный экран `DISPLAY=:99` (`1600x900x24`) и процесс `1cv8 ENTERPRISE /F /home/kesha/seedon-edo-db`.

### Как понять, вставлен ли Рутокен в ноутбук

Если `csptest -keyset -enum_cont -verifycontext -fqcn` возвращает `OK` без строки `\\.\SCARD\rutoken_lt_47995b1a\0A00\7E5D`, проверь USB на ноутбуке:

```bash
ssh -i /home/kesha/.ssh/tunnel_laptop -o IdentitiesOnly=yes -p 2222 maxim@127.0.0.1 'lsusb | grep -iE "0a89|rutoken|aktiv"'
```

- Если пусто — Рутокен физически вынут из USB-порта ноутбука (например, вместо него включён принтер). Просмотр базы, создание актов/счетов и формирование электронных документов работают **без токена**, а для финального нажатия **«Подписать»** или **«Отправить/получить»** попроси Максима вставить Рутокен в ноутбук.
- Если Рутокен в `lsusb` есть, а `csptest` на `orchestra-vps` его не видит — перезапусти проброс сокета:
  ```bash
  pkill -f "L /run/pcscd/pcscd.comm" || true
  /home/kesha/projects/seedon/scripts/edo/ensure_edo_env.sh
  ```

## 4. Управление окном 1С на `DISPLAY=:99`

Экран `:99` имеет размер **`1600x900`**.
- **Сделать скриншот:**
  ```bash
  DISPLAY=:99 import -window root /tmp/edo_screen.png
  ```
- **Перевод нормализованных координат (`0..1000` со скриншота) в пиксели `1600x900`:**
  - `X_px = round(X_norm * 1.6)`
  - `Y_px = round(Y_norm * 0.9)`
- **Клик мышью:**
  ```bash
  DISPLAY=:99 xdotool mousemove --sync <X_px> <Y_px> click 1
  ```
- **Ввод кириллического текста через буфер обмена (надёжнее `xdotool type`):**
  ```bash
  printf 'Текст без перевода строки' | DISPLAY=:99 xclip -selection clipboard
  DISPLAY=:99 xdotool key ctrl+v
  ```

## 5. Типовые операции в 1С:Клиент ЭДО 2.10

### А. Настройка обмена и приглашение контрагента
1. **Справочники -> Контрагенты**:
   - Нажать **«Создать»** (или **«Заполнить по ИНН»**, если подключён интернет-сервис), указать `Вид контрагента: Юридическое лицо`, `ИНН`, `КПП`, `Краткое наименование` и `Полное наименование`, нажать **«Записать»**.
2. В карточке контрагента нажать кнопку **«ЭДО» -> «Пригласить к обмену электронными документами»**:
   - Если известен точный ID ЭДО контрагента — вставить его в поле **«Идентификатор ЭДО контрагента»** и нажать **«Отправить»**.
   - Проверить статус приглашения можно в **Продажи -> Настройки ЭДО** (вкладки **«Настройки отправки»** и **«Настройки получения»**, кнопка **«Обновить статусы подключения»**).
3. **Приём входящего приглашения от контрагента:**
   - Открыть **Главное -> Текущие дела ЭДО** (или **Продажи -> ЭДО: Входящие документы**).
   - Нажать **«Отправить и получить»** внизу слева.
   - В папке **«Приглашения -> Требуется согласие»** выделить контрагента и нажать **«Принять»**.

### Б. Создание и подписание исходящего Акта / УПД (Статус 2) или Счёта
1. **Почему не через «Создать произвольный документ» до принятия приглашения:**
   - В БЭД 1С произвольный электронный документ (из PDF/файла) создаётся только при наличии активного маршрута ЭДО в статусе `Принято`.
   - Учётные документы (**Акт выполненных работ (Исходящий)** и **Счет покупателю**) можно создать, сформировать в электронный УПД 5.03 и подписать в любой момент.
2. **Обязательные поля для прохождения форматно-логического контроля УПД 5.03:**
   - В карточке **Договора** обязательно должны быть заполнены **«Номер»** (например, `2317/26`) и дата **«от»** (например, `30.10.2026`). Без даты договора выгрузка УПД падает с ошибкой `СведенияОПередаче...ДатаДокумента: значение не заполнено`.
   - В карточке **Номенклатуры** для работ/услуг обязательно указать `Вид номенклатуры: Услуги`, `Тип: Услуга`, `Ставка НДС: без НДС`.
   - В документе **Продажи -> Акты выполненных работ (Исходящие)**:
     - На вкладке **«Услуги»** заполнить строку (`Номенклатура`, `Содержание` с полным текстом по контракту/заявке, `Количество`, `Цена`, `% НДС: без НДС`).
     - На вкладке **«Сведения об отгрузке»** обязательно заполнить **«Период с ... по ...»** (или **«Дата отгрузки»**). Без этого 1С выдаёт ошибку `Необходимо указать дату отгрузки или заполнить период поставки`.
     - Нажать **«Провести»**.
3. **Формирование и подписание электронного документа:**
   - В проведённом Акте нажать **«ЭДО» -> «Просмотреть электронный документ»** (или **«Отправить электронный документ»**).
   - Откроется карточка электронного документа (УПД со статусом `2` — передаточный документ/акт).
   - Нажать **«Подписать»**.
   - Когда появится окно **«Ввод пароля сертификата»**, оставить поле **«Пароль»** пустым и нажать **«ОК»** (ПИН подхватывается КриптоПро автоматически из `/var/opt/cprocsp/users/kesha/local.ini`).

### В. Критичная настройка типа подписи (CAdES-BES вместо CAdES-T)
- По умолчанию 1С:Клиент ЭДО 2.10 выставляет тип подписи `С меткой доверенного времени (CAdES-T)` без настроенных серверов штампов времени (TSA), из-за чего подписание и диагностика падают с ошибкой `Службы меток времени недоступны`.
- В базе `/home/kesha/seedon-edo-db` уже выставлена правильная настройка:
  - **Администрирование -> Обмен электронными документами -> Обмен с контрагентами -> Настройки обмена -> Типы подписей -> Для электронных документов: `Базовая (CAdES-BES)`**.
- Не переключай её обратно на `CAdES-T` без настроенного и проверенного TSA-сервера.
