# Замеры и профилирование — грабли

Вынесено из `CLAUDE.md` осознанно (#76): триггер у этих правил узкий — они нужны, только
когда агент СОБИРАЕТСЯ мерить, а платили мы за них в системном промпте на каждом спавне.
В `CLAUDE.md` осталась строка-указатель сюда.

Читать целиком перед первым замером в задаче. Дальше — по памяти.

## Куда девать цифры

- **Замер печатает в stdout → перенаправляй в файл под `.orchestra/tasks/<id>/` ТОЙ ЖЕ
  командой, а не потом.** stdout живёт только в контексте, контекст сбрасывается — цифры
  пропадают вместе с ним. Имя файла — `measurements.md` или `<что мерил>.md`; каталог
  `artifacts/` НЕ использовать, он в `.gitignore:18` и цифры потеряются на мерже
  (замер #134: артефакт написан целиком и обнаружен игнором только на коммите).

## Чем мерить, чтобы не намерить не то

- **Меряешь то, что видит юзер → снимай через ТОТ ЖЕ вход** (домен, HTTP/2,
  `Accept-Encoding`) и печатай рядом, каким входом снято. Прямой порт идёт мимо сжатия и
  завышает байты примерно вшестеро.
- **Профилируешь, что блокирует event loop → снимай wall-clock.** `--gil` отвечает только на
  вопрос, кто держит интерпретатор: `sqlite3` и ORT отпускают GIL на I/O и в GIL-профиле
  выглядят дёшево, пока loop стоит. Прибор дважды за двое суток указал не туда — у perf на
  ONNX и у back на SQLite.
- **Процесс тормозит при `pressure_cpu full = 0.00` и нулевом `oom_kill`** → сперва
  `memory.events`/`memory.stat` его cgroup, потом профилировать внутри.
- **Цену подпроцесса (RSS/CPU) считай обходом СВОЕГО дерева по `ppid`**, а не суммой
  процессов с подходящим именем: чужой инстанс того же бинарника даст чужие числа.
- **Какой код исполняет ЖИВОЙ процесс** → HEAD из `git reflog` по времени старта +
  `find -newermt` по mtime, а не даты коммитов: `pull --rebase` их переписывает.
- **Число, которое надо проверить, есть только на графике чужой публикации → тяни `.svg` и
  считай из координат, а не на глаз.** Калибруйся по линиям сетки (`<line>` с `x1==x2` /
  `y1==y2`), а НЕ по координатам подписей: `<text>` смещён от своей линии на несколько
  пикселей. Дальше лог-ось — `10**(a + (x-x0)*k)`. **Корректность извлечения доказывается
  восстановлением подписей легенды:** если посчитанные значения совпали с напечатанными в
  легенде для нескольких серий, метод верный. Точку данных от края опорной линии отличай по
  наличию полноширинного `<line>` на той же `y`. Замер (#137): ответ на главный вопрос задачи
  («чем куплен прирост» — $944 против $20 660) существовал ТОЛЬКО в векторе, текстом эта цифра
  не публиковалась нигде, а на лог-шкале эти две точки на глаз неотличимы от «примерно одного
  порядка».

## Деньги и токены по нашей БД (#178, 11.08.2026)

- **Единственный ground truth по расходу — таблица `turn_usage`.** `sessions.total_*` для сессий
  старше 03.08 не сходится с пересчётом по ценам; для денежных выводов её не брать. (Порядок
  проверки, который сработал: заподозрив порчу данных, взять сессию ЦЕЛИКОМ внутри окна и
  сверить — там сходится точно, значит дело в границе, а не в порче.)
- **`date("now","now")` — невалидный модификатор SQLite: возвращает NULL молча, без ошибки.**
  Запрос с ним отдаёт пустую выборку, которая читается как «событий не было».
- **Размер промпта в байтах ≠ в символах.** Кириллица — 2 байта на символ: `CLAUDE.md` = 62 362
  байта, но 39 260 символов. Смешение этих двух чисел ломает любую оценку токенов.
- **Цена расхода почти линейна по round-trip'ам:** ≈$0.13 на tool-вызов (показатель 1.05,
  R=0.935), 68% суммы — `cache_read`, то есть перечитывание контекста на каждом вызове.
  Холодный старт воркера стоит $0.31–0.62, а не $4. Оптимизировать надо число вызовов,
  а не число спавнов.

## Токены на границе смены рантайма (#176, 11.08.2026)

Строки `turn_usage`, попавшие на смену рантайма, содержат мусорный `input_tokens` при живом
`cache_read`: замер поймал 4 строки `dev-lead` (09.08 07:22–07:37) с `input` = 149/143/139/4 при
`cache_read` в миллионы. **Хранимый `cost_usd` при этом ВЕРЕН** — кламп `cached ≤ input` стоит
внутри формулы (`backend_codex.py:161`), поэтому портится не он, а ручной пересчёт по колонкам.
Любой агрегат по токенам через границу переключения сверять условием `cache_read <= input` и
отбрасывать строки, которые его нарушают: без этого недельная доля саги вышла 12.5% вместо
настоящих 14.7%.
