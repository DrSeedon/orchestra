# Запись и актуализация знаний

Канонические правила проекта — AGENTS.md; база знаний хранит выводы и доказательства,
не вторую копию всех правил. Одна тема имеет одного владельца; README — только указатель.
CLAUDE.md — проверяемое побайтное зеркало AGENTS.md для другого CLI. Его не редактируют
отдельно: python scripts/check_instruction_contract.py --sync обновляет копию после
правки владельца. Проверка без --sync ничего не пишет и обязательна в CI.
Новая Markdown-тема должна получить краткое описание и ссылку в kb/README.md.
Оглавление платформа собирает из этого файла и вставляет в системный промпт агента
(app/kb_index.py) — тема видна на СЛЕДУЮЩЕМ ходе, без рестарта и без правки корня.
Полные тексты тем в корень не копируются. Тема без строки в README не показывается
никому: это и ловит check_instruction_contract.py.
Предел 16 KiB применяется к каждой загружаемой копии, не к сумме двух файлов на диске.

## Разделы Markdown

- Established: принятые выводы. Для изменяемого состояния обязателен источник-владелец
  и дата наблюдения; не переносить старый снимок в настоящее время без проверки.
- Rejected: опровергнутые гипотезы и отказанные решения с причиной. Сохранять, чтобы
  следующий агент не повторял проверенный тупик.
- Historical observations: замеры и сообщения о состоянии на указанную дату.
  Они остаются доказательствами прошлого, но не являются текущим конфигом.
- Gaps: вопросы, на которые источники не дают подтверждённого ответа.
- Источники: точные ссылки на исходные артефакты и код.

## Ссылка на артефакт задачи обязана открываться (#523)

Артефакты задач переезжают, архивируются и удаляются, а запись живёт дальше. Поэтому ссылка
в `.orchestra/tasks/**` или `docs/tasks/**` ценна не путём, а МОМЕНТОМ ВРЕМЕНИ, в котором файл
существовал. Путь, который резолвится в рабочем дереве, ничего дополнительно не требует.
Путь, который не резолвится, обязан быть закрыт полем `· открыть:` в этой же записи —
одним из трёх видов, и других видов нет:

- `<путь> → `<живой путь>`` — файл лежит здесь, просто по другому адресу (обычно
  `.orchestra/archive/laptop-tasks/…`);
- `` `git show <sha40>:<путь>` `` — снимок в истории; это ПОЛНАЯ команда, которой файл
  открывается, sha всегда 40 знаков;
- `<путь> — нет в репозитории: <почему>` — файла нет и в истории: он никогда не
  коммитился, вычищен намеренно либо это цитата литерала из чужого файла.

**Каждый вид НАЗЫВАЕТ закрываемый путь, и покрытие проверяется адресно.** Соседний
существующий путь в той же строке не закрывает ничего: запись с двумя ссылками обязана
открыть обе. Элементы поля разделяются `; `, поэтому внутри причины `; ` не ставится.

Коммит для снимка ищется так: `git log --all --format=%H -- <путь>`, затем первый сверху
sha, на котором `git cat-file -e <sha>:<путь>` возвращает 0. Коммит удаления не подходит —
в нём файла уже нет. **Брать sha, достижимый из `main` (`git merge-base --is-ancestor <sha>
main`): `git cat-file -e` доказывает наличие объекта в ЛОКАЛЬНОМ хранилище, а не
достижимость — якорь на коммит удалённой позже ветки переживёт проверку и умрёт при сборке
мусора.** Гейт этого не проверяет, это обязанность автора.

Гейт принуждает остальное машинно: `scripts/check_kb_contract.py` на каждой ДОБАВЛЕННОЙ
строке — не только в буллете, но и в абзаце, заголовке и строке продолжения — находит такие
пути, и нерезолвящийся путь без адресованного ему `· открыть:` — отказ. Снимок он проверяет
по объектному хранилищу; у переезда требует, чтобы цель существовала и лежала ВНУТРИ
репозитория (абсолютный путь и `..` отвергаются: иначе битую ссылку закрыл бы любой файл
снаружи); у отсутствия — непустой причины хотя бы из двух слов. Пустая причина закрывала бы
ровно тот случай, ради которого поле и заводилось.

**Порог «два слова» усиливать не надо, и это осознанное ограничение, а не недоделка.**
Осмысленность текста машине недоступна в принципе: никакая проверка не отличит «файл вычищен
вместе с боевыми токенами» от «foo bar». Более строгий критерий даст не защиту, а работу —
недобросовестный автор подделает любой порог, добросовестный будет с ним воевать. Настоящая
защита у этого поля одна: его читает человек, ровно как любое другое утверждение в записи.

Не ставить снимок на файл, вычищенный из-за секрета: указатель на коммит с боевым токеном —
это тот же секрет, только через одну команду.

Раздел Markdown — навигация, не новая схема статусов. При работе через typed knowledge
API использовать существующие status/resolution и validation в app/ia/knowledge.py:
замена принятого факта требует supersede, противоречие — disputed, одинаковый факт — no-op.
Не придумывать параллельные enum или считать срок перепроверки доказательством ложности.

## Изменение факта

1. Указать предмет и область: решение владельца, свойство кода либо датированный замер.
2. Приложить проверяемое доказательство и дату. Намерение не записывать как исполнение.
3. При отмене явно пометить старый вывод RETRACTED/superseded и связать с новым основанием.
   Не стирать причину отказа. Исторический документ можно сохранить без переписывания,
   но ссылаться на него как на исторический, а не как на действующий регламент.
4. Не выводить текущие версии, квоты, цены, маршруты, процессы и деплой из старых чисел.
   Прочитать актуального владельца либо явно оставить ответ неизвестным.
5. Не удалять сырьё по одному LLM-конспекту: полнота и корректность извлечения требуют
   отдельной проверки. Вывод без источника — кандидат, не принятый факт.
6. Новая тема получает ссылку в README. При переносе проверить входящие ссылки.

Проверять качество вопросами пользователя: найден ли нужный вывод, отличена ли отмена,
сохранена ли неизвестность. Число файлов, валидный JSON и исправные ссылки не заменяют это.
