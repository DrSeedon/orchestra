# Замеры: wall-clock, CPU, память, токены

## Воспроизводимое сравнение

До запуска определи вопрос, сравниваемые варианты и измеряемый эффект. Сохрани команду,
окружение, сырые результаты и ошибки в текущей задаче; тяжёлые/частные данные — под data/,
а в Git проверенный вывод и безопасная ссылка. Различай измерение, вывод по коду и гипотезу.
Не делай общий вывод из одного LLM-конспекта или одного зелёного промежуточного шага.

## Event loop и cgroup

Для задержки event loop нужен wall-clock: код SQLite/ORT может отпускать GIL и при этом
блокировать loop. Нулевой CPU pressure или oom_kill не исключает давление памяти — смотри
memory.events/memory.stat нужной cgroup. RSS/CPU процесса считай по его дереву ppid, а не
по всем процессам с таким именем. На ноутбуке ограничения запусков заданы в [AGENTS.md](../../AGENTS.md).

## Какой вход измерять

Для пользовательской задержки/байтов используй тот же HTTP-вход, сжатие и протокол.
Для работающей версии сверяй жизненный цикл процесса; путь на диске не раскрывает уже
импортированный Python. Для графика с числом без таблицы проверяй шкалу и калибровочные
подписи, не считывай на глаз. Отличай байты, символы и токены.
