# Код и тесты: воспроизведение, изоляция, восстановление

## Проверка по месту импорта

Запускай `python -m pytest` нужным интерпретатором и проверяй `app.__file__`/путь конкретного
модуля. Зелёный запуск чужого checkout не проверяет текущий diff. Сначала узкий сценарий;
общие контракты, хранение и конкурентность требуют проверки вызывающих сторон и восстановления.
[tests/conftest.py](../../tests/conftest.py) изолирует рабочую SQLite и внешние интеграции.

## Проверка результата

Регрессия должна ломаться при возвращении дефекта. Проверяй положительное и отрицательное
плечо, потерю соединения после успешного действия, повтор операции и сохранение данных.
Таймаут теста ограничивает зависание, но не является измерением производительности.
Проверки конкретного поведения важнее совпадения текста промпта с шаблоном.

## SQLite и процесс

OwnedConnection закрывает собственное соединение; заимствованное не закрывай и не коммить
самостоятельно. [db.py](../../app/db.py) проверяет версию схемы; рабочую SQLite копируют
через backup(), не cp при активном WAL. Код на диске не доказывает, что Python-процесс его
загрузил. [Миграция](tasks-and-projects.md), [замеры](evidence-methods.md).

## Положительное плечо, моки и состояние теста

При сужении условия негативный тест может стать пустой проверкой: докажи, что разрешённый
случай по-прежнему проходит и нужная ветка исполняется. Мутация, пережившая тест, может
означать неверный импорт или недостижимый сценарий, а не нечувствительность исправления.
`all([])` истинно: проверка пустого набора не доказывает полноту результата.

Константа в значении аргумента по умолчанию фиксируется при определении функции; monkeypatch
имени модуля не меняет уже связанный default. При добавлении lifecycle-поля проверь и реальные
записи, и test doubles. Созданная в тесте session с настоящим backend может удерживать teardown;
используй штатные моки и проверяй завершение принадлежащих тесту задач.

`asyncio.Lock` обеспечивает single-flight только внутри одного event loop. Для нескольких
процессов нужен владелец конкурентности на соответствующей границе. Тесты перехода состояния
должны включать повторную доставку и отказ между эффектом и записью подтверждения.

Источники консолидированных наблюдений: [back](https://github.com/DrSeedon/orchestra/blob/9a1735f1695519a445f393802c2154bd37337e38/.orchestra/archive/knowledge-20260909/workers/back.md), [feat-instant](https://github.com/DrSeedon/orchestra/blob/9a1735f1695519a445f393802c2154bd37337e38/.orchestra/archive/knowledge-20260909/workers/feat-instant.md).
