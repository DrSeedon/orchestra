# grep/ugrep в Claude Code: взрыв памяти на шаблоне контекста

## Established
- **`grep` в сессии Claude Code — это НЕ системный grep, а сам бинарь `claude.exe`, запущенный с `argv[0]=ugrep`.** Подмена делается функцией в `~/.claude/shell-snapshots/snapshot-bash-*.sh` (строки 126/128: `ARGV0=ugrep "$_cc_bin" -G --ignore-files --hidden -I --exclude-dir=.git …`). Отдельного `ugrep` в системе нет вовсе: `which ugrep` пусто · 19.08.2026, #350
- **Отсюда цена ошибки: у процесса поиска есть V8-heap, потолок ~8 ГБ.** До версии 2.1.117 grep был лёгким C-процессом (~30 МБ пика); после — профиль памяти V8 стал профилем памяти каждого grep'а · [claude-code#54394](https://github.com/anthropics/claude-code/issues/54394) · 19.08.2026
- **Шаблон `.{0,N}литерал.{0,M}` — детонатор.** Замер на VPS 19.08: четыре процесса за 15 минут, RSS 3.1 / 4.2 / 5.9 ГБ, состояние `R`, CPU 98–100%, рост ~1 ГБ/мин. Вход — файл **60 572 байта** с максимальной длиной строки **1085 символов**: размер файла ни при чём, взрывается длина СТРОКИ · #350
- **Воспроизведено локально через тот же wrapper** (файл 93 КБ, строки 1010 символов): литеральный `grep -c "школ"` — мгновенно, 650 совпадений; `grep -oE '.{0,100}школа № ?[0-9]+.{0,100}'` — **не завершился за 60 с** (`rc=124`), успев отдать 19 строк · 19.08.2026, #350
- **Наша версия 2.1.197 всё ещё подвержена** — тикет открыт, официального фикса нет; в issue сообщено о воспроизведении на 2.1.119–2.1.121 · 19.08.2026
- **Автор тикета связывает с этой же причиной ещё пять «утечек памяти»** Claude Code: #4953 (120 ГБ), #11155 (90 ГБ), #25926, #27421, #30470 · [claude-code#54394](https://github.com/anthropics/claude-code/issues/54394)
- **Тот же wrapper безусловно подставляет `-G`** (BRE), из-за чего вызов с `-E` может получить не ту семантику, а в неинтерактивном сабшелле — код возврата 127, читаемый как «команда не найдена» · [claude-code#59517](https://github.com/anthropics/claude-code/issues/59517)
- **Безопасная замена, дающая тот же результат:** `grep -aboF 'литерал' файл` (байтовые смещения) + вырезание контекста питоном по смещению. Литеральный поиск не строит автомат по длине строки · #350
- **На этом VPS взрыв опаснее, чем на ноутбуке:** у `orchestra.service` `OOMScoreAdjust=800`, то есть при исчерпании памяти ядро убивает оркестратор, а не виновника · CLAUDE.md, #350

## Rejected
- **«Это баг ugrep»** — ugrep как таковой DFA-движок (RE/flex) и по документации авторов не должен катастрофически бэктрекать; проблема появилась вместе с встраиванием его в бинарь с V8-heap · 19.08.2026, #350
- **«Виноват размер файла»** — 5.9 ГБ съедено на входе в 60 КБ. Предиктор — длина одной строки и форма шаблона, не объём · #350
- **«Это наш агент/наш код»** — все четыре процесса имели `cwd=/opt/cog-second-brain`, то есть чужую сессию на той же машине. Наши воркеры живут в worktree Orchestra · #350
