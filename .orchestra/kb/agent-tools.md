## Established

### Встроенные тула́ рантайма

- **grep-тул на машине без rg уходит в fallback `grep -rn <pattern> .` без `-E`: паттерн с `|`
  молча отвечает «(no matches)»** — в GNU-BRE `|` литерал. Это дефект ox-probe из задачи #367.
  Рабочая форма в BRE: `a\|b`. · замер: builtin-style rc=1 пусто, `grep -rnE` → 4 строки ·
  22.08.2026, #367
- **`glob_filter` исполняется только в rg-ветке; в fallback он молча игнорируется** — тул
  возвращает совпадения из чужих файлов под видом отфильтрованных (хуже пустого ответа:
  агент верит фильтру). · tools.py:241–245, замер с glob_filter="app/models.py" → 3 файла · #367
- **grep-тул не проверяет returncode и выбрасывает stderr**: rc=2 (ошибка опции) неотличим
  от «нет совпадений»; совпадения в non-UTF-8 текстовых файлах молча исчезают — grep пишет
  «binary file matches» в STDERR при rc=0, stdout остаётся чистым UTF-8. · замер V2 #367
- **Паттерн grep не защищён `-e`/`--`: паттерн `--` съедается getopt'ом, `.` становится
  паттерном «любой символ» и выдача затопляется** (GNU grep с `-r` и без операндов ищет cwd,
  НЕ stdin — и моя первая формулировка, и версия ревьюера про stdin опровергнуты замером). ·
  замер V1/V1b #367
- **read объявляет валидный UTF-8 файл «бинарным», если байтовый потолок 256 КиБ режет
  многобайтный символ пополам** (`read_bytes()[:CAP]` → строгий decode → UnicodeDecodeError).
  Тот же путь молча обрезает текстовые файлы >256 КиБ без пометки. · замер V4/код tools.py:144–150 · #367
- **read: offset 0-based при метках строк 1-based** — «с 5-й строки» начинает со строки
  с меткой 6; offset за EOF отвечает `(empty)`, неотличимо от пустого файла. · замер V5 #367
- **write/edit затирают права файла до 0600**: mkstemp создаёт temp 0600, os.replace делает
  его inode финальным; в su-deploy bash под другим uid теряет доступ к файлу сразу после edit.
  · замер V3: 0o755 → 0o600 · #367
- **dispatch() зовёт синхронные read/glob/grep/write/edit прямо на event loop сервера**
  (loop.py:247; в репо ни одного to_thread/run_in_executor): конкурентный 10 мс сон длился
  **2008 мс** под синхронным grep по дереву репо; контроль через to_thread — 10 мс. Только
  bash честно асинхронен. · замер block2.py #367
- **read блокируется навечно на FIFO** — блокирующий open() без таймаута; достижимо даже
  из read-only ревьюера, в связке с блокировкой цикла морозит весь сервер. · замер V4 #367
- **bash-тул корректен**: exit_code всегда в ответе; таймаут убивает всю группу процессов
  (осиротевших sleep нет); stderr слит со stdout последовательно. · замер #367
- **edit/write корректны по контракту**: атомарность temp+rename, громкие ошибки на
  неуникальном/отсутствующем old, синтаксис-гард .py до записи. · замеры #367
