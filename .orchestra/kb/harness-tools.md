# harness-tools — встроенные тула́ рантайма (app/harness/tools.py): что врут, что проверено

## Установлено
- **grep-тул на машине без rg уходит в fallback `grep -rn <pattern> .` без `-E`: паттерн с `|`
  молча отвечает «(no matches)»** — в GNU-BRE `|` литерал. Это дефект ox-probe из задачи #367.
  Рабочая форма в BRE: `a\|b`. · замер: builtin-style rc=1 пусто, `grep -rnE` → 4 строки ·
  22.08.2026, #367
- **`glob_filter` исполняется только в rg-ветке; в fallback он молча игнорируется** — тул
  возвращает совпадения из чужих файлов под видом отфильтрованных (хуже пустого ответа:
  агент верит фильтру). · tools.py:241–245, замер с glob_filter="app/models.py" → 3 файла · #367
- **grep-тул не проверяет returncode и выбрасывает stderr**: rc=2 (ошибка опции) неотличим
  от «нет совпадений»; совпадения в non-UTF-8 текстовых файлах молча исчезают — grep пишет
  «binary file matches» в STDERR при rc=0, stdout остаётся чистым UTF-8. · замер V2 #367
- **Паттерн grep не защищён `-e`/`--`: паттерн `--` съедается getopt'ом, `.` становится
  паттерном «любой символ» и выдача затопляется** (GNU grep с `-r` и без операндов ищет cwd,
  НЕ stdin — и моя первая формулировка, и версия ревьюера про stdin опровергнуты замером). ·
  замер V1/V1b #367
- **read объявляет валидный UTF-8 файл «бинарным», если байтовый потолок 256 КиБ режет
  многобайтный символ пополам** (`read_bytes()[:CAP]` → строгий decode → UnicodeDecodeError).
  Тот же путь молча обрезает текстовые файлы >256 КиБ без пометки. · замер V4/код tools.py:144–150 · #367
- **read: offset 0-based при метках строк 1-based** — «с 5-й строки» начинает со строки
  с меткой 6; offset за EOF отвечает `(empty)`, неотличимо от пустого файла. · замер V5 #367
- **write/edit затирают права файла до 0600**: mkstemp создаёт temp 0600, os.replace делает
  его inode финальным; в su-deploy bash под другим uid теряет доступ к файлу сразу после edit.
  · замер V3: 0o755 → 0o600 · #367
- **dispatch() зовёт синхронные read/glob/grep/write/edit прямо на event loop сервера**
  (loop.py:247; в репо ни одного to_thread/run_in_executor): конкурентный 10 мс сон длился
  **2008 мс** под синхронным grep по дереву репо; контроль через to_thread — 10 мс. Только
  bash честно асинхронен. · замер block2.py #367
- **read блокируется навечно на FIFO** — блокирующий open() без таймаута; достижимо даже
  из read-only ревьюера, в связке с блокировкой цикла морозит весь сервер. · замер V4 #367
- **bash-тул корректен**: exit_code всегда в ответе; таймаут убивает всю группу процессов
  (осиротевших sleep нет); stderr слит со stdout последовательно. · замер #367
- **edit/write корректны по контракту**: атомарность temp+rename, громкие ошибки на
  неуникальном/отсутствующем old, синтаксис-гард .py до записи. · замеры #367

## Отвергнуто
- **«Паттерн `--` заставляет grep читать унаследованный stdin» (версия ревьюера #367)** —
  сырой замер `grep -rn -- . </dev/null` всё равно выдал содержимое каталога: GNU grep
  с `-r` и без файловых операндов ищет `.` как cwd, паттерном становится `.`. · 22.08.2026, #367
- **«Non-UTF-8 файл валит grep-тул UnicodeDecodeError'ом» (версия ревьюера #367)** — stdout
  остаётся валидным UTF-8 (grep прячет строку в stderr-пометку «binary file matches»), крэша
  нет; реальный дефект — тихая ПОТЕРЯ совпадения, см. Установлено. · замер V2 #367

## Обновления починки (22.08, #367, фаза 3)
- **grep переведён на ОДИН питоновский движок** (os.walk+re): внешний движок выбирался
  молча по shutil.which — сам факт переключателя и был корнем D1–D3. Синтаксис паттерна —
  Python re, объявлен в схеме. Бюджет обхода 25 с, пропуски binary/large подсчитываются
  в хвосте выдачи. · tests/test_harness_tools.py, коммит 373df5d4
- **BRE-привычка `a\|b` после переезда означает литерал `a|b` — строка ниже в «Установлено»
  про «рабочую форму `a\|b`» верна только для внешнего GNU grep — ОТОЗВАНО для нового
  движка 22.08 #367.**
- **read: offset стал 1-based номером строки в выдаче** (0 = сентинел «с начала»);
  бинарик определяется NUL-байтом до декодирования; декод errors=replace — совпадение в
  non-UTF-8 файле показывается, не исчезает. · #367
- **write/edit: права существующего файла переносятся через S_IMODE (без setuid/setgid),
  новые файлы — 0o666 & ~umask; umask читается один раз на импорте из /proc/self/status,
  ядро печатает его ВОСЬМЕРИЧНЫМ (%04o) — hex-парс даёт 0o42 вместо 0o22.** · замер #367
- **dispatch гонит sync-тулы через asyncio.to_thread + общий лок на write/edit**
  (inline-исполнение блокировало цикл сервера: 10 мс сон длился 2008 мс). · #367
- **MAX_TOOL_ROUNDS 50→100 + wind-down за 10 и 3 раунда**, гарды turn-scoped (удаляются
  из истории в finally); усечение истории _fit_context перестало быть тихим — AgentEvent
  warning. Экономия раундов измерена на задаче с grep-дефектом: старые тула 5/9 раундов,
  новые 2/4. Экспериментальный безусловный `parallel_tool_calls` снят 24.08: optional
  параметры теперь отправляются только когда exact route декларирует capability. · #367

## Пробелы
- rg-ветка grep-тула на этой машине неисполнима (rg нет) — её поведение помечено чтением кода,
  не замером; если поиск сведут к одному движку, ветка исчезнет вместе с вопросом. · #367
- Не замерен порог размера дерева, при котором питоновский поисковый движок заметно медленнее
  внешнего grep — понадобится при выборе фикса. · #367
- ORCHESTRA_AGENT_UID/su-ветка bash не исполнена на стенде (env не задан); влияние 0600 на
  su-bash выведено из кода. · #367
