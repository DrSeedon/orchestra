# Контекст: размер промпта, результаты инструментов, измерение экономии

## Что уменьшать

В общий промпт включается оглавление KB, а не весь текст. Личные заметки загружаются
целиком, поэтому длинные расследования должны быть в доказательствах задачи и читаться по
запросу. Сохраняй точные ссылки/символы вместо повторного копирования одной инструкции.
[Сборка промпта](../../app/prompting.py), [оглавление](../../app/kb_index.py).

## Что не считать доказательством экономии

Меньше байтов в файле не означает измеренный выигрыш токенов, цены или качества. Различай
UTF-8 байты, символы, токенизацию модели и cache-read. Большой tool_result сохраняется в
истории; сокращение вывода проверяй на сохранение решающей информации.
Сравнивай одинаковую задачу и границу измерения, а не чужие проценты из статьи.
[Методика](evidence-methods.md), [учёт использования](../../app/usage_contract.py).

## Сжатие не равно сохранению всех знаний

LLM-конспект может пропустить отрицание, условие и отменённый вывод. Сохраняй исходные
доказательства для адресного повторного поиска. Эксперименты SKILL.state и старые оценки
эффективности находятся в архиве; их проценты не являются обещанием для текущей версии.

## Claude Max: cache-read, недельный пул и подогрев

09.09.2026, [исследование V-541](../tasks/V-541/research.md): 6 116 ходов Claude из
живой БД, выбранной по `ORCHESTRA_DB_PATH` процесса, и 126 трёхчасовых интервалов.
Наблюдательная регрессия дала cache-read **0,00286 п.п. недельного пула/М токенов**,
cache-create **0,871 п.п./М**. Day-bootstrap для чтения **−0,00474…0,01119** включает
ноль; это неопределённость регрессии, не гарантия тарифа. Модель с бесплатным чтением
не хуже на отложенных днях; API-пропорция предсказывает хуже. **Нельзя обосновывать
выгодность или невыгодность подогрева только API-долларами.**

Точный нулевой тариф Claude Code не установлен: процент округлён до целого,
turn quota берётся из кеша до 300 секунд, пул общий с личной работой вне платформы,
состав токенов коррелирует. В [официальном Help](https://support.claude.com/en/articles/9797557-usage-limit-best-practices)
бесплатное повторное использование описано для **Projects**, не формулой всех кеш-токенов
Code Max. Сохранение 1h TTL само по себе не означает бесплатный ход.

Подогрев выгоден при `n × H < (βwrite − βread) × K/1e6`, где H — дополнительные
п.п. одного пинга, K — предотвращённая пересборка старого префикса, а не все чтения
рабочего хода. **Установленного порога «раз в N часов» и правила «меньше 20» нет.**
Даже при бесплатном чтении остаются новые записи/output; без возврата до остывания
подогрев не экономит квоту. Числа сценариев и план пассивного замера — в отчёте.
