# Агенты: роли, промпты, личные заметки

## Источник промптов

[pipeline.yaml](../pipelines/default/pipeline.yaml) выбирает роли, модули, навыки и effort.
Тексты принадлежат `prompts/base.md`, `prompts/roles/`, `prompts/modules/`, `prompts/skills/`
в том же pipeline. [prompting.py](../../app/prompting.py) и [manager.py](../../app/manager.py)
собирают инструкции и память. Личный overlay содержит только особенности конкретного агента,
не копию общей политики. Версии в сохранённом system_prompt не доказывают актуальность
работающего native thread; проверяй сборку и жизненный цикл нужного рантайма.

## Роли и результат

`orchestrator` и `sub-orchestrator` координируют; `worker` исполняет определённую задачу;
`full-cycle` ведёт согласованный результат с исследованием при необходимости; `reducer`
собирает fan-out доклады. Точные возможности определяет pipeline, не исторический список
«постоянной команды». Все роли получают общий модуль knowledge и оглавление своего проекта.

[Создание и перенос агента](../pipelines/default/prompts/skills/orchestra-agents.md): сохраняй
его личный файл по имени и проекту. Не клонируй чужую инструкцию вместо выбора роли.
Исследование заканчивается отчётом; ни KB-запись, ни личная заметка не являются квитанцией
приёмки. Правила не предлагаются автоматически после каждой задачи.

## История после compaction/restart

Актуальные решения и незавершённая работа принадлежат текущей задаче. Статус воркеров
проверяется через платформу; старый отчёт не является live snapshot. Не создавай параллельные
суточные обзоры и обязательные сессионные хроники. Срезанные рестартом ходы проверяются
по `cut_names`; это не доказательство отказа работника выполнить задачу.
