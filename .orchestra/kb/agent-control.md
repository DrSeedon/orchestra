# Эксперименты доставки инструкций и контекста

## Промпт миграции не мог исправить отказ, происходящий до его доставки

В стенде #430 два временных Git-репозитория с прежней/частичной раскладкой и изолированная
SQLite использовались для проверки full-cycle prompt. Текст уже содержал инструкцию
исправить ORCHESTRA_LAYOUT_MISSING, но create_session падал с LayoutMigrationError до доставки
текста. manager.sessions и число строк сессий оставались нулевыми; никакой агент не получал
возможности выполнить подсказку.

Полезный вывод опыта: инструкция модели не обрабатывает ошибку на предшествующей границе
создания/подключения. Различающей проверкой была доставка целого сценария, а не успешная
сборка строки промпта. Прежний compatibility-контракт из отчёта не является рекомендацией
восстановить старые пути сегодня.
Источник: [сценарий, исключения и нулевые счётчики](https://github.com/DrSeedon/orchestra/blob/9a1735f1695519a445f393802c2154bd37337e38/.orchestra/tasks/430/prompt-assembly-cutover-measurement.md).

## Глобальный AGENTS не попадал в managed Codex (V-570, 13.09.2026)

На текущем VPS проверены 53 каталога `~/.orchestra/codex-home/<session>`: ни в одном
нет AGENTS.md. `_prepare_codex_home` в app/backend_codex.py переносит auth/config,
не `~/.codex/AGENTS.md`; процесс агента использует этот отдельный CODEX_HOME.
Поэтому редактирование обычного глобального файла само по себе не доставляет его
правила управляемым Codex-сессиям. Историческое «никогда» по всем версиям не проверялось.
В default Claude, напротив, включены user/project/local источники при inherit_claude_md.

Владелец отверг добавление второго канала AGENTS в managed homes: общие нормы должны
поступать через модули пайплайна, независимо от личных глобалов. Глобальный файл Codex
остаётся личным источником для ручного CLI. Иначе синхронизация двух невидимых для
managed Codex файлов могла бы выглядеть как исправление доставки, которой не было.
Проверки и пофрагментная карта норм: [V-570](../tasks/V-570/report.md).

## Поиск одного скилла пропускал вторую личную копию (V-572, 13.09.2026)

При подготовке laptop-access постановка называла только ~/.claude/skills. Проверка
также ~/.agents/skills нашла одноимённую Codex-адаптацию от12.09 с другим содержимым:
Claude-копия описывала недоступную платформе обёртку, Codex-копия — SSH и альтернативу
через ту же обёртку. Текущая Codex-сессия показывала именно ~/.agents-копию в индексе.
Проверка пересечения дала ещё html-artifacts: личные файлы побайтно совпали, но оба
отстали от сегодняшнего канона pipeline по сокращённому правилу title (8f4350a4…
против6bcaa9f6…). Первый случай — разное содержание маршрута, второй — пропущенное
распространение новой редакции. Html-копии в этой задаче не менялись.
Одного имени и наличия первого файла оказалось недостаточно для установления владельца
инструкции. Владелец выбрал канон в pipeline и короткие личные указатели, не новое имя
скилла рядом с прежними маршрутами. Это решение не устраняет дубли имён в native discovery,
а устраняет независимые описания маршрута. Свежие SHA и область поиска: [V-572](../tasks/V-572/report.md).
