# Чат, SSE, Telegram и происхождение сообщений

## Snapshot перед SSE

Чат получает свежий сетевой snapshot последних сообщений, затем события. IndexedDB или
stale-while-revalidate не должны возвращать старую историю вместо новой. При смене агента
проверяй, к какому агенту относится ответ, закрывай прежний поток; глобальный log ID не
является порядковым номером внутри отдельной сессии.
[chat.js](../../app/static/js/chat.js), [frontend tests](../../tests/test_frontend.py).

## Unknown у сообщения из dashboard

Поле `channel="dashboard"` отмечает канал отображения, не подтверждает личность оператора.
Анонимное dashboard-сообщение сохраняет origin unknown, но рисуется как сообщение чата.
Неизвестный API-отправитель без этого канала остаётся Unknown. Старые неподписанные записи
не переписываются задним числом. [sessions.py](../../app/routes/sessions.py),
[результат](https://github.com/DrSeedon/orchestra/blob/9a1735f1695519a445f393802c2154bd37337e38/.orchestra/tasks/idle-watch/result.md).

## Отказ доставки и частный журнал

`KEYED_AUTH_REQUIRED`, timeout и Telegram `TOPIC_ID_INVALID` требуют диагностики канала;
они не доказывают отсутствие результата у воркера. Проверяй [message_deliveries.py](../../app/message_deliveries.py)
и фактический статус доклада. HTTP 200 dashboard не доказывает здоровье Telegram.
Журнал хранит исходное содержимое; перед публикацией фрагмента в Git проверяй секреты,
не меняй рабочее отображение по правилам фильтра публикации.

## SSE, scroll и неизвестный исход сообщения

Scroll anchoring браузера может породить настоящее событие scroll без намерения пользователя.
Автопрокрутку проверяй при поступлении сообщений и при чтении старой части чата; замена высоты
контента сама по себе не должна отбирать позицию. Снимок, SSE и смена selectedAgent должны
сходиться к одной истории, без дубликатов и старых ответов соседней сессии.

Запись в logs обеспечивает историю/отображение, но сама по себе не отправляет сообщение в
ход модели. Для доставки используй владельца message delivery. Семантику «не доставлять»
нельзя подменять флагом оформления/важности сообщения.

При диагностике рестарта проверяй и HTTP-вход, и Telegram, который может вызывать manager
напрямую. Очередь restart_inbox принадлежит отдельному механизму; её подтверждение после
эффекта допускает повтор после сбоя, а подтверждение до эффекта может потерять сообщение.
Точный текущий порядок проверь в app/restart_inbox.py перед изменением гарантии доставки.

Источники консолидированных наблюдений: [frontend](https://github.com/DrSeedon/orchestra/blob/9a1735f1695519a445f393802c2154bd37337e38/.orchestra/archive/knowledge-20260909/workers/frontend.md), [report](https://github.com/DrSeedon/orchestra/blob/9a1735f1695519a445f393802c2154bd37337e38/.orchestra/tasks/269/report.md).
