# Эксперименты с CLI и MCP

## Grok 1.0.3: doctor видел 37 tools, а сессия загружала ноль

В расследовании Grok 1.0.3 `grok mcp doctor` сообщал «37 tools, healthy», но рабочая сессия
получала ноль серверов. `grok mcp list` тоже не отвечал на нужный вопрос: Orchestra передавала
сервер через ACP session/new, а list показывал конфигурационные источники Grok.

Различающие наблюдения нашли в `grok agent --debug --debug-file <file> stdio`:
`created with N MCP servers`, `folder untrusted: skipping repo-local`,
`ensure_mcp_tools_initialized: config_count=`. Оказалось, project .mcp.json объединялся
по имени до проверки folder trust. Коллизия имени вытесняла переданный сервер, а последующая
проверка trust удаляла замещающий. Пять способов подключения, включая --plugin-dir, дали
один отрицательный результат из-за общей причины, а не пяти независимых дефектов.

Не переносить порядок merge/trust на новую версию без проверки. Ценность опыта — разные
области проверки doctor/list/session и найденный общий confound.
Источник: [разбор Grok 1.0.3](https://github.com/DrSeedon/orchestra/blob/9a1735f1695519a445f393802c2154bd37337e38/.orchestra/workers/fix-grok-mcp.md);
[отчёт #264](https://github.com/DrSeedon/orchestra/blob/9a1735f1695519a445f393802c2154bd37337e38/.orchestra/tasks/264/report.md).

## Codex 0.153.4: наличие context-management tools проверяли контрольным запуском

В записи от 06.09.2026 описаны два изолированных CODEX_HOME: с
`[features.context_management] experimental_mode = true` модель сообщила о new_context и
get_context_remaining; без флага та же Astra перечислила набор без них. Зафиксированы
4382 и 3380 токенов. Это наблюдение о видимости tools в той версии, не замер экономии
недельного лимита и не основание автоматически включать флаг всему парку.

Та же запись содержит пробу vendor bwrap: RC=0 одновременно с
`loopback: Failed RTM_NEWADDR: Operation not permitted`. В этом окружении успешный код
запуска не подтверждал настройку loopback. Запись не содержит полного повторяемого стенда;
это историческое свидетельство, которое стоит проверить при аналогичной диагностике.
Источник: [запись двух проб от 06.09](https://github.com/DrSeedon/orchestra/blob/3208ceeda5a1c76ce9e0ed147b0c3fbce38ac497/AGENTS.md).

## #537: копирование истории в новый тред отвергнуто, корень вылечен иначе (11.09.2026)

Вариант «доказать, что старый писатель треда остановлен, и скопировать историю в новый»
реализовывался и был ОТМЕНЁН решением владельца: «хуйня надо удалить это все и просто сделать
чтобы он не сиротел сука корень лечить». Независимое ревью (Luna) пришло к тому же выводу
раньше: `NEEDS WORK — the post-proof resume race can create concurrent writers in the same
worktree`. Суть дефекта замысла: доказать «процесс спит» можно, а УДЕРЖАТЬ его в этом
состоянии нельзя — он вправе ожить сразу после проверки, и тогда в одном worktree окажутся
два писателя. Второй тупик того же подхода: в БД записан родитель-обёртка, а работу делает
его ребёнок, и доказать «этот процесс мой» существующими средствами не удалось.

Принятое лечение корня — держать деревья процессов рантайма внутри cgroup сервиса, чтобы
сирот не возникало вовсе (коммит `e6da7e30` в main, «stop runtime trees with Orchestra and
remove live adoption»); тогда механика подбора не нужна и удаляется. Цена названа заранее:
длинные фоновые прогоны перестают переживать рестарт.

Незаконченная реализация варианта C вместе с логами регрессий и `root-cause-plan.md` остаётся
в ветке `task-537/fix-stuck-writer` (HEAD `2402e3d4`, 8 коммитов, в main НЕ вливалась).
Ветку не удалять: это единственная копия доказательств, почему подход отвергнут.

## ARTEMIS (Google): управление Android из Claude Code — отклонён за отсутствием предмета (18.09.2026)

`google/artemis`, Apache 2.0, Python, команда Pixel Test Engineering. Превращает
инструкцию на естественном языке в действия на Android-устройстве и подключается к
Claude Code, Codex, Antigravity и Windsurf **как обычный MCP-сервер** — то есть
технически встроился бы к нам без доработок. Заявлен успех 99%+ на AndroidWorld;
бенчмарк принадлежит самому Google Research, независимого воспроизведения не нашлось.

Отклонён не по качеству, а по предмету: ему нужен физический телефон с включённой
USB-отладкой или эмулятор НА ТОЙ ЖЕ машине, где работает агент, плюс веб-консоль с
зеркалом экрана на `localhost:8000` (headless-режим в документации не заявлен). У нас
нет ни Android-приложения, ни мобильного QA, ни телефона рядом с VPS, а эмулятор на
ноутбуке владельца упирается в его лимит памяти. Единственный мыслимый сценарий —
смотреть отрисовку наших сообщений в Telegram на живом телефоне, но те же сущности
форматирования видны в вебе и десктопе.

Условие пересмотра: появляется задача, где предмет проверки — само мобильное
приложение или поведение телефона, и есть устройство рядом с исполнителем.

Отдельно к сведению: стартап Minitap публично заявил, что нашёл в репозитории свой
код из проекта mobile-use — совпадающие куски подключения устройства, дословно
совпадающие инструкции агента и кличку «Hopper», — а также коммит, убравший их имена
из истории. Ответа Google и независимой проверки на 18.09.2026 нет. Лицензия при этом
Apache 2.0, то есть юридического препятствия использовать инструмент это не создаёт.

## Inspo (MCP-архив дизайна): предмета у нас нет, но их бюджет на инструменты — образец (18.09.2026)

`Nutlope/inspo`, открытый код, бесплатно, ставится одной командой `npx -y inspo-mcp install`
или подключается как HTTP-MCP `https://inspomcp.dev/api/mcp`; можно поднять у себя (DEPLOY.md).
Архив: 2 320 страниц с 832 живых сайтов, каждая снята на десктопе и мобильном, с вытащенной
палитрой, реальными шрифтами, типографской шкалой и разбором по экранам; семантический поиск
на эмбеддингах Together AI. Есть оркестратор-инструмент, который из брифа на естественном языке
выдаёт макроструктуру, пять живых примеров и палитру.

Нам самим не нужен: дашборд уже свёрстан, сайтов мы не делаем, а подключение добавит 15
инструментов в каждый ход каждого агента ради задачи, которой нет. Пересмотр — если появится
работа по вёрстке нового интерфейса или зайдёт проект с сайтом.

Что действительно стоит перенять и почему это про нас: из 15 инструментов у них **9 помечены
«lite»** и только они отдаются текстовым клиентам, а каждый списочный инструмент принимает
потолок `maxTokens`. У нас на 18.09 обратная картина — 46 инструментов MCP, около 4 300 токенов
одних описаний (17 164 символа докстрок), и они уезжают в КАЖДЫЙ ход КАЖДОГО агента, включая те,
которые воркеру недоступны по роли (`spawn_worker`, `merge_worker`, `codex_review`). При 1 856
ходах Claude за неделю это ~8 млн токенов на каталог чужих возможностей. Оценка по длине
докстрок, а не замер реальной схемы с типами параметров, — значит скорее занижена.
