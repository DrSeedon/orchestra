# Задачи: приватный Git, SQLite-проекция, локальная работа

## Текущее хранение после 08.09.2026

[TaskStore](../../app/task_store.py) хранит канонические файлы задач в приватном Git.
[TaskRuntime](../../app/task_runtime.py) поддерживает проекцию tm_tasks в рабочей SQLite.
Это не второй независимый владелец состояния. Проект определяется своей идентичностью;
совпадение имени/пути на двух машинах не разрешает объединять проекты автоматически.

## Номера и Git sync

Новые задачи VPS получают V-, ноутбук создаёт свои обычные номера. Исторические номера
и локальные SQL ID сохраняются при миграции. UUID задачи и локальный числовой ID не
взаимозаменяемы. [sync_tasks](../../scripts/sync_tasks.py) соединяет Git и обновляет проекцию;
обычная работа не требует сети. Несовместимые правки одной задачи требуют разрешения
конфликта, а не молчаливого last-write-wins.

## Перенос схемы и активные назначения

[migrate_task_storage](../../scripts/migrate_task_storage.py) готовит отдельную пару DB/Git
из свежих источников, сохраняет исходный SQLite backup и проверяет связи/идентичность.
Нельзя ставить репетиционную копию поверх новых живых записей. Назначения работников и
квитанции повторного создания должны сохраниться вместе с задачами.
[Проверенное переключение 08.09](../tasks/storage-simplification/deployment.md).

## Что является результатом работы

Файлы `.orchestra/tasks/<id>/` — доказательства и рабочий отчёт, не каноническая карточка
задачи и не ещё одна KB. Состояние карточки меняется через task API/TaskRuntime. Коммит,
приёмка и доставленный доклад — отдельные события; проверяй нужное из них.
