# research-archestra — личная память

## Аудит ЧУЖОГО репозитория: рабочий рецепт (#470)

1. **Клон — `git clone --filter=blob:none`** в `/mnt/data/tmp/<задача>/`, НЕ в `/tmp` (там tmpfs =
   RAM на этой машине, `findmnt /tmp` подтверждает) и НЕ внутрь нашего дерева. Blobless даёт полную
   историю и все деревья (то есть `git log --all --diff-filter=A --name-only` работает), а блобы
   тянутся по требованию: 448 МБ вместо 663 МБ и минуты вместо десятков минут. Клон запускать через
   `bg_create(type="run")` — он почти наверняка длиннее 60 с.
2. **Метаданные — только `gh api repos/<owner>/<repo>`**, и помнить: `open_issues_count` **включает
   pull requests**. У Archestra API показывал 44, настоящих открытых issue было 24
   (`search/issues?q=…is:issue+is:open`).
3. **Проверка «существует ли фича» = греп по ВНУТРЕННЕМУ имени, а не по слову с лендинга.** У
   Archestra слова `taint` в коде нет вовсе, а механизм называется `contextIsTrusted`. Порядок:
   найти каталог (`git ls-files | grep -i <тема>`), прочитать типы, потом грепать вызывающих.
4. **Дампы чужих README отравляют счётные грепы.** У них это `mcp-catalog/data/mcp-evaluations/*.json`
   — один греп по общему слову вытащил мегабайт чужого текста в контекст. Все считающие грепы гнать
   с `--glob '!mcp-catalog/**'` (в любом репозитории — сперва найти такой каталог-помойку).
5. **Дословные цитаты с сайта — `curl` + снятие тегов питоном, НЕ `WebFetch`** (тот пересказывает
   маленькой моделью). Сохранённый HTML потом даёт бесплатный отрицательный контроль:
   `grep -c '60,000' landing.html blog.html` → 1 и 0, то есть число живёт ровно на лендинге.

## `rg -rn` — это НЕ «recursive + numbers»

`-r` в ripgrep это `--replace`. `rg -rn 'X' file` печатает совпадения с текстом, заменённым на
строку «n», и выглядит это как осмысленный, но неверный вывод. В #470 один такой греп соврал мне
про имена констант. Рекурсия у `rg` включена по умолчанию; нужны номера строк — только `-n`.

## Контракт `.orchestra/kb/` — три правила, на которых валидатор валит

`scripts/check_kb_contract.py --root .orchestra/kb --diff <patch>` проверяет ТОЛЬКО добавленные и
изменённые строки, поэтому легаси-строки рядом могут выглядеть иначе и это не образец:

1. Разделитель перед `искать:` — **` · `**, а не `;`. Легаси-факты написаны с `;` и проходят, потому
   что их не меняли; новая строка с `;` падает с «missing 'искать:' literal anchors».
2. Факт обязан быть **одной физической строкой**. Перенос по ширине даёт «fact fields must stay on
   the fact bullet line».
3. В `## Пробелы` структурные `- \`fact:\`` буллеты **запрещены** («structured facts belong only in
   Установлено or Отвергнуто») — там обычный текст. Модуль `research-method` показывает Пробелы с
   `fact:`-ключами; в споре побеждает валидатор, он и есть гейт мержа.

Проверять до коммита: `git diff -- .orchestra/kb > /tmp/kb-<id>.patch` и прогон валидатора.

## Гейт ревью для ресёрча

Предмет «проза/извлечение фактов» → маршрут 5 в `codex-debate`: сперва механические проверки
полноты, и для короткого low-consequence извлечения они могут быть финальным гейтом. Практическая
форма, которая реально ловит выдуманные ссылки (наш класс дефекта из #345): скрипт, вытаскивающий
из своего же `research.md` все `путь:строка` и печатающий ФАКТИЧЕСКИЙ текст каждой строки. Артефакт
кладётся рядом (`anchor-check.txt`) и цитируется в отчёте числом «N/N ok». Базы путей стоит
перечислить заранее (`platform/`, `platform/backend/src/`, `docs/pages/`), плюс fallback по
basename через `git ls-files -- '*/<файл>'`, иначе куча ложных MISSING на упоминаниях без каталога.
