# salvage-memory-branch — личная память

## Ревизия старой ветки: «файл есть на ветке, нет в main» ничего не значит (#513)

Отставшая ветка выглядит как работа: `git diff --diff-filter=A main <ветка>` показал 50
«новых» файлов, а своей работы в них было 6. Порядок, который решает вопрос за три команды
и не требует читать код файла вообще:

1. `git log --diff-filter=D -1 main -- <путь>` — main его удалил? Сообщение коммита обычно
   само называет причину и номер задачи.
2. `git rev-parse <ветка>:<путь>` против `git rev-parse <коммит-удаления>^:<путь>` — совпали
   blob'ы → ветка не внесла в файл ни строки, это чистый остаток.
3. Пусто на шаге 1 → файла в истории main не было вообще. **Только это кандидат в реальную
   неслитую работу.**

Замер #513: 17 из 20 файлов кода побайтово совпали с версией main перед удалением, ещё 3
оказались СТАРШЕ main (ветка не имела поздних правок main). Коммиты такой ветки — переписанные
копии коммитов main: совпадают дата и текст сообщения, различается только хеш. Не принимай их
за самостоятельную историю.

**И считай цену мержа с другой стороны:** `git diff --diff-filter=D --name-only main <ветка>`
дал 17 103 файла, которые есть в main и которых нет на ветке, включая всю `.orchestra/kb/`.
Аргумент «ветка устарела» слабее аргумента «мерж сотрёт 17 тысяч файлов».

## Живой агент или мёртвый — только строка `sessions`, не список в чате (#513)

`list_agents` показывает текущих; архивированные там не видны, и «нет в списке» не значит
«не существовал». Точный ответ:
`sqlite3 file:/mnt/data/Projects/Python/orchestra/data/orchestra.db?mode=ro` (URI, read-only,
боевую БД не трогает) → `SELECT name, status, created_at FROM sessions WHERE name=?`.
`status='archived'` = убит, `idle`/`running` = жив.

Так закрылся весь спорный кусок #513: аудит #188 снёс 17 файлов памяти «агентов, которых нет
в живой БД», но по одному из них ошибся — строка была на месте. Прежде чем повторять чужой
вывод об удалении, сверь его первоисточник сам: аудит, ошибшийся один раз, не помечен как
ошибочный нигде.
