Задача #177 — цена фаз `full-cycle`. Здесь только то, что переиспользуемо в следующий раз.

## Как мерить время фаз агента по логам

`sessions.total_turns` для Codex-бэкенда равен нулю, а `turn_usage.task_id` заполнен редко —
ни то ни другое для замера фаз не годится. Работает пара событий из таблицы `logs`:

- **начало хода** — запись `type='user_message'`;
- **конец хода** — запись `type='status'`, содержимое начинается с `turn ended (`; там же в
  скобках лежит стоимость хода (`$X turn`).

Сумма разностей по этим парам = **активное время**, простой между ходами в него не попадает.
Это принципиально: настенное время сессии завышает в разы (сессии висят idle сутками).

Фазы размечаются конечным автоматом по `type='text'`: `RESEARCH DONE` закрывает research,
`PLAN READY` закрывает plan, `DONE #` закрывает реализацию. Готовый скрипт —
`.orchestra/tasks/177/turns.py`, агрегация — там же рядом.

Что этим меряется помимо минут: **плотность tool-вызовов на активную минуту**. Она разделяет
«агент думал» и «агент ждал» — на #177 ресёрч дал 3.0 вызова/мин против 2.1 у реализации, и
это опровергло гипотезу, что фазы тормозят из-за ожидания.

## Грабли, на которые наступил лично

- **Правки промптов ушли в главный чекаут, а не в worktree.** Я собрал абсолютные пути
  (`/home/kesha/orchestra/.orchestra/pipelines/...`), потому что до этого читал файлы оттуда же для
  замера. `main` оказался грязным на трёх файлах. Лечение: `git diff > /tmp/x.patch` в главном,
  `git checkout --` там же, `git apply` у себя. **Правило: если задача требует ЧИТАТЬ главный
  чекаут, все пути на ЗАПИСЬ строить только относительными от своего cwd.**
- **Гейты я сначала объявил дорогими по `gap_before` между ходами.** Оказалось, большие паузы
  (196, 278, 171 мин) лежат внутри фазы реализации и вызваны лимитами квоты, а сами гейты
  стоят 1 и 0 минут медианы. Мерить надо интервал от хода с гейт-маркером до следующего хода,
  а не любой разрыв.

## Про доказательность чужого ревью

Перед тем как считать пользу ревью по историческим артефактам — **раздели выборку по дате,
когда инструмент был исправен**. На #177 все три «ревью ничего не нашло» из VPS-эпохи оказались
прогонами со сломанной песочницей; без разделения вышел бы вывод «ревью бесполезно», основанный
на поломке инструмента.

Проверять вердикт так: требовать **дословную строку из артефакта, которой не было в запросе**,
и прогонять её `grep -F` по файлу. Голая ссылка `file:line` не годится — ревьюер возвращает
путь из твоего же запроса. Следствие для формулировки запроса: **не цитируй ревьюеру содержимое
файлов**, давай пути и требуй цитату, иначе сам вручаешь ему материал для пересказа.
