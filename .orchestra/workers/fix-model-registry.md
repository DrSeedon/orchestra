# fix-model-registry — личная память

## Превращаешь литеральный словарь в ПРОИЗВОДНЫЙ — два капкана, оба молчаливые

1. **Кто-то читает этот словарь на import-time ВЫШЕ по файлу, чем стоит заполнение.**
   В `app/models.py` так был устроен `_REVIEWED_PROXY_ROUTES`: comprehension по `BACKENDS`/
   `MODEL_PROVIDERS` на строке 283, а заполнение — на 380. Получился бы dict без единой
   hardcoded-модели, без ошибки и без падения. Ловится за секунду:
   `grep -n "IMYA\[\|for .* in IMYA\b" file.py` и сверить номера строк с точкой заполнения.

2. **Словарь нельзя ПЕРЕСОЗДАВАТЬ, если его импортируют по имени.**
   `from app.models import CONTEXT_LIMITS` в `manager.py` связывает конкретный объект.
   `CONTEXT_LIMITS = {...}` после этого = у импортёра остаётся старый пустой. Только
   `IMYA: dict[...] = {}` один раз + наполнение in-place.

Проверка производности — мутацией, а не тестом, который сам же написал: добавить фиктивную
запись В ОДНО место, прогнать `python3 -c` по всем производным, откатить, посчитать маркер ДО и
ПОСЛЕ (`cp` → мутация → `mv` обратно → `touch`).

## Реестр моделей Orchestra: где лежит правда о `context_length`

Числа дублируются между `app/models.py` и бэкендами (`backend_opencode.py`,
`backend_codex.py`, `backend_grok.py`). При расхождении бэкенд оказался прав: для
`claude-opus-4-6` в `COMPAT_MODEL_SPECS` стояло 1000000, в `backend_opencode.py:60` — 200000,
верное 200000. Суффикс `[1m]` в id — единственный маркер расширенного окна.

## Codex на >95% квоты отдаёт `weekly_quota_blocked` ДО ревью

Это отказ инструмента, а не ответ ревьюера → раунд не тратится, но и вердикта нет. Писать в
отчёт «вердикта нет, N попыток» дословным текстом ошибки. Не подменять Spark'ом: на финальных
ревью он замеренно пропускает баги, которые ловит Sol.
