## `light-dark()` в скилле html-artifacts описан НАОБОРОТ

Скилл (`.claude/skills/html-artifacts/SKILL.md`, `.orchestra/pipelines/default/prompts/skills/html-artifacts.md`)
пишет `light-dark(тёмное, светлое)`. По спецификации CSS порядок обратный:
**`light-dark(<значение для СВЕТЛОЙ темы>, <значение для ТЁМНОЙ>)`**.

Проверено эмпирически (#123): `--bg: light-dark(#f7f4ee, #14120e)` под
`color_scheme="light"` в Playwright дал светлый фон — то есть первым читается светлое.
Писать по спецификации, парентезу в скилле игнорировать. Сообщено оркестратору.

## Проверка артефакта рендером — что реально ловит дефекты

Одного `wait_for_selector` мало, он ловит только «страница не пустая». Что дало находки:

- **скриншот первого экрана 1440×900 и посмотреть на него глазами** — так нашлось, что
  `5 из 5 → 0 из 5` во flex-строке переносится в «5 из → 0 из / 5   5». Ни одна авто-проверка
  этого не видит;
- **`scrollWidth > clientWidth` по всем элементам** — ловит переполнение; SVG `<text>` даёт
  ложные срабатывания (у него эти свойства не про перенос), их отсеивать по `tagName`;
- **отдельный прогон на 390px** — проценты ширин колонок таблицы держат сетку только пока
  влезает содержимое; `td` с `white-space: nowrap` рвёт вёрстку именно там;
- **`emulate_media(media="print")` + прочитать вычисленные `background/color` у `body`** —
  дешевле, чем смотреть PDF, и доказывает, что `@media print` реально применился.

Метрика «уникальных цветов» врёт: акцент надо брать из **объявленного токена** `--accent`,
а не из частоты цвета на странице (частоты выигрывают статусные цвета).
