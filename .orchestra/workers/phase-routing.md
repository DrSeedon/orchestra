# Личная память: phase-routing

Задача #194 — роутинг моделей по фазам. Здесь только переиспользуемое.

## Квоты обоих рантаймов лежат в ТЕКСТЕ статус-строк, не в колонках

`turn_usage.quota_*` заполнены **только для Claude** (проверено: 1268 из 1279 строк claude, 0 из 365
codex). Расход пула Codex достаётся исключительно парсингом `logs.content` у записей
`type='status' AND content LIKE 'turn ended%'` — там `Codex 7d:NN%`, у Claude `5h:NN% 7d:NN%`.
`utilization` = процент ИЗРАСХОДОВАННОГО (сверено с `GET /api/usage`, поле `utilization`).

У Codex только одно окно (7d, `window_minutes: 10080`), пятичасового у него нет вовсе.

Логирование квоты Codex началось 11.08.2026 — раньше этой даты истории не существует, не искать.

## Δ пула НЕ раскладывается по сессиям

Дельта процента пула глобальна для рантайма: она отражает всю работу на нём за период. Числитель
(токены) подмножеству задать можно, знаменатель — нет. Поэтому любое «сравним только ревьюеров»
на пуловых метриках технически не считается, и это надо говорить сразу, а не после попытки.

## Токены: две ловушки, обе проверены

- **`cache_read` у Anthropic НЕ входит в `input_tokens`, у OpenAI входит.** Проверка одной командой:
  `sum(cache_read_tokens <= input_tokens)` — claude 24/1279, codex 365/365.
- **`reasoning_output_tokens` у Codex лежит ВНУТРИ `output_tokens`**, а не рядом. Доказательство из
  сырого rollout: `total_tokens` = `input_tokens` + `output_tokens` РОВНО, при непустом
  `reasoning_output_tokens`. Значит выходные токены Sol сравнимы с Opus напрямую. Смотреть в
  `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl`, грепать `"total_token_usage":{[^}]*}`.

## Разметка фаз по логам: где она врёт

Приём из `.orchestra/workers/audit-phase-overhead.md` рабочий, но у автомата два слепых пятна, и оба
надо мерить и публиковать вместе с результатом:

1. **Стартовое состояние — research.** Сессия, вошедшая в окно уже посреди реализации, целиком
   попадёт в ресёрч.
2. **Сессии без маркеров.** У меня 13 из 35 не выдали ни `RESEARCH DONE`, ни `PLAN READY`, ни
   `DONE #` — их 20.5% времени ушло в ресёрч по умолчанию. Считать это число ОБЯЗАТЕЛЬНО, иначе
   доля первой фазы завышена на неизвестную величину.

Ещё: у persistent-воркеров надо сбрасывать фазу на новом `#N`, иначе всё после первого DONE
схлопывается в мусорный бакет (у меня там лежало 12.4% расхода, пока не починил).

## Доли фаз зависят от ПОПУЛЯЦИИ, а не от единицы измерения

Моё «ресёрч 68% минут» и «#177: реализация 57% минут» не противоречат друг другу: #177 брал только
ПОЛНЫЕ прогоны, я — всю активность, где большинство задач стоит на гейте ресёрча. Ограничил себя
полными прогонами — реализация поехала с 20.8% на 29.0%.
**Мораль: прежде чем объяснять расхождение с чужим замером разницей единиц — проверь, не разные ли
это популяции. Посчитать обе величины в обеих единицах стоит одну команду.**

## Веб-ресёрч подзадачами окупается

Два подворкера на разных рантаймах (Opus — практика вендоров, Sol — arXiv и замеры) за один ход
принесли 27 проверенных источников, включая цитату Anthropic, перевернувшую вывод. Дешевле одного
хода аудита. Разные рантаймы — чтобы не словить общий уклон.

Но: **цитаты подворкеров — это не мои цитаты.** Помечать `[из выписки]` и лично открывать те, на
которых стоят рекомендации. Из 27 я проверил 4; ревью поймало ровно это место.

## Проверка внешних цитат

- arXiv: `https://arxiv.org/abs/NNNN.NNNNN` для названия/абстракта, `https://arxiv.org/html/...`
  для таблиц. Снимать теги регуляркой и грепать по числу — числа в HTML идут подряд с `± \pm`.
- **URL не угадывать.** Я выдумал `anthropic.com/engineering/building-multi-agent-systems`, получил
  404 и чуть не записал «цитата не подтверждается». Настоящий адрес был в выписке подворкера.
