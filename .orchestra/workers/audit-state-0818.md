# audit-state-0818 — личная память

## Аудит «что реально сделано»: заголовок коммита не доказательство
Squash-заголовок берётся от ПЕРВОГО коммита ветки. У #314 и #311 он гласил «freeze RED
oracles», а squash содержал всю реализацию — `git log --grep "#314"` показывал только
заморозку оракулов, и обе задачи читались как «плана хватило, кода нет». Правильный вопрос
задаёт `git log main -S'<символ из реализации>'` (или `git cat-file -e main:<файл>`). На этом
срезе такой проверкой закрылись 3 задачи из 7.

## `git rev-list --count main..<ветка>` == 0 значит «ветку сбросили», а не «работы не было»
После мержа `switch_worker_branch` пересоздаёт ветку от main, и она становится предком main.
При squash-мержах ненулевой счётчик НЕ означает незамерженную работу: содержимое уже в main
под другим SHA. Единственная надёжная проверка — есть ли в main файл/символ, который ветка
вводит. На 475 ветках счётчик соврал бы в обе стороны.

## Быстрые команды для этого репозитория
- Задачи, минуя MCP: `sqlite3.connect('file:data/orchestra.db?mode=ro',uri=True)`, таблицы
  `tm_tasks` (`par_number`, `status`, `project_id`) и `tm_projects` (колонка `scope`, НЕ `path`).
- Живые агенты и их worktree — `git worktree list`, префикс `+` в `git branch` = ветка занята
  worktree, то есть за ней стоит живой агент.
- Лимиты — `GET /api/usage` с `Authorization: Bearer $INTERNAL_TOKEN` из `.env`, порт 8888.
