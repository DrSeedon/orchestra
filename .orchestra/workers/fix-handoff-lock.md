# fix-handoff-lock — личная память

- **Диагностическое поле, добавленное в структуру, которая считается против бюджета
  (контекстное окно, размер payload), стоит токенов на КАЖДОЙ записи.** Вешать только на те
  записи, которым оно нужно, и померить рост. Замер #340: `call_ts` на всех эффектах пакета
  — 68 040 байт у `direct-research`, на одних незакрытых — 1 260. Пакет переноса истории
  входит в `build_model_visible_manifest`, то есть в preflight контекста цели.
- **`search_memory` на этом сервере отваливается по таймауту (5 с) и сам советует grep.**
  Не повторять вызов, сразу `grep -rn` по `docs/`, `CLAUDE.md`.
- **Снимок боевой БД для замеров:** `sqlite3.Connection.backup` в `/tmp`, дальше читать
  `file:/tmp/x.db?mode=ro`. `cp` при WAL отдаёт устаревший срез.
- **Проверять свою правку в проде — отдельным процессом с `sys.path.insert(0, <worktree>)`
  по строкам боевой БД.** Живой сервер держит старый `app/` в памяти до рестарта, а свой же
  MCP-тул ходит именно в него: проверка через тул покажет старое поведение и прочитается
  как «не работает».
