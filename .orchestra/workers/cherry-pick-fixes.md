# Worker memory — cherry-pick-fixes

## Прогон тестов в этом репозитории

`python -m pytest` от системного `/usr/bin/python` падает на коллекции:
`ModuleNotFoundError: No module named 'starlette'`. Рабочий интерпретатор один:

```
/mnt/data/Projects/Python/orchestra/.venv/bin/python -m pytest -q <files>
```

Он же корректно резолвит `app` в СВОЙ worktree — проверяется одной строкой:
`... -c "import app.ia.runtime as m; print(m.__file__)"`.

## Замер репозитория: не мерить себя

Считать `git ls-files | wc -l`, суммарные строки или число каталогов в дереве, которое ты уже
успел изменить (`git checkout <ref> -- <path>`, свои новые файлы), — значит включить в срез
собственную работу. Поймано на #519: срез завышал 18 089 вместо 18 083 файлов и 11 вместо 5
в `docs/**` ровно на шесть только что застейдженных файлов. Мерить надо от пина:
`git ls-tree -r --name-only <base-sha> [-- <path>] | wc -l`, и называть этот sha в документе.

## Узкие места правки markdown в этом проекте

В документах проекта разряды чисел разделены U+202F (narrow no-break space), не пробелом:
`67 694` → `67 694`. Инструмент `Edit` на таком тексте молча не находит строку. Признак —
«String to replace not found», хотя `Read` показывает ровно то же. Лечится питон-скриптом с
явным `N=" "` в исходнике; при передаче скрипта через bash-heredoc сам символ иногда
нормализуется в обычный пробел, поэтому надёжен только escape-литерал.

## Проверка путей после миграции раскладки #430

`docs/tasks|kb|workers/` и `pipelines/` переехали в `.orchestra/`, но ссылки ВНУТРИ файлов не
переписывались (`fact:layout-migration-leaves-code-references`). Сторож —
`scripts/check_orchestra_paths.py`; правильный результат `live_old_path_occurrences=0` и
`unclassified_old_path_occurrences=0`. Он различает живые и исторические ссылки, поэтому
большое `historical_old_path_occurrences` — норма, а не долг.

## Проверять «отставшую ветку» надо по содержимому, а не по журналу

На #519 три пункта из четырёх уже лежали в `main` под другими номерами задач (#398 приехал с
`bc1a388f`, #450 — с `ed30d73c`/#464, #365 — целиком, с уехавшим в `chat.js` фронтом).
Дешёвая проверка перед любым переносом: `git diff <исходный-коммит> HEAD -- <файлы>` —
пустой вывод означает «уже на месте», а `grep` по ключевым символам находит код, переехавший
в другой файл при последующем рефакторинге.
